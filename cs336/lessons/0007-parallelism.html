分布式训练并行

现代大模型不可能在一张 GPU 上训练。这一课系统讲解分布式训练的四种并行策略——data、tensor、pipeline、sequence——以及它们如何组合。统一主题：通过复制/分片来编排计算，避免数据搬运瓶颈。

授课：Percy Liang 预计用时：80 分钟 难度：困难

为什么需要分布式训练

规模的力量

# 单张 H100 (80GB) 能训多大的模型？
# 参数: 80GB / 20 bytes ≈ 4B 参数
# 但 70B, 405B, 1T+ 模型需要多 GPU

# 训练时间 vs GPU 数:
# 1 张 H100 训 70B 15T tokens: ~162 天
# 1024 张 H100: ~1.5 天（理想线性加速）

统一主题

上一课（单 GPU）：通过 fusion/tiling 减少内存访问

这一课（多 GPU）：通过复制/分片减少跨 GPU 通信

核心权衡：计算 vs 内存 vs 通信——你可以选择重算、存内存、或存到另一张 GPU 然后通信。

通信原语

七种基本通信操作

操作输入输出描述
Broadcast1 个 GPU 有数据所有 GPU 有数据一对多
Scatter1 个 GPU 有大数据所有 GPU 各有一片分片分发
Gather所有 GPU 各有一片1 个 GPU 有大数据收集
Reduce所有 GPU 有数据1 个 GPU 有结果聚合（sum/max）
All-Gather所有 GPU 各有一片所有 GPU 有完整数据Gather 到所有
Reduce-Scatter所有 GPU 有完整数据所有 GPU 各有一片结果Reduce + Scatter
All-Reduce所有 GPU 有数据所有 GPU 有结果Reduce + Broadcast

关键等式

All-Reduce = Reduce-Scatter + All-Gather

# 直觉:
# Reduce-Scatter: 每个 GPU 得到最终结果的 1/N
# All-Gather: 把所有片拼起来，每个 GPU 都有完整结果

带宽分析

# All-Reduce 的通信量（ring algorithm）:
# 每个 GPU 发送: 2 × (N-1)/N × data_size
# 近似: 2 × data_size（与 N 无关！）

# Reduce-Scatter:
# 每个 GPU 发送: (N-1)/N × data_size
# 近似: data_size

# All-Gather:
# 每个 GPU 发送: (N-1)/N × data_size
# 近似: data_size

Data Parallelism (DP)

核心思想

每个 GPU 持有完整模型，处理不同的数据片。梯度通过 all-reduce 同步。

# Data Parallelism 流程
for each GPU in parallel:
    # 1. 获取不同的数据片
    x_local = data[rank * batch_size : (rank+1) * batch_size]

    # 2. 前向传播（本地计算）
    loss = model(x_local)

    # 3. 反向传播（计算本地梯度）
    loss.backward()

    # 4. 同步梯度（通信！）
    all_reduce(gradients)  # 所有 GPU 得到平均梯度

    # 5. 更新参数（所有 GPU 同步更新）
    optimizer.step()

通信开销

# 每步通信: All-Reduce 梯度
# 数据量: 参数量 P × 4 bytes (fp32) 或 P × 2 bytes (bf16)
# 70B 模型: 70×10⁹ × 4 = 280 GB（fp32 梯度）

# 在 NVLink (900 GB/s):
# 时间 ≈ 280 / 900 ≈ 0.31 秒

# 在 InfiniBand (50 GB/s):
# 时间 ≈ 280 / 50 ≈ 5.6 秒 ← 慢 18×！

Gradient Accumulation

当 batch size 太大，单 GPU 放不下时：

# 把一个大 batch 拆成多个 micro-batch
optimizer.zero_grad()
for micro_batch in micro_batches:
    loss = model(micro_batch)
    loss.backward()  # 梯度累积

# 只在最后一个 micro-batch 后通信
all_reduce(gradients)
optimizer.step()

Gradient Accumulation 的好处：

  • 模拟大 batch size（对训练稳定性重要）
  • 减少通信频率（每 N 个 micro-batch 通信一次）
  • 通信量不变（最终还是要同步所有梯度）

DDP vs FSDP

策略参数存储通信内存
DDP每个 GPU 完整副本All-Reduce 梯度高（冗余）
FSDP参数分片，需要时 All-GatherAll-Gather + Reduce-Scatter低（近乎 1/N）

Tensor Parallelism (TP)

核心思想

把模型的宽度切分到多个 GPU——每个 GPU 只持有参数的一部分。

# 标准 Linear 层: Y = X @ W
# W: (D_in, D_out)

# Tensor Parallel: 把 W 按列切分
# GPU 0: W_0: (D_in, D_out/2)  → Y_0 = X @ W_0
# GPU 1: W_1: (D_in, D_out/2)  → Y_1 = X @ W_1

# 需要 All-Gather 把 Y_0 和 Y_1 拼起来: Y = [Y_0, Y_1]

Megatron-LM 的切分策略

对于 Transformer 的 FFN 和 Attention，有特定的切分方式：

# FFN 的列切分 (Column Parallel):
# Y = X @ W_gate  → 切分 W_gate → All-Gather
# Y = X @ W_up    → 切分 W_up → All-Gather
# 然后 element-wise: Y = Swish(Y_gate) * Y_up
# 最后 W_down 行切分 → Reduce-Scatter

# Attention 的切分:
# W_q, W_k, W_v 按 head 切分（每个 GPU 负责部分 head）
# W_o 行切分 → All-Reduce

通信模式

# Transformer block 的 TP 通信:
# 1. Attention:
#    - Q, K, V 计算: 无需通信（head 独立）
#    - W_o: All-Reduce

# 2. FFN:
#    - W_gate, W_up: All-Gather
#    - W_down: Reduce-Scatter

# 总计: 每个 block 2 次 All-Reduce

TP 的代价：每次切分都需要通信，且通信必须在计算前/后立即发生（同步）。这意味着 GPU 经常处于等待状态。

TP 适合节点内（NVLink 900 GB/s），不适合跨节点（InfiniBand 50 GB/s）。

切分示例（4 GPU）

# 假设 d_model = 4096, num_heads = 32
# 每 GPU: 8 个 head, d_model_per_gpu = 1024

# W_q: (4096, 4096) → 切成 4 份: 每 GPU (4096, 1024)
# W_k: (4096, 4096) → 切成 4 份: 每 GPU (4096, 1024)
# W_v: (4096, 4096) → 切成 4 份: 每 GPU (4096, 1024)
# W_o: (4096, 4096) → 切成 4 份: 每 GPU (1024, 4096)

Pipeline Parallelism (PP)

核心思想

把模型的深度切分到多个 GPU——每个 GPU 持有连续的几层。

# Pipeline Parallel: 4 GPU, 16 层
# GPU 0: layers 0-3
# GPU 1: layers 4-7
# GPU 2: layers 8-11
# GPU 3: layers 12-15

# 数据流:
# Input → GPU 0 → activations → GPU 1 → ... → GPU 3 → Output

Pipeline Bubble

朴素的 pipeline 有大量空闲时间——"bubble"：

# 朴素 pipeline (4 stages, 1 batch):
# Time →
# GPU 0: [====L0-3====]  idle   idle   idle
# GPU 1:  idle  [====L4-7====]  idle   idle
# GPU 2:  idle   idle  [====L8-11===]  idle
# GPU 3:  idle   idle   idle  [====L2-15===]

# Bubble 比例: (p-1) / m
# p = pipeline stages, m = micro-batches
# 当 m >> p 时，bubble 可以忽略

1F1B Schedule（One Forward One Backward）

减少 bubble 的关键技术：

# 1F1B: 每个 stage 交替做 forward 和 backward
# 而不是等所有 forward 做完再做 backward

# 4 stages, 8 micro-batches:
# Time →
# GPU 0: F0 F1 F2 F3 B0 F4 B1 F5 B2 F6 B3 F7 B4 B5 B6 B7
# GPU 1: -- F0 F1 F2 B0 F3 B1 F4 B2 F5 B3 F6 B4 F7 B5 B6 B7
# ...
# Bubble 从 75% 降到 ~25%！

通信量

# Pipeline Parallel 的通信:
# 每对相邻 GPU 之间只传 activations
# 数据量: batch_size × seq_len × d_model × 2 (bf16)

# 例如: B=4, S=4096, D=8192
# = 4 × 4096 × 8192 × 2 = 256 MB（很小！）

# 但这是 P2P 通信，不能 overlap

TP vs PP 的选择：

  • TP：通信量大，但通信快（NVLink）。适合节点内。
  • PP：通信量小，但通信慢（跨节点）。适合跨节点。

实际中：节点内用 TP（8 GPU），跨节点用 PP/DP。

Sequence Parallelism (SP)

动机

当序列极长时（128K+），即使 TP 也无法放下所有激活。

核心思想

# 标准 TP 只切分宽度维度
# Sequence Parallel 额外切分序列维度

# 具体做法:
# 1. LayerNorm / Dropout 是逐 token 独立的 → 自然在序列维度并行
# 2. 输入 embedding 按序列切分到不同 GPU
# 3. Attention 内部需要完整序列（Q @ K^T）→ 做 All-Gather
# 4. 输出再 Scatter 回各 GPU

# 效果: LayerNorm 和 Dropout 的激活内存减少 1/N

混合并行策略

3D / 4D 并行

实际训练大规模模型时，所有并行策略组合使用：

# Llama 3 405B 训练配置:
# - 数据并行 (DP): 跨节点
# - 张量并行 (TP): 节点内 (8 GPU)
# - 流水线并行 (PP): 跨节点组
# - 序列并行 (SP): 长上下文

# 总 GPU 数 = DP_degree × TP_degree × PP_degree

并行策略选择

场景推荐策略原因
单节点 8 GPUTP=8NVLink 快，通信开销小
多节点，小模型DP + FSDP通信少，简单
多节点，大模型TP=8 + PP + DP节点内 TP，跨节点 PP
极长上下文+ SP减少序列维度内存

实际配置示例

# 训练 70B 模型，16 节点 (128 GPU):
# TP = 8 (节点内)
# PP = 4 (4 个 stages)
# DP = 128 / (8 × 4) = 4 (数据并行)
# 总计: 8 × 4 × 4 = 128 GPU

# 每个 GPU 内存:
# 参数: 70B / (8 × 4) = ~2.2B 参数
# 激活: 取决于 micro-batch size
# 梯度: 同参数
# 优化器: 2 × 参数 (AdamW)
# 总计: ~2.2B × 16 bytes = ~35 GB（放得下！）

通信量对比

并行策略通信类型每步通信量频率
Data ParallelAll-Reduce2P（梯度）每步
Tensor ParallelAll-Reduce × 22 × B×S×D × 2每层
Pipeline ParallelP2P send/recvB×S×D × 2stage 边界
FSDP (ZeRO-3) All-Gather + Reduce-ScatterP（参数）每层

统一视角：

  • DP/FSDP：复制参数，同步梯度
  • TP：分片参数，同步激活
  • PP：分片层，传递激活

每种策略都在"计算冗余 vs 内存节省 vs 通信开销"之间做权衡。
