如何开始？

0

Profile 优先

在写任何优化代码之前，先用 nsys/ncu 对基线实现做 profile。理解时间花在哪里、内存带宽利用率如何。不要凭直觉优化——数据说话。

1

理解 Triton 抽象

Triton 的编程模型不同于 CUDA：你写的是 block-level 的代码，编译器帮你处理内存合并和 shared memory。先读 Triton 文档，理解 tl.load、tl.store、tl.dot 的语义。

2

Fused RMSNorm → FlashAttention

建议的实现顺序：

  1. Fused RMSNorm — 第一个 Triton kernel，理解元素级操作如何合并
  2. FlashAttention-2 — 核心难点，理解 tiling 和 online softmax 如何避免 materialize 完整的 attention matrix
  3. DDP — 理解 AllReduce 如何同步梯度
  4. ZeRO Stage 1/2/3 — 逐步增加内存优化
3

Benchmark 和验证

每个优化后都要做两件事：正确性验证（与 PyTorch 参考实现对比）和性能测试（测量加速比）。注意：先保证正确，再追求速度。

常见陷阱

Memory coalescing： GPU 对 global memory 的访问以 32/128 字节为单位。如果相邻 thread 访问不连续的地址，会导致 bandwidth 利用率极低。

Bank conflict： Shared memory 分为 32 个 bank。如果同一 warp 中多个 thread 访问同一 bank 的不同地址，访问会串行化。

Numerical precision： FlashAttention 在 fp16/bf16 下做 reduction 时要注意累加顺序。online softmax 的数值稳定性证明需要理解。

Communication overhead： DDP 的 AllReduce 如果和计算不重叠，会成为瓶颈。注意 gradient bucketing 和 gradient accumulation 的影响。

Triton 的自动优化： Triton 编译器会做很多优化（如自动使用 tensor core），但也可能做出你不期望的选择。学会读 PTX/LLVM IR 来理解实际生成的代码。

Profiling 与 Benchmark 方法

常用工具

# 用 nsys 做时间线 profile
nsys profile -o output python train.py

# 用 ncu 做 kernel 级分析
ncu --set full -o report python train.py

# PyTorch profiler（高层视图）
with torch.profiler.profile() as prof:
    train_step()
print(prof.key_averages().table())

Benchmark 原则

  • Warmup：第一次运行通常慢（JIT 编译、CUDA 初始化），丢弃前几次
  • 多次采样取平均：GPU 频率波动会影响结果
  • 控制变量：只改变你要测试的那一个因素
  • 报告 wall-clock time 和 throughput：tokens/second 比 FLOPs 更直观
