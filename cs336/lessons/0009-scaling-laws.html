Scaling Laws

给定固定计算预算，应该训练多大的模型、用多少数据？这不是直觉问题，是可量化的科学问题。这一课讲 Kaplan et al. 2020 和 Hoffmann et al. 2022 的 scaling laws，以及它们如何改变了大模型训练的范式。

授课：Tatsu Hashimoto 预计用时：80 分钟 难度：中等

为什么需要 Scaling Laws？

核心问题

问题：给定 100 万美元的训练预算，应该训练多大的模型、用多少数据？

  • 小模型 + 多数据？
  • 大模型 + 少数据？
  • 某个中间配置？

在没有 scaling law 之前，这些决策主要靠直觉和试错。有了 scaling law，我们可以在小模型上做实验，预测大模型的最优配置。

历史背景

时间事件影响
2020 年 1 月Kaplan et al. (Chinchilla 前作)首次提出幂律关系
2020 年 5 月GPT-3 发布验证了"大模型 + 少数据"的路线
2022 年 3 月Hoffmann et al. (Chinchilla)发现 GPT-3 训练不足
2022 年 9 月Llama 发布遵循 Chinchilla 比例

Kaplan et al. 2020：幂律关系

核心发现

语言模型的 loss 与模型大小、数据量、计算量之间存在幂律关系：

# 模型大小 N 的幂律
L(N) = (N_c / N)^α_N

# 数据量 D 的幂律
L(D) = (D_c / D)^α_D

# 其中:
# N_c, D_c 是常数
# α_N ≈ 0.076, α_D ≈ 0.095 (Kaplan et al. 的值)

直觉理解

  • 模型翻倍 → loss 降 ~5%（α_N ≈ 0.076 意味着 2^0.076 ≈ 1.054，即 loss 降 5.4%）
  • 数据翻倍 → loss 降 ~6.5%（α_D ≈ 0.095 意味着 2^0.095 ≈ 1.068）
  • scaling 的回报递减（对数尺度下线性）

Isoflop 曲线

给定固定计算预算 C（FLOPs），最优的 N 和 D 满足：

# 计算量公式
C ≈ 6 × N × D

# Kaplan et al. 的发现:
N_opt ∝ C^0.73
D_opt ∝ C^0.27

# 含义: 计算预算增加时，应该主要增大模型，少量增加数据

GPT-3 的路线

GPT-3 175B 只用了 ~300B tokens（约 2× 模型参数数），远低于 Chinchilla 推荐的 20×。

根据 Kaplan et al. 的 scaling law，这是合理的——模型大小比数据量更重要（α_N > α_D）。

Kaplan et al. 的偏差：他们的实验中，大模型往往训练不足（没训到收敛）。这导致他们低估了数据的重要性，得出了"模型越大越好"的结论。

Chinchilla (Hoffmann et al. 2022)

核心发现

DeepMind 的 Chinchilla 论文重新做了实验——确保每个模型都训练到收敛：

# Chinchilla 的 scaling law
N_opt ∝ C^0.50
D_opt ∝ C^0.50

# 或者等价地:
D_opt ≈ 20 × N_opt

# 含义: 模型和数据应该等比例增长

Chinchilla vs Gopher

模型参数量训练 tokens比例Loss
Gopher280B300B1:1基准
Chinchilla70B1.4T1:20更低！

Chinchilla 70B 在所有 benchmark 上击败 Gopher 280B——用 1/4 的参数量，20× 的数据。

为什么 Kaplan 和 Chinchilla 结论不同？

# Kaplan et al. 的实验设置:
# - 小模型训到收敛
# - 大模型训练步数不够（没训完）
# → 大模型的 loss 被高估 → 低估了数据的重要性

# Hoffmann et al. 的实验设置:
# - 所有模型都训到收敛
# - 25 个不同计算预算，每个做 4 个 (N, D) 组合
# → 更准确的 scaling law

Chinchilla 公式

更精确的 loss 预测公式：

L(N, D) = E + A/N^α + B/D^β

其中:
E ≈ 1.69 (irreducible loss, 数据本身的熵)
A ≈ 406.4, α ≈ 0.34
B ≈ 410.7, β ≈ 0.28

# 给定计算 C = 6ND:
N_opt = G × (C/6)^b
D_opt = G' × (C/6)^(1-b)

其中 G = (αA / βB)^(1/(α+β)), b = α/(α+β) ≈ 0.55

如何拟合 Scaling Law

实验设计

# Step 1: 选择一系列模型大小
model_sizes = [70M, 130M, 350M, 700M, 1B, 2B, 4B, 8B, 16B]

# Step 2: 对每个模型，选择多个训练步数
# (不同步数 = 不同数据量 D)

# Step 3: 训练并记录 loss
# 得到 (N, D, L) 三元组列表

# Step 4: 拟合 L(N, D) = E + A/N^α + B/D^β
# 用 L-BFGS 或类似优化器

拟合的注意事项

常见陷阱：

  • 训练不足：大模型需要更多步数才能收敛
  • 学习率不匹配：不同大小模型的最优 lr 不同
  • batch size 不匹配：影响 loss 曲线
  • 数据质量：不同实验用相同数据

Isoflop 曲线绘制

# 固定计算 C，变化 N 和 D = C/(6N)

C = 10^18  # 1 exaFLOP
for N in [100M, 300M, 1B, 3B, 10B]:
    D = C / (6 * N)
    # 训练并记录 loss
    # 找到该 C 下最优的 N

# 对多个 C 重复 → 得到 isoflop 曲线

Scaling Laws 的影响

对模型设计的意义

# Chinchilla 比例: D = 20 × N
# 这意味着:
# - 7B 模型 → 140B tokens
# - 70B 模型 → 1.4T tokens
# - 700B 模型 → 14T tokens

# 数据需求增长极快！
# 这也是为什么数据成为瓶颈

对训练策略的意义

  • 不要 under-train 大模型：大模型需要更多数据才能发挥优势
  • 小模型做超参搜索：用小模型找到最优超参，再 scale up
  • 预测大模型 loss：用小模型的 loss 曲线预测大模型

对推理的意义

# Chinchilla 对推理的影响:
# - 70B 模型 (Chinchilla) vs 175B 模型 (GPT-3)
# - 70B 推理更快（小模型）
# - 但训练成本更高（更多数据）

# 训练成本 vs 推理成本的权衡:
# 如果推理是主要成本 → 训练更多数据的小模型
# 如果训练是主要成本 → 训练更少数据的大模型

争议与局限

批评 1：Chinchilla 比例可能不适用于更大尺度

Chinchilla 的拟合基于 ~10B 以下的模型。外推到 1T+ 模型可能不准确。

一些后续研究（如 Llama 3）认为更大的模型可能需要更多数据。

批评 2：只优化 loss 不够

Chinchilla 优化的是 next-token prediction loss。但用户关心的是：

  • 指令遵循能力
  • 推理能力
  • 安全性
  • 这些能力的 scaling 行为可能不同

批评 3：数据质量被忽略

# Chinchilla: D = 20 × N
# 假设所有 token 等权

# 实际上:
# 高质量 token 的价值可能是低质量 token 的 10×
# → 1T 高质量 token 可能比 10T 低质量 token 更好

# 这也是为什么数据过滤如此重要

批评 4：架构的影响

Scaling law 是在特定架构（标准 Transformer）上拟合的。

MoE、SSM、线性 attention 的 scaling 行为可能不同。

批评 5：batch size 的影响

# Chinchilla 假设 batch size 固定
# 但实际上:
# - 大 batch 训练更高效（更好的硬件利用率）
# - 但大 batch 需要调整学习率（linear scaling rule）
# - 最优 batch size 随模型大小变化

Beyond Chinchilla

Fine-tune Scaling Laws

SFT/RLHF 阶段的 scaling 行为和 pre-training 不同：

  • Fine-tune 数据少得多（10K-100K samples）
  • Loss 下降更快
  • 过拟合是主要风险

Test-time Compute Scaling

OpenAI o1/o3 的新范式——推理时投入更多计算：

# 传统: 固定模型，单次前向
output = input → model → answer

# Test-time compute: 推理时多步思考
for step in range(reasoning_steps):
    thought = model.generate_thought(context)
    context += thought
    if should_stop(thought):
        break
answer = model.generate_answer(context)

Data-Centric Scaling

不再追求更多数据，而是追求更好的数据：

  • 数据过滤（去低质量）
  • 数据去重（减少冗余）
  • 数据混合（平衡不同来源）
  • 合成数据（针对性增强）

实践指南

如何为你的模型找最优配置

# Step 1: 确定计算预算

# Step 3: 在小模型上验证
# 训练 4-5 个不同大小的模型（10M - 1B）
# 拟合 scaling law 参数

# Step 4: 外推到大模型
# 预测最优 N 和 D

# Step 5: 训练目标模型，监控 loss
# 如果 loss 高于预测，可能需要更多数据
