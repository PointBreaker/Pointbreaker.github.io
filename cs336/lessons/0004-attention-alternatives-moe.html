注意力替代方案与混合专家

标准 attention 的 $O(n^2)$ 复杂度是 Transformer 的致命瓶颈。这一课探索两条突围路径：(1) 设计更高效但近似的注意力机制；(2) 用稀疏激活的 MoE 让模型容量随参数增长而计算量亚线性增长。

授课：Tatsu Hashimoto 预计用时：80 分钟 难度：中等 → 困难

标准 Attention 的瓶颈

$O(n^2)$ 问题

标准 self-attention 对长度为 n 的序列：

scores = Q @ K^T    # (n, d) @ (d, n) → (n, n)  ← $O(n^2)$ FLOPs
attn = softmax(scores)
output = attn @ V   # (n, n) @ (n, d) → (n, d)  ← $O(n^2)$ FLOPs

内存: 需要存储 (n, n) 的 attention matrix

当 n = 128K（长上下文），n² = 16G 元素，光 attention matrix 就要 ~32 GB（bf16）。这就是为什么需要替代方案。

两条突围路径

路径思路代表
高效 attention近似或稀疏化 attentionLinear Attention, FlashAttention
稀疏激活每次只激活部分参数Mixture of Experts

注意力替代方案

1. Linear Attention

核心思想：把 softmax 去掉，用核函数近似：

# 标准 attention: $O(n^2)$
attn = softmax(Q @ K^T / $√$d) @ V

# Linear attention: $O(n^2)$
# 利用 (Q @ K^T) @ V = Q @ (K^T @ V) 的结合律
# 先算 K^T @ V（d $\times$ d），再算 Q @ (K^T @ V)
output = $φ$(Q) @ ($φ$(K)^T @ V)  # $φ$ 是核函数（如 ReLU, elu+1）

# 复杂度: $O(n^2)$ —— 当 n >> d 时远优于 $O(n^2)$

关键洞察：矩阵乘法满足结合律。标准 attention 先算 (Q @ K^T) 得到 n$\times$n 矩阵，再乘 V。Linear attention 先算 (K^T @ V) 得到 d$\times$d 矩阵，再被 Q 乘。当 n >> d 时，后者快得多。

代价：失去了 softmax 的"聚焦"能力——所有 token 被平等对待，无法动态关注最相关的 token。

2. Sliding Window Attention

Mistral 7B 和 LongFormer 使用：

# 每个 token 只看前后 w 个 token
for i in range(n):
    scores[i] = Q[i] @ K[max(0,i-w):i+w]^T  # 只看窗口内的 key
    attn[i] = softmax(scores[i])
    output[i] = attn[i] @ V[max(0,i-w):i+w]

# 复杂度: $O(n^2)$ —— 线性于 n

直觉：大多数语言建模任务中，附近的 token 比远处的更重要。

3. Sparse Attention（全局 + 局部混合）

# 大多数层用 sliding window
# 少数层用 full attention（"全局层"）
# 例如: 每 6 层有 1 层全局 attention

# 有效上下文 = windo$w_{size}$ $\times$ nu$m_{layers}$
# 例如: w=4096, L=32 → 有效上下文 ~128K

4. State Space Models（Mamba）

完全抛弃 attention，用经典控制论的状态空间模型：

# SSM: 递推形式
h(t) = A $\times$ h(t-1) + B $\times$ x(t)
y(t) = C $\times$ h(t)

# 训练时: 展开为卷积（并行）
# 推理时: 递推（$O(n^2)$ 内存）

# Mamba 的改进: A, B, C 是输入相关的（选择性 SSM）
# 让模型学会"忘记"不相关的信息

SSM 的弱点：不擅长 associative recall（"找到之前出现过的 X"）。Transformer 的 attention 天然支持这个，SSM 需要极大的 state 维度才能近似。

方法训练复杂度推理内存长程依赖

Grouped-Query Attention (GQA)

从 MHA 到 MQA 到 GQA

# Multi-Head Attention (MHA)
# N 个 Q 头, N 个 K 头, N 个 V 头
# KV cache: N $\times$ $d_{head}$ $\times$ 2 (K+V) per token per layer

# Multi-Query Attention (MQA)
# N 个 Q 头, 1 个 K 头, 1 个 V 头
# KV cache: 1 $\times$ $d_{head}$ $\times$ 2 per token per layer
# 问题: 质量损失大（所有 Q 头被迫共享同一个 K/V）

# Grouped-Query Attention (GQA)
# N 个 Q 头, K 个 KV 头 (1 < K < N)
# 每 N/K 个 Q 头共享 1 个 KV 头
# KV cache: K $\times$ $d_{head}$ $\times$ 2 per token per layer

为什么 GQA 有效？

KV cache 是推理瓶颈：生成一个 token 时，需要读取所有层的 KV cache。对于长序列和大 batch，这占了推理时间的大部分。

GQA 把 KV cache 缩小 N/K 倍（例如 8 倍），直接提升推理速度。

实际效果

# Llama 2 70B 配置:
# $n_{heads}$ = 64, $n_{kv}$_heads = 8
# GQA ratio = 8:1
# KV cache 缩小 8 倍！

# 质量影响: 几乎无损
# Ainslie et al. (2023) 论文显示:
# GQA $≈$ MHA 的质量，但快得多
# MQA 质量明显下降

Multi-head Latent Attention (MLA)

DeepSeek-V2 的进一步创新：

# 不存储完整的 K, V 向量
# 存储一个低秩压缩的 "latent" 向量 c (C 维)
# 需要时通过上投影恢复 K, V

# KV cache 存储: C 维 (而不是 N $\times$ $d_{head}$ = 16384 维)
# DeepSeek-V2: C = 512 (压缩 32 倍！)

# 注意: MLA 和 RoPE 不兼容
# 需要额外的 64 维用于 RoPE
# 总: 512 + 64 = 576 维 per layer per token

Mixture of Experts (MoE)

核心思想

MoE 的直觉：把一个大 FFN 替换为多个小 FFN（"专家"），每次只激活其中几个。

模型总参数 = 所有专家参数之和

每次计算量 = 被激活的专家参数之和

效果：用 1/8 的计算量，获得 8$\times$ 的参数量！

MoE 层结构

class MoELayer(nn.Module):
    def __init__(self, $d_{model}$, $d_{ff}$, nu$m_{experts}$, to$p_{k}$):
        self.gate = nn.Linear($d_{model}$, nu$m_{experts}$)  # 路由器
        self.experts = nn.ModuleList([
            FFN($d_{model}$, $d_{ff}$) for _ in range(nu$m_{experts}$)
        ])
        self.to$p_{k}$ = to$p_{k}$  # 通常 2-4

    def forward(self, x):
        # 1. 路由: 每个 token 选择 to$p_{k}$ 个专家
        gat$e_{scores}$ = self.gate(x)  # (batch*seq, nu$m_{experts}$)
        to$p_{k}$_scores, to$p_{k}$_indices = gat$e_{scores}$.topk(self.to$p_{k}$)

        # 2. 分发: 把 token 送到对应的专家
        output = torch.zero$s_{like}$(x)
        for k in range(self.to$p_{k}$):
            exper$t_{idx}$ = to$p_{k}$_indices[:, k]
            exper$t_{mask}$ = (exper$t_{idx}$.unsqueeze(1) == torch.arange(nu$m_{experts}$))
            # 把属于该专家的 token 送入计算
            for i, expert in enumerate(self.experts):
                toke$n_{mask}$ = exper$t_{mask}$[:, i]
                if toke$n_{mask}$.any():
                    output[toke$n_{mask}$] += expert(x[toke$n_{mask}$]) * to$p_{k}$_scores[...]

        return output

负载均衡问题

MoE 最大的挑战：负载不均衡。热门专家过载，冷门专家饥饿。

负载不均衡的后果：

  • 热门专家 OOM（太多 token 路由到同一个专家）
  • 冷门专家训练不足（梯度信号弱）
  • 通信不均衡（某些 GPU 上的专家过载）

辅助损失（Auxiliary Loss）

# Shazeer et al. (2017) 提出的辅助损失
# 鼓励均匀路由

def loa$d_{balancing}$_loss(gat$e_{scores}$, nu$m_{experts}$):
    # gat$e_{scores}$: (num_tokens, nu$m_{experts}$)
    # 每个专家被选中的比例
    exper$t_{fraction}$ = gat$e_{scores}$.mean(dim=0)  # (nu$m_{experts}$,)
    # 每个专家的平均路由概率
    pro$b_{fraction}$ = gat$e_{scores}$.sum(dim=0) / gat$e_{scores}$.sum()
    # 负载均衡损失: 鼓励均匀分布
    loa$d_{loss}$ = nu$m_{experts}$ * (exper$t_{fraction}$ * pro$b_{fraction}$).sum()
    return loa$d_{loss}$

# 总损失 = 主损失 + $α$ $\times$ 辅助损失
# $α$ 通常 0.01-0.1

MoE 的通信挑战

在多 GPU 上，不同专家分布在不同 GPU 上：

# Token 需要"旅行"到专家所在的 GPU
# 这需要 all-to-all 通信

# 例如: 8 GPU, 64 experts (每 GPU 8 experts)
# 每个 token 选 2 个专家
# → 平均每个 token 需要发送到 ~2 个远程 GPU
# → 通信量 $≈$ 2 $\times$ toke$n_{hidden}$_size $\times$ 2 (bf16)

并行策略

Expert + Data ParallelDP 组内 EPall-to-all within group
Token Dropping超载 token 直接跳过无（但损失信息）

MoE 的 scaling 优势：参数量可以随专家数线性增长，而计算量只随 to$p_{k}$ 增长。这意味着你可以用固定计算预算训练更大的模型——只需增加专家数，保持 to$p_{k}$ 不变。

MoE 的挑战与解决方案

挑战 1：训练不稳定

MoE 训练容易发散，特别是当某些专家被过度使用时。

解决方案：

  • 辅助负载均衡损失
  • 路由器 z-loss（惩罚过大的 logits）
  • 专家容量的硬限制（超载 token 被丢弃）

挑战 2：通信开销

all-to-all 通信在跨节点时成为瓶颈。

解决方案：

  • 节点内 expert parallel，节点间 data parallel
  • 通信与计算 overlap
  • 局部性感知路由（让相关 token 去同一节点）

挑战 3：专家质量不均

某些专家可能学到重复或低质量的模式。

解决方案：

  • 专家特定的学习率
  • 定期重置低质量专家
  • 共享专家（某些专家始终激活，学习通用知识）

挑战 4：推理内存

虽然激活参数少，但推理时所有专家都要在内存中。

解决方案：

  • 专家卸载（不活跃的专家放 CPU）
  • 专家量化（低精度存储）
  • 专家剪枝（移除不重要的专家）
