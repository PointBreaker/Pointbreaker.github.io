Benchmarking 与 Profiling

为什么要 benchmark？

没有替代 benchmark。

Spec sheet 是营销材料，论文是理想情况。真正的性能取决于你的库版本、硬件、工作负载。

每次改动后都要 benchmark！

Benchmark 的正确姿势

import time

def benchmark(func, nu$m_{warmups}$=1, nu$m_{trials}$=5):
    """正确的 benchmark 方法。"""
    # 1. 预热: 让 JIT 编译、缓存预热
    for _ in range(nu$m_{warmups}$):
        func()
    torch.cuda.synchronize()  # 等待 GPU 完成！

    # 2. 正式计时
    times = []
    for _ in range(nu$m_{trials}$):
        start = time.time()
        func()
        torch.cuda.synchronize()  # 关键！GPU 是异步的
        times.append(time.time() - start)

    return sum(times) / len(times)

关键：torch.cuda.synchronize()

GPU kernel launch 是异步的——func() 返回时 kernel 可能还在跑。不 synchronize 的话，你只测了 launch 时间，不是执行时间。

Kernel Fusion

问题：每个操作都读/写 HBM

# 假设计算 GeLU(A @ B)
# 不 fused 的版本:

# Kernel 1: matmul
tmp = A @ B          # 读 A, B from HBM; 写 tmp to HBM

# Kernel 2: gelu
output = gelu(tmp)   # 读 tmp from HBM; 写 output to HBM

# 问题: tmp 被写入 HBM，然后立即读回——浪费！

解决：融合成一个 kernel

# Fused 版本: 一个 kernel 完成
# 读 A, B from HBM
# 计算 A @ B，直接在寄存器中做 GeLU
# 写 output to HBM

# 省掉了 tmp 的 HBM 读写！

仓库 vs 工厂类比：

不 fused：把零件从仓库搬到工厂，搬回仓库，再搬回工厂...

Fused：零件只搬一次，所有加工在工厂内完成。

Benchmark 对比

# GeLU 的 benchmark 结果（dim=16384, bf16）:

# pytorc$h_{gelu}$ (fused):    ~0.8 ms  ← 一次 HBM 读写

# Fused 版本快 3$\times$！

CUDA Kernel 入门

CUDA 执行模型

# Grid: 所有 thread blocks 的集合
# Thread Block: 一组共享 shared memory 的 threads
# Thread: 基本执行单位

# 启动 kernel
kerne$l_{name}$<<<nu$m_{blocks}$, bloc$k_{size}$>>>(args)

# 例如: 1024 个 thread, bloc$k_{size}$=256
# → nu$m_{blocks}$ = 4
# → 4 个 block, 每个 256 个 thread

第一个 CUDA Kernel：GeLU

// gelu.cu
#include <cud$a_{fp16}$.h>

__global__ void gel$u_{kernel}$(
    const half* __restrict__ x,
    half* __restrict__ y,
    int nu$m_{elements}$
) {
    // 每个 thread 处理一个元素
    int i = blockIdx.x * blockDim.x + threadIdx.x;

    if (i < nu$m_{elements}$) {
        float xi = __half2float(x[i]);
        // tanh approximation of GELU
        float a = 0.79788456f * (xi + 0.044715f * xi * xi * xi);
        float ex$p_{2a}$ = expf(2.0f * a);
        float tan$h_{a}$ = (ex$p_{2a}$ - 1.0f) / (ex$p_{2a}$ + 1.0f);
        float result = 0.5f * xi * (1.0f + tan$h_{a}$);
        y[i] = __float2half(result);
    }
}

Triton 入门

Triton 是什么？

Triton 是 OpenAI 2021 年发布的 GPU 编程语言——用 Python 语法写 GPU kernel。

Triton 编程模型

import triton
import triton.language as tl

@triton.jit
def gel$u_{kernel}$(
    $x_{ptr}$, $y_{ptr}$,
    nu$m_{elements}$,
    BLOC$K_{SIZE}$: tl.constexpr,
):
    # 每个 program (block) 处理 BLOC$K_{SIZE}$ 个元素
    pid = tl.progra$m_{id}$(0)
    bloc$k_{start}$ = pid * BLOC$K_{SIZE}$

    # 这个 block 处理的元素索引
    offsets = bloc$k_{start}$ + tl.arange(0, BLOC$K_{SIZE}$)
    mask = offsets < nu$m_{elements}$  # 边界保护

    # 读取
    x = tl.load($x_{ptr}$ + offsets, mask=mask)

    # 计算 (和标准 GeLU 一样)
    a = 0.79788456 * (x + 0.044715 * x * x * x)
    exp = tl.exp(2 * a)
    tanh = (exp - 1) / (exp + 1)
    y = 0.5 * x * (1 + tanh)

    # 写回
    tl.store($y_{ptr}$ + offsets, y, mask=mask)

def trito$n_{gelu}$(x):
    y = torch.empt$y_{like}$(x)
    nu$m_{elements}$ = x.numel()
    bloc$k_{size}$ = 1024
    nu$m_{blocks}$ = triton.cdiv(nu$m_{elements}$, bloc$k_{size}$)
    gel$u_{kernel}$[(nu$m_{blocks}$,)](x, y, nu$m_{elements}$, BLOC$K_{SIZE}$=bloc$k_{size}$)
    return y

Triton 的优势

  • Python 语法：不需要写 C++/CUDA
  • 自动优化：memory coalescing、shared memory 管理
  • 可调试：可以 step through Python 代码
  • 性能：接近甚至超过手写 CUDA

Triton 实战：Fused Softmax

Naive Softmax 的问题

# Naive 实现: 5 次遍历数据
def manua$l_{softmax}$(x):
    $x_{max}$ = x.max(dim=1)[0]      # 遍历 1: 求 max
    x = x - $x_{max}$[:, None]        # 遍历 2: 减 max
    numerator = torch.exp(x)      # 遍历 3: exp
    denominator = numerator.sum(dim=1)  # 遍历 4: sum
    y = numerator / denominator[:, None]  # 遍历 5: 除法
    return y

# 5MN 次读取 + 3MN 次写入
# 理论上只需要 MN 读 + MN 写（4$\times$ 差距！）

Fused Softmax Kernel

@triton.jit
def softma$x_{kernel}$(
    $x_{ptr}$, $y_{ptr}$,
    $x_{row}$_stride, $y_{row}$_stride,
    nu$m_{cols}$,
    BLOC$K_{SIZE}$: tl.constexpr,
):
    # 每个 program 处理一行
    ro$w_{idx}$ = tl.progra$m_{id}$(0)
    co$l_{offsets}$ = tl.arange(0, BLOC$K_{SIZE}$)

    # 读取一行（从 HBM 到 SRAM）
    $x_{start}$_ptr = $x_{ptr}$ + ro$w_{idx}$ * $x_{row}$_stride
    $x_{ptrs}$ = $x_{start}$_ptr + co$l_{offsets}$
    $x_{row}$ = tl.load($x_{ptrs}$, mask=co$l_{offsets}$ < nu$m_{cols}$, other=float("-inf"))

    # 在 SRAM 中完成所有计算
    $x_{row}$ = $x_{row}$ - tl.max($x_{row}$, axis=0)        # 减 max
    numerator = tl.exp($x_{row}$)                     # exp
    denominator = tl.sum(numerator, axis=0)       # sum
    $y_{row}$ = numerator / denominator                # 除法

    # 写回 HBM
    $y_{start}$_ptr = $y_{ptr}$ + ro$w_{idx}$ * $y_{row}$_stride
    $y_{ptrs}$ = $y_{start}$_ptr + co$l_{offsets}$
    tl.store($y_{ptrs}$, $y_{row}$, mask=co$l_{offsets}$ < nu$m_{cols}$)

关键：整个 softmax 在 SRAM 中完成，HBM 只读一次、写一次。

Naive: 5MN reads + 3MN writes

Fused: MN reads + MN writes

理论加速：4$\times$

Tiling（分块）与 Shared Memory

为什么需要 Tiling？

矩阵乘法 C = A $\times$ B，朴素实现每个元素独立计算：

# 朴素 matmul: 每个 C[i,j] 独立读 A 的一行和 B 的一列
# C 有 MN 个元素，每个需要读 K 个元素
# 总读取: 2 $\times$ M $\times$ N $\times$ K 次 HBM 访问

# 问题: A 的同一行被读了 N 次（每列一次）
#       B 的同一列被读了 M 次（每行一次）

Tiled Matmul

# 关键思想: 分块加载到 shared memory
# 每个 block 计算 C 的一个 TIL$E_{SIZE}$ $\times$ TIL$E_{SIZE}$ 子矩阵

# 步骤:
# 1. 把 A 的一个 TILE $\times$ TILE 块加载到 shared memory
# 2. 把 B 的一个 TILE $\times$ TILE 块加载到 shared memory
# 3. 用这两个 shared memory 块计算部分结果
# 4. 重复直到覆盖整个 K 维度

# 效果: A 的每个元素只从 HBM 读一次（被多个 C 元素复用）

PTX：GPU 的汇编语言

什么是 PTX？

PTX (Parallel Thread Execution) 是 NVIDIA GPU 的底层指令集——类似于 CPU 的汇编。

# Triton 生成的 PTX 示例（GeLU kernel）:
ld.global.v4.f32  {%f0, %f1, %f2, %f3}, [%rd0];  # 读 4 个 float
fma.rn.f32        %f4, %f0, %f5, %f6;            # 融合乘加
ex2.approx.f32    %f7, %f8;                      # 近似 exp
st.global.v4.f32  [%rd1], {%f0, %f1, %f2, %f3};  # 写 4 个 float

从 PTX 读出的信息

  • ld.global.v4：每个 thread 一次读 4 个 float（coalesced access）
  • fma.rn.f32：融合乘加（FMA），GPU 最基本的计算指令
  • ex2.approx：近似 exp2 指令（快但精度低）
  • thread coarsening：一个 thread 处理 8 个元素（编译器优化）

核心原则：

  • Kernel fusion：合并操作，减少 HBM 读写
  • Tiling：分块到 shared memory，数据复用
  • Benchmark everything：不要猜测，要测量
  • Profile to understand：看时间花在哪

趋势：自动编译器（Triton、torch.compile）在快速进步。手写 kernel 的价值在于：(1) 自定义操作；(2) 极端性能优化；(3) 理解底层。
