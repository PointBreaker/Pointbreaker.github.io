通用过滤框架：给定目标数据 T（小量、高质量）和原始数据 R（大量、噪声），找到 R 中与 T 相似的子集 T'。算法需要满足两个要求：(1) 能从 T 泛化（T 和 T' 不完全相同），(2) 极快（要处理海量 R）。

过滤算法

统一框架

所有过滤算法都遵循相同的模式：

# 给定目标 T 和原始 R
# 1. 基于 R 和 T 估计一个模型 → 得到评分函数 score(x)
# 2. 根据 score(x) 保留 R 中的样本

# 三种实例化:
# - KenLM: score(x) = $p_{T}$(x)（生成模型）
# - fastText: score(x) = p(T|x)（判别分类器）
# - DSIR: score(x) = $p_{T}$(x) / $p_{R}$(x)（重要性采样）

KenLM：N-gram 语言模型

KenLM 是数据过滤中最常用的工具之一：

# N-gram 语言模型:
# p(in | the cat) = count(the cat in) / count(the cat)

# 问题: 很多 n-gram 的 count 为 0
# 解决: Kneser-Ney 平滑
# - 插值: p(in | the cat) 也依赖于 p(in | cat)
# - 折扣: count > 0 的 n-gram 的计数"分给" count=0 的

# KenLM 的特点:
# - 极快（C++ 实现）
# - 内存效率高（基于 trie 和量化）
# - 广泛用于机器翻译和 LM 数据过滤

KenLM 用于质量过滤

import kenlm

# 在目标数据（如 Wikipedia）上训练 KenLM
model = kenlm.Model("wikipedia.arpa.bin")

def comput$e_{perplexity}$(text):
    """计算文本在模型下的 perplexity"""
    score = model.score(text)
    num_tokens = len(text.split())
    perplexity = math.exp(-score / num_tokens)
    return perplexity

# 高质量文本 → 低 perplexity
print(comput$e_{perplexity}$("Stanford University was founded in 1885."))
# → perplexity $≈$ 50

# 低质量文本 → 高 perplexity
print(comput$e_{perplexity}$("asdf asdf asdf asdf asdf"))
# → perplexity $≈$ 5000

# CCNet 策略: 按 perplexity 排序，保留 top 1/3

KenLM 的局限：N-gram 模型只看局部上下文（5-gram = 5 个词），无法捕捉长距离的语义质量。一个句子内部通顺但语义荒谬的文本，KenLM 可能给高分。

fastText 分类器

fastText 是一个快速的文本分类器：

# fastText 的核心思想:
# 1. 把文本表示为词嵌入的平均（bag of embeddings）
# 2. 通过线性分类器分类

# 模型结构:
# x = [word1, word2, ..., wordN]  (token 序列)
# embed = mean(W[x] for x in tokens)  (平均词嵌入)
# y = softmax(U @ embed)  (分类)

# 参数: W (V $\times$ H) + U (H $\times$ K) = H(V + K)
# 对比 bag-of-words: V $\times$ K 参数

# 对于质量过滤（K=2 类）:
# 参数 = H(V + 2)，即线性分类器

Bag of n-grams 和 Hashing Trick

# 问题: n-gram 数量可能无限
# 解决: Hashing trick

import mmh3

nu$m_{bins}$ = 10_000_000  # 10M 哈希桶

def has$h_{ngrams}$(text, n=2):
    """将文本的 n-gram 哈希到固定数量的桶"""
    tokens = text.split()
    ngrams = [tokens[i:i+n] for i in range(len(tokens)-n+1)]
    hashed = [mmh3.hash(" ".join(ngram)) % nu$m_{bins}$ for ngram in ngrams]
    return hashed

# 这样无论有多少唯一 n-gram，都映射到 10M 个桶

DSIR：重要性重采样

Data Selection for Language Models via Importance Resampling：

# 核心思想: 用重要性采样从 R 中采样出 T 的分布

# 步骤:
# 1. 在目标 T 上估计分布 p
# 2. 在原始 R 上估计分布 q
# 3. 对 R 中每个样本 x，计算权重 w(x) = p(x) / q(x)
# 4. 按权重 w(x) 重新采样

# 问题: T 太小，无法估计好的 p 和 q
# 解决: 使用 hashed n-grams（高维但稀疏的特征）

去重

为什么要去重？

  • 训练效率：重复数据浪费算力
  • 避免记忆：重复导致模型记忆而非泛化
  • 隐私/版权：重复可能放大隐私和版权问题
  • 评估有效：测试集重复会导致评估虚高

两种重复

类型来源检测方法
精确重复镜像站点、GitHub fork哈希
近似重复模板文本、小修改MinHash/LSH

惊人的事实：C4 中有一条产品描述被重复了 61,036 次。Common Crawl 中大量内容是模板生成的（免责声明、许可证、导航栏）。

去重的设计空间

# 三个关键决策:

# 1. 什么是"项"（item）？
#    - 句子？段落？文档？
#    - 越小越精细，越大越高效

# 2. 如何匹配？
#    - 精确匹配（哈希）
#    - 存在公共子项
#    - 公共子项比例（Jaccard 相似度）

# 3. 匹配后如何处理？
#    - 删除所有重复项
#    - 只保留一个
#    - 保留"最好"的一个

精确去重

# 简单方法: 哈希 + 去重
import mmh3

def exac$t_{dedup}$(documents):
    """精确去重"""
    seen = set()
    unique = []
    for doc in documents:
        h = mmh3.hash(doc)  # 计算哈希
        if h not in seen:
            seen.add(h)
            unique.append(doc)
    return unique

# C4 的方法:
# - 项: 3 个句子的 span
# - 匹配: 精确匹配
# - 处理: 删除所有但一个
# 注意: 删除中间的 span 可能导致文档不连贯

# 可以 MapReduce 并行化:
# Map: 每个文档 → (hash, document)
# Reduce: 每个 hash 保留一个文档

Bloom Filter

当数据量太大，set 放不进内存时：

# Bloom Filter: 概率性集合成员检测

# 特点:
# - 内存高效（每个元素 ~10 bits）
# - 如果返回"不在" → 100% 正确
# - 如果返回"在" → 大概率正确（有 false positive）
# - 无法删除

# 结构:
# - 一个 bit array（m 位）
# - k 个哈希函数

# 操作:
# - 插入: 对 item 计算 k 个哈希，将对应位置 1
# - 查询: 对 item 计算 k 个哈希，检查是否全为 1

from bitarray import bitarray
import mmh3

class BloomFilter:
    def __init__(self, size, nu$m_{hashes}$):
        self.size = size
        self.nu$m_{hashes}$ = nu$m_{hashes}$
        self.table = bitarray(size)
        self.table.setall(0)

    def add(self, item):
        for seed in range(self.nu$m_{hashes}$):
            h = mmh3.hash(item, seed) % self.size
            self.table[h] = 1

    def migh$t_{contain}$(self, item):
        for seed in range(self.nu$m_{hashes}$):
            h = mmh3.hash(item, seed) % self.size
            if not self.table[h]:
                return False
        return True  # 可能在（false positive 可能）

False Positive Rate

# 假设哈希函数独立，给定:
# m = bit array 大小
# k = 哈希函数数量
# n = 已插入元素数量

# False positive rate:
# f = (1 - (1 - 1/m)^(k*n))^k
# 近似: f $≈$ (1 - e^(-kn/m))^k

# 最优 k（给定 m/n）:
# k = ln(2) * m / n

# 例: Dolma 设置 false positive rate = 1e-15
# 每个元素约需 50 bits

MinHash 与 Jaccard 相似度

检测近似重复：

# Jaccard 相似度:
# J(A, B) = |A $∩$ B| / |A $∪$ B|
# 范围: [0, 1]

# 例:
# A = {"the", "cat", "in", "the", "hat"}
# B = {"the", "cat", "on", "the", "mat"}
# J(A, B) = 3 / 7 $≈$ 0.43

# MinHash 的核心思想:
# - 对集合 A，计算其 minhash 签名
# - 两个集合的 minhash 签名相同的概率 = Jaccard 相似度
# - 这样可以用固定大小的签名近似 Jaccard 相似度

def minhas$h_{signature}$(shingles, nu$m_{hashes}$=128):
    """计算集合的 minhash 签名"""
    signature = []
    for i in range(nu$m_{hashes}$):
        mi$n_{hash}$ = float('inf')
        for s in shingles:
            h = mmh3.hash(s, seed=i)
            mi$n_{hash}$ = min(mi$n_{hash}$, h)
        signature.append(mi$n_{hash}$)
    return signature

# 两个集合的 Jaccard 估计:
# J $≈$ (signature1 == signature2) 的比例

Locality-Sensitive Hashing (LSH)

MinHash 签名仍然需要两两比较。LSH 将相似签名分到同一个桶：

# LSH 的核心思想:
# - 将 minhash 签名分成 b 个 band
# - 每个 band 有 r 行（b $\times$ r = nu$m_{hashes}$）
# - 如果两个签名在某个 band 完全相同 → 进入同一个候选桶
# - 只在候选桶内做精确比较

# 参数选择:
# - b 个 band, 每个 r 行
# - 相似度为 s 的文档成为候选的概率:
#   P = 1 - (1 - s^r)^b

# 例: nu$m_{hashes}$=128, b=16, r=8
# s=0.5: P $≈$ 0.004（不太可能被选中）
# s=0.8: P $≈$ 0.99（几乎一定被选中）

# 这样可以在 $\\($O(\1)$\\) 时间内找到所有相似度 > 阈值的文档对

SemDedup

语义层面的去重（更先进的方法）：

# SemDedup 的核心思想:
# 1. 用 embedding 模型编码每个文档
# 2. 聚类相似的文档
# 3. 在每个聚类内随机保留一个

# 步骤:
# 1. 编码: embedding = model.encode(documents)
# 2. 聚类: clusters = kmeans(embedding, k=...)
# 3. 去重: 每个 cluster 只保留一个

# 优势:
# - 能检测语义重复（不同措辞但相同含义）
# - 比基于字符串的方法更强大

# 劣势:
# - 需要 embedding 模型（计算成本高）
# - 聚类质量影响去重效果

数据配比

为什么需要配比？

不同来源的数据有不同的能力和偏差。最终训练数据是多种来源的混合：

# The Pile 的配比（按 tokens）:
# - Pile-CC (网页): 22.0%
# - Books3 (书籍): 10.3%
# - OpenWebText2 (Reddit): 8.1%
# - ArXiv (论文): 7.8%
# - GitHub (代码): 7.6%
# - PubMed Central (医学): 6.3%
# - Wikipedia: 3.9%
# - 其他 20+ 来源: 34%

# 配比的影响:
# - 代码比例高 → 编程能力强，但可能"代码腔"
# - 书籍比例高 → 叙事能力强，但可能过时
# - 论文比例高 → 推理能力强，但可能"学术腔"

DoReMi：自动数据配比

用 reference model 指导数据配比：

# DoReMi 的核心思想:
# 1. 训练一个小的 reference model
# 2. 用 reference model 的 excess loss 作为权重
# 3. 优化配比使 reference model 的 loss 最小

# 算法:
# 1. 用均匀配比训练 reference model
# 2. 计算每个 domain 的 excess loss
# 3. 用 excess loss 更新配比权重
# 4. 用新配比训练 target model
