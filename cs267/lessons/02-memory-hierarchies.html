内存层次结构与矩阵乘法

大多数应用程序只发挥了峰值性能的不到 10%——损失的性能主要花在数据移动上。理解内存层次结构是释放硬件潜力的关键。

日期：2025-01-23

难度：中等

视频：Lecture 2 Video

为什么关注串行性能？

核心观点：并行化慢速串行代码只会产生慢速并行代码。

矩阵乘法的例子：通过串行优化（向量化、缓存优化等）可以在单核上获得 131x 加速。10 倍的串行优化收益很常见。

现代处理器的成本模型

理想化单处理器模型

最初的理想化假设：

  • 每个操作（+, *, 等）的开销大致相同
  • 读写变量是"免费"的

更真实的模型

实际上，内存访问有两个成本：

  • 延迟 (Latency, α)：加载/存储 1 个字的时间
  • 带宽 (Bandwidth, β)：加载/存储大块的速率（时间/字节）

移动 $n$ 个连续字的时间：$\alpha + n\beta$

关键数值：

处理器频率: 1 GHz → 1 周期 = 1 ns
内存延迟:    ~100 ns（加载/存储 1 个字）
Load/Store ≈ 100x 算术操作的开销

编译器的角色

编译器执行的关键优化：

  • 寄存器分配 (Register Allocation)：决定何时加载/存储 vs 重用寄存器（使用图着色算法）
  • 循环展开 (Loop Unrolling)：减少控制开销
  • 循环融合/交换/分块 (Fusion/Interchange/Tiling)
  • 强度削减 (Strength Reduction)：如用左移代替乘以 2
  • 死代码消除 (Dead Code Elimination)

内存层次结构

局部性原理

程序具有高度的局部性：

  • 时间局部性 (Temporal Locality)：重用最近访问过的数据
  • 空间局部性 (Spatial Locality)：访问相邻的数据

缓存基础概念

  • Cache Line：一次加载的字节数（通常 64 字节）
  • Cache Hit：数据在缓存中 —— 快速
  • Cache Miss：数据不在缓存中 —— 需访问下一级
  • Associativity：直接映射 vs n-way 组相联

Little 定律与并行

来自排队论：$\text{concurrency} = \text{latency} \times \text{bandwidth}$

示例：延迟 = 10 ns，带宽 = 2 GB/s → 需要 20 字节在途才能达到带宽速度

这意味着需要找到 20 个独立操作来隐藏延迟。

单处理器中的并行性

指令级并行 (ILP) 与流水线

以 Patterson 的"洗衣服"为例：

任务: 洗衣服
  洗衣: 30 min
  烘干: 40 min
  折叠: 20 min
  总延迟: 90 min

4 批衣服:
  串行: 4 × 90 = 360 min
  流水线: 30 + 4×40 + 20 = 210 min  (≈ 1.7x 加速)
  峰值带宽: 1/40 min = 1.5 loads/hour

SIMD 单元

单指令多数据：一条指令同时处理多个数据元素。

SIMD 扩展 寄存器宽度 双精度数 单精度数
SSE2128 bits24

使用 SIMD 的要求：

  • 向编译器暴露并行性（或使用 intrinsics）
  • 数据在内存中连续
  • 缓存对齐（通常 64 字节）

FMA：融合乘加

乘加操作 $x = y + c \times z$ 极其常见。FMA 指令：

  • 以与 + 或 * 相同的吞吐率执行
  • 只进行一次舍入：$x = \text{round}(c \times z + y)$
  • 提高精度和性能

案例研究：矩阵乘法

为什么研究矩阵乘法？

  • 是许多问题的核心 kernel
  • 稠密线性代数是最重要的 motif
  • 优化收益的最佳案例
  • HPC 中研究最深入的算法

简单内存模型

假设只有两级内存（快/慢）：

m = 在快/慢内存间移动的元素数
tm = 每次慢内存操作时间
f = 算术操作数
tf = 每次算术操作时间 (<< tm)
CI = f / m = 计算强度 (Computational Intensity)

最小时间 = f × tf（所有数据在快内存）
实际时间 = f × tf + m × tm = f × tf × (1 + tm/tf × 1/CI)

Machine Balance = Peak FLOPS / Peak Bandwidth → 典型值 5-10 Flops/Byte

热身：矩阵-向量乘法 (Matrix-Vector Multiply)

{实现 y = y + A*x}
for i = 1:n
  for j = 1:n
    y(i) = y(i) + A(i,j)*x(j)

分析：

  • $f = 2n^2$ 次算术操作
  • $m = 3n + n^2 \approx n^2$ 次慢内存访问
  • $CI = f/m \approx 2$（低计算强度）
  • 结论：受限于内存带宽，无法通过优化改善

朴素矩阵乘法

{实现 C = C + A*B}
for i = 1 to n
  for j = 1 to n
    for k = 1 to n
      C(i,j) = C(i,j) + A(i,k) * B(k,j)

分析：

  • $f = 2n^3$ 次算术操作
  • $m = n^3 + 3n^2$ 次慢内存访问（B 的列被读取 n 次）
  • $CI = 2n^3 / (n^3 + 3n^2) \approx 2$（大 n 时）
  • 结论：与矩阵-向量乘法一样受限于带宽！

分块 (Tiled) 矩阵乘法

将 A, B, C 视为 N×N 个 b×b 子块的矩阵，块大小 $b = n/N$：

for i = 1 to N
  for j = 1 to N
    {将 C(i,j) 读入快内存}
    for k = 1 to N
      {将 A(i,k) 读入快内存}
      {将 B(k,j) 读入快内存}
      C(i,j) = C(i,j) + A(i,k) * B(k,j)  {块矩阵乘法}
    {将 C(i,j) 写回慢内存}

分析（假设 3 个 b×b 块能放入快内存）：

  • $f = 2n^3$（不变）
  • $m = 2n^2 \text{ (C)} + N \cdot n^2 \text{ (A)} + N \cdot n^2 \text{ (B)} = (2N + 2) \cdot n^2$
  • $CI = f/m = 2n^3 / ((2N+2) \cdot n^2) \approx n/N = b$

关键洞察：CI 从 $\\(O(\1)\\) 提升到 $\\(O(\1)\\)。若 $b$ 足够大，CI 可以接近 Machine Balance，使计算受限而非带宽受限。

Cache-Oblivious 矩阵乘法

递归矩阵乘法不需要知道缓存大小：

C = RMM(A, B, n)
  if n == 1: C = A * B
  else:
    C00 = RMM(A00, B00, n/2) + RMM(A01, B10, n/2)
    C01 = RMM(A00, B01, n/2) + RMM(A01, B11, n/2)
    C10 = RMM(A10, B00, n/2) + RMM(A11, B10, n/2)
    C11 = RMM(A11, B01, n/2) + RMM(A11, B11, n/2)

内存移动分析：

$$W(n) = 8 \cdot W(n/2) + 4 \cdot 3(n/2)^2 \text{ if } 3n^2 > M_{\text{fast}}

$$W(n) = $\\(O(\1)\\)$$

优点：不需要知道 $M_{\text{fast}}$ 即可工作，自动适应任意深度的内存层次。

实践中的优化

自动调优 (Autotuning)

ATLAS (Automatically Tuned Linear Algebra Software)：

  • 自动生成大量代码变体
  • 通过实验搜索最快的实现
  • 在多种平台上超越厂商库

BLAS (Basic Linear Algebra Subroutines)

BLAS 级别 操作 CI
BLAS1 (1970s)向量-向量 (dot, saxpy)~1
BLAS2 (1980s)矩阵-向量 (matvec)~2
BLAS3 (1980s)矩阵-矩阵 (matmul)$\\(O(\1)\\)

结论：尽可能使用 BLAS3 操作以获得最佳性能。

Strassen 算法

传统算法：$$\\(O(\1)\\)$ 次乘法。Strassen：$$\\(O(\1)\\) \approx $\\(O(\1)\\)$。

2x2 矩阵乘法:
  传统: 8 次乘法 + 4 次加法
  Strassen: 7 次乘法 + 18 次加法

p1 = (a12 - a22) * (b21 + b22)
p2 = (a11 + a22) * (b11 + b22)
p3 = (a11 - a21) * (b11 + b12)
p4 = (a11 + a12) * b22
p5 = a11 * (b12 - b22)
p6 = a22 * (b21 - b11)
p7 = (a21 + a22) * b11

m11 = p1 + p2 - p4 + p6
m12 = p4 + p5
m21 = p6 + p7
m22 = p2 - p3 + p5 - p7

要点总结

数据移动是瓶颈

性能损失主要来自数据移动而非计算。Load/Store 的开销是算术操作的 ~100x。

计算强度是关键

CI = f/m，衡量每次内存访问的算术操作数。CI 越高，越接近计算峰值。

分块提升 CI

矩阵乘法的 CI 从 $\\(O(\1)\\) 提升到 $\\(O(\1)\\)，通过分块使 CI 接近 Machine Balance。

使用库！

BLAS/LAPACK 经过高度优化，手写代码很难超越。优先使用库函数。
