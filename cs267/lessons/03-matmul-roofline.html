矩阵乘法与 Roofline 性能模型

Roofline 模型为我们提供了一个直观的可视化工具，用于理解算法性能是受限于计算峰值还是内存带宽。

回顾：矩阵乘法的计算强度分析

简单内存模型

m = 在快/慢内存间移动的元素数
tm = 每次慢内存操作时间（带宽的倒数）
f = 算术操作数
tf = 每次算术操作时间 (<< tm)
CI = f / m = 计算强度 (Computational Intensity)

最小时间 = f × tf（所有数据在快内存）
实际时间 = f × tf + m × tm = f × tf × (1 + tm/tf × 1/CI)

Machine Balance = Peak FLOPS / Peak Bandwidth

当 CI ≈ Machine Balance 时，算法达到最佳效率。

分块矩阵乘法的 CI

\[CI = \frac{f}{m} = \frac{2n^3}{(2N+2) \cdot n^2} \approx \frac{n}{N} = b \text{ (大 n 时)}\]

\[b \leq \sqrt{M/3}\]

因为 M 必须容纳 3 个 b×b 块。

通信下界 (Communication Lower Bound)

定理 (Hong & Kung, 1981)：

任何重组矩阵乘法的算法（仅使用交换律和结合律），其计算强度 \(q = O(M_{\text{fast}}^{1/2})\)。

因此：

\[\text{\#words\_moved} = \Omega(n^3 / M_{\text{fast}}^{1/2})\]

分块矩阵乘法达到了这个下界，因此是最优的（在常数因子内）。

并行情况的下界

扩展到 P 个处理器：

  • 每处理器迭代数：\(n^3/P\)（负载均衡）
  • 每处理器数据：\(M = 3n^2/P\)
  • \[\text{\#words\_moved} \geq M \cdot \frac{n^3/P}{M^{3/2}} = \Omega(n^2 / P^{1/2})\]

Roofline 性能模型

什么是性能模型？

性能模型是一个估算性能的公式，可用于：

  • 理解性能行为
  • 识别性能瓶颈
  • 决定是否需要更好的软件、硬件或算法
  • 确定何时优化已完成

Roofline 模型的组成

Roofline 模型由三个部分组成：

组件 描述 来源
算术性能峰值浮点运算率 (FLOPS)机器
内存带宽峰值内存带宽 (Bytes/sec)机器
计算强度FLOPs / Bytes（算术强度）应用/算法

Roofline 公式

可达性能 (Attainable Performance)：

\[P_{\text{attainable}} = \min\begin{cases} P_{\text{peak}} \\ CI \times B_{\text{peak}} \end{cases}\]

其中 \(P_{\text{peak}}\) 是峰值计算性能，\(B_{\text{peak}}\) 是峰值内存带宽。

Roofline 图示


Attainable GFLOP/s
    ^
    |        /-------------
    |       /  ← 计算受限 (Compute Bound)
    |      /
    |     /  ← 带宽受限 (Bandwidth Bound)
    |    /
    |---/------------------->
    0   Machine Balance     Computational Intensity (FLOP/byte)
  • Machine Balance = \(P_{\text{peak}} / B_{\text{peak}}\)（屋顶的"转角"）
  • 当 CI < Machine Balance：带宽受限
  • 当 CI > Machine Balance：计算受限

Roofline 应用示例

示例 1：TRIAD

#pragma omp parallel for
for(i = 0; i & N; i++) {
  Z[i] = X[i] + alpha * Y[i];
}
  • 每迭代：2 FLOPs，3 个 double（24 bytes）
  • CI = 2/24 ≈ 0.083 FLOP/byte → 带宽受限

示例 2：3D 7-point Stencil

for x,y,z in 0 to n-1
  Next[x,y,z] = C0 * Current[x,y,z] +
    C1 * (Current[x-1,y,z] + Current[x+1,y,z] +
          Current[x,y-1,z] + Current[x,y+1,z] +
          Current[x,y,z-1] + Current[x,y,z+1]);

无缓存时：8 FLOPs，8 个 double 引用 → CI = 8/64 = 0.125 FLOP/byte

有缓存时：缓存过滤后只需 1 读 1 写 → CI = 8/16 = 0.5 FLOP/byte

重要：常数因子很重要！虽然 stencil 的渐近 CI 是 O(1)，但常数决定了实际性能。

Roofline 模型的细节

影响可达性能的因素

实际可达性能可能低于理论峰值：

  • 无 FMA → 乘/加不平衡
  • 无 SIMD → 失去向量化加速
  • 无 ILP → 失去指令级并行
  • 无软件预取 → 失去隐藏延迟的能力
  • NUMA 效应 → 非均匀内存访问
  • 多级缓存 → L1/L2/L3 各有不同带宽

DRAM vs Cache Roofline

可以为不同层次的内存构建多条 Roofline：

  • DRAM Roofline（数据初始在主存）
  • L3 Roofline（数据初始在 L3）
  • L1 Roofline（数据初始在 L1）

要点总结

Roofline 直观有效

Roofline 模型用一张图展示了算法性能的两个上限：计算峰值和带宽峰值。

Machine Balance 是关键

典型值为 5-10 FLOP/byte，且随时间在恶化（计算增长快于带宽）。

提升 CI 是优化目标

通过分块、融合等技术提升计算强度，使算法从带宽受限转向计算受限。

通信下界是理论极限

Hong & Kung 定理证明了分块矩阵乘法在通信量上是最优的。
