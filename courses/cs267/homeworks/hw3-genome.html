并行基因组组装（UPC++）

用 UPC++ 的 PGAS 模型并行化 de novo 基因组组装——实现分布式哈希表，遍历 k-mer 生成 contigs，体验 one-sided 通信与 RDMA 的力量。

这个 Homework 要你做什么？

一句话总结：使用 UPC++ 并行化 de novo 基因组组装——实现分布式哈希表来存储和遍历 k-mer，从 reads 中重建 contigs。修改 kmer_hash.cpp 和 hash_map.hpp，在 1-8 节点、每节点 60 任务上测试扩展性。

这是你第一次用 PGAS 模型编程。与 MPI 的 two-sided 通信不同，UPC++ 的 rget/rput 让你可以直接读写远程 rank 的内存——无需远端 CPU 参与，硬件 RDMA 让通信与计算重叠。

如何开始？

0

理解串行算法

先理解串行版本的基因组组装流程：

  1. 读取所有 reads，提取 k-mer
  2. 将 k-mer 插入哈希表（记录出现次数）
  3. 从高频 k-mer 出发，遍历 de Bruijn 图
  4. 输出 contigs（无分支的路径）

数据集：/global/cfs/cdirs/mp309/cs267-spr2025/hw3-datasets/human-chr14-synthetic.txt（51-mers）

1

设计分布式哈希表

核心挑战：k-mer 分布在多个 rank 上，如何高效存取？

  • 分区策略：按 k-mer 的哈希值决定归属 rank
  • 通信模式：插入时用 rput 写到远端，查询时用 rget 读取
  • 批量操作：聚合多次操作为一次通信，摊销延迟
2

避免"平凡解"

关键约束：不能通过 RPC 调用本地 std::unordered_map。这看似简单，但违背了 PGAS 的设计意图——每个请求都要触发远程调用，性能极差。

正确做法：在 UPC++ 的框架下直接操作分布式内存，利用 rget/rput 的异步性和批量能力。

3

实现 contig 生成

哈希表构建完成后，需要遍历 k-mer 图生成 contigs：

  • 选择一个起始 k-mer（高频、非重复）
  • 沿着图遍历，每次扩展一个碱基
  • 遇到分支或低覆盖度时停止
  • 输出完整的 contig 序列
4

扩展性实验

设计两组实验：

  • 多节点：1-8 节点，每节点 60 任务（固定每 rank 工作量）
  • 节点内：1 节点，1-64 秩（观察共享内存上的扩展）

绘制扩展图（speedup vs rank 数），分析扩展效率。

常见陷阱

平凡解陷阱： 用 UPC++ 的 RPC 调用本地 std::unordered_map 是最容易走的路，但性能极差且违反题目要求。评委会检查你的实现方式。

同步过度： 每次 rget/rput 都等待完成会丧失异步优势。应该批量发起操作，最后统一 wait。

数据倾斜： 基因组中某些 k-mer 出现频率极高（如重复序列）。简单的哈希分区可能导致某些 rank 负载过重。

忘记 barrier： UPC++ 的异步操作需要显式同步。在关键阶段后忘记 upcxx::barrier() 会导致数据竞争。

内存泄漏： upcxx::new_ 分配的内存必须用 upcxx::delete_ 释放。分布式内存泄漏比本地更隐蔽且更致命。

UPC++ 编程模式

One-Sided 通信

// rank 0 读取 rank 1 上的数据
upcxx::global_ptr<int> remote = ptr;  // rank 1 上的指针
int value;
upcxx::future<> fut = upcxx::rget(remote, &value, sizeof(int));
// ... 做其他工作 ...
fut.wait();  // 等待读取完成

批量操作

// 批量 rput：聚合多次写入为一次通信
std::vector<upcxx::global_ptr<int>> dst_ptrs;
std::vector<int> src_values;
// ... 填充数据 ...
upcxx::future<> fut = upcxx::rput(
  src_values.data(), dst_ptrs.data(), sizeof(int) * dst_ptrs.size()
);
fut.wait();

分布式对象

// 在所有 rank 上分配一个对象
upcxx::global_ptr<int> ptr = upcxx::new_<int>(0);

// 检查 affinity（该指针指向哪个 rank）
int owner = ptr.where();

// 仅在拥有者 rank 上操作
if (owner == upcxx::rank_me()) {
  *ptr.local() = 42;  // 转为本地指针访问
}

性能分析方法

报告要求

  • 扩展图：多节点（1-8 节点）和节点内（1-64 秩）两组曲线

  • 优化讨论：批量操作、通信隐藏、负载均衡策略

关键指标

  • 加速比：T(1 rank) / T(N ranks)
  • 扩展效率：加速比 / 理想加速比 × 100%
  • 通信时间占比：one-sided 操作耗时 / 总时间
  • 负载均衡度：最大 rank 工作量 / 平均工作量

学习心态

PGAS 是一种新的思维范式。 从 MPI 的"发消息"到 UPC++ 的"直接读内存"，你需要重新思考数据放置和访问模式。Affinity 是关键——数据在谁的手里，谁访问它最便宜。

基因组组装是一个不规则应用（irregular application）：k-mer 分布不均、图结构不规则。这正是 PGAS 擅长的场景——one-sided 通信天然适合不规则访问。

卡住时的正确顺序： 复习 Lecture 11 → 读 UPC++ 文档 → 从单机单 rank 开始调试 → 逐步增加 rank 数 → 分析通信瓶颈。
