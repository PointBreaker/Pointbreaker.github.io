如何开始？

0

理解串行算法

回顾 HW2 的粒子模拟：每个时间步，每个粒子根据与其他粒子的相互作用更新位置和速度。核心循环是每个粒子遍历所有其他粒子——O(n²) 的朴素算法。理解这一步是设计 GPU kernel 的前提。

1

映射到 GPU 线程

最自然的映射是一个线程处理一个粒子：

// 全局线程 ID 计算
int i = threadIdx.x + blockIdx.x * blockDim.x;
if (i < n) {
  // 粒子 i 的更新逻辑
}

选择合适的 block size（通常 128 或 256 线程/block），计算所需的 block 数量。

2

管理内存

你需要：

  • 在 host 上分配粒子数据（位置、速度）
  • 用 cudaMalloc 在 device 上分配对应空间
  • 用 cudaMemcpy 将数据拷贝到 GPU
  • 每个时间步调用 kernel，最后拷回结果
3

优化访问模式

GPU 性能的关键是内存合并（coalesced access）：

  • 确保相邻线程访问相邻内存地址
  • 考虑使用 shared memory 缓存频繁访问的数据
  • 避免 warp 内的分支发散
4

性能评测

用不同粒子数（100K - 10M）测试，绘制 log-log 图，与 HW2 的 OpenMP / MPI 版本对比。注意：小粒子数看不出差异，必须用大规模数据。

常见陷阱

忘记边界检查： 当 n 不是 blockDim 的整数倍时，最后一个 block 会有多余线程。必须用 if (i < n) 保护，否则会访问越界。

Host/Device 指针混用： 不能在 host 代码中解引用 device 指针，反之亦然。这是最常见的运行时错误。

分支发散： 如果 warp 内线程走不同分支（如某些粒子需要特殊处理），性能会大幅下降。尽量让 warp 内线程执行相同路径。

非合并访问： 如果线程 i 访问 data[i * stride] 且 stride > 1，会导致非合并访问，带宽利用率可能只有 1/32。

同步位置错误： __syncthreads() 必须在所有线程都能到达的位置调用。放在条件分支内可能导致死锁。

GPU 关键概念速览

线程层次映射

概念含义HW2-3 中的对应
Thread单个执行单元处理一个粒子的更新
Warp32 个线程的调度组锁步执行，注意分支发散
Block驻留在一个 SM 上的线程组共享 shared memory，可同步
Grid所有 block 的集合一次 kernel 启动的全部工作

内存层次选择

内存延迟用途
寄存器~1 cycle线程私有变量（循环计数器、累加器）
Shared Memory~5 cyclesBlock 内线程共享数据（tile 缓存）
Global Memory~400-800 cycles粒子位置/速度的主存储

性能分析方法

报告要求

  • log-log 图：横轴粒子数 n，纵轴运行时间，对比 OpenMP / MPI / GPU 三条线
  • 数据结构设计：解释你如何组织粒子数据（AoS vs SoA）
  • GPU 同步策略：说明 kernel 调用与数据拷贝的同步点
  • 与 CPU 版本对比：分析加速比和瓶颈

关键指标

  • 加速比：GPU 时间 / CPU 时间（同问题规模）
  • 带宽利用率：实际带宽 / 理论峰值带宽（A100 ~2 TB/s）
  • 弱扩展性：固定每线程工作量，增加线程数
  • 强扩展性：固定总问题规模，增加线程数

学习心态

GPU 编程是一种思维转变。 在 CPU 上，你优化的是算法复杂度；在 GPU 上，你优化的是内存访问模式和并行效率。同一个算法，不同的实现方式，性能可能差 10 倍以上。

不要期望第一次就写出最优版本。先让它正确运行，再逐步优化——合并访问、shared memory、occupancy 调优。

卡住时的正确顺序： 复习 Lecture 9-10 → 读 handout → 从最小 kernel 开始 → 用 printf 调试 → 用 nsight compute 分析。
