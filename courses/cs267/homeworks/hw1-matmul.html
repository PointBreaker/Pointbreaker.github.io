任务概述

你只能修改 dgemm-blocked.c 中的 square_dgemm() 函数，目标是在 Perlmutter 的单核上逼近理论峰值 56 GFlop/s。

理论峰值
3.5 GHz × 4 (FMA) × 2 (FLOP/FMA) × 2 (流水线) = 56 GFlop/s

运算下界
不能少于 2n³ 次浮点运算（Strassen 可选，但不推荐）

存储顺序
矩阵按列主序（Column-major）存储，注意遍历顺序

正确性验证
|square_dgemm(n,A,B,0) − A×B| < ε·n·|A|·|B|

优化路线（Step by Step）

1

理解 Roofline 与瓶颈

先用 dgemm-bench 跑参考实现，观察当前 GFlop/s 与 Roofline 的关系。Perlmutter 节点的计算峰值 56 GFlop/s，L1/L2/DRAM 带宽决定了你的上限。问自己：这个矩阵是 compute-bound 还是 memory-bound？

  • 绘制初始 Roofline 点
  • 计算运算强度 (Arithmetic Intensity = FLOP / Byte)
  • 确定目标分块层级 (L1 / L2 / L3)
2

Cache 分块 (Blocking / Tiling)

把大矩阵切成小块，让数据在 Cache 中驻留。这是从 O(n³) 内存流量 → O(n³/√M) 的关键一步。

  • 外层循环按 Block 大小 (MC, NC, KC) 切分
  • 注意列主序遍历：内层循环应沿列方向访问
  • 尝试不同 Block 大小：64、128、256、512
⚠️ 常见坑：不要假设行主序！列主序意味着内层循环应遍历行索引，以获得连续内存访问（stride-1）。
3

寄存器分块内核 (Register Blocking)

把每个 Block 再切成 4×4、6×6 的小核，让 CPU 寄存器直接累加。手写 AVX2 内联函数（_mm256_fmadd_pd）或内联汇编。

  • 每个内核使用 16+ 个 YMM 寄存器
  • 手动展开内层循环以减少循环开销
  • 考虑使用 __restrict__ 帮助编译器别名分析
4

手动预取 (Software Prefetching)

当数据还在 L2 时就用 _mm_prefetch 提前拉入 L1，隐藏内存延迟。

  • 预取距离要足够远（通常 8-16 个 Cache Line）
  • 不要预取过远导致 Cache 污染
  • 区分 L1 (_MM_HINT_T0) 与 L2 (_MM_HINT_T1) 预取
5

打包 (Packing / Copy Optimization)

把 Block 从主存拷贝到连续的局部缓冲区，减少 TLB miss 并改善向量化对齐。

  • Pack A 的子矩阵为连续内存
  • Pack B 的子矩阵为连续内存
  • 确保 32 字节对齐以获得最佳 AVX 性能
