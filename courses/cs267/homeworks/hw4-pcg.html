如何开始？

0

理解串行 PCG 算法

先回顾串行 PCG 的伪代码：

r = b - A*x          # 残差
z = M^{-1} * r       # 预处理
p = z                # 搜索方向
while not converged:
  alpha = (r·z) / (p·A*p)
  x = x + alpha * p
  r_new = r - alpha * A*p
  z_new = M^{-1} * r_new
  beta = (r_new·z_new) / (r·z)
  p = z_new + beta * p
  r = r_new; z = z_new

每步的主要计算：1 次 SpMV（A*p）、2 次内积（dot）、3 次向量更新（axpy）。

1

稀疏矩阵格式转换

输入可能是 map 格式（键值对 (i,j) → value），需要转为 CSR（Compressed Sparse Row）：

  • values：非零元素的值
  • col_indices：非零元素的列索引
  • row_ptr：每行在 values 中的起始位置

1D Poisson 矩阵是三对角矩阵：每行最多 3 个非零元素。

2

设计分布式布局

将 N 个未知数划分到 P 个秩（N 必须是 P 的倍数）：

  • 行划分：每个秩负责连续的 N/P 行
  • Halo 区域：边界行需要相邻秩的数据（ghost cells）
  • 向量划分：x 和 b 按相同方式分布
3

并行化核心操作

  • SpMV（A*p）：每个秩计算本地行的乘积，边界行需要 halo 交换
  • 内积（dot）：本地计算后 MPI_Allreduce 求和
  • 向量更新（axpy）：完全并行，无需通信
4

优化策略

  • 重用中间值：r·z 在迭代开始和结束时都要用，保存它
  • 通信隐藏：用非阻塞 halo 交换与计算重叠
  • 重排序：对矩阵重排序以减少通信量（进阶）
5

扩展性实验

设计实验矩阵：

  • 问题规模：N = 2²⁰, 2²², 2²⁴, 2²⁶
  • 秩数：1, 2, 4, 8, 16, 32, 64
  • 每组实验：记录求解时间、迭代次数、通信时间占比

常见陷阱

N 不是 P 的倍数： 题目明确要求 N 必须是秩数的倍数。如果不是，行划分会不均匀，导致负载不均衡甚至错误。

Halo 交换遗漏： SpMV 时，边界行需要相邻秩的第一个/最后一个元素。忘记 halo 交换会导致错误结果。

Allreduce 性能瓶颈： 每次迭代有 2 次全局归约（内积），这是主要的通信开销。用 MPI_Allreduce 而不是手动 send/recv。

收敛条件错误： PCG 的收敛判断通常是 ||r|| / ||b|| < tol。注意计算全局范数（需要 Allreduce），而不是用局部残差。

内存泄漏： MPI 分配的请求对象（MPI_Request）和 buffer 必须正确释放，尤其在迭代循环中。

PCG 算法详解

1D Poisson 矩阵

在 [0,1] 区间上用中心差分离散 -u'' = f，步长 h = 1/(N+1)：

# 三对角矩阵：主对角线 = 2/h²，次对角线 = -1/h²
A = 1/h² × [ 2  -1   0   0  ...  0 ]
            [-1   2  -1   0  ...  0 ]
            [ 0  -1   2  -1  ...  0 ]
            [ ...                       ]
            [ 0  ...   0  -1   2  -1 ]
            [ 0  ...   0   0  -1   2 ]

预处理技术

预处理器说明代价
Jacobi (Diagonal)M = diag(A)，M⁻¹ = 1/diag(A)O(N)，简单但效果一般
Block Jacobi每个秩的本地块作为预处理器本地求解，无通信
Incomplete LU (ILU)不完全 LU 分解效果更好但通信复杂
Multigrid多尺度方法最优 O(N) 但实现复杂

参考：Block Jacobi 预处理器详解

分布式 SpMV 的通信模式

# 每个秩 i 负责行 [start_i, end_i]
# 计算 A*p 时：
# 1. 接收左邻居的 p[start_{i-1}]（如果存在）
# 2. 接收右邻居的 p[end_{i+1}]（如果存在）
# 3. 本地计算 SpMV
# 4. 发送本地 p[start_i] 和 p[end_i] 给邻居

性能分析方法

报告要求

  • 实现策略：解释你的分布式布局、数据结构和通信方案
  • 性能对比：不同 N 和 P 下的求解时间
  • 扩展性结果：强扩展图（固定 N，增加 P）
  • 挑战分析：通信瓶颈、负载均衡、收敛性问题

关键指标

  • 每迭代时间：单次 PCG 迭代的墙钟时间
  • 通信时间占比：halo 交换 + Allreduce 耗时 / 总时间
  • 收敛迭代数：达到收敛所需的 PCG 步数
  • FLOPs 利用率：实际 FLOPs / 峰值 FLOPs

Roofline 分析

PCG 的主要计算是 SpMV，对于三对角矩阵：

  • 计算量：每行 ~3 FLOPs（2 次乘加）→ 3N FLOPs/iteration
  • 通信量：halo 交换 2 个值 + Allreduce 2 个值
  • 计算强度：~3N / (halo + allreduce) — 通常通信受限

学习心态

PCG 是科学计算的"hello world"。 它麻雀虽小五脏俱全：稀疏矩阵、分布式内存、集合通信、收敛分析——几乎涵盖了 HPC 的所有核心问题。

不要急于写代码。先花时间理解串行算法、设计数据分布、画出通信图。一个清晰的纸面设计胜过十次盲目调试。

卡住时的正确顺序： 复习 Lecture 7-8, 16 → 在纸上画分布式布局 → 用 P=2 调试 → 验证数值正确性 → 再扩展到更多秩 → 分析性能。

调试黄金法则： 先保证正确（串行和分布式结果一致），再追求性能。一个快但错的结果毫无价值。
