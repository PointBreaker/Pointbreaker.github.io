常见陷阱

Weight matrix 的方向： Assignment 中很多 weight 的 shape 是 (d_out, d_in)，计算时需要转置。这是最常见的 bug 来源。

Numerical stability： Softmax 和 cross-entropy 要注意数值溢出。直接计算 exp(x) 在大数值时会溢出。

Attention mask： 因果 mask（causal mask）确保位置 i 只能 attend 到 ≤i 的位置。注意 mask 的应用方式（加到 softmax 前的 logits 上）。

RoPE 的维度： RoPE 应用在 head 维度上（d_model // num_heads），不是整个 d_model。

unicode2Unicode 编码任务 · 提示 · 验收
Handout 完整本土化可离线实施不含参考实现

完整任务

背景

虽然 Unicode 标准定义了字符到码点（整数）的映射，但直接在 Unicode 码点上训练 tokenizer 并不现实：词表过大（约 15 万项）且稀疏。因此我们使用 Unicode 编码将字符转换为字节序列。Unicode 标准定义了三种编码：UTF-8、UTF-16、UTF-32，其中 UTF-8 是互联网主流编码（超过 98% 的网页使用）。

在 Python 中，可用 .encode("utf-8") 将 Unicode 字符串编码为 UTF-8，用 list() 查看字节值，用 .decode("utf-8") 将字节串解码回 Unicode 字符串。注意：一个字节不一定对应一个 Unicode 字符。

>>> test_string = "hello! こんにちは!"
>>> utf8_encoded = test_string.encode("utf-8")
>>> list(utf8_encoded)
[104, 101, 108, 108, 111, 33, 32, 227, 129, 147, 227, 130, 147, 227, 129, 171, 227, 129, 161, 227, 129, 175, 33]
>>> len(test_string)
13
>>> len(utf8_encoded)
23

将 Unicode 码点转换为字节序列（如通过 UTF-8），相当于把范围在 0 到 154,997 的整数序列映射为范围在 0 到 255 的字节值序列。长度为 256 的字节词表更易于处理，且使用字节级分词时不存在 out-of-vocabulary 问题——任何输入文本都可表示为 0 到 255 的整数序列。

问题

本题共 3 分，包含以下三个小问：

(a) 相较于 UTF-16 或 UTF-32，我们更倾向于在 UTF-8 编码的字节上训练 tokenizer，原因有哪些？建议比较不同编码在各种输入串下的输出。

交付物：用一到两句话回答。

def decode_utf8_bytes_to_str_wrong(bytestring: bytes):
    return "".join([bytes([b]).decode("utf-8") for b in bytestring])

>>> decode_utf8_bytes_to_str_wrong("hello".encode("utf-8"))
'hello'

交付物：给出一个使 decode_utf8_bytes_to_str_wrong 产生错误输出的输入字节串示例，并用一句话解释该函数为何错误。

(c) 给出一个无法解码为任何 Unicode 字符的两字节序列。

交付物：给出示例，并用一句话解释。

查看解题提示

  • 对于 (b)：思考逐字节单独解码为何会破坏多字节字符——每个多字节字符的后续字节（continuation byte）单独来看并非有效的 UTF-8 起始字节。

train_bpeBPE 分词器训练任务 · 提示 · 验收
Handout 完整本土化可离线实施不含参考实现

完整任务

实现一个函数，给定输入文本文件的路径，训练一个（字节级）BPE 分词器。你的 BPE 训练函数应至少处理以下输入参数：

  • input_path: str：包含 BPE 分词器训练数据的文本文件路径。

  • vocab_size: int：一个正整数，定义最终词汇表的最大大小（包括初始字节词汇表、合并产生的词汇项以及任何特殊 token）。

  • special_tokens: list[str]：要添加到词汇表中的字符串列表。这些特殊 token 不影响 BPE 训练。

你的 BPE 训练函数应返回所得的词汇表与合并列表：

  • vocab: dict[int, bytes]：分词器词汇表，从 int（词汇表中的 token ID）到 bytes（token 字节）的映射。

  • merges: list[tuple[bytes, bytes]]：训练产生的 BPE 合并列表。列表中的每一项是一个字节元组 (<token1>, <token2>)，表示 <token1> 与 <token2> 被合并。合并应按创建顺序排列。

为了用提供的测试验证你的 BPE 训练函数，你需要先实现测试适配器 adapters.run_train_bpe，然后运行 uv run pytest tests/test_train_bpe.py。你的实现应能通过全部测试。

\[ \text{RMSNorm}(a_i) = \frac{a_i}{\text{RMS}(\mathbf{a})}\, g_i \]

\[ \text{RMS}(\mathbf{a}) = \sqrt{\frac{1}{d_{\text{model}}}\sum_{i=1}^{d_{\text{model}}} a_i^2 + \varepsilon} \]

完整任务

背景

在原始 Transformer（Vaswani et al., 2017, §3.3）中，前馈网络由两层线性变换夹一个 ReLU 激活组成，内层维度通常为输入的 4 倍。现代 LLM（如 LLaMA 3、Qwen 2.5）在此基础上做了两项改动：将激活函数替换为 SiLU（又称 Swish），并引入 门控线性单元（Gated Linear Unit, GLU） 构成 SwiGLU。自 PaLM 与 LLaMA 起，现代 LLM 通常省略线性层的 bias。

SiLU / Swish 激活（Hendrycks and Gimpel, 2016; Elfwing et al., 2017）定义为：

\[ \text{SiLU}(x) = x \cdot \sigma(x) = \frac{x}{1 + e^{-x}} \]

其形状与 ReLU 相似，但在零点处光滑（参见 Figure 3）。

GLU（Dauphin et al., 2017）定义为经 sigmoid 的线性变换与另一线性变换的逐元素乘积：

\[ \text{GLU}(x, W_1, W_2) = \sigma(W_1 x) \odot W_2 x \]

将 SiLU 与 GLU 结合得到 SwiGLU，即本题要求实现的前馈网络：

\[ \text{FFN}(x) = \text{SwiGLU}(x, W_1, W_2, W_3) = W_2\bigl(\text{SiLU}(W_1 x) \odot W_3 x\bigr) \]

其中 \(x \in \mathbb{R}^{d_{\text{model}}}\)，\(W_1, W_3 \in \mathbb{R}^{d_{\text{ff}} \times d_{\text{model}}}\)，\(W_2 \in \mathbb{R}^{d_{\text{model}} \times d_{\text{ff}}}\)，且通常 \(d_{\text{ff}} = \frac{8}{3}\,d_{\text{model}}\)。

任务

实现 SwiGLU 前馈网络（由 SiLU 激活与 GLU 组成）。

注意：出于数值稳定性考虑，你可以直接使用 torch.sigmoid 计算 sigmoid。

在你的实现中，应将 \(d_{\text{ff}}\) 设为约 \(\frac{8}{3} \times d_{\text{model}}\)，同时确保内层维度是 64 的整数倍，以充分利用硬件。

Handout 完整本土化可离线实施不含参考实现

完整任务

背景

为了让模型感知位置信息，本题实现 旋转位置编码（Rotary Position Embeddings, RoPE）（Su et al., 2021）。对于位置 \(i\) 上的查询 token \(q^{(i)} = W_q x^{(i)} \in \mathbb{R}^d\)，施加一个分块旋转矩阵 \(R_i\)，得到 \(q'^{(i)} = R_i q^{(i)} = R_i W_q x^{(i)}\)。

\(R_i\) 将嵌入的成对元素 \(q^{(i)}_{2k-1:2k}\) 视为二维向量，按角度 \(\theta_{i,k} = i / \Theta^{2k/d}\) 旋转，其中 \(k \in \{1, \dots, d/2\}\)，\(\Theta\) 为常数。于是 \(R_i\) 是一个 \(d \times d\) 的分块对角矩阵，每个分块 \(R_i^k\)（\(k \in \{1, \dots, d/2\}\)）为：

\[ R_i^k = \begin{bmatrix} \cos(\theta_{i,k}) & -\sin(\theta_{i,k}) \\ \sin(\theta_{i,k}) & \cos(\theta_{i,k}) \end{bmatrix} \]

完整的旋转矩阵为：

\[ R_i = \begin{bmatrix} R_i^1 & 0 & 0 & \dots & 0 \\ 0 & R_i^2 & 0 & \dots & 0 \\ 0 & 0 & R_i^3 & \dots & 0 \\ \vdots & \vdots & \vdots & \ddots & \vdots \\ 0 & 0 & 0 & \dots & R_i^{d/2} \end{bmatrix} \]

其中 \(0\) 为 \(2 \times 2\) 零矩阵。实际实现中应利用该矩阵的结构特性高效地完成变换，而不需要构造完整的 \(d \times d\) 矩阵。

由于我们只关心序列内 token 的相对旋转，\(\cos(\theta_{i,k})\) 与 \(\sin(\theta_{i,k})\) 可在不同层和不同 batch 间复用。你可以让所有层共享同一个 RoPE 模块，并在 __init__ 中用 self.register_buffer(persistent=False) 创建 sin/cos 的预计算缓冲区（它们不是 nn.Parameter，因为不需要学习）。对查询 \(q^{(i)}\) 和键 \(k^{(j)}\) 施加相同的旋转过程。该层没有可学习参数。

  • device: torch.device | None = None — 缓冲区所在设备。

处理形状为 (..., seq_len, d_k) 的输入张量，返回同形状的张量。注意：x 可包含任意数量的 batch 维度。token_positions 为形状 (..., seq_len) 的张量，表示 x 沿序列维度的位置。

实现 softmax 操作。

编写一个函数，对张量应用 softmax 操作。你的函数应接受两个参数：一个张量和一个维度 i，并对输入张量的第 i 维应用 softmax。输出张量的形状应与输入张量相同，但其第 i 维将是一个归一化的概率分布。

其中 \(\text{head}_i = \text{Attention}(\mathbf{Q}_i, \mathbf{K}_i, \mathbf{V}_i)\)，\(\mathbf{Q}_i, \mathbf{K}_i, \mathbf{V}_i\) 分别是 \(\mathbf{Q}, \mathbf{K}, \mathbf{V}\) 在嵌入维度上切出的第 \(i \in \{1, \ldots, h\}\) 个切片，大小为 \(d_k\) 或 \(d_v\)。Attention 为第 3.5.4 节定义的缩放点积注意力。

Problem (decoding): 文本解码（3 分）

实现一个从你的语言模型解码（生成文本）的函数。我们建议支持以下功能：

  • 为用户提供的 prompt 生成补全（即接收某个 \(x_{1...t}\) 并采样补全直到遇到 <filename> token）

  • 允许用户控制生成的最大 token 数

  • 给定期望的 temperature 值，在采样前对预测的 next-word 分布应用 softmax temperature scaling

  • Top-p 采样（Holtzman et al., 2020；也称为 nucleus sampling），给定用户指定的阈值

背景知识

Softmax：按照标准约定，语言模型输出是最终线性层的输出（"logits"），因此我们需要通过 softmax 操作将其转换为归一化概率：

\[ \text{softmax}(v)_i = \frac{\exp(v_i)}{\sum_j \exp(vj)} \]

解码：为了从模型生成文本（解码），我们将前缀 token 序列（"prompt"）提供给模型，让它产生一个预测序列中下一个词的概率分布。然后我们从这个词汇表上的分布中采样以确定下一个输出 token。

具体来说，解码过程的一个步骤应接收序列 \(x_{1...t}\) 并通过以下方程返回 token \(x_{t+1}\)：

\[ P(x_{t+1} = i \mid x_{1...t}) = \frac{\exp(v_i)}{\sum_j \exp(vj)} \] \[ v = \text{TransformerLM}(x_{1...t})_t \in \mathbb{R}^{\text{vocab\_size}} \]

其中 TransformerLM 是我们的模型，接收长度为 sequence_length 的序列并产生大小为 \((\text{sequence\_length} \times \text{vocab\_size})\) 的矩阵，我们取该矩阵的最后一个元素，因为我们要找的是第 \(t\) 个位置的 next-word 预测。

通过反复采样这些单步条件分布（将先前生成的输出 token 附加到下一个解码时间步的输入中），直到生成 end-of-sequence token <filename>（或用户指定的最大生成 token 数），我们得到一个基本的解码器。

Temperature scaling：我们用 temperature 参数 \(\tau\) 修改 softmax：

\[ \text{softmax}(v, \tau)_i = \frac{\exp(v_i/\tau)}{\sum_{j=1}^{|\text{vocab\_size}|} \exp(v_j/\tau)} \]

注意当 \(\tau \to 0\) 时，\(v\) 中最大元素占主导，softmax 输出变为集中在最大元素上的 one-hot 向量。

Top-p 采样（nucleus sampling）：设 \(q\) 是（temperature 缩放后的）softmax 产生的概率分布，大小为 (vocab_size)。具有超参数 \(p\) 的 nucleus sampling 根据以下方程产生下一个 token：

\[ P(x_{t+1} = i \mid q) = \begin{cases} \frac{q_i}{\sum_{j \in V(p)} q_j} & \text{if } i \in V(p) \\ 0 & \text{otherwise} \end{cases} \]

其中 \(V(p)\) 是索引的最小集合，使得 \(\sum_{j \in V(p)} q_j \geq p\)。你可以通过首先按大小对概率分布 \(q\) 排序，然后选择最大的词汇表元素直到达到目标水平来轻松计算这个量。
