这个 Assignment 要你做什么？

一句话总结：使用提供的训练 API，在不同的模型大小和 token 预算组合上运行实验，收集损失数据，拟合 scaling law，然后基于定律预测最优的 compute allocation。

Assignment 3 是一个实验科学练习：你需要像一个研究员一样设计实验、收集数据、拟合模型、做出预测。重点不是写代码，而是理解 scaling law 的理论和实验方法。

如何开始？

0

理解 API 和约束

仔细阅读 handout 中的训练 API 文档。理解：你可以控制哪些超参数（model size, learning rate, batch size 等）、你的总 compute 预算是多少、每次训练运行需要多长时间。

1

设计实验矩阵

你需要选择一组 (model_size, num_tokens) 组合来运行实验。考虑：

  • 覆盖足够大的范围（太小或太大的模型都要有）
  • 在关键区域增加密度（曲线变化快的地方）
  • 控制变量：一次只改变一个维度
2

高效利用预算

你的 FLOPs 预算有限。策略建议：

  • 先用小模型快速验证 pipeline
  • 优先在"信息丰富"的区域采样（中等大小模型）
  • 保留一些预算用于验证/补充实验
  • 记录每次实验的实际 FLOPs 消耗
3

拟合与验证

收集数据后：

  1. 在对数坐标上可视化数据
  2. 拟合 scaling law（考虑不同的拟合方法）
  3. 检查残差，识别异常点
  4. 用拟合结果预测最优配置

常见陷阱

数据噪声： 训练本身有随机性（初始化、数据顺序）。同一个配置跑多次可能有不同的 loss。不要过度解读单次运行的噪声。

过拟合少量数据点： 如果你只跑了 3-4 个点，拟合结果可能非常不稳定。确保有足够的数据点来验证幂律假设。

外推风险： Scaling law 在观测范围内可能拟合得很好，但外推到未验证的区域可能完全错误。对远距离预测保持警惕。

忽略训练动态： 假设你的模型没有充分训练（不在 asymptotic regime），scaling law 可能不成立。注意 loss curve 是否还在明显下降。

超参数不一致： 不同大小的最优超参数（learning rate、warmup 等）可能不同。如果混用不合适的超参数，数据点会偏离真实 scaling 趋势。

训练运行详情

训练运行使用 Transformer 语言模型，架构与作业 1 基本一致，但有以下关键差异：

  1. 使用绝对位置编码（Absolute Position Embeddings），而非旋转位置编码（RoPE）。

完整任务

（本题 5 分。）

复现上述使用一组训练运行的最终训练损失来拟合缩放律的 IsoFLOPs 方法。对于本题，使用文件 data/isoflops_curves.json 中给出的（合成）训练运行数据。该文件包含一个 JSON 数组，其中每个元素是一个描述训练运行的对象，包含 parameters、compute_budget、final_loss 字段。以下是前两次运行的格式示例：

[
  {
    "parameters": 49999999,
    "compute_budget": 6e+18,
    "final_loss": 7.192784500319437
  },
  {
    "parameters": 78730505,
    "compute_budget": 6e+18,
    "final_loss": 6.750171320661809
  },
  ...
]

对于拟合缩放律，scipy 包（特别是 scipy.optimize.curve_fit）可能会有用，但你可以使用任何你喜欢的曲线拟合方法。虽然 Hoffmann et al. [2022] 对每个 IsoFLOP 剖面拟合二次函数来寻找最小值，但我们建议直接取每个计算预算下训练损失最低的运行作为最小值。

背景： 训练一个含 \(N\) 个参数的 Transformer 在含 \(D\) 个 token 的数据集上的计算预算近似为 \(C = 6ND\)。对每个计算预算 \(C_i\)，在不同模型大小 \(N_{ij}\) 下（数据大小 \(D = C/(6N)\)）训练语言模型，得到最终训练损失 \(L_{ij}\)。在每个预算内找到使训练损失最小的模型大小 \(N_{opt}(C_i)\)，得到数据点序列 \(\langle C_i, N_{opt}(C_i) \rangle\)（以及对应的 \(D_{opt}\)）。用这些数据点拟合幂律 \(N_{opt} \propto C^a\) 和 \(D_{opt} \propto C^b\)，并外推到目标计算预算。

  1. 展示你外推出的计算最优模型大小，以及你获得的 \(\langle C_i, N_{opt}(C_i) \rangle\) 点。对于 \(10^{23}\) FLOPs 的预算，你预测的最优模型大小是多少？对于 \(10^{24}\) FLOPs 呢？

交付物： 一张展示模型大小随计算预算变化的缩放律图，显示用于拟合的数据点并外推到至少 \(10^{24}\) FLOPs。然后，用一句话回答你预测的最优模型大小。

  1. 展示你外推出的计算最优数据集大小，以及来自训练运行的 \(\langle C_i, D_{opt}(C_i) \rangle\) 数据点。对于 \(10^{23}\) 和 \(10^{24}\) FLOPs 的预算，你预测的最优数据集大小是多少？

交付物： 一张展示数据集大小随计算预算变化的缩放律图，显示用于拟合的数据点并外推到至少 \(10^{24}\) FLOPs。然后，用一句话回答你预测的最优数据集大小。

查看解题提示

  • 先修概念：理解 IsoFLOPs 剖面的含义——固定 FLOPs 预算下，模型大小与数据大小的权衡；理解幂律拟合 \(y = ax^b\) 通常通过对数变换后线性回归实现。

  • 实施顺序：先加载 data/isoflops_curves.json 并探索数据结构（计算预算的分布、模型大小的范围）；对每个计算预算分组并找到 final_loss 最小的运行；分别提取 \(N_{opt}\) 和 \(D_{opt}\)（通过 \(D_{opt} = C_i / (6 N_{opt})\) 计算）；在对数空间拟合幂律；绘制数据点与拟合曲线并外推。

  • 调试策略：检查每个计算预算下是否确实找到了唯一的最低损失运行；验证 \(D_{opt}\) 的计算是否正确；检查拟合曲线是否合理穿过数据点；外推时注意幂律在远离数据范围时的可靠性。

  • 自检方法：确认拟合的指数 \(a\) 和 \(b\) 为正数且合理；确认外推曲线在数据点附近与观测值吻合；用一句话清晰陈述 \(10^{23}\) 和 \(10^{24}\) FLOPs 下的预测值。

完整任务

（本题 50 分。）

构建一个缩放律，以准确预测 FLOPs 预算为 \(10^{19}\) 时的最优模型大小、其超参数以及相关的训练损失。为了构建缩放律，你将使用我们的训练 API 查询各种实验配置的最终训练损失（§3.1）；你不得查询超过 \(2 \times 10^{18}\) FLOPs 的实验来拟合你的缩放律。这是一个由 API 强制执行的上限（hard cap）。

交付物： 一份排版的报告（write-up），包含你拟合缩放律的方法和完整描述。此外，还应描述你如何使用缩放律来预测给定 FLOPs 预算下的最优模型大小，以及你的预测值。报告应包含关于为何做出特定设计决策的评论，描述应足够详细以复现你的方法和结果。

关于 batch size 的说明： 对于 \(10^{19}\) FLOPs 预算下你报告的超参数，我们基本没有限制，只要求你的 batch size 必须是 128 或 256。这是为了确保运行具有合理的模型 FLOPs 利用率。如果我们在运行你报告的超参数配置时遇到内存不足（OOM）错误，我们将使用梯度累积或扩展数据并行 GPU 的数量来维持你期望的 batch size。

为了帮助你入门，我们建议至少思考以下问题。你的报告应包含关于以下每个因素如何做出决策的额外评论：

  • 给定固定的缩放律预算 \(2 \times 10^{18}\)，你决定查询哪些运行？

  • 你如何拟合你的缩放律？描述你使用的具体方法。熟悉 Kaplan et al. [2020] 和 Hoffmann et al. [2022] 使用的方法可能会很有用。

  • 你的缩放律对实验数据的拟合程度如何？

  • 对于我们给定的 \(10^{19}\) FLOPs 预算，你的缩放律预测的最优模型大小是多少？预测的损失是多少？

  • 如果你要训练一个具有预测最优参数数量的模型，你会使用什么超参数？要估计给定模型超参数配置的非嵌入参数数量，使用 \(12 n_{layer} d_{model}^2\)。

除了报告外，还需通过 Google 表单 https://forms.gle/sAUSLwCUETew2hYN6 提交：(1) 预测的最优模型大小，(2) 要使用的训练超参数（包括 batch size 128 或 256），以及 (3) 模型的训练损失。作业的部分成绩将由你预测的最优模型的性能决定。

训练 API（§3.1）

你将使用训练 API 查询你想要运行的缩放律实验的最终训练损失。你的 API key 与开学时提交给课程组的 SSH 公钥相同（不含换行符）。注意：必须在斯坦福网络内才能查询 API，因此可能需要使用 VPN。作为 sanity check，你应该能够在 http://hyperturing.stanford.edu:8000/docs 看到 API 文档页面。训练 API 具有以下端点：

GET /loss：给定训练运行的规格，返回最终训练损失。参数如下：

  • d_model：整数，范围 [64, 1024]

  • num_layers：整数，范围 [2, 24]

  • num_heads：整数，范围 [2, 16]

  • batch_size：整数，取值 {128, 256}

  • learning_rate：浮点数，范围 [1e-3, 1e-4]

  • train_flops：整数，取值 {1e13, 3e13, 6e13, 1e14, 3e14, 6e14, 1e15, 3e15, 6e15, 1e16, 3e16, 6e16, 1e17, 3e17, 6e17, 1e18}

  • api_key：字符串 API key

注意：使用之前查询过的实验配置查询此端点不会消耗额外的 FLOPs 预算。此端点返回一个 JSON 对象，包含 loss（浮点训练损失）和 total_flops_used（该 API key 已使用的总 FLOPs）。如果超参数值不在可接受范围内，返回 404 响应及附带消息。

GET /total_flops_used：给定 API key，返回该 key 在所有先前查询的运行中使用的总 FLOPs。参数：api_key。如果 API key 没有查询记录，返回 422 响应及附带消息。

GET /previous_runs：给定 API key，返回使用该 API key 查询的所有先前运行的列表。参数：api_key。返回 JSON 对象包含 previous_runs 键，值为所有先前运行配置及其结果的数组。
