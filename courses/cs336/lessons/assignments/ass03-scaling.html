这个 Assignment 要你做什么？

一句话总结：使用提供的训练 API，在不同的模型大小和 token 预算组合上运行实验，收集损失数据，拟合 scaling law，然后基于定律预测最优的 compute allocation。

Assignment 3 是一个实验科学练习：你需要像一个研究员一样设计实验、收集数据、拟合模型、做出预测。重点不是写代码，而是理解 scaling law 的理论和实验方法。

如何开始？

0

理解 API 和约束

仔细阅读 handout 中的训练 API 文档。理解：你可以控制哪些超参数（model size, learning rate, batch size 等）、你的总 compute 预算是多少、每次训练运行需要多长时间。

1

设计实验矩阵

你需要选择一组 (model_size, num_tokens) 组合来运行实验。考虑：

  • 覆盖足够大的范围（太小或太大的模型都要有）
  • 在关键区域增加密度（曲线变化快的地方）
  • 控制变量：一次只改变一个维度
2

高效利用预算

你的 FLOPs 预算有限。策略建议：

  • 先用小模型快速验证 pipeline
  • 优先在"信息丰富"的区域采样（中等大小模型）
  • 保留一些预算用于验证/补充实验
  • 记录每次实验的实际 FLOPs 消耗
3

拟合与验证

收集数据后：

  1. 在对数坐标上可视化数据
  2. 拟合 scaling law（考虑不同的拟合方法）
  3. 检查残差，识别异常点
  4. 用拟合结果预测最优配置

常见陷阱

数据噪声： 训练本身有随机性（初始化、数据顺序）。同一个配置跑多次可能有不同的 loss。不要过度解读单次运行的噪声。

过拟合少量数据点： 如果你只跑了 3-4 个点，拟合结果可能非常不稳定。确保有足够的数据点来验证幂律假设。

外推风险： Scaling law 在观测范围内可能拟合得很好，但外推到未验证的区域可能完全错误。对远距离预测保持警惕。

忽略训练动态： 假设你的模型没有充分训练（不在 asymptotic regime），scaling law 可能不成立。注意 loss curve 是否还在明显下降。

超参数不一致： 不同大小的最优超参数（learning rate、warmup 等）可能不同。如果混用不合适的超参数，数据点会偏离真实 scaling 趋势。

这次作业更像一个研究项目。 没有唯一的"正确"答案——你的预测质量取决于实验设计的合理性和数据分析的严谨性。

关键心态：数据 > 直觉。不要因为"感觉某个配置更好"就不做实验验证。让数据说话。
