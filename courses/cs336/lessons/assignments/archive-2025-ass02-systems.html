开工 Cheatsheet

Benchmark contract

  • 计时区间前后同步 GPU；记录 warmup 与 measurement 次数。
  • 固定 batch、sequence length、dtype、模型配置和编译模式。
  • 同时报告 latency、tokens/s、峰值显存与正确性误差。
  • profile 用于解释变化，benchmark 用于量化变化。

FlashAttention invariants

\(m_{new}=\max(m_{old},\max s_{tile})\)

\(\ell_{new}=e^{m_{old}-m_{new}}\ell_{old}+\sum e^{s_{tile}-m_{new}}\)

  • 不物化完整 (T\times T) scores。
  • causal mask、边界 mask 与 backward 数值必须和参考实现对齐。

Distributed timeline

  • Backward 产生梯度的顺序决定 collective 可启动的时间。
  • Bucket 太小：latency 多；太大：启动晚、overlap 少。
  • 用 trace 证明 overlap，不只比较总运行时间。
  • gradient accumulation 会改变通信频率与有效 batch。

Memory accounting

  • 分开计算 parameters、gradients、optimizer states、activations。
  • 明确每项 dtype 与字节数，区分 steady state 和峰值。
  • FSDP 峰值取决于参数何时 All-Gather、何时释放。
  • 理论核算与实测不一致时，检查 allocator cache 与临时 buffer。

如何开始？

0

Profile 优先

在写任何优化代码之前，先用 nsys/ncu 对基线实现做 profile。理解时间花在哪里、内存带宽利用率如何。不要凭直觉优化——数据说话。

1

理解 Triton 抽象

Triton 的编程模型不同于 CUDA：你写的是 block-level 的代码，编译器帮你处理内存合并和 shared memory。先读 Triton 文档，理解 tl.load、tl.store、tl.dot 的语义。

2

Activation Checkpointing → FlashAttention 2 → 分片训练

建议的实现顺序：

  1. Activation checkpointing — 先量化用重计算换显存的收益与代价
  2. FlashAttention-2 — 核心难点，理解 tiling 和 online softmax 如何避免 materialize 完整的 attention matrix
  3. DDP — 理解 AllReduce 如何同步梯度
  4. Optimizer state sharding 与 FSDP — 分别验证状态分片与全分片训练的内存/通信权衡
3

Benchmark 和验证

每个优化后都要做两件事：正确性验证（与 PyTorch 参考实现对比）和性能测试（测量加速比）。注意：先保证正确，再追求速度。

常见陷阱

Memory coalescing： GPU 对 global memory 的访问以 32/128 字节为单位。如果相邻 thread 访问不连续的地址，会导致 bandwidth 利用率极低。

Bank conflict： Shared memory 分为 32 个 bank。如果同一 warp 中多个 thread 访问同一 bank 的不同地址，访问会串行化。

Numerical precision： FlashAttention 在 fp16/bf16 下做 reduction 时要注意累加顺序。online softmax 的数值稳定性证明需要理解。

Communication overhead： DDP 的 AllReduce 如果和计算不重叠，会成为瓶颈。注意 gradient bucketing 和 gradient accumulation 的影响。

Triton 的自动优化： Triton 编译器会做很多优化（如自动使用 tensor core），但也可能做出你不期望的选择。学会读 PTX/LLVM IR 来理解实际生成的代码。

Profiling 与 Benchmark 方法

常用工具

# 用 nsys 做时间线 profile
nsys profile -o output python train.py

# 用 ncu 做 kernel 级分析
ncu --set full -o report python train.py

# PyTorch profiler（高层视图）
with torch.profiler.profile() as prof:
    train_step()
print(prof.key_averages().table())

Benchmark 原则

  • Warmup：第一次运行通常慢（JIT 编译、CUDA 初始化），丢弃前几次
  • 多次采样取平均：GPU 频率波动会影响结果
  • 控制变量：只改变你要测试的那一个因素
  • 报告 wall-clock time 和 throughput：tokens/second 比 FLOPs 更直观

使用 nsys

使用 nsys profile 剖析 Python 脚本，例如：

uv run nsys profile -o result python benchmark.py

可在本地使用 NVIDIA Nsight Systems 桌面应用查看剖析结果。

可尝试 nsys profile 的各种命令行选项。特别地：

  • 使用 --python-backtrace=cuda 可获取每个 CUDA API 调用的 Python 回溯（可能引入额外开销）。

  • 使用 NVTX ranges 标注代码，在剖析结果的 NVTX 行中显示为块，捕获所有 CUDA API 调度和相应的 kernel 执行。应使用 NVTX ranges 忽略基准测试脚本中的预热步骤（通过对 NVTX 行应用过滤器）。

  • 还可以隔离模型的哪些 kernel 负责前向和反向传播，甚至通过标注实现来隔离自注意力层中不同部分的 kernel：

import torch.cuda.nvtx as nvtx

@nvtx.range("scaled dot product attention")
def annotated_scaled_dot_product_attention(...):
    ...
    with nvtx.range("computing attention_scores"):
        ...  # 计算 Q 和 K 之间的注意力分数
    with nvtx.range("computing softmax"):
        ...  # 计算注意力分数的 softmax

flash_forwardFlashAttention-2 前向传播任务 · 提示 · 验收
Handout 完整本土化可离线实施不含参考实现

完整任务

本问题要求你按照 FlashAttention-2 论文（Dao, 2023）实现一个显著改进的 Triton 注意力实现。FlashAttention-2 使用平铺（tiling）技术计算前向传播，实现高效的内存访问模式，并避免在全局内存中实例化完整的注意力矩阵。

背景：标准注意力的低效性

回顾注意力的前向传播（暂时忽略掩码）：

\[S = QK^\top / \sqrt{d}\]

\[P_{ij} = \text{softmax}_j(S)_{ij}\]

\[O = PV\]

标准反向传播：

\[dV = P^\top dO\]

\[dP = dOV^\top\]

\[dS_i = (\text{diag}(P_i) - P_iP_i^\top)dP_i\]

\[dQ = dSK / \sqrt{d}\]

\[dK = dS^\top Q / \sqrt{d}\]

反向传播依赖于前向传播中的大型激活值。例如，计算 \(dV\) 需要 \(P\)，即形状为 \((batch\_size, n\_heads, seq\_len, seq\_len)\) 的注意力分数——这个激活矩阵的大小随序列长度二次增长。

FlashAttention 的主要目标是避免将注意力矩阵读写到 HBM（高带宽内存），以减少 IO 和峰值内存成本。通过三种技术实现：平铺（Tiling）、重计算（Recomputation） 和 算子融合（Operator Fusion）。

Online Softmax 与重计算

使用下标 \(i\) 表示当前 query tile，上标 \((j)\) 表示当前 key tile。query 维度的 tile 大小为 \(B_q\)，key 维度的 tile 大小为 \(B_k\)。不在隐维度 \(d\) 上分 tile。

维护行方向的运行值 \(m_i^{(j)} \in \mathbb{R}^{B_q}\) 和 \(l_i^{(j)} \in \mathbb{R}^{B_q}\)。\(m_i^{(j)}\) 是运行最大值，用于数值稳定地计算 softmax。\(l_i^{(j)}\) 是 softmax 分母的代理值。

Algorithm 1：FlashAttention-2 前向传播

输入： \(Q \in \mathbb{R}^{N_q \times d}\)，\(K, V \in \mathbb{R}^{N_k \times d}\)，tile 大小 \(B_q\)、\(B_k\)

将 \(Q\) 分割为 \(T_q = \lceil N_q/B_q \rceil\) 个 tile \(Q_1, \ldots, Q_{T_q}\)，每个大小为 \(B_q \times d\)

将 \(K, V\) 分割为 \(T_k = \lceil N_k/B_k \rceil\) 个 tile \(K^{(1)}, \ldots, K^{(T_k)}\) 和 \(V^{(1)}, \ldots, V^{(T_k)}\)，每个大小为 \(B_k \times d\)

for \(i = 1, \ldots, T_q\) do

从全局内存加载 \(Q_i\)

初始化 \(O_i^{(0)} = 0 \in \mathbb{R}^{B_q \times d}\)，\(l_i^{(0)} = 0 \in \mathbb{R}^{B_q}\)，\(m_i^{(0)} = -\infty \in \mathbb{R}^{B_q}\)

for \(j = 1, \ldots, T_k\) do

从全局内存加载 \(K^{(j)}\)、\(V^{(j)}\)

计算 softmax 前的注意力分数 tile \(S_i^{(j)} = Q_i(K^{(j)})^\top / \sqrt{d} \in \mathbb{R}^{B_q \times B_k}\)

计算 \(m_i^{(j)} = \max(m_i^{(j-1)}, \text{rowmax}(S_i^{(j)})) \in \mathbb{R}^{B_q}\)

计算 \(\tilde{P}_i^{(j)} = \exp(S_i^{(j)} - m_i^{(j)}) \in \mathbb{R}^{B_q \times B_k}\)

计算 \(l_i^{(j)} = \exp(m_i^{(j-1)} - m_i^{(j)}) l_i^{(j-1)} + \text{rowsum}(\tilde{P}_i^{(j)}) \in \mathbb{R}^{B_q}\)

计算 \(O_i^{(j)} = \text{diag}(\exp(m_i^{(j-1)} - m_i^{(j)})) O_i^{(j-1)} + \tilde{P}_i^{(j)} V^{(j)}\)

end for

计算 \(O_i = \text{diag}(l_i^{(T_k)})^{-1} O_i^{(T_k)}\)

计算 \(L_i = m_i^{(T_k)} + \log(l_i^{(T_k)})\)

将 \(O_i\) 写入全局内存作为 \(O\) 的第 \(i\) 个 tile。

将 \(L_i\) 写入全局内存作为 \(L\) 的第 \(i\) 个 tile。

end for

返回 输出 \(O\) 和 logsumexp \(L\)。
