这个 Assignment 要你做什么？

一句话总结：从 Common Crawl 的原始 HTML 网页出发，构建一个完整的数据处理 pipeline：提取文本、过滤低质量内容、检测有害信息、去重，最终产出可用于训练 LM 的高质量语料。

Assignment 4 是数据工程的实战。你会理解为什么"数据质量"是 LLM 训练中最被低估的因素之一，以及如何系统性地处理互联网规模的数据。

如何开始？

0

理解数据格式

Common Crawl 数据存储为 WARC 格式。先下载一个小样本（几百 MB），手动查看几个文件的结构。理解 HTTP header、HTML body、metadata 的位置。

1

文本提取

从 HTML 中提取纯文本是第一步。关键挑战：

  • 移除 boilerplate（导航栏、页脚、广告）
  • 保留有意义的正文内容
  • 处理不同语言的编码问题
  • 决定保留还是丢弃表格、列表等结构
2

训练质量分类器

你需要一个模型来判断"这段文本是否适合训练 LM"。思路：

  1. 定义"高质量"参考语料（如 Wikipedia、Books）
  2. 定义"低质量"参考语料（随机网页、垃圾内容）
  3. 设计特征，训练二分类器
  4. 在验证集上评估 precision/recall
3

MinHash 去重

互联网数据有大量近似重复（模板、爬虫镜像）。MinHash + LSH 是标准方案：

  • 选择合适的 shingle 大小（n-gram 长度）
  • 选择 hash 函数数量和 band 数量
4

Pipeline 调优

整合所有步骤，调整阈值参数。最终评估指标通常是：在固定 token budget 下，下游 LM 的 perplexity。

常见陷阱

编码问题： 互联网数据有各种编码（UTF-8, Latin-1, GBK...），还有 mojibake（编码错误导致的乱码）。不处理会导致 tokenizer 行为异常。

内存效率： Common Crawl 是 TB 级别的数据。不能把所有文件加载到内存。学会用流式处理、分块读写、外部排序等技术。

去重参数选择： MinHash 的 band 数和 row 数直接影响 recall 和 precision。太宽松的去重等于没做，太严格会误删有价值的内容。

质量分类器的 bias： 如果你的"高质量"参考语料主要是英文 Wikipedia，分类器可能会歧视其他语言或文体（如口语化文本）。

过度过滤： 过滤太激进会导致数据多样性下降，模型在长尾任务上表现变差。要在"干净"和"多样"之间权衡。

数据处理与评估方法

Pipeline 调试技巧

  • 从小样本开始：先用 100 个文件调试，确认逻辑正确后再放大
  • 记录过滤统计：每个阶段记录被过滤了多少、为什么
  • 人工检查样本：随机抽取保留/丢弃的样本，人工判断是否合理
  • 可视化分布：文本长度、质量分数、语言分布的直方图

最终评估

数据处理 pipeline 的终极目标是提升下游 LM 的性能。评估方式：

  • 用你的语料训练一个小 LM，测量 perplexity
  • 对比 baseline（未过滤/未去重）的效果
  • 注意控制变量：训练配置、token 数、模型大小保持一致

学习心态

数据工程是 LLM 训练中最"脏"也最重要的工作。 模型架构的改进容易被关注，但数据质量的提升往往带来更大的实际收益。

关键心态：数据没有"干净"，只有"更适合"。 每个过滤决策都是在做权衡——理解你的选择会如何影响模型的行为。
