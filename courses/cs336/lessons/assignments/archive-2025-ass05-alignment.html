Recursive prerequisite map

递归知识树：一次 RL update 在优化什么？

Root 01 · Prompting & evaluation

训练前，任务和奖励是否已经定义清楚？

对应 prompting baseline、grader 与 reward decomposition。

  • Prompt → response distribution
    • zero-shot / few-shot / CoT
    • temperature、stop 与格式
  • Response → parsed answer
    • 格式解析失败和答案错误要区分
    • grader 必须先通过人工样本检查
  • Score → baseline
    • accuracy / total reward
    • 多次采样与随机种子方差
Root 02 · Sequence probability

一个回答的概率怎样分解到 token？

对应 tokenization、response mask、log-prob 与 entropy。

  • Prompt + output → aligned tensors
    • input/target shift
    • 只在 response token 上计 loss
  • Logits → token log-prob
    • log-softmax + gather
    • padding 与 EOS mask
  • Token scores → sequence score
    • sum、mean 或 constant normalization
    • 长度归一化改变样本权重
Root 03 · Reward & advantage

相对好坏怎样变成梯度权重？

对应 group baseline、normalization、RFT 与 MaxRL。

  • Reward signal
    • answer reward / format reward
    • sparse、verifiable feedback
  • Group → baseline
    • 减均值降低共同偏移
    • 除标准差会改变困难题权重
  • Advantage → estimator
    • 正负样本推动方向
    • difficulty reweighting 与 variance
Root 04 · Policy update

on-policy 与 off-policy 差在哪里？

对应 surrogate objective、importance ratio 与 clipping。

  • Current samples → on-policy loss
    • 直接使用当前 policy rollout
    • 数据新鲜但生成成本高
  • Old samples → importance weighting
    • (r=\exp(\log\pi_\theta-\log\pi_{old}))
    • ratio 方差与 clipping bias
  • Token → sequence ratio
    • GRPO token-level weighting
    • GSPO sequence-level geometric mean

Before training

开工 Cheatsheet

Tensor contract

  • Prompt/output 拼接后，明确每个 token 的 source 与 target。
  • response_mask 只覆盖需要优化的 response tokens。
  • log-prob、advantage、loss 与 mask 的 broadcast 维度必须一致。
  • padding、EOS 后 token 和空 response 必须有定义好的行为。

Core estimators

\(A_i=(R_i-\bar R)/(\sigma_R+\epsilon)\)

\(r_t(\theta)=\exp(\log\pi_\theta(a_t|s_t)-\log\pi_{old}(a_t|s_t))\)

公式只是起点；题目会显式比较是否除标准差、怎样聚合 token、怎样做 importance reweighting。

Monitoring panel

  • Reward 与 accuracy：是否真的更会解题。
  • Format reward：是否只是更会迎合解析器。
  • Entropy / KL / ratio：policy 是否变化过快。
  • Response length：归一化是否诱发长度偏置。
  • Seed-to-seed variance：单次最好结果不能替代稳定性。

Ablation discipline

  • 保留完全相同的 base model、data split 与 evaluation。
  • 每次只改 baseline、normalizer、aggregation 或 reweighting 中一项。
  • 同时报告训练曲线、最终指标、样本输出与失败模式。
  • 安全 supplement 与主 GRPO 接口分开理解和验收。

如何开始？

0

理解任务和数据

Assignment 聚焦于数学推理任务。先理解：输入是什么格式、期望输出是什么格式、如何判断答案正确。这会直接影响你的 reward 设计。

1

先建立 prompting 基线

在训练之前，分别运行 zero-shot、few-shot 与 chain-of-thought prompt，确认模型输出能被 grader 稳定解析，并记录 GSM8K 基线表现。

  • 先验证答案格式与停止字符串是否正确
  • 分别记录总 reward、格式 reward 与答案 reward
  • 保留基线结果，后续判断 RL 是否真正带来提升
2

理解 GRPO 循环

GRPO 的核心循环：

  1. 从当前 policy 采样一组回答（group）
  2. 对每个回答计算 reward
  3. 用 group 内的相对 reward 作为 baseline
  4. 更新 policy，增加高 reward 回答的概率

理解每一步的为什么比记住公式更重要。

3

Reward 设计

Reward 是 RL 的"指挥棒"。设计时考虑：

  • 正确性奖励：答案是否正确
  • 格式奖励：是否遵循了要求的输出格式
  • 避免 reward hacking：模型可能学会"骗"奖励
4

监控和调试

RL 训练不稳定，需要密切监控：

  • Reward 曲线（应该在上升）
  • KL divergence（不应该偏离太远）
  • Response length（可能异常增长）
  • 采样输出质量（人工检查）

常见陷阱

Reward hacking： 模型可能学会获得高 reward 但不真正"解题"的策略。比如输出特定格式让解析器误判正确，或输出无意义但符合某种模式的文本。

KL penalty 过大/过小： KL 约束防止 policy 偏离太远。太大则学习太慢，太小则可能 mode collapse 或遗忘预训练知识。

Numerical stability： Policy ratio 涉及 exp(log_prob_diff)，容易溢出。始终在 log 空间计算，使用 log-sum-exp 技巧。

采样效率： GRPO 需要采样多个回答来估计 baseline。采样太少则方差大，采样太多则计算贵。需要权衡。

Response length 膨胀： RL 可能让模型输出越来越长的回答（更多 token = 更多机会"看起来正确"）。监控长度分布。

def evaluate_vllm(

    """

任务目标

背景：长度归一化（Length Normalization）

在实现 masked_mean 时，我们已经具备将每个 token 的标量损失聚合为一个标量损失的能力。然而，对序列长度求平均并非唯一的聚合方式；如何对 token 维度的损失求和是一个重要的超参数选择，会导致对策略动作不同的信用分配（credit attribution）。

回顾 GRPO 的训练步骤，我们先得到每个 token 的 policy gradient 损失（暂不考虑 clipping）：

  • advantages：形状 (batch_size, 1)

  • per_token_probability_ratios：形状 (batch_size, sequence_length)

  • per_token_loss = -advantages * per_token_probability_ratios

其中 advantages 被广播（broadcast）到序列长度维度。我们比较两种聚合方式：

方法一：masked_mean —— 对每条序列中未掩码（unmasked）的 token 求平均。

方法二：masked_normalize —— 对未掩码的 token 求和，再除以给定的常数 normalize_constant（即 masked_normalize 方法在 normalize_constant != 1.0 时的行为）。

    [2, 2, 2, 2, 2, 2, 2,],
])

    # generation 1: 4 tokens
    [1, 1, 1, 1, 0, 0, 0,],
    # generation 2: 7 tokens
    [1, 1, 1, 1, 1, 1, 1,],
])

masked_mean_result = masked_mean(ratio * advs, masks, dim=1)
masked_normalize_result = masked_normalize(

# masked_mean tensor([2., 2.])
# masked_normalize tensor([1.1429, 2.0000])

完整任务

dpo_loss实现 DPO 损失函数任务 · 提示 · 验收
Handout 完整本土化可离线实施不含参考实现

完整任务

背景

DPO（Direct Preference Optimization）是一种从偏好数据对齐语言模型的方法。与 RLHF 不同，DPO 不需要显式训练奖励模型，而是直接优化策略模型。DPO 的每实例损失为：

\[ \ell_{\text{DPO}}(\pi_\theta, \pi_{\text{ref}}, x, y_w, y_l) = -\log \sigma\left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} \right) \]

其中：

  • \(\pi_\theta\) 是正在优化的策略模型

  • \(\pi_{\text{ref}}\) 是参考策略（SFT 后的模型）

  • \(x\) 是指令（prompt）

  • \(y_w\) 是偏好响应（chosen）

  • \(y_l\) 是非偏好响应（rejected）

  • \(\beta\) 是控制偏离参考策略惩罚强度的超参数

  • \(\sigma\) 是 sigmoid 函数

问题（2 分）

编写一个函数，计算每实例 DPO 损失。你的函数将接收两个语言模型，以及两个字符串（分别包含根据偏好数据更好和更差的响应）。使用 Alpaca 模板（与 SFT 中使用的相同）来格式化提示和响应，并确保在响应后添加 "end of sequence" token。

为了简化实现，你可以使用以下观察：当计算同一模型下的条件对数概率之差时（例如 \(\log \pi_\theta(y_w|x) - \log \pi_\theta(y_l|x)\)），这等价于计算无条件对数概率之差（例如 \(\log \pi_\theta(x \oplus y_w) - \log \pi_\theta(x \oplus y_l)\)，其中 \(\oplus\) 表示 token 序列的拼接），因为提示的对数概率会被抵消。

交付物：一个函数，接收两个 LM（\(\pi_\theta\) 和 \(\pi_{\text{ref}}\)）、一个 tokenizer 和两个字符串（分别拼接了 chosen 响应 \(y_w\) 和 rejected 响应 \(y_l\) 的提示），计算每实例 DPO 损失。实现适配器 [adapters.per_instance_dpo] 并通过 uv run pytest -k test_per_instance_dpo_loss 测试。

查看解题提示

  • 先修概念：DPO 损失推导；条件对数概率与无条件对数概率的关系；Alpaca 模板格式；sigmoid 函数。

  • 实施顺序：先用 Alpaca 模板格式化提示和响应；添加 EOS token；计算两个模型下的无条件对数概率；应用 DPO 损失公式。

  • 调试策略：注意两个模型可能在不同设备上，需在计算时处理跨设备问题；确保返回的损失与优化模型在同一设备；使用数值稳定的对数概率计算。

  • 自检方法：运行 uv run pytest -k test_per_instance_dpo_loss 并确保通过。
