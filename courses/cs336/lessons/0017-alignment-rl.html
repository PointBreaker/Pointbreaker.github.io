RL 在语言模型中的设置

将语言建模为 RL 问题：

RL 概念语言模型对应
State (s)prompt + 已生成的 response
Action (a)下一个 token
Policy (π)语言模型 p(next_token | context)
Reward (R)response 质量（outcome reward）
Transition确定性：s' = s + a
Episodes → a → ... → a → R（完整 response）

关键简化：与机器人不同，语言模型的 transition 是确定性的（给定 state 和 action，下一个 state 完全确定）。而且我们使用 outcome reward（整个 response 的奖励），而非 per-token reward。这大大简化了问题。

目标函数

# 目标: 最大化期望奖励
# J(θ) = E[R(s, a)]
#       = ∫ p(s) π(a|s) R(s, a) ds da

# 其中:
# - p(s): prompt 的分布（数据集）
# - π(a|s): 语言模型（参数 θ）
# - R(s, a): response a 在 prompt s 下的奖励

# 对于语言模型，"action a" 是整个 response（token 序列）
# 所以 π(a|s) = Π_t π(a_t | s, a_<t)

Policy Gradient

推导

目标函数 J(θ) = E[R(s, a)]，我们需要计算梯度：

# ∇_θ J(θ) = ∇_θ E[R(s, a)]
#           = ∇_θ ∫ p(s) π(a|s) R(s, a) ds da
#           = ∫ p(s) ∇_θ π(a|s) R(s, a) ds da

# 技巧: ∇π = π × ∇log π (log-derivative trick)
# ∇_θ π(a|s) = π(a|s) × ∇_θ log π(a|s)

# 代入:
# ∇_θ J(θ) = ∫ p(s) π(a|s) ∇_θ log π(a|s) R(s, a) ds da
#           = E[∇_θ log π(a|s) × R(s, a)]

# 最终形式:
# ∇_θ J(θ) = E[∇_θ log π(a|s) × R(s, a)]

直觉解释

# ∇_θ log π(a|s) × R(s, a) 的含义:
#
# - ∇_θ log π(a|s): 让 action a 概率增加的方向
# - R(s, a): 这个 action 有多好
#
# 如果 R > 0（好）: 沿着 ∇logπ 方向更新 → 增加 a 的概率
# 如果 R < 0（差）: 沿着 -∇logπ 方向更新 → 减少 a 的概率
# 如果 R = 0: 不更新

朴素 Policy Gradient 的问题

当 R ∈ {0, 1}（正确/错误）时：

# 只有 R=1 的样本产生梯度
# R=0 的样本: gradient = 0 → 不更新

# 这类似于 SFT，但:
# - SFT 的数据是固定的
# - PG 的数据是模型自己生成的（随 policy 变化）

# 问题:
# 1. 高方差: 只有一小部分样本有非零梯度
# 2. 稀疏信号: 大多数 response 没有奖励
# 3. 探索不足: 模型可能只探索少数几种回答

关键问题：朴素 policy gradient 的方差很高。同一个 prompt，两次采样可能得到完全不同的 reward（一个对、一个错），导致梯度估计不稳定。

Baseline：降低方差

核心思想

从 reward 中减去一个 baseline b(s)：

# 原始: ∇J = E[∇log π(a|s) × R(s, a)]
# Baseline: ∇J = E[∇log π(a|s) × (R(s, a) - b(s))]

# 为什么可以减去 baseline?
# E[∇log π(a|s) × b(s)] = b(s) × E[∇log π(a|s)]
#                       = b(s) × ∇ ∫ π(a|s) da
#                       = b(s) × ∇ 1 = 0
# 所以减去 baseline 不改变梯度的期望值，但降低了方差

选择 Baseline

最优 baseline 的推导（最小化方差）：

# 最优 baseline:
# b*(s) = E[(∇π(a|s))^2 × R | s] / E[(∇π(a|s))^2 | s]

# 对于单参数模型，这可以简化为:
# b*(s) = E[R | s] = V(s)

# 直觉: baseline = 这个 state 下的平均 reward

Advantage Function

# 当 baseline = V(s) = E[R|s] 时:
# A(s, a) = R(s, a) - V(s) = Q(s, a) - V(s)

# Advantage 的含义:
# "action a 比这个 state 的平均水平好多少？"

# A > 0: action a 比平均好 → 增加概率
# A < 0: action a 比平均差 → 减少概率
# A = 0: action a 就是平均水平 → 不更新

降低方差的效果

# 例: 两个 states
# s1: a1 → reward 11, a2 → reward 9
# s2: a1 → reward 0, a2 → reward 2

# 没有 baseline:
# gradients = [∇π1 × 11, ∇π2 × 9, ∇π3 × 0, ∇π4 × 2]
# std = 4.92

# 有 baseline (b(s1)=10, b(s2)=1):
# gradients = [∇π1 × 1, ∇π2 × (-1), ∇π3 × (-1), ∇π4 × 1]
# std = 1.00

# 方差降低了 5 倍！

PPO：Proximal Policy Optimization

核心问题

Policy gradient 更新后，旧的采样数据不能用。PPO 解决这个问题：

Importance Sampling Ratio

# 更新后，想用旧数据继续训练
# 需要 importance sampling 修正:

# ratio = π_new(a|s) / π_old(a|s)

# 如果 ratio ≈ 1: 新旧 policy 相似，旧数据仍然有效
# 如果 ratio >> 1: 新 policy 比旧 policy 更倾向于 a
# 如果 ratio << 1: 新 policy 比旧 policy 更不倾向于 a

Clipped Objective

# PPO 的核心创新: clip ratio 防止过大更新

# Unclipped loss:
# L_unclipped = ratio × Advantage

# Clipped loss:
# L_clipped = clip(ratio, 1-ε, 1+ε) × Advantage

# PPO loss:
# L_PPO = -min(L_unclipped, L_clipped)

# 直觉:
# - 当 Advantage > 0（好 action）:
#   - ratio 增大 → loss 增大（鼓励增加概率）
#   - 但 ratio > 1+ε 时，loss 不再增大（防止过度更新）
# - 当 Advantage < 0（差 action）:
#   - ratio 减小 → loss 增大（鼓励减少概率）
#   - 但 ratio < 1-ε 时，loss 不再增大

PPO 完整算法

# PPO 训练循环:

for iteration in range(num_iterations):
    # 1. 用当前 policy 收集数据
    for prompt in batch:
        response = policy_old.generate(prompt)
        log_prob_old = policy_old.log_prob(prompt, response)
        reward = reward_model(prompt, response)
        value = value_model(prompt, response)
        advantage = compute_gae(reward, value)

    # 2. 用收集的数据更新 policy（多轮）
    for epoch in range(ppo_epochs):
        log_prob_new = policy_new.log_prob(prompt, response)
        ratio = exp(log_prob_new - log_prob_old)

        # Clipped surrogate loss
        L1 = ratio * advantage
        L2 = clip(ratio, 1 - epsilon, 1 + epsilon) * advantage
        loss = -min(L1, L2).mean()

        # Value function loss
        value_pred = value_model(prompt)
        value_target = reward  # 或 GAE target
        value_loss = (value_pred - value_target).pow(2).mean()

        # 总 loss
        total_loss = loss + c1 * value_loss - c2 * entropy_bonus
        total_loss.backward()
        optimizer.step()

GAE：Generalized Advantage Estimation

# GAE 是 advantage 估计的一种方法
# 平衡偏差和方差

# TD residual: δ_t = r_t + γV(s_{t+1}) - V(s_t)
# Advantage: A_t = Σ (γλ)^l × δ_{t+l}

# λ = 0: 纯 TD（低方差，高偏差）
# λ = 1: 纯 Monte Carlo（高方差，低偏差）
# λ ∈ (0,1): 折中

PPO 成功的关键：

  • Clip：防止 policy 变化过大
  • 多轮更新：同一批数据用多次，提高样本效率
  • Value function：降低 advantage 估计的方差
  • Entropy bonus：鼓励探索，防止模式崩塌

DPO：Direct Preference Optimization

动机

PPO 很复杂——需要同时维护 4 个 model（policy、reference、reward、value）。DPO 提出一个更简单的方法：直接从偏好数据优化 policy，不需要 reward model。

推导

# 起点: PPO 的最优 policy 有闭式解:
# π*(a|s) ∝ π_ref(a|s) × exp(R(s,a) / β)

# 反解 reward:
# R(s, a) = β × log(π*(a|s) / π_ref(a|s)) + β × log Z(s)
# 其中 Z(s) = Σ_a π_ref(a|s) exp(R(s,a)/β) 是 partition function

# 代入 Bradley-Terry 偏好模型:
# P(a_w > a_l) = σ(R(s, a_w) - R(s, a_l))

# 神奇的事情发生了: Z(s) 被消掉了！
# P(a_w > a_l) = σ(β × log(π*(a_w|s)/π_ref(a_w|s))
#                  - β × log(π*(a_l|s)/π_ref(a_l|l)))

# DPO loss:
# L_DPO = -E[log σ(β × log(π_θ(a_w|s)/π_ref(a_w|s))
#                 - β × log(π_θ(a_l|s)/π_ref(a_l|s)))]

DPO 的直觉

# DPO loss 的含义:
#
# 如果 π_θ(a_w|s)/π_ref(a_w|s) > π_θ(a_l|s)/π_ref(a_l|s):
#   → 模型相比 ref 更偏好 chosen
#   → σ 接近 1，loss 接近 0 ✓
#
# 如果 π_θ(a_w|s)/π_ref(a_w|s) < π_θ(a_l|s)/π_ref(a_l|s):
#   → 模型相比 ref 更偏好 rejected
#   → σ 接近 0，loss 很大 ✗
#
# 直觉: DPO 让模型对 chosen 的"提升"大于对 rejected 的"提升"

DPO vs PPO 对比

维度PPODPO
需要 Reward Model是否
需要 Value Model是否
训练模型数4（policy, ref, reward, value）2（policy, ref）
数据需要 rollout（在线生成）离线偏好数据
实现复杂度高低
探索能力强（在线采样）弱（受限于数据分布）
Reward hacking有风险风险较低

DPO 的局限：

  • 离线：不能探索训练数据之外的区域
  • 分布偏移：如果 policy 偏离 ref 太远，DPO 可能不稳定
  • 对 ref 敏感：ref model 的质量直接影响 DPO 效果

GRPO 深入

GRPO 的推导

GRPO 是 PPO 在语言模型设置下的简化：

# PPO 的 advantage: A(s, a) = R(s, a) - V(s)
# 其中 V(s) 需要单独训练 value model

# GRPO 的 insight:
# 对同一个 prompt，生成 G 个 responses
# 用 G 个 rewards 的均值作为 V(s) 的估计

# V(s) ≈ (1/G) × Σ_i R(s, a_i)
# A(s, a_i) = R(s, a_i) - V(s)

# 为什么这是合理的?
# E[R(s, a) | s] = V(s) 的定义
# G 个样本的均值是 V(s) 的无偏估计

GRPO 的 Loss

# GRPO 的完整 loss:

# 对每个 prompt q:
# 1. 生成 G 个 responses: {o_1, ..., o_G}
# 2. 计算 rewards: {r_1, ..., r_G}
# 3. 计算 baseline: b = mean(r_1, ..., r_G)
# 4. 标准化 advantage: A_i = (r_i - b) / (std(r) + ε)
# 5. 计算 ratio: ρ_i = π_θ(o_i|q) / π_old(o_i|q)
# 6. Clipped loss:
#    L = -1/G × Σ_i min(ρ_i × A_i, clip(ρ_i, 1-ε, 1+ε) × A_i)
# 7. 加 KL 惩罚:
#    L_total = L + β × KL(π_θ || π_ref)

GRPO 中的 KL 估计

# GRPO 使用的 KL 估计器（非负）:

# KL(p || q) = E_p[log(p/q)]
#            = E_p[q/p - log(q/p) - 1]  （因为 E_p[q/p] = 1）

def kl_penalty(log_probs, ref_log_probs):
    """计算 KL(π || π_ref) 的估计"""
    # ratio = exp(ref_log_probs - log_probs)
    # kl = ratio - (ref_log_probs - log_probs) - 1
    return (torch.exp(ref_log_probs - log_probs)
            - (ref_log_probs - log_probs) - 1).sum(dim=-1).mean()

# 这个估计器保证 KL ≥ 0（由 Jensen 不等式）

冻结参数的重要性

# 在计算 ratio = π_θ / π_old 时
# 必须对 π_old 使用 torch.no_grad() 或 detach()

# 错误做法:
ratio = torch.exp(log_probs_new - log_probs_old)
ratio.backward()
# 这会对 log_probs_old 也计算梯度！

# 正确做法:
with torch.no_grad():
    log_probs_old = model(prompts)  # 冻结
ratio = torch.exp(log_probs_new - log_probs_old)
ratio.backward()
# 只对 log_probs_new 计算梯度

如何选择？

  • SFT：快速入门，让模型能遵循指令
  • DPO：有大量偏好数据，想要简单稳定的训练
  • PPO：需要在线探索，有 reward model
  • GRPO：RLVR 场景（数学/代码），需要在线生成
