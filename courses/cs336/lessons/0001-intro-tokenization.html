课程总览与 Tokenization

语言模型从字符串开始——如何把文本切分成模型可以理解的单元，是整个流程的第一步。这一课建立对全课的宏观理解，然后深入这个看似简单却影响深远的问题。

授课：Mike Lewis & Sida Wang & Kangwook Lee 预计用时：80 分钟 难度：入门 → 中等

这门课为什么存在？

抽象层在泄漏

八年前，研究者会自己实现和训练模型。六年前，研究者下载 BERT 做 fine-tune。今天，研究者直接调用 GPT-4/Claude/Gemini 的 API。

向上抽象提升了生产力，但语言模型的抽象层和编程语言或操作系统不同——它是泄漏的。不理解底层，就无法做真正的研究。

这门课的核心信念：理解源于构建 (understanding via building)。

不是读论文、不是调 API，而是从第一行代码开始，构建一个语言模型的每一个组件。

工业化的现实

GPT-4 据称有 1.8T 参数，训练成本约 1 亿美元。xAI 用 20 万张 H100 训练 Grok。Stargate 项目计划 4 年投资 5000 亿美元。

更关键的是：没有公开细节。GPT-4 的技术报告明确说不会披露架构、训练数据或方法。

"More is different"

前沿模型遥不可及。但课堂上训练的小模型 (<1B 参数) 能代表大模型吗？

例 1：Attention 和 MLP 的 FLOPs 占比随规模变化。小模型训得好的超参数，大模型上不一定最优。

例 2：某些能力是"涌现"的——在小模型上不存在，到一定规模才突然出现。

什么知识可以迁移？

Mechanics 机制

事物如何运作——Transformer 是什么、模型并行如何利用 GPU

Mindset 思维

榨干硬件、认真对待规模——scaling laws 的思维方式

Intuitions 直觉

哪些数据和建模决策效果好——这部分不能完全教会

这门课能教的是前两者。机制（how things work）和 mindset（efficiency-first）在任何规模都适用。直觉则需要你自己在大规模实验中积累。

The Bitter Lesson（苦涩教训）：错误的解读是"规模万能，算法不重要"。正确的解读是"能随规模扩展的算法才是关键"。效率在大规模时更加重要——你承受不起浪费。

公式：accuracy = efficiency × resources

  • N-gram 模型：用于机器翻译、语音识别，统治 NLP 几十年

  • T5 (11B)：把所有任务统一为 text-to-text

开放模型时代 (2022-至今)

GPT-J、OPT、BLOOM、Llama 系列、Mistral、Qwen、DeepSeek、OLMo——开放权重和开放数据的模型生态快速发展。

开放度的三个层次：

  1. 闭源模型（如 GPT-4o）：只能 API 调用
  2. 开放权重（如 DeepSeek）：权重可用，论文有架构细节，无数据细节
  3. 开源模型（如 OLMo）：权重+数据可用，论文有大部分细节

Tokenization：核心内容

本节灵感来自 Andrej Karpathy 的 Tokenization 讲解，强烈推荐观看。

什么是 Tokenization？

原始文本通常表示为 Unicode 字符串。语言模型对 token 序列（通常用整数索引表示）放置概率分布。

所以我们需要两个过程：

  • Encode：字符串 → token 索引序列
  • Decode：token 索引序列 → 字符串

词表大小 (vocabulary size) 是可能的 token 数量。

关键指标：压缩比 (compression ratio)

compression_ratio = num_bytes / num_tokens

即每个 token 对应多少字节。压缩比越高，同样信息用更少的 token 表示，模型处理效率越高。

方案一：Character Tokenization（字符级）

Unicode 字符串是字符序列。每个字符可通过 ord() 转为码点（整数）：

ord("a")  = 97
ord("🌍") = 127757
ord("你") = 20320

问题：

  • 词表极大——Unicode 约有 150,000 个字符
  • 很多字符罕见（如 🌍），对词表是低效利用
  • 语义粒度太细——单个字符几乎没有意义

字符级 tokenization 的压缩比 ≈ 1 字符/token，压缩效率极低。

方案二：Byte Tokenization（字节级）

Unicode 字符串可以表示为 字节序列（0-255 的整数）。最常用的 Unicode 编码是 UTF-8：

"a"  → b"a"              # 1 字节
"🌍"  → b"\xf0\x9f\x8c\x8d"  # 4 字节
"你"  → b"\xe4\xbd\xa0"      # 3 字节

优势：词表极小且固定——只有 256 个可能的值。

劣势：压缩比 = 1 字节/token，压缩效果极差。序列会非常长。

为什么序列长度重要？ Transformer 的 attention 是 O(n²) 复杂度。序列越长，计算和内存开销越大。上下文长度受限于序列长度，所以极低的压缩比意味着模型能"看到"的有效内容更少。

不过，字节级 tokenization 有一个优雅的理论优势：它是无损、通用的——任何文本都可以被编码，没有 out-of-vocabulary 问题。这个优势在最近的研究中被重新发掘（ByT5、MEGABYTE、BLT、TFree 等）。

方案三：Word Tokenization（词级）

经典 NLP 的做法：把文本按词分割。

import regex
pattern = r"\w+|."
segments = regex.findall(pattern, "I'll say supercalifragilisticexpialidocious!")
# → ["I", "'", "ll", " ", "say", " ", "supercalifragilisticexpialidocious", "!"]

更精细的版本（GPT-2 使用的预分词正则）：

GPT2_TOKENIZER_REGEX = r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"""

问题：

  • 词的数量极大（和 Unicode 字符一样多）
  • 大量罕见词，模型学不到它们的有效表示
  • 词表大小不固定
  • 未见过的词只能映射到 UNK token——这既丑陋，又会扰乱 perplexity 计算

词级 tokenization 的压缩比高（~4 字符/token），但词表问题让它不实用。

方案四：Byte Pair Encoding (BPE)

历史

BPE 算法最初由 Philip Gage 于 1994 年提出，用于数据压缩。后来被 Sennrich et al. (2016) 引入 NLP，用于神经机器翻译。GPT-2 采用了 BPE tokenization，成为现代 LLM 的标准做法。

核心思想

从数据中学习 token——不是人为规定哪些字符组合是一个 token，而是通过算法自动发现。

直觉：常见的字符序列合并为单个 token，罕见序列保持拆分。

算法描述

BPE 的训练过程：

  1. 初始化：每个字节是一个初始 token（256 个）
  2. 统计：计算所有相邻 token 对的出现频率
  3. 合并：找到最频繁的对，将它们合并为一个新 token，新 token ID = 256, 257, ...
  4. 重复：回到步骤 2，直到达到目标词表大小

手动推演

用字符串 "the cat in the hat" 演示 3 轮合并：

初始状态（每个字节是一个 token）：

t | h | e |   | c | a | t |   | i | n |   | t | h | e |   | h | a | t

第 1 轮：统计所有相邻对频率。(t, h) 出现 2 次（"the" ×2），(h, e) 出现 2 次，(a, t) 出现 2 次... 假设 (t, h) 被选为最频繁对，合并为 th（新 ID = 256）：

th | e |   | c | a | t |   | i | n |   | th | e |   | h | a | t

第 2 轮：重新统计。(th, e) 出现 2 次 → 合并为 the（ID = 257）：

the |   | c | a | t |   | i | n |   | the |   | h | a | t

第 3 轮：继续合并最频繁的对。

这个过程让高频组合（如 "the"、"ing"）逐步成为独立 token，而罕见组合保持拆分。

Encoding（编码新文本）

训练完成后，对新的文本进行编码：

  1. 将文本转为字节序列
  2. 按训练时合并的顺序，依次应用所有合并规则
  3. 查找每个最终 token 的 ID

Decoding（解码）

给定 token ID 序列，查找每个 ID 对应的字节，拼接后转为字符串。

重要细节：合并顺序——Encoding 时必须按照训练时合并的顺序应用合并规则。如果顺序不同，同一个文本可能得到完全不同的 token 序列。这是 BPE 的一个关键特性。

GPT-2 的改进

原始的 BPE 直接在字节上运行。GPT-2 做了两个关键改动：

  • Pre-tokenization：先用正则把文本拆成"词"，再在每个词内部运行 BPE。这防止跨词边界合并（如把 "cat" + "erpillar" 合并）。
  • 特殊 token：如 <|endoftext|>，不参与 BPE 合并，始终作为一个整体。

Tokenization 的权衡

方法词表大小压缩比OOV 问题无损
Character~150K~1.0无是
Byte256~1.0无是
Word无限~4.0有 (UNK)否
BPE可控~3-4.0无 (fallback to bytes)是

BPE 是必要的恶

原版 Transformer 论文用的是 BPE。今天的主流模型（GPT 系列、Llama、Mistral）都用 BPE 或其变体。

但 BPE 也有问题：

  • 对罕见词/拼写变体处理不佳（"hello" vs "hellooo" 可能完全不同）
  • 对多语言不友好（非拉丁文字的压缩比极差）
  • 对数字和符号的切分不自然（GPT-2 把数字每几位切一次）
  • Tokenization 是有状态的——依赖于训练数据分布

未来方向：Tokenizer-free

直接用字节作为输入（ByT5、MEGABYTE、BLT、TFree），让模型自己学组合。理论上更优雅，但目前尚未扩展到前沿规模。这是一个开放问题。
