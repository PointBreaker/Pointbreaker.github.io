RLVR：基于可验证奖励的强化学习

RLHF 依赖人类主观偏好，成本高且不稳定。RLVR (Reinforcement Learning from Verifiable Rewards) 用客观、可验证的奖励信号替代人类标注，开启了模型自我改进的新范式。

授课：Sida Wang & Kangwook Lee 预计用时：80 分钟 难度：中等 → 较高

动机：RLHF 的局限

第 15 课学习的 RLHF 是 alignment 的主流方法，但有几个根本性局限：

局限表现影响
主观性不同标注者有不同偏好Reward model 有噪声
成本高需要大量人类偏好数据难以规模化
Reward hacking模型学会欺骗 reward model实际质量未提高
不可验证无法自动检查 reward 是否正确难以调试
天花板受限于标注者的能力无法超越人类水平

核心洞察：如果我们能找到客观、可自动验证的奖励信号，就可以绕过人类标注的限制。数学题有标准答案，代码可以执行测试——这些都是"可验证奖励"。

什么是 RLVR？

定义

RLVR = Reinforcement Learning from Verifiable Rewards。使用可以程序化验证正确性的奖励函数，而非人类主观判断。

可验证奖励的例子

领域任务验证方式
数学解方程检查最终答案是否匹配 ground truth
代码写函数运行单元测试
逻辑推理谜题检查推理链条是否符合逻辑规则
形式化证明证明定理Lean/Coq 验证器检查证明
算法实现算法测试输出是否正确
# RLVR 的核心循环:

for prompt in batch:
    # 1. 模型生成 response（可能包含推理过程 + 答案）
    response = model.generate(prompt)

    # 2. 从 response 中提取答案
    answer = extract_answer(response)

    # 3. 用验证器检查答案
    reward = verifier.check(answer, ground_truth)
    # reward = 1 if correct, 0 if wrong

    # 4. 用 reward 做 policy gradient 更新
    loss = -log_prob(response) * reward
    loss.backward()

RLVR vs RLHF 对比

维度RLHFRLVR
奖励来源人类偏好客观验证
奖励性质连续、主观离散、客观
可扩展性受限于标注人力可自动化、规模化
适用任务开放式（写作、对话）封闭式（数学、代码）
Reward hacking严重几乎不存在
天花板人类水平可以超越人类

RLVR 的局限：不是所有任务都有可验证的奖励。开放式任务（创意写作、对话、主观问答）仍然需要 RLHF 或其他方法。RLVR 和 RLHF 是互补的，不是替代关系。

GRPO：群组相对策略优化

背景

GRPO (Group Relative Policy Optimization) 是 DeepSeek-R1 使用的算法，是 PPO 的简化版本：

  • 去掉了 Critic（Value Function）——PPO 需要一个额外的 value model 来估计 advantage
  • 利用群组结构——对同一个 prompt 生成多个 response，用组内相对奖励作为 baseline
  • 更简单、更稳定——需要维护的模型更少

核心思想

# PPO 的 advantage 估计需要 value model:
# A(s, a) = R(s, a) - V(s)
# 其中 V(s) 需要额外训练一个 critic network

# GRPO 的 insight:
# 对同一个 prompt，生成 G 个 responses
# 用这 G 个 responses 的平均 reward 作为 baseline

# 例: prompt = "Solve x + 3 = 7"
# response 1: "x = 4" → reward = 1 (正确)
# response 2: "x = 5" → reward = 0 (错误)
# response 3: "x = 4" → reward = 1 (正确)
# response 4: "x = 3" → reward = 0 (错误)

# baseline = mean(rewards) = (1 + 0 + 1 + 0) / 4 = 0.5
# advantages = rewards - baseline = [0.5, -0.5, 0.5, -0.5]

# 直觉: 比平均好的 response 被强化，比平均差的被抑制

GRPO 的数学形式

# GRPO 的 loss 函数:

# 对每个 prompt q:
# 1. 用旧 policy π_old 生成 G 个 responses: {o_1, o_2, ..., o_G}
# 2. 计算每个 response 的 reward: {r_1, r_2, ..., r_G}
# 3. 计算 baseline: b = mean(r_1, ..., r_G)
# 4. 计算 advantage: A_i = (r_i - b) / std(r)
# 5. 计算 policy ratio: ρ_i = π_θ(o_i|q) / π_old(o_i|q)
# 6. 计算 clipped loss:

# L = -1/G × Σ_i min(ρ_i × A_i, clip(ρ_i, 1-ε, 1+ε) × A_i)
#     + β × KL(π_θ || π_ref)

# 注意:
# - 与 PPO 类似，但 baseline 来自组内均值而非 value model
# - KL 惩罚仍然需要 reference model (π_ref)

GRPO 的优势

优势说明
无需 Critic减少一个模型的计算和内存
自然 baseline组内均值是 V(s) 的无偏估计
更稳定减少了 value model 训练的方差
易于实现比 PPO 代码更简洁

DeepSeek-R1 的方法

概述

DeepSeek-R1 是 RLVR 的里程碑工作，展示了纯强化学习可以让模型自发学会推理能力：

  • DeepSeek-R1-Zero：纯 RL，无 SFT
  • DeepSeek-R1: Cold start + RL + 蒸馏

DeepSeek-R1-Zero：纯 RL

# DeepSeek-R1-Zero 的训练流程:
# 1. 从 DeepSeek-V3-Base 开始（纯预训练模型）
# 2. 使用 GRPO 算法
# 3. 奖励信号:
#    - 数学: 检查最终答案是否正确
#    - 代码: 运行测试用例
#    - 推理: 格式正确性 + 答案正确性
# 4. 模型自发学会了:
#    - Chain-of-thought（链式推理）
#    - Self-verification（自我验证）
#    - Reflection（反思和纠错）

# 关键发现:
# 这些推理行为是 RL 自发涌现的，不是 SFT 教导的！

涌现的推理行为

在 RL 训练过程中，研究人员观察到模型自发发展出高级推理策略：

行为描述涌现时间
CoT生成中间推理步骤早期
Self-verification检查自己的推理过程中期
Reflection发现错误后重新推理中期
Aha moment"Wait, let me reconsider..."后期

"Aha Moment"：在 RL 训练到一定阶段时，模型开始出现"Wait, I made a let me recalculate..."这样的反思行为。这完全是自发涌现的——训练数据中没有教过模型这样做。

DeepSeek-R1 的完整流程

# DeepSeek-R1 (非 Zero) 的训练流程:

# Stage 1: Cold Start
# - 收集数千个高质量 CoT 样本
# - SFT DeepSeek-V3-Base
# - 目的: 给 RL 一个好的初始化

# Stage 2: RL (推理导向)
# - 用 GRPO 训练
# - 奖励: 答案正确性 + 格式正确性
# - 专注数学、代码、推理

# Stage 3: Rejection Sampling + SFT
# - 用 Stage 2 的模型生成大量样本
# - 过滤（只保留正确的 + 格式好的）
# - 混合通用数据做 SFT
# - 目的: 恢复通用能力

# Stage 4: RL (全场景)
# - 再次 RL，但奖励包括:
#   - 推理任务的正确性
#   - 通用任务的有用性 (reward model)
# - 目的: 同时提升推理和通用能力

奖励设计

# DeepSeek-R1 的奖励函数:

def compute_reward(response, ground_truth, task_type):
    if task_type == "math":
        # 1. 答案正确性
        answer = extract_answer(response)
        correctness = (answer == ground_truth)

        # 2. 格式正确性（是否使用了规定的格式）
        format_ok = check_format(response)  # e.g., "Answer: XXX"

        reward = float(correctness) + 0.1 * float(format_ok)

    elif task_type == "code":
        # 运行测试用例
        code = extract_code(response)
        tests_pass = run_tests(code, test_cases)
        reward = float(tests_pass)

    return reward

涌现的推理能力

Chain-of-Thought 的涌现

最令人惊讶的发现之一是：CoT 不是 SFT 教的，而是 RL 涌现的：

# 训练初期:
# Q: "Solve x + 3 = 7"
# A: "4"  (直接回答，无推理)

# 训练中期:
# Q: "Solve x + 3 = 7"
# A: "x + 3 = 7, so x = 7 - 3 = 4"  (开始出现推理)

# 训练后期:
# Q: "Solve x + 3 = 7"
# A: "Let me solve this step by step.
#     We have x + 3 = 7.
#     Subtract 3 from both sides: x = 7 - 3 = 4.
#     Let me verify: 4 + 3 = 7. Yes!
#     Answer: 4"  (完整的 CoT + 验证)

为什么 RL 能涌现出 CoT？

  • 探索：RL 让模型尝试不同的回答策略
  • 选择：CoT 策略更容易得到正确答案（奖励）
  • 强化：CoT 策略被强化，逐渐成为默认行为
  • 自我改进：CoT 让模型能发现和纠正错误

关键洞察：CoT 不是"让模型推理"的工具，而是"让模型学会推理"的训练结果。通过 RL，模型发现 CoT 是获得高奖励的有效策略，从而自发采用它。

RLVR 的挑战

1. 奖励稀疏

在很多任务中，只有最终答案是对/错，中间步骤没有奖励：

# 问题: 数学题只有最终答案有奖励
# 模型可能通过"猜"得到正确答案
# 或者推理过程全错但答案碰巧对

# 缓解:
# - 加入格式奖励（要求特定格式）
# - 加入过程奖励（检查中间步骤）
# - 多次采样取一致答案

2. 奖励设计困难

设计一个好的奖励函数并不容易：

  • 代码：单元测试可能不全面
  • 数学：等价表达式的匹配（"2+2" vs "4"）
  • 推理：格式正确性难以定义

3. 分布偏移

RL 训练可能让模型偏离预训练分布：

  • 过度优化推理格式，丧失通用能力
  • 语言风格变化（变得过于正式或机械）
  • 遗忘预训练知识

4. 计算成本

RL 训练比 SFT 昂贵得多：

  • 需要多次采样（每个 prompt 生成多个 response）
  • 需要多次迭代更新
  • 需要维护 reference model（计算 KL）

RLVR 的未来方向

1. 更丰富的奖励信号

  • 过程奖励模型 (PRM)：不仅奖励最终答案，还奖励中间步骤
  • 多维度奖励：正确性 + 简洁性 + 可读性
  • 自我奖励：模型自己评估自己的输出

2. 扩展到更多领域

  • 科学推理：化学、物理问题的验证
  • 形式化证明：Lean/Coq 验证器
  • 多模态：图像生成的质量评估

3. RLVR + RLHF 结合

  • 用 RLVR 提升推理能力
  • 用 RLHF 提升对话和通用能力
  • 两者互补，不是替代
