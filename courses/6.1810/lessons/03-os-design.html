操作系统设计

操作系统设计的核心目标是隔离（isolation）。本课探讨如何实现隔离：硬件支持（用户/超级模式、虚拟内存）、宏内核与微内核的权衡、以及 xv6 系统调用的实际实现。

授课：nz (Nickolai Zeldovich) 日期：2025-01-28 难度：中等

操作系统全景

操作系统由应用程序（sh、echo 等）、系统调用接口（open、read、fork 等）、内核（实现系统调用的代码）、以及底层硬件（CPU、RAM、磁盘）组成。严格来说，"操作系统"包含内核 + 用户态服务，而"内核"是其中运行在特权模式的核心部分。

隔离：为什么需要受保护的内核？

稻草人设计：没有操作系统

如果应用程序直接与硬件交互——高效、灵活，但完全没有隔离：

问题后果
资源隔离一个程序耗尽内存、CPU 或磁盘，其他程序全部崩溃
内存隔离一个程序的 bug 写入另一个进程的内存，破坏其状态

UNIX 系统调用如何帮助隔离

  • fork() + 进程：抽象 CPU 核心，OS 在进程间透明切换，可拥有比核心更多的进程。
  • exec() + sbrk() + 虚拟地址：抽象 RAM，每个进程有自己的地址空间，OS 决定物理布局。
  • 文件：抽象磁盘块，OS 确保不同用户不冲突，并执行权限检查。
  • 管道：抽象共享内存，提供受控的进程间通信。

隔离不仅是防 bug，更是防攻击

安全假设：

  • 用户代码是恶意的——会主动试图打破隔离、欺骗系统调用、干扰其他程序。
  • 内核代码是可信的——开发者善意且胜任（尽管仍有 bug）。

内核必须谨慎处理所有用户交互。任何内核 bug 都可能成为安全漏洞——这就是 security mindset。内核位于 可信计算基（TCB） 中。

内核如何防御恶意用户代码？

两大支柱：

  1. 硬件级控制：限制用户态指令的行为
  2. 谨慎的系统调用接口与实现：防御性编程

硬件级隔离

CPU 与内核协同设计：

机制作用
用户/超级模式超级模式可执行特权指令（访问设备、修改页表）；用户模式不能
虚拟内存页表将 VA → PA，限制进程可访问的内存；页表只在超级模式下可修改

系统调用如何跨越模式？

应用程序运行在用户模式，但系统调用需要超级模式。RISC-V 提供 ecall 指令：

// 用户代码
open():
    ecall SYS_open   // 触发系统调用
    // ecall 会：
    //   1. 切换到超级模式
    //   2. 跳转到内核已知的入口点
    //   3. 内核接管执行

没有硬件隔离也能实现隔离吗？

可以！使用强类型语言（如 Singularity OS）。但用户只能使用经过批准的编译器/语言，灵活性受限。目前主流仍是硬件用户/超级模式。

宏内核 vs. 微内核

宏内核（Monolithic Kernel）

整个内核是一个大程序——xv6、Linux 都采用这种设计。

优点缺点
子系统易于协作（共享缓存、直接函数调用）复杂度高、bug 多、内部无隔离
性能高（无 IPC 开销）一个模块崩溃可能导致整个内核崩溃

微内核（Microkernel）

把大部分 O/S 功能移到用户态服务进程，内核只保留最小功能：地址空间、内存管理、线程、IPC。

期望收益设计挑战
更小 → 更少 bug → 更安全（可形式化验证，如 seL4）最小功能集是什么？能否保证安全？
更简单 → 更易优化性能（IPC 开销）能否接受？
用户态 → 更易扩展/替换/重启服务如何让程序共享磁盘/网络？

xv6 在 RISC-V 上的实现

硬件平台

xv6 运行在 SiFive HiFive Unleashed 开发板上（QEMU 模拟为 virt 机器）：

  • 4 个 RISC-V 核心
  • 128 MB RAM
  • UART 控制台、磁盘、以太网

什么是仿真（Emulation）？

QEMU 是一个 C 程序，忠实地模拟硬件：

// 简化模型
uint64 reg[32];
for (;;) {
    instruction = read_mem(pc);
    decode(instruction);
    execute(instruction);  // e.g., add, ld, ecall
}

构建与运行 xv6

$ make              # 编译内核 + 用户程序 + 文件系统镜像
$ ls -l kernel/kernel
$ more kernel/kernel.asm
$ ls -l fs.img
$ make qemu          # QEMU 仿真运行

xv6 启动过程

  1. QEMU 加载内核到 0x80000000，跳转到第一条指令。
  2. main() 初始化内核与硬件。
  3. userinit() 创建第一个用户进程，执行 exec("/init")。
  4. init 是顶级进程，打开控制台 fd 0/1，fork/exec 启动 shell。

系统调用实现示例：exec

// user/usys.S 中的 exec
exec:
  li a7, SYS_exec   # 系统调用号
  ecall             # 进入内核
  ret

// kernel/syscall.c
void syscall(void) {
    num = p->trapframe->a7;
    syscalls[num]();  // → sys_exec()
}

    return kexec();   // → kernel/exec.c

防御性编程的重要性

用户程序可能故意构造恶意 ELF 文件。kexec() 必须检查：文件大小、魔数、段边界、栈溢出等。内核绝不能信任用户数据！

本课要点

隔离是核心

内核的首要目标是隔离——防 bug、防攻击。硬件提供用户/超级模式和虚拟内存作为基础。

安全思维

假设用户代码恶意，内核必须防御性编程。任何内核 bug 都可能是安全漏洞。

宏内核 vs. 微内核

宏内核性能高但复杂；微内核简洁但 IPC 开销大。现代 OS 是两种设计的混合体。

xv6 是起点

xv6 是一个小型的宏内核，代码量小但包含所有核心机制——是理解 OS 的理想案例。
