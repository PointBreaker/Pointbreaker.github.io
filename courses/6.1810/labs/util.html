sleep 简单

为 xv6 实现一个用户级 sleep 程序，类似于 UNIX sleep 命令。你的 sleep 应该暂停用户指定的 tick 数。tick 是 xv6 内核定义的时间概念，即定时器芯片两次中断之间的时间。你的解决方案应该在文件 user/sleep.c 中。

一些提示：

  • 在开始编码之前，阅读xv6 手册的第 1 章。
  • 将代码放在 user/sleep.c 中。查看 user/ 中的一些其他程序（例如 user/echo.c、user/grep.c 和 user/rm.c），了解命令行参数如何传递给程序。
  • 将你的 sleep 程序添加到 Makefile 中的 UPROGS；完成后，make qemu 将编译你的程序，你可以从 xv6 shell 运行它。
  • 如果用户忘记传递参数，sleep 应该打印错误消息。
  • 命令行参数作为字符串传递；你可以使用 atoi 将其转换为整数（参见 user/ulib.c）。
  • 使用 pause() 系统调用。

从 xv6 shell 运行程序：

$ make qemu
...
init: starting sh
$ sleep 10
(一段时间内什么也不会发生)
$

在命令行（qemu 外部）运行 make grade 看看是否通过 sleep 测试：

$ ./grade-lab-util sleep

sixfive 中等

对于每个输入文件，sixfive 必须打印文件中所有 5 或 6 的倍数的数字。数字是由字符串 " -\r\t\n./," 中的字符分隔的十进制数字序列。因此，对于 "xv6" 中的 six，sixfive 不应该打印 6，但对于 "/6,"，应该打印。

$ sixfive sixfive.txt
5
100
18
6
$

一些提示：

  • 逐个字符读取输入文件
  • 你可以使用 strchr（参见 user/ulib.c）测试字符是否与任何分隔符匹配
  • 文件的开始和结束是隐式分隔符

memdump 简单

这个练习将使你更多地练习使用 C 指针。在开始之前，阅读 K&R 的《C 程序设计语言》第 5.1 节（指针和地址）到 5.6 节（指针数组）和第 6.4 节（指向结构的指针）。

查看 user/memdump.c。你的工作是实现 memdump(char *fmt, char *data, int len) 函数。memdump() 的目的是以 fmt 参数描述的格式打印 data 指向的 len 个有效字节的内容。

你的 memdump() 应该处理以下格式字符：

  • i：将接下来的 4 个字节打印为十进制 32 位整数
  • p：将接下来的 8 个字节打印为十六进制 64 位整数
  • h：将接下来的 2 个字节打印为十进制 16 位整数
  • c：将接下来的 1 个字节打印为 8 位 ASCII 字符
  • s：接下来的 8 个字节包含一个指向 C 字符串的 64 位指针；打印该字符串
  • S：数据的其余部分包含一个以 null 结尾的 C 字符串的字节；打印该字符串

实现 memdump()。

find 中等

为 xv6 编写一个简单版本的 UNIX find 程序：查找目录树中具有特定名称的所有文件。你的解决方案应该在文件 user/find.c 中。

一些提示：

  • 查看 user/ls.c 了解如何读取目录
  • 使用递归允许 find 进入子目录
  • 不要递归进入 "." 和 ".."
  • 你需要使用 C 字符串。查看 K&R（C 书籍），例如第 5.5 节
  • 注意 == 不像 Python 那样比较字符串。改用 strcmp()
  • 将程序添加到 Makefile 中的 UPROGS

exec 中等

为 find 添加 "-exec cmd" 选项，对 find 找到的每个文件 f 执行 "cmd file" 程序，而不是打印匹配的文件名。

$ find . wc -exec echo hi
hi ./wc
$

一些提示：

  • 使用 fork 和 exec 在每个文件上调用命令。在父进程中使用 wait 等待子进程完成命令
  • kernel/param.h 声明了 MAXARG，如果你需要声明 argv 数组可能有用
