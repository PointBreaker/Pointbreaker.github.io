Ray 分布式计算框架

Ray 用 task、actor 和分布式对象引用统一动态 AI/科学计算工作负载，让调度与数据移动由对象依赖图驱动。

预计用时：48 分钟难度：进阶Distributed Systems · Raft · Replication · Consistency

学习目标

  • 解释task 与 object ref的核心问题
  • 按协议顺序推演actor
  • 评估工程取舍：动态任务图和去中心化调度提升灵活性，却让资源、对象局部性和 lineage 管理更复杂。

先修回顾

  • 能区分网络延迟、节点崩溃与部分失败
  • 会用状态机和不变量描述协议

task 与 object ref

remote function 调用立即返回 object ref，任务在依赖对象就绪后执行。引用而不是值在控制面传播，真实对象放入共享对象存储；这允许调用者继续构造动态 DAG。不可变对象简化共享和容错，也避免多个 worker 原地修改同一份状态。

actor

actor 是有状态 worker，方法调用按其并发规则执行并返回引用。它适合参数服务器、模拟器和长期服务，但状态使调度、恢复和背压更复杂。调用者应避免把单个 actor 变成所有任务的串行瓶颈。

分布式调度

每个节点的 raylet 负责本地资源和任务调度，优先本地决策，必要时把任务转移到其他节点。任务的 CPU/GPU 等资源需求与对象位置共同影响放置。去中心化减少中央 scheduler 瓶颈，但需要一致的资源视图和失败检测。

容错与 lineage

无状态 task 的输出丢失时，可沿 lineage 重新执行生成它的任务；对象重建要求输入仍可得且任务近似确定。actor 状态则需要 checkpoint 或应用级恢复。lineage 不能无限保留，系统要在重建能力与元数据规模之间做截断。

常见误区

object ref 本身包含完整对象数据。

它是对分布式对象的引用；对象由对象存储管理，并按依赖和位置传输。

只记住正常路径就足以实现协议。

分布式协议的正确性主要由超时、重试、重排、崩溃恢复和旧消息路径决定。
