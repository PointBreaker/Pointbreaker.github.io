题型概览（练习问题，非原题逐字复述）

问题 1：为 BufferA / BufferB / BufferY 写规格、RI 与 AF

给定三种固定大小缓冲区的实现（addLast 版、addFirst 版、双端版），要求：

  • 写适用于三个构造函数的 TypeDoc 规格。
  • 写适用于 BufferA.addLast 与 BufferY.addLast 的规格。
  • 写出 BufferA 的 rep 不变量 RI 与抽象函数 AF。
  • 判断 BufferB 的 RI / AF 是否与 BufferA 相同，并解释。

要点：BufferA 与 BufferB 的 RI 相同（都用 count + 数组 + capacity），但 AF 不同——同一 rep 值在 BufferB 中代表元素顺序相反的缓冲区。

问题 2：完成 BufferY 实现并论证防 rep 暴露

补全 at(idx) 与 toArray()，并写防 rep 暴露论证。

public at(idx: number): Element {
    if (idx < 0 || idx >= this.buff.length) { throw new Error(); }
    return this.buff[idx] ?? assert.fail();
}
public toArray(): Array<Element> {
    return this.buff.slice();   // 返回副本，防 rep 暴露
}

防 rep 暴露：capacity 不可重新赋值且不可变；buff 不可重新赋值；唯一返回 Array 的 toArray 做了拷贝；buff 中的 Element 即使可变也只依赖其对象身份。

问题 3：BufferR 的 bug、修复与 AF

BufferR 用 Map 记住插入顺序，但 trim() 有 bug：forEach 中的 return 只返回给 forEach 的回调，不会让 trim() 退出。效果是缓冲区满时再加元素会把整个缓冲区清空。

private trim(): void {
    if (this.buff.size > this.capacity) {
        for (const key of this.buff.keys()) {
            this.buff.delete(key);
            return;   // 在 for..of 里 return 会真正退出 trim()
        }
    }
}

toArray() 补一行：return entries.map(entry => entry[1]);

问题 4：FixSizeBuffer 接口能包含什么

接口只能包含规格（构造函数规格、at 与 toArray 的规格），不能包含 rep、AF、RI、SRE、实现代码或 addLast/addFirst（因为 BufferA/BufferB 没有实现二者）。接口的规格必须弱于或等于实现（实现规格更强才能成为子类型）。

问题 5：LivePhoto 子类型问题与 Equatable 泛型

  • Photo 被声明为不可变，但 LivePhoto.show(frame) 是 mutator（改变 getPixels() 返回值），因此 LivePhoto 不是 Photo 的规格子类型。修复：把 show 改为返回像素的 videoFrame(frame) 操作。
  • 用 Equatable<Other> 接口与 FixSizeUniqBuffer<Element extends Equatable<Element>> 实现去重缓冲区。addLast 签名：public addLast(elt: Element): void;

备考建议

  • 动手为每个 PS2 实现写出 RI 与 AF，用自然语言清晰表达。
  • 练习在 10 分钟内为一个 ADT 写出 TypeDoc 规格。
  • 理解结构子类型 ≠ 规格子类型：可变性会破坏规格子类型关系。
  • 复习泛型边界 extends 的含义。

常见失分点

  • AF 没有描述"恰好一个"抽象值。
  • 把 rep 细节（如 buff 字段）写进接口。
  • 规格比实现还强：实现无法满足。
  • 防 rep 暴露论证遗漏某个 rep 字段。
