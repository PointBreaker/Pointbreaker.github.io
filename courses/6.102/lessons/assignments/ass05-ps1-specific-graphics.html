PS1：Specific Graphics

练习测试先行（test-first）编程与规格说明：为 RGB 颜色、Bézier 曲线、线性插值与动画编写测试、强化规格并实现代码。

实验目标

  • 实践测试先行工作流：规格 → 测试 → 实现。
  • 为符合规格的函数编写单元测试，实现代码满足规格，并强化现有规格。
  • 理解规格中的前置条件、后置条件与浮点误差容限。
  • 掌握线性插值（lerp）、Bézier 曲线、缓动函数（easing）与动画。

先修知识

  • PS0 的 TypeScript 与 Mocha 经验。
  • 阅读材料：规格说明、测试、抽象数据类型相关讲次。

主题概览

  • RGB 颜色：颜色插值、渐变填充、调色板生成。
  • Bézier 曲线：求曲线上一点、求点列。
  • 线性插值 (lerp)：一维、三维颜色空间、二维欧氏空间。
  • 缓动函数 (easing)：控制插值位置。
  • 动画：用线性与缓动运动驱动点。

测试先行工作流：分步指引

Step 1：阅读已有规格

类型别名 Color、Point；已有规格的函数：lerp、lerpColor、fillGradient、makePalette、interpolate、bezierPath、bezierInterpolate。

Step 2：lerp 与 lerpColor

  1. 为 lerpWeak 写一个弱规格（尽可能弱但仍可理解、可用来实现 lerpColor）。
  2. 写少量测试，实现 lerpWeak。
  3. 测试并实现 lerpColor（调用 lerp，不能改其规格）。

Step 3：fillGradient

先写测试，再实现。

Step 4：makePalette

注意使用 utils.ts 提供的 hslToRgb 与 rgbToHsl。

Step 5：lerp 强化 与 interpolate

  1. 解释为什么用 lerpWeak 规格的 lerp 无法实现 interpolate。
  2. 写一个强规格 lerpStrong，适用于所有使用场景。
  3. 分析 lerpWeak 与 lerpStrong 的关系。
  4. 测试并实现 lerpStrong，把 export const lerp = lerpWeak 改为使用 lerpStrong。
  5. 测试并实现 interpolate。

Step 6：bezierInterpolate 与 bezierPath

强化 src/curves.ts 中的规格（只能强化、不能弱化），重命名 renameMe，测试并实现。

Step 7：动画

  1. 审阅 animateToFile 规格。
  2. 在 src/toolbox.ts 中草拟至多 3 个函数的规格。
  3. 写测试、实现，并用 toolbox 实现 handoutExampleOne 与 handoutExampleTwo。

规格约定

  • 整数 number 值假定为安全范围。
  • 非整数计算允许误差容限 tolerance = 0.001。
  • 测试浮点数用 assertApproxEqual（来自 utils.ts）。
  • 不可变值用 strictEqual；数据结构用 deepStrictEqual。

测试建议

  • 对输入/输出做划分（partition），在测试套件顶部注释记录策略。
  • 测试用例要小、要精、要能发现 bug。
  • 测试必须是规格的合法客户端——不得做额外假设。
  • 每个测试用例单独一个 it()。
  • 用 npm run coverage 检查覆盖。
  • 不要在测试中调用 src/ 里新写的辅助函数（测试会针对 staff 实现运行）。

提交与验收

  • commit 并 push 到 github.mit.edu，评分使用 9:00pm 截止时的仓库状态。
  • Didit 构建运行公开测试（自动评分的子集）。
  • 通过公开测试 ≠ 通过全部自动评分。

评分构成

  • ~30% alpha 自动评分
  • ~20% alpha 人工评分
  • ~25% beta 自动评分
  • ~25% beta 人工评分

Alpha 更侧重测试；beta 在测试与实现之间平衡。人工评分会审查规格、解释、测试、实现与 git 历史。

常见陷阱

  • 修改已有函数签名或弱化已有规格：不允许。
  • 测试依赖超出规格的假设：测试会针对其他实现运行，可能失败。
  • 混淆 lerpWeak 与 lerpStrong 的适用范围。
  • 在测试里调用 src/ 新辅助函数：无法针对 staff 实现运行。
  • toolbox 超过 3 个新函数。
