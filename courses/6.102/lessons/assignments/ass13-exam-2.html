Exam 2

期末考试：递归数据类型、解析、并发、回调、规格与 Star Battle 设计。闭卷，120 分钟，6 道题。

考试形式

  • 时间：120 分钟，共 6 道题。
  • 闭卷、闭笔记，但允许携带一张 8.5×11″ 双面手写笔记（不得复印/打印）。
  • 不得使用 6.102 网站、TypeScript 解释器/编程工具、网络搜索或与他人讨论。
  • 官方 PDF：exam2.pdf（题目）| exam2-solutions.pdf（解答）

主题覆盖

  • 语法（grammar）与递归数据类型（recursive data type）
  • 解析与抽象语法树
  • 循环缓冲区 ADT 的 RI / AF
  • 并发与竞态条件（race condition）
  • 回调、事件队列、setTimeout
  • 异步函数、Promise、Deferred
  • map 规格、fail fast、mapper 高阶函数
  • Star Battle 项目设计变更

题型概览（练习问题，非原题逐字复述）

问题 1：整数差值表达式语言

设计一个"差值表达式"语言：二元减号运算，叶节点为非负整数常量，必须括号化，不允许空白。

  • 写语法，根非终结符为 diff。
  • 定义不可变递归 ADT Diff，实现 toString()。
  • 写递归数据类型定义：Diff = Constant(value: number) + Difference(left: Diff, right: Diff)。
  • 实现 invert()，返回值为原表达式负值的表达式，尽量复用原表达式节点（只新建必要节点）。
  • 例如 ((1-2)-(3-4)).invert() 只新建 1 个对象。

问题 2：EventLog 循环缓冲区与并发

EventLog 是存储最近 capacity 个事件的可变循环日志，带监听器。

  • 写 RI 与 AF。
  • 两个 Worker 并发读 / append / 写同一文件，给出一个让事件 "x" 丢失的交错序列：A1, A2, B1, B2, A3, B3。最终 total() = 6。
  • checkRep() 不会在 append 末尾失败——因为每个 Worker 的本地对象满足 RI，丢失更新发生在 B3 覆盖 A3 时。
  • 修复：用单 coordinator 通过消息传递处理 append，避免交错。

问题 3：onAppend 监听器与回调顺序

监听器同步、按注册顺序调用；setTimeout(cb, 0) 在事件队列中排队，FIFO。练习：

  • 给定代码，列出打印顺序。
  • 两个监听器在不同 append 之间注册，判断哪些事件触发哪些监听器。
  • 监听器内 setTimeout：区分"定时器回调前打印的"与"全部打印的"。

问题 4：异步并发与 watch

  • 把 f(g()+h())/f(0) 改写成异步版，使 g() 与 h() 并发执行。
  • 实现 watch<T>(func)：返回 { funcWithWatch, promise }，调用 funcWithWatch 会把返回值 resolve 到 promise。若 func 抛异常，promise 保持未解决。Promise 只能 resolve 一次，所以不能用来观察每次调用。

问题 5：map 规格与 mapper

  • map 中函数 f 的规格如何约束输入数组？这是 map 的前置条件。
  • Louis 提议让 map 在 f 违反前置条件时跳过该元素——新规格更强（前置条件更弱，但在合法输入上行为相同）。但 f 在前置条件不满足时可以做任何事，不一定抛异常；且该实现不 fail fast。
  • 实现 mapper(f)，把 number→number 函数提升为 Array→Array 函数。
  • 限制输入数组只含整数：f 的规格不变，g 的规格变弱（前置条件更强），mapper 的规格变弱。

问题 6：Star Battle 设计变更

对每个设计变更，说明系统哪些部分需要改：

  • 显示可选谜题列表：服务器需提供列出磁盘谜题的 Web API；客户端需在页面中显示该列表。
  • 标记必空格：客户端需支持点击标记/取消标记（如 shift-click）；客户端谜题 ADT 需记录该标记并在显示时呈现。

备考建议

  • 复习 PS3 的递归 ADT 与语法：能独立写语法、AST、toString、equalValue。
  • 练习并发交错分析：列出步骤、找出竞态、给出修复。
  • 理解事件循环、setTimeout 与同步回调的执行顺序。
  • 动手写 Promise / Deferred 包装器。
  • 复习规格强弱、前置/后置条件在 map / filter 类操作中的交互。

常见失分点

  • 语法允许空白或不必要括号。
  • invert() 没有尽量复用原表达式节点。
  • 并发交错不满足"每个 Worker 内部步骤有序"的约束。
  • 规格强弱判断错误：前置条件更强 → 函数规格更弱。
  • 把设计变更归因到错误的系统组件。
