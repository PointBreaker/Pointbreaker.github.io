MIT 6.102 · PS4 · Assignment 9

PS4：Memory Scramble

探索并发共享可变数据类型的编程：构建多人网络 Memory 翻牌游戏，处理等待、并发玩家与实时更新。

实验目标

  • 设计并实现可变 Board ADT 表示游戏棋盘。
  • 通过 HTTP 协议连接 Web 服务器，支持多客户端。
  • 用异步方法 / await / Promise 实现等待与并发玩家。
  • 实现 map() 与 watch()，练习观察者模式与原子性思考。

先修知识

  • PS3 的解析器与 ADT 经验。
  • 阅读材料：并发、互斥、Promise、回调、消息传递与网络。

任务概述

Memory Scramble 是翻牌配对游戏的多人实时版。玩家同时翻牌找配对：

  • 第一次翻牌：控制该牌；若被他人控制则等待。
  • 第二次翻牌：配对成功则保持控制；失败则放弃控制。
  • 下次翻牌前：已配对的牌移出，未配对且无人控制的牌翻回背面。

棋盘从文件加载，ROW x COLUMN 格式，随后逐行逐张卡列出。

分步指引

Problem 1：棋盘 ADT

规格 / 测试 / 实现可变 Board ADT。必须支持 parseFromFile(filename)。实现 AF、RI、防 rep 暴露、checkRep、toString。先不考虑并发。

Problem 2：连接 Web 服务器

实现 commands.ts 的 look() 与 flip()（粘合代码，每函数不超过 3 行）。用 npm start 8080 boards/perfect.txt 启动服务器，在浏览器多标签页测试。

Problem 3：并发玩家

把 Board 改为异步，用 await / Promise 实现等待。不要用忙等待（busy-wait）。用 simulation.ts 增加玩家数测试。

Problem 4：换牌 map()

实现 map()：把每张卡替换为 f(card)。f 是异步的，替换期间允许其他命令交错执行，但必须保持一致性（配对卡仍配对）。

Problem 5：棋盘事件 watch()

实现 watch()：挂起直到棋盘变化（翻面、移出、换牌）。设计变更通知机制（单次或持续监听），用 callback 或 promise。

HTTP 协议

玩家用 ID 标识。服务器返回棋盘状态，每格为 none/down/up CARD/my CARD。

命令：look、flip、map、watch。失败用拒绝的 promise（async 函数 throw）表示。

提交与验收

  • commit 并 push 到 github.mit.edu，评分使用 9:00pm 截止时的仓库状态。
  • PS4 的 Didit 处理时间比前面问题集长，请尽早 push。
  • 正确性完全由你自己负责。

评分构成

  • ~30% alpha 自动评分（含在线练习）
  • ~20% alpha 人工评分
  • ~25% beta 自动评分
  • ~25% beta 人工评分（含代码审查）

Alpha 自动评分侧重非并发场景；beta 覆盖完整并发情况。

常见陷阱

  • 忙等待（busy-wait）：必须用 Promise / await。
  • commands.ts 函数超过 3 行：说明 Board 操作设计得不够强大。
  • 在实现代码里放 timeout()：这是 race condition 的信号。
  • detached HEAD / 忘记 push。
  • 并发测试用很长超时：会导致 Didit 测试超时，应使用很短超时。
