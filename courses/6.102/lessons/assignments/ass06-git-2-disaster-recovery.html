Git 2：Disaster Recovery

用 Git 命令查看与找回旧版本代码：git show、git revert、git checkout，从灾难中恢复。

实验目标

  • 用 Git 命令查看与检索旧版本。
  • 理解 commit 在 Git 内部以 diff 形式呈现、但本质是完整快照。
  • 掌握 git show、git revert、git checkout 恢复旧版本的方式。
  • 区分"撤销整次提交"与"把单个文件恢复到某个旧版本"。

为什么 commit 看起来像 diff

Git 定义上把每次 commit 存为完整快照，但 git show 默认只显示 diff，因为大多数 commit 只改动项目的一小部分，diff 更实用。我们也可以让 Git 展示某个 commit 时的完整状态：

git show 3e62e60:hello.scm       # 某次 commit 时某文件的内容
git show 3e62e60:                # 空路径 = 根目录，列出该 commit 所有文件

分步指引：三种恢复手段

1. 用 git clone 预防灾难

只要定期 add / commit / push，远程仓库就有完整备份。在新机器上 git clone 即可恢复。

2. 用 git revert 撤销整次提交

git revert <commit-id>    # 新增一次提交，抵消旧提交的改动

git revert 不会删除旧提交，而是在 HEAD 上新增一个反向提交。安全、可共享。

3. 用 git show + git checkout 恢复单个文件

git show 1255f4e:hello.txt        # 查看旧版本内容，手动复制
git checkout 41c4b8f -- hello.txt  # 把文件恢复到某次 commit 的状态（并暂存）

注意 -- 与路径必不可少。git checkout 的 revision 是你希望恢复到的版本（包含该版本及之前的所有改动）。

关键命令速查

命令作用
git show <id>查看某次提交的 diff
git show <id>:<path>查看某次提交时某文件的内容
git revert <id>新增反向提交，撤销旧提交
git checkout <id> -- <file>把某文件恢复到某次提交的状态（并暂存）

常见陷阱

  • git checkout <id>（不带 -- <file>）：会让 HEAD 指向旧 commit，进入 detached HEAD 状态，可能导致工作丢失。
  • 误以为 git revert 会删除历史——它只是新增反向提交。
  • 在 git show 的长输出里：空格翻页，q 退出。
