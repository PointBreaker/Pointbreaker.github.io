Git 1：版本控制

理解 Git 的对象图模型，掌握 clone / add / commit / push / pull 工作流，作为单人开发者管理代码版本。

实验目标

  • 解释版本控制（version control）的核心需求：回退、比较、备份、合并。
  • 理解 Git 把版本历史存储为有向无环图（DAG, directed acyclic graph）。
  • 掌握工作目录、暂存区（staging area）与 HEAD 三者的关系。
  • 熟练使用 git clone、add、commit、push、pull、status、diff、log。

为什么需要版本控制

没有版本控制时，我们常靠复制文件加版本号来保存历史。这带来三个问题：难以比较版本差异、容易覆盖他人的改动、无法回到某个稳定节点。Git 通过对象图（object graph）记录每次提交的完整快照与父子关系，使回退、比较、合并和协作成为可能。

Git 对象图模型

Git 仓库由三部分组成：

  • .git 目录：存储对象图（所有版本与日志）。
  • 工作目录（working directory）：你编辑的文件副本。
  • 暂存区（staging area / index）：下一次提交的原型。

每次提交是一个项目快照，用 commit ID（SHA 哈希）唯一标识。提交之间通过父指针连成一条有向无环图。HEAD 指向当前分支（如 main），分支再指向当前提交。

分步指引：基础工作流

克隆仓库

git clone ssh://github.mit.edu/.../ps0-username.git ps0
cd ps0

查看历史

git lol          # 图形化历史（log --graph --oneline --decorate --all）
git show         # 查看最近一次提交
git show <commit-id>   # 查看指定提交

修改、暂存、提交

git status                  # 查看工作目录与暂存区状态
git diff                    # 查看未暂存的改动
git add src/turtlesoup.ts   # 把改动加入暂存区
git diff --staged           # 查看已暂存的改动
git commit                  # 打开编辑器写提交信息后提交

推送到远程

git push origin main        # 把本地 main 分支推到 origin 远程

拉取远程更新

git pull                    # 拉取并合并远程最新改动

理解 git status 的四种状态

  • Untracked：全新文件，从未被 Git 跟踪。
  • Modified (unstaged)：已跟踪文件被修改，但未 git add。
  • Staged：改动已加入暂存区，下次提交会包含。
  • Committed：改动已安全保存在本地仓库。

注意：同一个文件可以同时拥有已暂存和未暂存的改动——git add 后再修改就会出现这种情况。

关键命令速查

命令作用
git clone <url>复制远程仓库到本地
git status查看工作目录与暂存区状态
git add <file>把改动加入暂存区
git commit把暂存区快照提交到本地仓库
git push origin main把本地提交推送到远程
git pull拉取远程更新并合并
git log / git lol查看提交历史
git diff比较工作目录与暂存区
git show <id>查看某次提交的内容

常见陷阱

  • 忘记 git push：6.102 评分以 github.mit.edu 上的历史为准，本地提交不会自动上传。
  • 用 VS Code / GitHub Desktop 执行 add/commit：课程推荐命令行，出问题时助教才能帮你。
  • 提交信息空洞：应写清"改了什么"和"为什么"，方便未来的自己。
  • 把编译产物（.js、node_modules）提交进仓库：这些应由构建生成，不该入库。

阅读练习要点

  • Git 历史是 DAG：分叉表示并行开发，合并（merge）把分叉重新接回。
  • 循环在历史图中不可能出现——提交不可能是自己的祖先。
  • commit ID 是内容的全局哈希，几乎不会碰撞。
