01 / PROBLEM

接口把契约与实现分开

TypeScript 的 接口（interface） 是一组方法签名列表，没有方法体。它只描述“能做什么”，不描述“怎么做”。当某个类 implements 一个接口时，它承诺提供这些方法的具体实现。

接口对 ADT 的意义在于：把契约（操作签名）变成一种可命名的类型。客户端可以依赖接口类型编程，而实现类随时可换。这正是表示独立性在类型系统层面的直接表达。

interface MyString {
  charAt(i: number): string;
  length(): number;
  concat(other: MyString): MyString;
}

一个类可以实现多个接口，一个接口也可以被多个类实现。这种多对多关系让“同一抽象、多种表示”真正可落地。

FIELD TRACE

把接口想象成一份合同：接口是合同文本，实现类是签字方。只要合同条款（方法签名）不变，换一家签字方（换实现类），依赖合同的客户端不受影响。

02 / DEEP READING

子类型是超类型的子集

子类型（subtype） 的定义非常干净：B 是 A 的子类型，当且仅当每个 B 的实例都满足 A 的规格说明。换句话说，子类型是超类型的子集。

这个定义直接导出里氏替换原则（Liskov Substitution Principle）：如果 B 是 A 的子类型，那么任何期望 A 的上下文都可以安全地接受 B，而无需修改程序行为。

子类型关系由规格说明决定，而不是由代码继承决定。一个类即便没有 extends 另一个类，只要它满足对方的规格说明，就可以被视为子类型。TypeScript 的结构子类型（structural subtyping）正是按这个思路工作的：只要形状（字段与方法签名）匹配，就视为兼容。

03 / DERIVATION

MyString：同一接口的多种实现

课堂用 MyString 展示接口的价值。定义 MyString 接口后，可以提供多种实现：

  • SimpleMyString：内部用 JavaScript 原生字符串包装。
  • ArrayMyString：内部用字符数组实现。
  • FastConcatMyString：内部用树状结构优化拼接。

三种实现都满足 MyString 的规格说明，因此客户端代码可以在它们之间自由切换。这正是表示独立性的工程落地：接口让“可替换实现”变成类型安全的现实。

class SimpleMyString implements MyString {
  private readonly s: string;
  charAt(i: number): string { return this.s.charAt(i); }
  length(): number { return this.s.length; }
  concat(other: MyString): MyString { /* ... */ }
}
04 / DEEP READING

为什么需要接口

接口的价值不止于“支持多实现”。它至少带来三类收益：

  • 文档：接口把 ADT 的契约显式化、可命名，成为比注释更可靠的文档。
  • 性能取舍：不同实现可以在时间/空间上做不同权衡，客户端按需选择。
  • 一个类的多个视图：一个类可以实现多个接口，在不同上下文中扮演不同角色。

这些收益合起来，让“依赖抽象、而非依赖具体类”从一句口号变成编译器可检查的约束。

05 / DEEP READING

子类与子类型的区别

子类（subclass） 是通过 extends 继承另一个类的代码；子类型（subtype） 是规格说明层面的子集关系。两者相关但不相同：

  • 子类自动获得超类的字段与方法，但不一定满足超类的规格说明（子类可能强化前置条件、弱化后置条件）。
  • 子类型强调可替换性：子类型必须满足超类型的规格说明。

一个类可以是子类却不是子类型（如果它违反了里氏替换），也可以在没有 extends 关系的情况下成为子类型（TypeScript 的结构子类型）。本课强调：设计时应追求子类型关系，而不是盲目使用子类继承。

06 / DEEP READING

泛型类型

泛型类型（generic type） 是用占位类型（type parameter）描述的一族类型。例如 List<T> 中的 T 是占位符，实例化时再绑定到具体类型。

泛型让 ADT 抽象与元素类型解耦：ImmutableSet<number> 与 ImmutableSet<string> 共享同一套操作与规格说明，只是元素类型不同。这大幅提升了代码复用，同时保留编译期类型安全。

interface List<T> {
  get(i: number): T;
  size(): number;
  append(item: T): List<T>;
}
07 / DEEP READING

枚举：有限值域抽象

枚举（enumeration） 定义一个小的、有限的不可变值集合作为命名常量。当 ADT 的值域天然有限时——比如布尔值、方向、状态码——枚举是最自然的表达。

枚举的关键特征是：值集合在编译期就固定，且每个值都是不可变的单例。这让客户端不可能构造出非法值，从源头上消除了“非法表示”这一类 bug。

enum Direction { North, South, East, West }
enum Color { Red, Green, Blue }
08 / DEEP READING

Getter 与 Setter

TypeScript 用 get 关键字定义 getter 方法，让方法调用看起来像字段访问。Getter/setter 的价值在于：它们把“访问表示”封装成操作，未来可以在不改变客户端代码的前提下加入校验或计算逻辑。

但要注意：大量 getter/setter 往往意味着抽象太薄——客户端仍要自己拼接复杂逻辑，等于把 ADT 降级成“装着字段的容器”。好的 ADT 应优先提供有语义的操作，而不是把每个字段都暴露成 getter/setter。

09 / DEEP READING

非面向对象语言中的 ADT

ADT 并不依赖面向对象。在非 OOP 语言里，ADT 可以定义为一组全局可访问的函数，操作一个不透明（opaque）的数据类型——客户端只能看到类型的名字，看不到其内部结构，所有操作都通过函数完成。

这种“模块 + 不透明类型 + 全局函数”的组合，与 OOP 的“接口 + 类”在抽象能力上等价。它提醒我们：ADT 是一种设计思想，接口和类只是 TypeScript 表达这种思想的方式之一。

10 / DEEP READING

TypeScript 中的 ADT 实现方式

本课把 TypeScript 实现 ADT 的方式汇总成一张对照表：

  • 类：private 字段 + 公开方法，绑定单一实现。
  • 接口 + 类：接口定义契约，多个类实现，客户端依赖接口。
  • 泛型：用占位类型参数化 ADT，复用操作与规格说明。
  • 枚举：表达有限值域，编译期固定、不可变。
  • 全局函数 + 不透明类型：非 OOP 风格的 ADT 表达。

实际项目中这些方式常常混用：一个泛型接口、多个实现类、配合枚举定义特殊值，是常见组合。

12 / CALIBRATION

把直觉校准成类型规则

误区

子类就是子类型。

子类是代码继承关系，子类型是规格说明层面的子集关系。子类未必满足里氏替换，未必是子类型。

误区

接口和抽象类可以随意互换。

接口定义契约而不绑定实现，天然支持多实现与结构子类型；抽象类会引入继承耦合。追求表示独立性时应优先用接口。

- **interfaces**: separating the interface of an ADT from its implementation

- **enumerations**: defining an ADT with a small finite set of values
- **global functions operating on an opaque type**

## Interfaces

An interface in TypeScript is a list of method signatures without method bodies.

## Subtypes

A *subtype* is simply a subset of the *supertype*. B is a subtype of A means every B satisfies the specification for A.

## Example: MyString

Using an interface instead of a class for the ADT supports multiple implementations.

## Why interfaces?

- Documentation
- Allowing performance trade-offs

## Subclassing

Subclassing means defining a class as an extension of another class.

## Generic types

A *generic type* is a type whose specification is in terms of a placeholder type.

## Enumerations

An **enumeration** defines a small, finite set of immutable values as named constants.

## Getters and setters
