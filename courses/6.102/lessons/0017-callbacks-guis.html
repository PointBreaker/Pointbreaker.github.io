01 / PROBLEM

回调：客户端提供的函数

回调（callback）是一个函数，由客户端提供给模块，供模块在适当时机调用。回调是"控制反转"（inversion of control）的典型体现：不是客户端主动轮询模块，而是模块在事件发生时主动通知客户端。

回调让模块保持通用性：模块只负责"何时调用"，客户端决定"做什么"。

02 / DEEP READING

同步回调 vs. 异步回调

回调有两种风格：

  • 同步回调（synchronous callback）：在调用模块的函数期间立即执行。例如 Array.map(fn) 中的 fn。
  • 异步回调（asynchronous callback）：被保存起来，在未来某个时刻调用。例如事件处理函数、setTimeout 的回调。

区分两者很关键：同步回调在调用栈中直接返回，异步回调则要等事件循环调度。

03 / DEEP READING

定时器回调与事件循环

setTimeout(callback, ms) 接受一个回调和一个毫秒延迟，在延迟到期后把回调放入事件队列（event queue）。

TypeScript/JavaScript 使用事件循环（event loop）模型：主线程执行完当前任务后，从事件队列取出下一个回调执行。这意味着：

  • setTimeout(cb, 0) 不会立即执行，而是等当前任务完成后才执行
  • 长时间同步代码会阻塞事件队列中的所有回调
  • 多个回调按入队顺序依次执行（FIFO）
FIELD TRACE

把事件循环想成"前台 + 等候室"：主线程是前台，一次接待一位顾客（执行一个任务）。setTimeout 的回调在等候室（事件队列）排队，等前台空闲才进入。同步代码太长，等候室的顾客就永远进不来——这就是"阻塞"。

04 / DEEP READING

用回调组合 Promise

Promise<T>.then(callback) 附加一个回调，当 Promise fulfill 时调用它，并返回一个新的 Promise（其值是回调的返回值）。这是组合异步操作的基础：

fetchUser(1)
  .then(user => fetchPosts(user.id))   // 返回 Promise<Post[]>
  .then(posts => console.log(posts));  // 当 posts 就绪时执行

.then 让 Promise 链可以一步步传递结果，避免"回调地狱"。配合 async/await，异步代码的可读性进一步提升。

05 / DEEP READING

解构异步函数

await 的本质是什么？它把函数中剩余的计算包装成一个 then 回调，附加到被 await 的 Promise 上。换句话说：

// 写法 A：async/await
async function f() {
  const x = await promise;
  console.log(x);
}

// 写法 B：等价的手动 .then
function f() {
  return promise.then(x => {
    console.log(x);
  });
}

两种写法等价，但 async/await 让异步代码看起来像同步代码，大幅降低认知负担。理解这个等价关系，是调试异步代码的关键。

06 / DEEP READING

HTML 与文档对象模型

HTML 元素形成一棵树，称为文档对象模型（Document Object Model, DOM）。DOM 是 JavaScript 操作网页内容的接口：可以读取元素、修改内容、添加或删除节点、注册事件监听器。

// 通过 DOM 访问元素
const button = document.getElementById("myButton");
button.textContent = "Clicked!";
07 / DEEP READING

输入处理：Listener 模式

GUI 事件处理使用监听器模式（Listener pattern）：

  • 事件源（event source）：生成事件的对象（如按钮）
  • 监听器（listener）：客户端提供的回调函数
  • 模块（GUI 框架）负责在事件发生时调用监听器
// 注册监听器
button.addEventListener("click", (event) => {
  console.log("button clicked!");
});

监听器模式是回调在 GUI 中的具体应用。事件源不知道监听器会做什么，它只负责在事件发生时调用。

08 / DEEP READING

监听器中的陷阱

使用监听器时有三类常见陷阱：

  • 运行太久：监听器在主线程执行，长时间运行会阻塞所有后续事件。应快速返回，把重活交给 Worker 或分批处理。
    • 循环引用：监听器持有对事件源的引用，事件源又持有监听器，导致内存泄漏。
  • 忘记清理：模块销毁时必须移除监听器，否则已销毁的模块仍会被调用。
FIELD TRACE

把监听器想象成"订阅报纸"：订阅（addEventListener）后，每期都会送来。如果你搬家了（模块销毁）没退订（removeEventListener），报纸仍会寄到旧地址——在程序里就是内存泄漏或调用已销毁对象。

# Reading 17: Callbacks and Graphical User Interfaces

## Objectives

This reading covers **callbacks**, promises/`await` with callbacks,
and GUI **listener** functions.

## Callbacks

A **callback** is a function that a client provides to a module
for the module to call.

### Synchronous vs. Asynchronous

Synchronous callbacks execute during the enclosing call.
Asynchronous callbacks are saved for a future call.

## Timer callbacks

`setTimeout` takes a callback and a millisecond delay.

## Event loop

TypeScript/JavaScript uses an **event loop** and **event queue**.

## Using callbacks with promises

`Promise<T>.then(callback)` attaches a callback and returns a new promise.

## Unpacking an asynchronous function

`await` takes the remainder of the function's computation and wraps
it into a `then` callback.

## HTML and the Document Object Model

HTML elements form a tree called the **Document Object Model (DOM)**.

## Input handling

GUI event handling uses the **Listener pattern**: event sources generate
events; modules subscribe with callbacks.

## Pitfalls in listeners

- Listeners should run quickly and return quickly
- Be careful about cycles
- Don't forget to clean up

## Summary

- Callbacks are first-class functions (synchronous or asynchronous)
- Event loop and event queue execute asynchronous callbacks
- GUI event handling uses the Listener pattern
