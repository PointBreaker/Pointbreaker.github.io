01 / PROBLEM

图书馆例子

用一个图书馆系统作为贯穿本讲的例子。图书馆有 checkout（借书）和 checkin（还书）操作。当一本书被借出后，其他读者必须等待它归还才能借。

这个例子足够简单，却能暴露异步 ADT 的所有核心问题：竞态条件、死锁、以及互斥的必要性。

02 / DEEP READING

同步 ADT 的实现

如果所有操作都是同步的，图书馆 ADT 很直接：用一个 rep（如 Set<Book>）记录当前在馆的书，checkout 从集合移除，checkin 加回集合。

但同步实现有一个局限：如果书已被借出，checkout 只能失败或抛异常——它无法"等待书归还后再借"。这就需要异步方法。

03 / DEEP READING

异步方法

把 checkout 改成异步：当书不在馆时，返回一个 Promise，等书被归还时才 fulfill。这样调用者可以 await checkout(book)，语义清晰。

但异步方法引入了新的复杂性：在等待期间，其他操作可能修改共享状态，导致竞态条件。

04 / DERIVATION

创建和保持 Promise：Deferred<T>

异步方法需要"先创建一个 Promise，稍后再 resolve 它"。标准 Promise 构造函数把 resolve 函数放在 executor 里，不适合这种"延迟 resolve"的场景。

6.102 使用 Promise.withResolvers() 或一个 Deferred<T> ADT 来创建 Promise：

// Promise.withResolvers() 返回 { promise, resolve, reject }
const { promise, resolve, reject } = Promise.withResolvers<T>();

// 稍后，当结果就绪时：
resolve(value);   // promise 变为 fulfilled
// 或
reject(error);    // promise 变为 rejected

Deferred<T> 把 promise 与其 resolve/reject 控制柄分开，让异步方法可以先返回 promise，再在适当时机 resolve。

FIELD TRACE

把 Deferred 想成"寄存柜"：你拿到一个柜门（promise），把钥匙（resolve/reject）留在手里。别人拿走柜门等东西，你稍后把东西放进去（resolve），柜门就开了。没有 Deferred，你就没法把"等"和"完成"分开。

05 / DEEP READING

异步方法创建 Promise

在图书馆例子中，checkout 的实现逻辑是：

  1. 如果书在馆，立即借出并返回已 fulfill 的 Promise
  2. 如果书不在馆，创建一个 hold（等待记录），等 checkin 归还时 resolve 它
async function checkout(book: Book): Promise<void> {
  if (this.available.has(book)) {
    this.available.delete(book);  // 立即借出
  } else {
    // 等待归还
    const { promise, resolve } = Promise.withResolvers<void>();
    this.holds.get(book).push(resolve);
    await promise;
    this.available.delete(book);
  }
}
06 / DEEP READING

竞态条件

图书馆例子在等待多本书时存在竞态条件。假设读者要借两本都被借出的书，如果分别 await checkout(book1) 和 await checkout(book2)，在等待期间，另一个读者可能抢先借走其中一本，导致永远等不到。

修复思路：尽早借出每本书——一旦书在馆就立即借出，而不是等到所有书都就绪。

07 / DEEP READING

死锁

死锁（deadlock）发生在并发模块互相等待、都无法推进时。经典场景：A 持有书 1 等书 2，B 持有书 2 等书 1，两人永远等下去。

死锁的四个必要条件：互斥、持有并等待、不可抢占、循环等待。破坏任一条件即可避免死锁。

08 / DERIVATION

互斥：await 之间的代码

JavaScript 单线程模型给出一个关键性质：两个 await 之间的代码会连续执行，不会被交错。因为 await 是唯一让出控制权的点，没有 await 就不会有切换。

利用这个性质，可以实现互斥（mutual exclusion）：一段代码在同一时刻只有一个计算在执行。只要把需要互斥的操作放在同一对 await 之间，就不会被其他操作打断。

// 这段代码在两个 await 之间，不会被交错
async function criticalSection(): Promise<void> {
  // 点 A：上一个 await 之后
  const x = this.sharedState;  // 读取
  this.sharedState = x + 1;    // 修改
  // 点 B：下一个 await 之前
  // A 到 B 之间没有其他代码能运行
}
FIELD TRACE

把 await 想成"检查站"：代码在检查站之间是安全的独木桥，同一时刻只能有一个人。过了检查站（await），才可能换人。所以需要互斥的操作，必须放在同一对检查站之间。

09 / DEEP READING

重新设计 checkout

结合 hold 队列与互斥，重新设计 checkout：

  1. 用 await 等待书归还（进入 hold 队列）
  2. 书一旦归还，在互斥段内一次性借出所有需要的书

这样既避免了竞态条件（尽早借出），又避免了死锁（互斥段内原子操作）。

10 / DEEP READING

其他互斥技术

互斥不是 JavaScript 独有的概念。其它技术包括：

  • 抢占式并发（preemptive concurrency）使用锁（locks）、互斥量（mutexes）、信号量（semaphores）
  • 数据库使用事务（transactions）提供可串行化隔离

这些技术的核心思想相同：保护共享状态，让并发操作表现得像串行执行。JavaScript 的 await 之间互斥是一种轻量级的、协作式的实现。

误区

异步代码不会有竞态条件。

异步代码仍然共享状态，await 让出控制权时仍可能产生竞态。互斥是必要的。

误区

死锁只发生在有多把锁的程序里。

任何"互相等待"都会死锁，包括 Promise 等待链形成的循环。

# Reading 16: Mutual Exclusion

[6.102 — Software Construction](http://web.mit.edu/6.102/www/sp26/)
Spring 2026

## Objectives

- Asynchronous ADTs with concurrent operations
- Race conditions and deadlocks
- Mutual exclusion to defend against bugs

## Library example

A library with `checkout` and `checkin` operations.

## Synchronous ADT

Straightforward implementation with a rep.

## Asynchronous methods

Making `checkout` asynchronous so it can wait for books to be returned.

## Making and keeping a promise

Use `Promise.withResolvers()` or a `Deferred<T>` ADT to create promises.

## Asynchronous method making a promise

Put holds on books and resolve them when books are returned.

## Race conditions

The library example has a race condition when waiting for multiple books.

## Fixing the race

Check out each book as soon as possible.

## Deadlock

**Deadlock** occurs when concurrent modules are stuck waiting for each other.

## Interleaving and mutual exclusion

- Code between `await` points executes continuously without interleaving.
- **Mutual exclusion**: a region with only one computation running at a time.

## Redesigning `checkout`

Use the hold queue with `await`, then check out all books at once
in a mutually exclusive section.

## Other techniques for mutual exclusion

- Preemptive concurrency uses locks, mutexes, semaphores.
- Databases use *transactions*.

## Summary

- Asynchronous ADTs need safeguards against race conditions and deadlock
- `Deferred<T>` allows promisers to create promises
- Mutual exclusion in code between `await` expressions
