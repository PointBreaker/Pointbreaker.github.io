01 / PROBLEM

两种并发模型回顾

第 14 讲建立了两种并发模型，本讲深入消息传递这一侧：

  • 共享内存（shared memory）：并发模块通过读写共享的可变对象交互。需要互斥保护。
  • 消息传递（message passing）：并发模块通过发送不可变消息交互。没有共享状态。

消息传递避免了同步共享可变数据的许多 bug，但如我们所见，它并不能消除竞态条件。本讲把消息传递从单机 Worker 扩展到网络上的客户端与服务器。

02 / DEEP READING

Worker 之间的消息传递

Node.js 的 worker_threads 接口提供 postMessage 和 parentPort，用于在主线程与 Worker 之间传递消息。消息是不可变的——发送后接收方无法修改它，从而避免了共享可变状态的问题。

// 主线程
import { Worker } from "worker_threads";
const worker = new Worker("./worker.js");
worker.postMessage({ type: "add", a: 1, b: 2 });
worker.on("message", (result) => {
  console.log("result:", result);
});

// worker.js
import { parentPort } from "worker_threads";
parentPort.on("message", (msg) => {
  if (msg.type === "add") {
    parentPort.postMessage(msg.a + msg.b);
  }
});
03 / DEEP READING

消息类型与判别联合

当系统有多种消息时，用判别联合（discriminated union）表示不同消息种类。每个变体共享一个 type 字段作为判别符，TypeScript 编译器能据此收窄类型。

type WorkerMessage =
  | { type: "add"; a: number; b: number }
  | { type: "multiply"; a: number; b: number }
  | { type: "shutdown" };

function handle(msg: WorkerMessage): number | void {
  switch (msg.type) {
    case "add":      return msg.a + msg.b;
    case "multiply": return msg.a * msg.b;
    case "shutdown": return;
  }
}
04 / DEEP READING

接收消息

Worker 通过事件监听器接收消息：parentPort.on('message', callback)。回调在消息到达时由事件循环调用——这是异步回调的典型应用。

注意：消息处理是异步的，多个消息可能排队等待处理。如果处理顺序很重要，需要在应用层保证。

05 / DEEP READING

停止：毒丸消息

如何优雅地停止一个 Worker？使用毒丸消息（poison pill）：一种特殊的消息，告诉 Worker 完成当前工作后退出。

// 主线程发送毒丸
worker.postMessage({ type: "shutdown" });

// Worker 处理毒丸
parentPort.on("message", (msg) => {
  if (msg.type === "shutdown") {
    parentPort.close();  // 退出 Worker
  }
});

毒丸消息是消息传递系统中的常见模式：不强制杀死进程，而是让 Worker 自愿、有序地退出。

FIELD TRACE

把毒丸消息想成"打烊通知"：店主（主线程）告诉店员（Worker）"这是最后一单，做完关门"。店员做完手头工作后关门，而不是立刻放下手中的活。这保证了系统状态的一致性。

06 / DEEP READING

消息传递与竞态条件

消息传递不能消除竞态条件。当多个客户端同时向服务器发送请求时，消息到达的顺序可能影响结果。例如两个用户同时预订最后一个座位，谁的消息先到服务器，谁就订到了。

消息传递让竞态更可控（因为状态不共享），但正确性仍取决于消息处理的逻辑。

07 / DERIVATION

客户端/服务器设计模式

网络编程的核心模式是客户端/服务器（client/server）：

  • 客户端（client）：发送请求（request）
  • 服务器（server）：接收请求，处理后发送回复（reply）

这个模式是 Web、数据库、文件共享等几乎所有网络服务的基础。理解它，就能理解网络编程的本质。

08 / DEEP READING

网络基础：IP、主机名、端口

网络通信依赖三个概念：

  • IP 地址（IP address）：32 位数字（IPv4），唯一标识网络上的主机，如 192.168.1.1
  • 主机名（hostname）：人类可读的名字，如 web.mit.edu，通过 DNS 翻译成 IP 地址
  • 端口号（port number）：16 位数字，把流量导向主机上的特定进程，如 HTTP 用 80，HTTPS 用 443

IP 地址找到主机，端口号找到进程——两者结合才能把消息送到正确的应用。

09 / DEEP READING

Web API 与 HTTP

HTTP（HyperText Transfer Protocol）是万维网的语言。一个 HTTP 请求包含：

  • 路径（path）：如 /api/users/1
  • 查询参数（query parameters）：如 ?page=2
  • 请求体（body）：POST 请求携带的数据
  • 方法：GET（无 body，获取资源）和 POST（有 body，提交数据）

服务器返回状态码（status code）和回复体（通常 JSON）：

  • 200：成功
  • 404：未找到
  • 500：服务器内部错误
10 / DEEP READING

TypeScript Web 服务器

用 Express 创建路由处理 HTTP 请求：

import express from "express";
const app = express();

// GET /api/users/1
app.get("/api/users/:id", async (req, res) => {
  const id = Number(req.params.id);
  const user = await fetchUser(id);
  if (user) {
    res.status(200).json(user);
  } else {
    res.status(404).json({ error: "not found" });
  }
});

app.listen(3000, () => {
  console.log("server running on port 3000");
});

Express 把 HTTP 路由映射到处理函数，处理函数接收请求、返回响应。这是客户端/服务器模式的具体实现。

# Reading 18: Message-Passing and Networking

[6.102 — Software Construction](http://web.mit.edu/6.102/www/sp26/)
Spring 2026

## Objectives

- Use message passing between TypeScript workers
- Understand client/server communication over the network

## Two models for concurrency

**Shared memory**: concurrent modules interact by reading/writing
shared mutable objects.

**Message passing**: concurrent modules interact by sending
immutable messages.

## Message passing between workers

Using Node's `worker_threads` interface with `postMessage` and `parentPort`.

### Message types

Use discriminated unions for different message kinds.

### Receiving messages

Provide an event listener with `parentPort.on('message', callback)`.

## Stopping

Use a *poison pill* message to signal shutdown.

## Race conditions

Message-passing doesn't eliminate race conditions.

## Client/server design pattern

Clients send requests; servers send replies.

## Networking basics

- **IP addresses**: 32-bit numbers (IPv4)
- **Hostnames**: names translated to IP addresses via DNS
- **Port numbers**: 16-bit numbers directing traffic to processes

## Web APIs

HTTP is the language of the World Wide Web.

### Routes, Parameters, Results

- Path components, Query parameters, Body parameters
- GET (no body) and POST (with body) requests
- Status codes and reply bodies (often JSON)

## Web server in TypeScript

Using Express to create routes with `app.get()`.

## Summary

- Message passing avoids bugs of synchronizing shared mutable data
- Client/server design pattern for network communication
