01 / PROBLEM

Promise：表示尚未完成的计算

Promise 表示一个已经启动、但结果可能尚未准备好的并发计算。Promise<T> 是一个可变值（注意：这里的可变指状态变迁，不是指 Promise 对象本身被替换），有三种状态：

  • pending：计算还在进行中
  • fulfilled：计算成功完成，附带一个 T 类型的值
  • rejected：计算失败，附带一个错误

Promise 一旦从 pending 变为 fulfilled 或 rejected，就不可再变——这正是"承诺"的含义：它最终会给出一个确定的交代。

FIELD TRACE

把 Promise 想成一张"取餐小票"：你点了餐（启动计算），拿到小票（Promise），此时餐还没好（pending）。等到厨房做好，小票对应的餐就确定了（fulfilled），或者卖完了（rejected）。小票本身不会再变成另一份餐。

02 / DEEP READING

await：把 Promise<T> 变成 T

await 关键字把一个 Promise<T>类型的值"解开"成 T。如果 Promise 已经 fulfilled，await 立即返回其值；如果还在 pending，await 会让出控制权，等 Promise 就绪后再恢复执行。

async function fetchUser(id: number): Promise<User> {
  const response = await fetch(`/api/users/${id}`);
  // await 让出控制权，等 fetch 的 Promise 完成
  const user: User = await response.json();
  return user;  // 返回值被包装成 Promise<User>
}

await 只能在 async 函数内部使用。它的本质是"在这里暂停，等结果就绪后继续"。

03 / DEEP READING

异步函数

异步函数（asynchronous function）用 async 声明，它在计算完成前就把控制权交还给调用者。异步函数的返回值自动被包装成 Promise：

async function greet(): Promise<string> {
  return "hello";
}
// greet() 返回 Promise<string>，不是 string

异步函数让异步代码看起来像同步代码——这是 async/await 最大的价值。但要注意：异步函数的"同步外表"下仍然是异步执行，调用者必须 await 才能拿到结果。

04 / DEEP READING

JavaScript 的并发模型：单线程

JavaScript 在每个全局环境中只有一条控制线程。这意味着同一时刻只有一个函数在执行。await 是唯一让出控制权的机制——当函数 await 一个 Promise 时，其他等待中的任务（定时器回调、事件处理等）才有机会执行。

这个模型消除了共享内存的竞态条件（因为同一时刻只有一个函数在跑），但也意味着：长时间同步计算会阻塞整个线程。所以异步函数不应包含耗时的同步操作。

05 / DERIVATION

聚合 Promise

实际程序常常需要同时处理多个 Promise。三个聚合方法对应三种逻辑组合：

  • Promise.all(promises)：等待所有 Promise 完成（逻辑 AND）。任一失败则整体失败。
  • Promise.any(promises)：等待任一 Promise fulfill（逻辑 OR）。全部失败则整体失败。
  • Promise.race(promises)：等待任一 Promise fulfill 或 reject（最先出结果的）。
// 同时请求多个资源，等全部完成
const [user, posts] = await Promise.all([
  fetchUser(1),
  fetchPosts(1)
]);

// 哪个快用哪个
const fastest = await Promise.race([
  fetchFromCache(key),
  fetchFromServer(key)
]);
FIELD TRACE

把 Promise.all/any/race 想成"多人竞赛"的裁判：all 等所有人冲线（有人摔倒就全体失败），any 等第一个冲线（全部摔倒才失败），race 等第一个发生的结果（无论冲线还是摔倒）。根据业务语义选裁判。

06 / DEEP READING

永远不要忙等待

Promise 没有任何方法可以查询当前状态（没有 isPending()、getValue() 等）。你不能写这样的代码：

// 错误示范：试图忙等待
while (promise.isPending()) { /* 循环检查 */ }
const value = promise.getValue();

正确的做法永远是用 await 或 .then(callback)。这保证了单线程模型不被阻塞，也避免了竞态条件。

07 / DEEP READING

Promise 与异常处理

Promise 的异常处理遵循两条规则：

  • 当 async 函数抛出异常时，返回的 Promise 变为 rejected
  • 对 rejected 的 Promise 执行 await 会抛出该异常
async function risky(): Promise<string> {
  throw new Error("boom");  // Promise 变为 rejected
}

async function caller() {
  try {
    await risky();           // 这里会抛出 "boom"
  } catch (e) {
    console.log("caught:", e);
  }
}

这使得 try/catch 能像处理同步异常一样处理异步异常，大幅简化异步代码的错误处理。

# Reading 15: Promises

[6.102 — Software Construction](http://web.mit.edu/6.102/www/sp26/)
Spring 2026

## Objectives

This reading discusses concurrent computation using *promises*.

## Promises

A *promise* represents a concurrent computation that has been started
but whose result may not be ready yet.

A `Promise<T>` is a mutable value with three states:
*pending*, *fulfilled*, *rejected*.

## Await

The `await` keyword converts a value of type `Promise<T>`
into a value of type `T`.

## Asynchronous functions

An *asynchronous function* returns control to its caller before its
computation is done, declared with `async`.

## Concurrency model

JavaScript has only one thread of control per global environment.
`await` gives up control.

## Aggregating promises

- `Promise.all()`: waits for all promises (logical AND)
- `Promise.any()`: waits for any promise to fulfill (logical OR)
- `Promise.race()`: waits for any promise to fulfill or reject

## Never busy-wait

There is no method to interrogate a promise's state. Use `await`.

## Promises and exception handling

- When an `async` function throws, the promise becomes *rejected*.
- `await` on a rejected promise throws the exception.

## Summary

- A promise is a concurrent computation that might still be unfinished.
- `await` waits for and accesses the value.
- `Promise.all()`, `Promise.any()`, `Promise.race()` aggregate promises.
- Functions that return a promise are *asynchronous*.
