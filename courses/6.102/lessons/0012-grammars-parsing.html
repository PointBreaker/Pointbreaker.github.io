01 / PROBLEM

文法：产生式、非终结符与终结符

文法（grammar）定义一个字符串集合。它由一组产生式（production）组成，每个产生式把一个非终结符（nonterminal）展开为终结符和非终结符的组合。终结符（terminal）是字母表中的实际字符或 token，不能再展开。

例如，一个简单算术表达式的文法：

expr   = number '+' number
       | number '-' number
       | number
number = digit number
       | digit
digit  = '0' | '1' | ... | '9'

这里 expr、number、digit 是非终结符，'0'...'9'、'+'、'-' 是终结符。文法的起点通常是某个指定的非终结符（如 expr）。

FIELD TRACE

把文法想象成一组重写规则：从起始非终结符出发，反复用产生式替换非终结符，直到串中只有终结符。所有能这样得到的终结符串就是该文法描述的语言。读产生式时注意"能生成什么"，而不是"怎么生成"——文法只定义集合，不规定解析顺序。

02 / DEEP READING

文法运算符：重复、连接、联合

文法中常用的运算符让书写更紧凑：

  • 重复 *：前面的符号出现零次或多次
  • 连接（concatenation，用空格表示）：两个符号依次出现
  • 联合 |：取其一

此外还有：?（零次或一次）、+（一次或多次）、{n}（恰好 n 次）、[...]（字符类）、[^...]（否定字符类）。

// 用运算符重写 number 的产生式
number = digit+        // 一个或多个 digit
digit  = [0-9]         // 单个数字字符

这些运算符本质上都是产生式的语法糖，但能让文法更接近我们描述语言时的直觉。

03 / DEEP READING

解析树

把文法应用于一个具体字符串，若该字符串属于文法描述的语言，就得到一棵解析树（parse tree，也叫具体语法树 concrete syntax tree）。树的内部节点是非终结符，叶子是终结符，每个内部节点的子节点对应一次产生式展开。

解析树记录了"这个字符串是怎样由文法生成的"。同一文法可能对同一字符串生成多棵不同的解析树（歧义文法），这是语言设计中要尽量避免的。

04 / DEEP READING

正则表达式：正则文法的紧凑形式

正则表达式（regular expression）是正则文法（regular grammar）的紧凑记法。它描述的语言可以用有限自动机识别。正则表达式在 6.102 中广泛用于词法分析（tokenization）和模式匹配。

需要注意的是，正则表达式不能描述所有文法——例如它无法匹配任意深度的嵌套括号，因为那需要更强的表达能力。

05 / DEEP READING

上下文无关文法

能用文法描述的语言称为上下文无关语言（context-free language），对应的文法是上下文无关文法（context-free grammar, CFG）。CFG 的产生式左侧必须是单个非终结符，右侧可以是任意终结符/非终结符串。

大多数编程语言的语法都用 CFG 描述。6.102 使用的 ParserLib 处理的正是这类文法。

06 / DERIVATION

解析器生成器与 ParserLib

解析器生成器（parser generator）接受一个文法，自动生成一个解析器（parser）。6.102 使用 ParserLib。

使用流程分两步：

  1. 生成解析器：把文法字符串编译成 Parser 对象
  2. 构造 AST：用 Parser 解析输入字符串，得到解析树，再转换为抽象语法树
import { Grammar, Parser } from "parserlib";

// 定义文法
const grammar: Grammar = Grammar.fromGrammar(`
  expr = number '+' number | number ;
  number = digit+ ;
  digit = [0-9] ;
`);

// 生成解析器
const parser: Parser = grammar.parser();

// 解析字符串
const parseTree = parser.parse("12+34");
FIELD TRACE

把解析过程想成两步流水线：文法 → Parser（一次性编译），Parser → parse tree（每次输入）。文法是"语言的定义"，Parser 是"识别该语言的机器"，parse tree 是"一次具体识别的记录"。三者不要混淆。

07 / DEEP READING

从解析树到抽象语法树

解析树包含大量文法细节（每个非终结符、每个运算符都变成节点），对后续处理并不方便。我们需要把它翻译成抽象语法树（abstract syntax tree, AST）——一种递归数据类型，只保留程序的结构含义。

例如 "12+34" 的解析树会有 expr → number '+' number、number → digit digit 等多层节点；而 AST 可能只是一个 BinaryExpr(left=12, op=+, right=34)。AST 正是第 11 讲递归数据类型与解释器模式的用武之地。

// AST 的递归数据类型定义（简化）
type Expr = NumberLiteral(value: number)
          | BinaryExpr(left: Expr, op: string, right: Expr);

// 把 parse tree 翻译成 AST

08 / DEEP READING

错误处理

文法本身的语法错误（如产生式写错）和无法解析的输入字符串都会让 ParserLib 抛出 ParseError。健壮的解析器需要捕获这些错误，并向用户报告有意义的提示（出错位置、期望的 token 等）。

设计文法时，应尽量让常见错误能产生清晰的 ParseError，而不是静默接受错误输入或给出误导性的 AST。

09 / DEEP READING

左递归与 ParserLib 限制

ParserLib 生成的是自顶向下递归下降解析器（top-down recursive descent parser）。这种解析器有一个重要限制：左递归（left recursion）会导致无限循环。

左递归指产生式右侧的第一个符号就是产生式左侧的非终结符，例如：

expr = expr '+' number | number;  // 左递归！

递归下降解析器处理 expr 时会先调用 expr，于是无限递归。解决办法是把左递归改写为右递归或使用重复运算符：

expr = number ('+' number)*;  // 等价但无左递归
FIELD TRACE

每次写 ParserLib 文法时，先扫描一遍所有产生式，检查是否有左递归。左递归是自顶向下解析器的经典陷阱，改写为右递归或重复运算符是标准做法。记住：递归下降 = 从左到右展开，左递归 = 展开的第一步就回到自身。

误区

解析树和抽象语法树是一回事。

解析树记录文法展开的每个细节（具体语法树），AST 只保留结构含义。AST 是递归数据类型，便于后续解释、求值与变换。

误区

正则表达式能描述所有文法。

正则表达式只能描述正则语言，无法处理任意嵌套结构。CFG 的表达能力更强。

# Reading 12: Grammars & Parsing

## Objectives

- Understand grammars and regular expressions
- Read and write grammars
- Use a grammar with a parser generator
- Convert a parse tree into a useful data type

## Grammars

A *grammar* defines a set of strings with productions, nonterminals,
terminals, and operators.

### Grammar operators

- Repetition (`*`), Concatenation (space), Union (`|`)
- Additional: `?`, `+`, `{n}`, `[...]`, `[^...]`

## Parse trees

Matching a grammar against a string generates a **parse tree**.

## Regular expressions

A **regular expression** is a compact form of a regular grammar.

## Context-free grammars

Languages expressible with grammars are **context-free**.

## Parser generators

A **parser generator** takes a grammar and generates a **parser**.

6.102 uses [ParserLib](https://web.mit.edu/6.102/www/parserlib/4.0.2/typedoc/).

### Generating the parser

Compile a grammar string into a Parser.

### Constructing an abstract syntax tree

Translate a **parse tree** (concrete syntax tree) into an
**abstract syntax tree** (AST).

## Handling errors

Grammar syntax errors and unparseable strings throw `ParseError`.

## Left recursion and other ParserLib limitations

ParserLib generates a top-down recursive descent parser.
Left recursion causes infinite loops.

## Summary

- **Grammars**: productions, operators
- **Parse trees**: diagramming string matches
- **Regular expressions**: compact form of regular grammars
- **Parser generators**: automate parsing with grammars
