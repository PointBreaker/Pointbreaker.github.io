01 / PROBLEM

一等函数：函数作为数据值

函数式编程的起点是一等函数（first-class functions）：函数可以像普通数据值一样，被存入变量、作为参数传递给其他函数、以及动态创建。当语言把函数提升到一等地位，我们就能把“一段计算”当作值来组合，从而抽象掉大量重复的控制模式。

一等函数让“行为参数化”成为可能。例如排序不再写死比较逻辑，而是接受一个比较函数作为参数；事件处理不再写巨大的分支，而是注册一个回调函数。这种抽象能力是 map/filter/reduce 等更高层抽象的基础。

FIELD TRACE

判断一门语言是否把函数当作一等值，看三条：能赋给变量吗？能作参数吗？能在运行时创建并返回吗？TypeScript 三条都满足。

02 / DEEP READING

TypeScript 中的函数表达式

TypeScript 提供两种主要写法来创建函数值：

  • 箭头函数（arrow function）：(x) => x + 1，简洁、词法绑定 this。
  • 函数表达式（function expression）：function(x) { return x + 1; }，拥有自己的 this 与 arguments。

两者都能产生函数值，但在本课的函数式风格中，箭头函数更常见：它鼓励写短小的、返回新值的表达式，而不是长过程体。

const add = (a: number, b: number) => a + b;
const isEven = (n: number) => n % 2 === 0;
const square = (n: number) => n * n;
03 / DEEP READING

抽象掉控制：map/filter/reduce

写循环时，真正关心的通常不是“如何遍历”，而是“对每个元素做什么”。map / filter / reduce 把“做什么”从“如何遍历”中分离出来，让我们用声明式的方式操作序列，而不写显式的 for/while 控制语句。

这是本课“抽象”主题的又一次体现：控制流细节被框架隐藏，程序员只描述意图。下一节先看序列如何被逐个访问——迭代器。

04 / DEEP READING

迭代器：逐个走过序列

迭代器（iterator） 是一个对象，它逐个走过一个序列的元素，每次返回一个。迭代器把“如何遍历某个具体数据结构”封装起来，对外只暴露“还有下一个吗？下一个是什么？”的统一接口。

迭代器是 map/filter/reduce 的底层机制之一：这些高阶函数接受可迭代对象，按迭代器协议依次访问元素。理解迭代器，就能理解 for...of 循环和展开运算符 ... 的工作原理。

05 / DEEP READING

生成器函数与 yield

生成器函数（generator function） 是用 function* 定义的特殊函数，通过 yield 语句每次产生一个元素。调用生成器函数不会立即执行函数体，而是返回一个生成器对象；每次请求下一个值时，函数体执行到下一个 yield 再暂停。

生成器让“描述一个序列”变得极其自然：不必一次性把整个序列放进数组，而是按需产生元素。这对无限序列或大序列尤其有价值。

function* naturals(): Generator<number> {
  let n = 0;
  while (true) { yield n++; }
}
const it = naturals();
it.next(); // { value: 0, done: false }
it.next(); // { value: 1, done: false }
06 / DERIVATION

Map / Filter / Reduce 抽象

三个高阶函数各承担一种职责，组合起来几乎能表达任意序列变换：

  • Map：对每个元素应用一元函数，返回等长的新序列。map(f) 把“逐个变换”抽象掉。
  • Filter：用谓词测试每个元素，保留使谓词为真的元素。filter(p) 把“按条件筛选”抽象掉。
  • Reduce：用二元函数从左到右把序列归约为单个值。reduce(f, init) 把“累积计算”抽象掉。

三者都只依赖生产者和观察者，不修改原序列——这正是函数式风格与不可变性的天然契合。

const nums = [1, 2, 3, 4, 5];
const sumOfEvenSquares = nums
  .filter(n => n % 2 === 0)   // [2, 4]
  .map(n => n * n)            // [4, 16]
  .reduce((a, b) => a + b, 0); // 20
07 / DEEP READING

抽象掉控制的好处

用 map/filter/reduce 替代显式循环，通常能让代码更短、更易读、更易于推理：

  • 意图更清晰：filter 直接说“筛选”，不必暴露下标与临时数组。
  • 减少状态：显式循环常常依赖可变累加变量；reduce 把累积过程封装成纯函数。
  • 可组合：每个高阶函数返回新序列，可以链式组合，像搭积木一样构造复杂变换。

这不是说循环永远不该写，而是说：当你能用 map/filter/reduce 表达时，优先用它们，把控制细节留给运行时。

08 / DEEP READING

在 TypeScript 中避免显式循环

惯用（idiomatic）的 TypeScript 倾向于用 map 和 filter 替代 for 循环处理数组。这不仅是风格问题：它强制你以“输入 → 输出”的函数式视角思考，减少可变状态带来的意外。

当然，复杂到难以用单个链式调用表达的流程，仍可用循环或递归清晰表达。函数式风格是工具箱里的一件利器，而不是非用不可的教条。

10 / CALIBRATION

把直觉校准成函数式思维

误区

函数式编程就是不用循环。

函数式编程的核心是“用不可变数据与纯函数建模”；避免显式循环是结果，不是目的。复杂流程仍可用循环或递归清晰表达。

误区

map/filter/reduce 一定比循环快。

它们的主要收益是清晰、可组合、少状态，而不是性能。在性能关键路径上，仍需根据实际测量做选择。

# Reading 10: Functional Programming

## Objectives

- Iterators and generators
- Map/filter/reduce
- Higher-order functions
- Immutability

## First-class functions

Functions as *first-class* data values, meaning they can be stored in variables, passed as arguments, and created dynamically.

## Function expressions in TypeScript

Arrow syntax and `function` expressions.

## Abstracting out control

Map/filter/reduce enables operating on sequences with no explicit control statements.

## Iterator

An **iterator** is an object that steps through a sequence of elements and returns them one at a time.

## Generator functions in TypeScript

A generator function produces each element using the `yield` statement.

## Map/filter/reduce abstraction

- **Map** applies a unary function to each element.
- **Filter** tests each element with a predicate.
- **Reduce** combines elements using a binary function.

## Benefits of abstracting out control

Map/filter/reduce can often make code shorter and simpler.

## Avoiding loops in TypeScript

Idiomatic TypeScript uses `map` and `filter` to avoid loops.

## Summary

Functional programming: modeling problems with *immutable data* and *pure functions*.
