PS1 · Specific Graphics

特定图形：测试驱动开发与规格说明

本作业旨在练习测试驱动编程（test-first programming）与规格说明。学生需为规格编写单元测试、实现满足规格的代码、强化现有规格，并自行编写、测试与实现规格。

关键要求与截止时间

作业PS1

  • 按测试驱动流程（规格 → 测试 → 实现）完成 7 个步骤
  • 禁止修改 lerp.ts、colors.ts、curves.ts 中的函数签名与导出
  • 不得削弱 curves.ts 中导出函数的规格（仅允许强化）
  • 使用 assertApproxEqual 进行浮点比较，容差 0.001
  • 评分比例：Alpha 自动 ~30% + Alpha 手动 ~20% + Beta 自动 ~25% + Beta 手动 ~25%

概述

主题覆盖

  • RGB 颜色：颜色插值、渐变填充、调色板生成
  • 贝塞尔曲线：求单点和多点
  • 线性插值（lerp）：一维、三维颜色空间、二维欧几里得空间
  • 缓动函数：控制插值位置
  • 动画：线性与缓动运动动画

示例动画

  • "alley-oop"：一秒循环动画，贝塞尔定义的圆沿曲线平移，使用缓动函数 4·(t - ½)³ + ½，RGB 颜色从 (128,128,128) 过渡到 (173,255,47)。
  • "rainbow connection"：两秒循环动画，由两条贝塞尔曲线构成的心形，通过一维贝塞尔缓动函数揭示，配彩虹渐变。

起步

  1. 在 Didit 上创建远程 psets/ps1 仓库。
  2. 使用 Didit 分配的 git clone 命令克隆仓库。
  3. cd ps1-«username»，运行 npm install，在 VS Code 中打开。

测试驱动工作流程（规格 → 测试 → 实现）

步骤 0：通读全文

首先完整阅读整个作业文档。

步骤 1：阅读已有规格

类型别名：Color 与 Point

已提供规格的函数：

  • lerp(..) — 两数之间的线性插值
  • lerpColor(..) — RGB 颜色之间的线性插值
  • fillGradient(..) — 填充颜色间的渐变
  • makePalette(..) — 通过改变色相生成调色板
  • interpolate(..) — 带缓动函数的线性插值
  • bezierPath(..) — 求贝塞尔曲线上的点
  • bezierInterpolate(..) — bezierPath 的辅助函数

步骤 2：lerp 与 lerpColor

  1. 在 src/lerp.ts 中为 lerpWeak(..) 编写弱规格：可理解、适合实现 lerpColor，且"尽可能弱"。
  2. 在 test/lerp.test.ts 中测试 lerpWeak — 保持测试套件极小。
  3. 实现 lerpWeak，审查质量。
  4. 在 test/colors.test.ts 中测试 lerpColor — 不可修改其规格；测试针对其他实现运行。
  5. 在 src/colors.ts 中通过调用 lerp（使用 lerpWeak 规格）实现 lerpColor。

Didit 签到：预期 lerpColor 测试针对损坏的职工实现和示例测试通过。

步骤 3：fillGradient

  1. 在 test/colors.test.ts 中编写 fillGradient 测试。
  2. 实现 fillGradient。

步骤 4：makePalette

  1. 编写 makePalette 测试（注意 utils.ts 提供了 hslToRgb 与 rgbToHsl）。
  2. 实现 makePalette。

步骤 5：lerp（再次）与 interpolate

  1. 写一句话解释：为何使用 lerpWeak 规格的 lerp 无法实现 interpolate。
  2. 编写强规格 lerpStrong，适用于所有使用 lerp 的地方以及 interpolate。
  3. 分析 lerpWeak 与 lerpStrong 的关系。
  4. 测试 lerpStrong。
  5. 实现 lerpStrong。
  6. 更新 export const lerp = lerpWeak 为使用 lerpStrong。
  7. 测试 interpolate。
  8. 通过调用 lerp（现使用强规格）实现 interpolate。

步骤 6：bezierInterpolate 与 bezierPath

  1. 强化 src/curves.ts 中的规格（仅可比提供的更强），然后在 test/curves.test.ts 中测试：
    • bezierInterpolate：强化，重命名 renameMe，削弱前置条件，确定后置条件
    • bezierPath：强化，使用联合类型重命名 renameMe，强化后置条件
  2. 实现两个函数。

步骤 7：动画

  1. 审查 lib/animate.ts 中 animateToFile(..) 的规格。
  2. 为 src/toolbox.ts 中创建动画的最多三个函数起草规格。
  3. 在 test/toolbox.test.ts 中编写测试。
  4. 实现函数。
  5. 使用 toolbox 实现 handoutExampleOne(..) 与 handoutExampleTwo(..) — 无需测试。

可修改与不可修改的内容

禁止操作

  • 修改已提供的文件/文件夹名称
  • 修改 lerp.ts 中的函数签名
  • 修改 colors.ts 中导出函数的签名与规格
  • 削弱 curves.ts 中导出函数的规格（仅允许强化）
  • 从 lerp.ts、colors.ts、curves.ts 导出新内容
  • 包含非法测试用例（必须遵守规格）

允许操作

可自由添加新的函数和类。

规格说明要点

  • 部分规格有前置条件——违反时行为完全未指定。
  • 部分规格有欠确定后置条件——允许一定范围的行为。
  • 导出函数是独立模块，必须处理所有合法输入。

浮点约定

  • 整数 number 值假定安全（在 MIN_SAFE_INTEGER 与 MAX_SAFE_INTEGER 之间）。
  • 非整数 number 计算允许误差至多容差 = 0.001。
  • 不得使用其他浮点等价定义。
  • 测试中使用 utils.ts 的 assertApproxEqual。

测试建议

  • 划分输入/输出，在测试套件顶部注释中记录策略。
  • 测试用例应小而有针对性。
  • 测试应发现 bug——考虑实现可能失败的方式。
  • 测试必须是规格的合法客户端——不做额外假设。
  • 每个测试用例放在独立的 it() 函数中。
  • 使用 npm run coverage 运行覆盖率。
  • 不要在测试中调用 src/ 的新辅助函数（测试针对职工实现运行）。
  • 对不可变值使用 strictEqual；对数据结构使用 deepStrictEqual。
  • 频繁提交/推送。

实现建议

  • 小辅助函数：放在实现文件中；不从 lerp.ts/colors.ts/curves.ts 导出；必须保持小巧。
  • 较大辅助函数：放在 utils.ts；在 utils.test.ts 中测试。
  • 消除 TypeScript 与 ESLint 警告。
  • 进行玻璃盒测试以提高覆盖率。
  • 审查代码是否做到 SFB、ETU、RFC。
  • 使用 npm test -- -f 'pattern' 调试单个测试。

设计你的 Toolbox

  • 识别两个示例都需要的计算或动画中频繁出现的部分。
  • 保持 toolbox 小巧（最多三个新函数）。
  • 可从 utils.ts 导入/重导出（不重复测试）。
  • 规格应安全免于缺陷、易于理解、随时可变。
  • 检查前置条件，无法静态检查时快速失败。

评分构成

  • Alpha 自动评分：~30%
  • Alpha 手动评分：~20%
  • Beta 自动评分：~25%
  • Beta 手动评分：~25%

Alpha 更强调测试；Beta 平衡测试与实现。手动评分审查规格、解释、测试、实现与 Git 历史。
