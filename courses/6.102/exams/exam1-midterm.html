期中考试：固定大小缓冲区与抽象数据类型

80 分钟，5 道题。考察固定大小缓冲区的实现、表示不变量、抽象函数、规格说明、表示泄露与子类型。

考试信息

期中闭卷80 分钟5 题

  • 闭卷闭笔记，可携带一张 8.5×11″ 双面手写笔记页
  • JavaScript/TypeScript 数组类似 Python 列表，无界增长；本考试考虑固定大小缓冲区，容量在构造时设置
  • 代码中 TypeScript 的 no unchecked indexed access 选项关闭——Array<Element> 索引返回类型仍为 Element 而非 Element|undefined

背景：固定大小缓冲区

Alyssa 向 AI 索要固定大小缓冲区实现，得到 BufferA 的代码。Bobby 也向 AI 索要，得到 BufferB 的代码。两个实现非常相似：构造函数完全相同，new Array(capacity) 创建长度为 capacity 的稀疏数组，fill(undefined) 填充使其不再稀疏。BufferA 提供 addLast(..)，BufferB 提供 addFirst(..)。at(..) 与 toArray() 规格相似但代码略有不同。

BufferA 使用示例

const things = new BufferA<string>(2);
things.addLast("Thing 1");
console.log(things.at(0));    // "Thing 1"
things.addLast("Thing 2");
things.addLast("Thing 3");
console.log(things.at(0));    // "Thing 2"
console.log(things.toArray()); // ["Thing 2", "Thing 3"]

BufferB 使用示例

const things = new BufferB<string>(2);
things.addFirst("Thing 1");
console.log(things.at(0));    // "Thing 1"
things.addFirst("Thing 2");
things.addFirst("Thing 3");
console.log(things.at(0));    // "Thing 3"
console.log(things.toArray()); // ["Thing 3", "Thing 2"]

Yasmin 想要同时支持 addLast 与 addFirst 的缓冲区，开始编写 BufferY（未完成）。Ryan 的 BufferR 从 Problem 3 开始讨论。

Problem 1：规格与不变量

确保理解 BufferA、BufferB、BufferY 各自提供的抽象。回顾 ADT 由其操作定义。

Question 1.1：构造函数规格

Write an excellent spec, in TypeDoc format, that works for all three of the constructors for BufferA, BufferB, and BufferY as they are implemented.

参考答案 / Solution

/**
 * Make a new empty fixed-size buffer of the given capacity.
 * @param capacity nonnegative integer maximum number of elements
 */

解析：三个构造函数都创建一个给定容量的空缓冲区。规格需描述"创建"操作的效果与容量的前置条件。

Question 1.2：addLast 规格

Write an excellent spec, in TypeDoc format, that works for both BufferA.addLast and BufferY.addLast as they are implemented.

参考答案 / Solution

/**
 * Modify this buffer to add the given element at the end.
 * If the buffer would have more than capacity elements,
 * also removes the element at index 0.
 * @param elt the element to add
 */

解析：两个实现的 addLast 都在末尾添加元素；若超出容量则移除索引 0 处（最旧）元素。规格需捕获此溢出行为。

Question 1.3：BufferA 的 RI 与 AF

Write an excellent rep invariant and abstraction function for BufferA. Write them clearly as functions RI(…) = … and AF(…) = ….

参考答案 / Solution

Rep invariant:

RI(capacity, count, buff) = capacity is a nonnegative integer
    and count is a nonnegative integer
    and buff.length = capacity
    and buff[i] != undefined for all 0 <= i < min(count, capacity)

Abstraction function:

AF(capacity, count, buff) = the fixed-size buffer of capacity capacity
    that contains min(count, capacity) elements, where the element at index i
    is buff[(max(count, capacity) + i) % capacity]

解析：RI 保证容量和计数字段为非负整数，缓冲数组长度等于容量，且有效索引范围内无 undefined。AF 将表示映射到抽象的固定大小缓冲区，使用模运算处理循环缓冲区的索引。

Question 1.4：BufferB 的 RI 与 AF 比较

Will the rep invariant and the abstraction function for BufferB be identical, or will one or both be different?

参考答案 / Solution

  • RI for BufferB is identical to the RI for BufferA — 两者表示结构完全相同（capacity, count, buff 数组）。
  • AF for BufferB is different — 对于表示值 R 代表的抽象缓冲区 A，同一表示值 R 在 BufferB 中代表元素顺序相反的缓冲区。

解析：BufferB 使用 addFirst，元素以相反顺序存储，故 AF 反映逆序映射。

Problem 2：完成 BufferY 实现

Complete the implementation of BufferY with straightforward, readable code that assumes no unchecked indexed access is on.

Question 2.1：实现 at() 与 toArray()

public at(idx: number): Element {
    // TODO
}
public toArray(): Array<Element> {
    // TODO
}

参考答案 / Solution

public at(idx: number): Element {
    if (idx < 0 || idx >= this.buff.length) {
        throw new Error();
    }
    return this.buff[idx] ?? assert.fail();
}
public toArray(): Array<Element> {
    return this.buff.slice();
}

解析：at() 检查索引边界，返回对应元素（使用 ?? assert.fail() 处理可能的 undefined）。toArray() 返回数组副本。

Question 2.2：BufferY 的表示泄露安全性论证

Write an excellent safety from rep exposure argument for BufferY.

参考答案 / Solution

The rep fields are capacity and buff:

  • capacity is unreassignable and immutable
  • buff is unreassignable
  • buff is of mutable type Array, the only operation to take or return an Array is toArray, where we make a copy
  • Element values in buff may be mutable, but we rely only on their object identity

解析：不可重新赋值的字段保证引用安全；数组仅在 toArray 中返回时创建副本防止外部修改；元素可变性不影响安全因为我们仅依赖对象身份。

Problem 3：BufferR 的 Bug 修复

Ryan 利用 Map 记住键值对插入顺序的特性实现 BufferR，支持 addLast 和 addFirst，且总是丢弃最旧项。代码编译运行，但 trim() 有 bug。

Question 3.1：解释 Bug

Explain the bug in one clear sentence.

参考答案 / Solution

The "return" inside the function argument to buff.forEach does not return from trim(), it only returns from that single function invocation by forEach!

解析：forEach 中的 return 仅从当前回调函数返回，不会终止 trim() 或停止 forEach 的迭代。

Question 3.2：对客户端的影响

Say what effect it will have for the clients of BufferR in another one clear sentence.

参考答案 / Solution

When the buffer is at capacity and the client adds another item, the buffer becomes empty instead.

解析：由于 forEach 遍历整个 Map 并删除所有键，缓冲区在溢出时会被清空而非仅删除最旧的一项。

Question 3.3：修复 Bug

private trim(): void {
    // TODO
}

参考答案 / Solution

private trim(): void {
    if (this.buff.size > this.capacity) {
        for (const key of this.buff.keys()) {
            this.buff.delete(key);
            return;
        }
    }
}

解析：使用 for...of 循环，return 可真正从 trim() 返回，仅删除第一个（最旧）键。

Question 3.4：完成 toArray()

Complete the BufferR implementation of toArray() in exactly one additional line of code.

    entries.sort((a, b) => a[0] - b[0]);
    // TODO - exactly one line

参考答案 / Solution

return entries.map(entry => entry[1]);

解析：将排序后的键值对映射为仅含值的数组。

Question 3.5：BufferR 的抽象函数

Write an excellent abstraction function for BufferR.

参考答案 / Solution

AF(capacity, buff) = the fixed-size buffer of capacity capacity where
    the elements are the values in the key/value pairs of buff,
    ordered by the numerical value of the keys,
    and added in the insertion order of those pairs

解析：AF 将 Map 表示映射到抽象缓冲区，按数值键排序，并保持插入顺序。

Problem 4：FixSizeBuffer 接口

Suppose BufferA, B, Y, and R all implement an interface called FixSizeBuffer. What could we include in that interface? Pick all that apply.

  • a. An overall spec stronger than any of the implementations
  • b. An overall spec weaker than any of the implementations
  • c. The RIs of the implementations
  • d. The AFs of the implementations
  • e. The SREs of the implementations
  • f. A declaration for buff
  • g. A spec for the constructor
  • h. An implementation for the constructor
  • i. Specs for addLast and addFirst
  • j. Implementations for addLast and addFirst
  • k. Specs for at and toArray
  • l. Implementations for at and toArray

参考答案 / Solution

可包含：b, g, k

  • b（更弱规格）：实现的规格必须比接口更强（而非更弱）才能成为子类型。
  • g（构造函数规格）：接口可包含构造函数规格（尽管接口无法定义构造函数本身）。
  • k（at 和 toArray 规格）：所有实现都有这两个操作。

不可包含：a, c-f, h, i, j, l

  • RI、AF、SRE 和字段声明都与特定表示相关，接口仅提供规格，不包含表示。
  • 接口不包含实现代码（构造函数实现、addLast/addFirst 实现等）。
  • 由于 BufferA 和 BufferB 分别不实现 addFirst 和 addLast，不能将这些方法包含在接口中。

Problem 5：照片帧与子类型

构建使用 FixSizeBuffer<Photo> 存储照片的电子相框。Photo 是不变接口。

Question 5.1：LivePhoto 子类型问题

根据 TypeScript 的结构子类型，LivePhoto 是 Photo 的子类型。解释为何根据规格说明它不是子类型，并提出修复方案。

参考答案 / Solution

为何不是子类型：Photo 是不变的，但 LivePhoto.show(..) 是一个变更器——它改变了 getPixels() 的返回值！

修复方案：getPixels() 始终返回静态照片。将 show(..) 替换为操作 videoFrame(frame: number)，接受帧号并返回该帧的二维像素数组。

解析：子类型要求子类型满足父类型的不变性。LivePhoto 的 show 方法引入了可变性，违反了 Photo 的不变规格。

Question 5.2：FixSizeUniqBuffer 设计

设计 FixSizeUniqBuffer<Element extends Equatable<Element>> 以确保缓冲区不含重复项。

Question 5.2a：Equatable 的用途

Explain the purpose of Equatable and its contents (lines 2–5) in one clear sentence.

参考答案 / Solution

Defines an interface for types that provide an equalValue operation allowing comparison with type Other.

解析：Equatable 定义了一组提供相等性比较操作的类型的接口。

Question 5.2b：Photo extends Equatable<Photo> 的用途

Explain the purpose in one clear sentence.

参考答案 / Solution

Photo is a subtype of Equatable<Photo> and thus must include an equalValue that takes a Photo input.

解析：所有 Photo 实现都将拥有 equalValue，使它们可与其他 Photo 值比较。

Question 5.2c：addLast 方法签名

Write the method signature of addLast as it will appear in FixSizeUniqBuffer.

参考答案 / Solution

public addLast(elt: Element): void;

解析：由于 Element 已限定为 Equatable<Element>，addLast 的参数类型为 Element。
