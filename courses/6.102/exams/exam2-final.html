Problem 1：整数差值表达式语言

Ben 设计一种整数差值表达式语言。每个表达式将一个表达式从另一个中减去，叶子为非负整数常量。

有效表达式示例：

3
(3-5)
((9-2)-3)
(9-(2-3))
(((8-4)-(3-1))-7)

语言规则：唯一运算是二元减法；叶子常量为非负整数，无前导零；每个复合表达式必须加括号；整个表达式不得有多余括号；不允许空白。

Question 1 (a)：语法

Write a grammar for this language. The root nonterminal should be diff.

参考答案 / Solution

diff ::= INT | "(" diff "-" diff ")"
INT ::= [1-9][0-9]* | 0

解析：语法以 diff 为根非终结符，递归定义二元减法表达式，叶子为无前导零的非负整数。

Question 1 (b)：递归数据类型

Define an immutable recursive data type Diff suitable for representing the AST. Write TypeScript code with no comments. Start with only toString operation.

参考答案 / Solution

type Diff = Constant | Difference;
interface Constant {
    toString(): string;
    invert(): Diff;
}
interface Difference {
    toString(): string;
    invert(): Diff;
}

解析：定义递归数据类型，包含叶子常量 Constant 和复合差值 Difference 两个变体。

Question 1 (c)：递归数据类型定义

Write a recursive data type definition for Diff.

参考答案 / Solution

Diff = Constant(value: number) + Difference(left: Diff, right: Diff)

解析：Diff 要么是包含数值的常量，要么是包含左右两个 Diff 子表达式的差值。

Question 1 (d)：invert() 操作

Implement invert() whose integer value is the negative of e's integer value. For e.toString() = (9-(2-3)), e.invert().toString() may be ((2-3)-9). Alias as many subexpressions as possible.

参考答案 / Solution

// For Difference:
public invert(): Diff {
    return new Difference(this.right, this.left);
}
// For Constant:
public invert(): Diff {
    return new Constant(-this.value);
}

解析：(a-b) 的逆为 (b-a)，只需交换左右子表达式（可共享原对象）。常量的逆为负值常量。

Question 1 (e)：invert() 创建的对象数

If e.toString() is ((1-2)-(3-4)), how many new objects are created by e.invert()?

参考答案 / Solution

Just one, a new Difference object; all the rest are shared with the original expression.

解析：invert 仅在根节点创建一个新的 Difference 对象（交换左右引用），所有子表达式均被别名共享。

Problem 2：EventLog 并发问题

EventLog 是循环事件日志，存储最近的 capacity 个事件。满时覆盖最旧事件。

EventLog 代码

export class EventLog {
    private readonly slots: Array<string>;
    private pos: number;
    private count: number;
    private readonly listeners: Array<(event: string) => void> = [];
    // ...
    public constructor(public readonly capacity: number) {
        this.slots = new Array(capacity).fill('');
        this.pos = 0;
        this.count = 0;
        this.checkRep();
    }
    public append(event: string): void {
        this.slots[this.pos] = event;
        this.pos = (this.pos + 1) % this.capacity;
        this.count++;
        for (const listener of [...this.listeners]) { listener(event); }
        this.checkRep();
    }
    public recent(): Array<string> { /* ... */ }
    public total(): number { return this.count; }
    public onAppend(listener: (event: string) => void): void { /* ... */ }
}

Question 2 (a)：RI 与 AF

Write a precise rep invariant and abstraction function.

参考答案 / Solution

Rep invariant:

RI(slots, pos, count, capacity) = slots.length = capacity
    and 0 <= pos < capacity
    and count >= 0

Abstraction function:

AF(slots, pos, count, capacity) = the sequence of min(count, capacity) most recent events,
    where the element at index i (from oldest to newest) is
    slots[(pos - min(count,capacity) + i + capacity) % capacity] if count >= capacity
    otherwise slots[i]

解析：RI 保证数组长度等于容量、写入位置在有效范围内、计数非负。AF 将循环缓冲区映射到抽象的事件序列。

Question 2 (b)：并发交错导致事件丢失

log.txt 初始存储 capacity 3 的 EventLog，recent() = ['c','d','e']，total() = 5。Worker A 追加 "x"，Worker B 追加 "y"。展示一个使 "x" 丢失的交错。

参考答案 / Solution

Bad interleaving: A1, A2, B1, B2, A3, B3.

解析：A 读取文件 → A 追加 x → B 读取文件（尚未看到 x）→ B 追加 y → A 写入 → B 写入（覆盖 A 的结果）。

结果：

  • recent() = ['d', 'e', 'y']（B 的写入覆盖了 A 的写入）
  • total() = 6（B 在 A 的结果 total=6 基础上加 1 变为 6，但注意 B 的读取基数为 5，append 后为 6）

注：根据解题，total() 返回 6。

Question 2 (d)：checkRep 是否失败？

During the interleaving, does either checkRep() at the end of append() fail? Explain.

参考答案 / Solution

No. After A2 and B2, each worker's local object satisfies the rep invariant; the lost update happens later when B3 writes an older local result over A3's result in the shared file.

解析：每个 Worker 的本地对象操作后都满足 RI。丢失更新发生在 B3 用较旧的本地结果覆盖共享文件时，而非 checkRep 检查的本地状态。

Question 2 (e)：使用消息传递修复

Complete the coordinator's message handler in at most 4 lines. Explain why this prevents the race condition.

import { parentPort } from 'node:worker_threads';
const filename = 'log.txt';
const capacity = 3;
parentPort.on('message', (msg: { event: string }) => {
    // TODO - at most 4 lines
});

参考答案 / Solution

parentPort.on('message', (msg: { event: string }) => {
    const log = readLog(filename, capacity);
    log.append(msg.event);
    writeLog(filename, log);
});

为何能防止竞争条件：The coordinator handles one message at a time, so no two read-append-write sequences on the file can interleave.

解析：单协调者顺序处理消息，消除了多个 Worker 同时读写共享文件的交错可能性。

Problem 3：回调与事件循环

Question 3 (a)：打印顺序

const log = new EventLog(3);
log.onAppend((event) => { console.log('heard ' + event); });
console.log('start');
log.append('a');
console.log('middle');
setTimeout(() => { log.append('b'); console.log('done'); }, 0);
log.append('c');
console.log('end');

参考答案 / Solution

start
heard a
middle
heard c
end
done
heard b

解析：同步代码先执行（start, heard a, middle, heard c, end），setTimeout 回调在事件循环空闲时运行（done, heard b）。

Question 3 (b)：两个监听器的打印顺序

const log = new EventLog(2);
log.onAppend((event) => { console.log('L1:' + event); });
log.append('a');
log.onAppend((event) => { console.log('L2:' + event); });
log.append('b');
log.append('c');

参考答案 / Solution

L1:a
L1:b
L2:b
L1:c
L2:c

解析：L1 在 append('a') 前注册，故接收所有三个事件。L2 在 append('a') 后注册，仅接收 'b' 和 'c'。监听器按注册顺序同步调用。

Question 3 (c)：监听器内使用 setTimeout

const log = new EventLog(2);
log.onAppend((event) => {
    console.log('heard ' + event);
    setTimeout(() => { console.log('later ' + event); }, 0);
});
log.append('a');
log.append('b');
console.log('done');

参考答案 / Solution

定时器回调运行前打印：

heard a
heard b
done

整个程序打印顺序：

heard a
heard b
done
later a
later b

解析：同步代码先执行完毕，然后事件队列中的 setTimeout 回调按 FIFO 顺序运行。

Problem 4：异步编程

Question 4 (a)：最大并发重写

function compute(): number {
    return f(g() + h()) / f(0);
}

Suppose f, g, h are changed to asynchronous. Rewrite compute to run as concurrently as possible.

参考答案 / Solution

async function compute(): Promise<number> {
    const [gh, f0] = await Promise.all([g().then(async gx => gx + await h()), f(0)]);
    return f(gh) / f0;
}

或更简洁的版本：

async function compute(): Promise<number> {
    const gPromise = g();
    const hPromise = h();
    const f0Promise = f(0);
    const sum = (await gPromise) + (await hPromise);
    return f(sum) / (await f0Promise);
}

解析：g()、h() 和 f(0) 可并发启动。g 和 h 的和计算完成后，再调用 f(sum)，同时 f(0) 已在并行计算中。

Question 4 (b)：watch() 实现

function watch<T>(func: void=>T): {
    funcWithWatch: void=>T,
    promise: Promise<T>
} {
    // TODO
}

参考答案 / Solution

function watch<T>(func: void=>T): {
    funcWithWatch: void=>T,
    promise: Promise<T>
} {
    const { promise, resolve } = Promise.withResolvers<T>();
    const funcWithWatch = (): T => {
        const result = func();
        resolve(result);
        return result;
    };
    return { funcWithWatch, promise };
}

解析：使用 Promise.withResolvers() 创建承诺和解析器。funcWithWatch 调用 func，解析承诺，并返回结果。

异常影响：

  • watch() 的调用者：funcWithWatch 在 watch 返回后才被调用，故其不受 func 抛异常的影响。
  • funcWithWatch() 的调用者：func 抛出的异常向上传播给 funcWithWatch 的调用者。
  • 承诺：承诺保持未解决状态，不会进入 rejected 状态。

Louis Reasoner 为何不能重复使用此承诺：The promise can only be resolved once.

解析：承诺一旦被解析，后续对 resolve 的调用无效，故无法通过同一承诺观察每次调用的返回值。

Problem 5：规格说明与 map

Question 5 (a)：map 的规格与 Louis 的修改

f 的规格如何约束输入数组？

参考答案 / Solution

map needs a precondition that the input array must consist entirely of values that satisfy the precondition of f.

解析：map 的规格要求输入数组的所有元素都满足 f 的前置条件。

STRONGER, because it has a weaker precondition (no more requirement on the input array), and behaves the same on all inputs that satisfy the old f's precondition.

解析：Louis 放宽了 map 的前置条件（不再要求所有元素满足 f 的前置条件），但对满足旧前置条件的输入行为不变，故规格更强。

Question 5 (b)：mapper 实现与规格变化

function mapper(f: number=>number): (arr:Array<number>)=>Array<number> {
    // TODO
}

参考答案 / Solution

function mapper(f: number=>number): (arr:Array<number>)=>Array<number> {
    return (arr: Array<number>) => arr.map(f);
}

解析：mapper 返回一个函数，该函数对输入数组应用 f。

输入数组仅限整数时各函数规格变化：

  • 传递给 mapper 的函数 f：UNCHANGED — f 不看到数组，且对 f 非法的元素已被现有规格排除。
  • mapper 返回的函数 g：WEAKER — 该函数的前置条件现在更强（要求整数输入）。
  • mapper 本身：WEAKER — 其后置条件（返回函数的规格）现在更弱。
