协作、分享与 AI 工具

根据 MIT 的学术诚信政策，以下是我们对协作和分享工作的期望。

协作

我们鼓励大家在课程中互相帮助，但对你能做的事情有限制，以确保每个人都有良好的个人学习体验。本节描述了这些限制。

下表提供了政策的简要概述，后续章节提供了更多解释和示例。

活动 是否允许？ 详情
本学期 6.102 教职员工提供的帮助 是 鼓励；有很多方式可以获得受过培训的教职员工的帮助。你可以使用教职员工提供的任何帮助（一对一、电子邮件或课程网站上的材料）。
与当前 6.102 学生的协作 视情况而定 仅鼓励高层次的讨论；禁止代码层面的交流。这条规则比较微妙，请参阅下面的完整政策。
通过 MIT 项目（如 HKN）获得的导师帮助 视情况而定 允许，规则与当前 6.102 学生之间的协作相同。请确保你的导师也已阅读并理解这些政策。
非当前 6.102 教职员工或学生的其他人的帮助 否 禁止！如果你希望从此类人员获得任何帮助，请征得讲师的许可。他们通常没有受过如何有效帮助的培训，可能会真正"替你完成大部分工作"。
查阅非自己编写的代码 视情况而定 如果代码是在 6.102（或其前身 6.031）的背景下编写的，则禁止，本学期教职员工分发的代码除外。使用的任何外部代码必须在你的解答中正确注明出处。
分享你编写的代码 否 以任何格式禁止，包括通过 GitHub 或 GitLab 等公共代码仓库。
使用生成式 AI 工具编写文本或代码 否 禁止。

个人作业

本课程的习题集主要要求个人独立完成。

你不得使用其他学生创作的课程作业材料，无论是本学期还是之前学期的，也不得为其他学生提供作业供其使用。

我们鼓励你与其他学生讨论方法，但这些讨论不得以书面或口头形式涉及逐步的、算法式的指令，你的代码和报告必须是你自己完成的。 字面的代码是学生之间不允许的交流形式中最明显的例子，但该政策也禁止用"伪代码"进行交流，伪代码混合了编程语法和更模糊的自然语言片段。伪代码暴露了太多我们希望你在每次作业中自己摸索的算法构思。 这也适用于我们在 6.102 中撰写的各类文档，包括测试策略、规格说明、抽象函数、表示不变量和数据类型定义。 一个结果是，在一组协作或互相帮助的学生中，任何人都不得查看任何为 6.102（或其前身 6.031）编写的代码（包括伪代码和文档）。

帮助他人时请始终合上你的笔记本电脑。 帮助其他学生是件好事。 但作为一般规则，在你帮助另一名学生的期间，你自己的解答不应让你或他们看到。 养成在帮助时关闭代码的习惯。

不要从代码审查中抄袭。 在代码审查期间，你会看到同学对习题集的解答。 虽然可以从他们的方法中获取灵感，但不要抄袭他们的作品。

所有外部代码片段均需注明公共来源。 虽然可以使用来自 StackOverflow 等外部公共来源的短代码片段，但你必须提供适当的出处标注。

外部代码不得解决作业的明确部分。 特别是，如果作业要求"实现 X"，那么你必须创建自己的 X，而不是重用外部来源或库中的。

禁止自动生成代码。 你不得使用由高级代码编写工具生成的代码或文本，例如 Claude Code、Cursor、GitHub Copilot 或其他生成式 AI 工具或聊天机器人，例如 ChatGPT。 如果你不确定某个代码生成工具是否适合在 6.102 中使用，请在使用前向我们咨询。

使用本学期教职员工的代码无需注明出处。 使用本学期 6.102 教职员工提供的任何代码（在课堂、阅读材料、习题集或项目中）都是可以的，无需注明出处。 然而，教职员工提供的代码未经许可不得公开分享，这将在本文档后面讨论。

不得使用额外库。使用 JavaScript 或 TypeScript 内置的任何内容或 Node 标准库中包含的内容是可以的。 （以前的课程如 6.101 [原 6.009] 有时会限制从标准库导入；6.102 没有此限制。） 但你不应使用 npm install 从 npm 包仓库添加任意的 JavaScript 或 TypeScript 库。 如果你这样做，你的代码将无法在 Didit 上编译。

示例

  1. Alyssa 和 Ben 在写习题集时坐在旁边，各自开着笔记本电脑。 他们大致地讨论了完成习题集的不同方法。他们在白板上画图。当 Alyssa 在 JavaScript 库中发现一个有用的类时，她向 Ben 提起。当 Ben 找到一个有帮助的 StackOverflow 答案时，他把 URL 发给了 Alyssa。允许。

    • 当他们查看代码时，他们具体讨论了代码采取哪些步骤来解决问题，以确保两个人都有正确的可行解答。禁止。

    • 在习题集的一个棘手部分，Alyssa 查看 Ben 的屏幕以确保她的代码是正确的。Ben 坐在桌子另一边，所以 Alyssa 在自己的笔记本电脑和看 Ben 屏幕之间来回，但从不同时看到两个屏幕。禁止。

  2. Jerry 已经完成了习题集，但他的朋友 Ben 现在被一个棘手的 bug 困扰。Jerry 坐在 Ben 旁边，看他的代码，帮助他调试。允许。

    • Jerry 打开自己的笔记本电脑，找到自己对这个习题集的解答，在帮助 Ben 找 bug 时偶尔参考。禁止。

  3. Louis 这周有三份习题集和两次测验，因田径比赛离校好几天，然后又生病了。他已经在截止日期用了两天的宽限日，对习题集几乎没有进展。Ben 同情 Louis 并想帮助他，所以他和 Louis 坐下来，在 Louis 写作业时高层次地和他讨论如何完成习题集。Ben 已经提交了自己的解答，但在帮助 Louis 时他没有打开自己的笔记本电脑查看代码。允许。

    • Ben 打开自己的笔记本电脑，在帮助 Louis 时阅读自己的代码。禁止。

    • Ben 现在已经和 Louis 待了几个小时，Louis 仍然需要帮助，但 Ben 确实需要回去做自己的作业。他把代码放到 Dropbox 里分享给 Louis，Louis 承诺只在确实需要时才看。禁止。

  4. John 和 Ellen 各自独立完成了习题集。他们互相交换测试用例来检查作业。禁止。测试用例是习题集材料的一部分，也是课程学习体验的一部分。使用别人的测试用例，即使是临时的，也属于抄袭。

请注意，在上面标记为不当的示例中，双方都要对违反学术诚信的行为负责。 抄袭作品或故意使作品可供抄袭，违反本政策属严重违规行为，可能导致降低成绩、课程不及格和纪律处分。 抄袭或帮助他人抄袭，可能导致在你的成绩单上记为 F，且无法删除。

此政策适用于所有由个人提交的作业：习题集、阅读练习等。

团队作业

你应该在小组项目工作和课堂协作练习的所有方面与队友合作，每个人都被期望对设计和实现做出大致相等的贡献。

你可以重用本学期早期自己作品中的设计、想法和代码。 你也可以使用本学期 6.102 教职员工提供的任何代码。

你也可以使用外部来源的材料片段，遵循与习题集相同的政策：来源必须是公开的，你必须提供适当的出处标注，且不得解决作业的明确部分（如果作业要求"实现 X"，那么你的小组必须创建自己的 X，而非使用他人的）。

最后，你的小组不得重用本学期或之前学期其他小组创建的设计、想法或代码。

禁止公开分享

习题集起始代码和项目代码的版权归 6.102 教职员工所有，未经许可不得分发衍生作品。你的解答属于衍生作品，因此你不得公开分发你的习题集或项目解答。这意味着你不能将它们发布在公共 Dropbox 文件夹中、在他人可访问的公共服务器上，或在 GitHub 上。（请注意，GitHub 仓库默认是公开的。）

人们通常希望公开分享他们的代码，例如在 GitHub 上，以便向潜在雇主展示他们编写的代码作品集。建立作品集是个好主意，但 6.102 不是一个适合用来建立作品集的课程，因为习题集和项目是由教职员工设定的，而非你自己选择的。个人项目、黑客松和 IAP 竞赛是建立作品集的更好方式，可以展示你的创造力和技能。

如果你确实需要与潜在雇主分享你在 6.102 中编写的代码，你可以将其放入 GitHub 秘密 gist，然后直接将链接发送给雇主。不要使用公开 gist；不要在公开网站上发布你的 gist 链接；不要使用 Pastebin 或其他代码片段分享网站。这些做法都会使你的代码公开，而你无权这样做。

如果你确实创建了包含 6.102 代码的秘密 gist 以便与潜在雇主分享，无论何时这样做，请通知 6.102-personal@mit.edu，并在邮件中包含 gist 链接。

请记住，当习题集或项目的作业被抄袭时，抄袭材料的提供者和使用者都违反了学术诚信标准，如上所述。
