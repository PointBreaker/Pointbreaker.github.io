魔法数字

对于本课程的所有习题集，你都需要在 beta 提交中回应代码审查意见。

但对于习题集 0，有一个方面要求更严格：你的 beta 提交还必须消除所有魔法数字。

这是习题集 0 练习的必需部分。 你应该以这种具体方式应用本课程的原则，从而彻底避免魔法数字。

在开始修改之前，请确保打开 ESLint，方法见本页底部，这样你就能看到魔法数字出现在哪里。

然后，思考如何编写代码使其：

  • 远离 bug，尽可能通过计算来表达常量之间的关系，使得未来的维护者能够（例如）弄清楚如何将你的个人艺术作品放大 2 倍而不引入 bug。

  • 易于理解，使得（例如）像 4 这样可能令人困惑的数字，转而由一个清晰的名称如 sidesOfSquare 来描述。

  • 便于修改，使得（例如）如果 Turtle 库突然从使用角度改为使用弧度，你也不会难找到代码中表示角度的常量，只需稍作修改即可适应。

如果你的代码中有许多任意数字，考虑如何将它们表示为数据而非常量，将它们存储在一个设计良好的数据结构中，由你的代码进行处理。 请注意，ESLint 的魔法数字检测器并不十分智能，因此即使数字存储在设计良好、命名清晰、文档完善的结构中，它仍可能将其标记为魔法数字。 但 ESLint 不是判断你是否消除了所有魔法数字的最终裁决者。 人类会审查你的代码。

如果你对消除魔法数字的好方法有疑问，请在 Piazza 或办公时间提问！

修复测试失败

在每个习题集期间，你会收到一份 alpha 自动评分报告，其中展示了 Didit 对你的代码运行的隐藏测试的结果：包括检查你的实现正确性的测试，以及在许多情况下，检查你的测试正确性的测试！

这些隐藏测试在你修改 beta 版本期间仍然保持隐藏。 在 beta 自动评分报告出来之前，你不会再次看到这些测试的结果。

在开始修改之前，查看你的自动评分报告，并编写回归测试来复现所有失败。

使用 ESLint

运行 npm run lint 在命令行中查看 ESLint 输出。

更方便的做法是在你的 Visual Studio Code 中安装 ESLint 插件。转到 View → Extensions，搜索 ESLint 扩展（来自 Microsoft）并安装。 你可能发现它已经安装了。 现在你应该可以在编辑器中打开你的 ps0 .ts 文件，并在问题面板中看到 ESLint 的警告，以及在代码中看到橙色的波浪下划线。
