区间集

在问题 1—3 中，我们将实现区间集抽象类型，这是一个可变集合，包含唯一标签，每个标签与数轴上的一个不重叠区间相关联。

例如，我们可以将区间集 { A = [0,5), B = [10,30), C = [30,35) } 想象为：

在此示例中，标签是唯一的字符串 "A"、"B" 和 "C"；每个标签关联一个区间，在我们的类型中，该区间是 bigint 值的区间。 每个区间都是半开（也称为半闭）的，这意味着它包含其起点但不包含其终点，因此 [0,5) 表示 { x ∈ ℝ | 0 ≤ x < 5 }。

阅读从 src/intervalset.ts 生成的 IntervalSet 的 TypeDoc 文档。

我们的区间集将支持任意类型的标签。 IntervalSet<Label> 是一个泛型类型，类似于 Array<E> 或 Map<K,V>。 在 Array 的规格中，E 是列表中元素类型的占位符。 在 Map 中，K 和 V 是键和值类型的占位符。 只有在后面，Array 或 Map 的客户端才会通过构造例如 Array<Clown> 或 Map<Car,number> 来为这些占位符选择特定类型。

在本习题集中，我们将用两种不同的 rep 来实现 IntervalSet，以练习选择抽象函数和 rep invariant 并防止 rep 暴露。 一个库为某种类型提供多个实现有很多充分的理由，例如具有不同的性能权衡，我们正在遵循这种模式。

实现将在 src/intervalset-impls.ts 中。

多区间集之间的相似度

有了我们的多区间集数据类型，你的新创“” 初创公司的 MVP 需要一项关键的专有技术——一种衡量多区间集之间相似度的方法。 这就是问题 5。

例如，给定 { A = [[0,5),[20,25)], B = [[10,20),[25,30)] } 和 { A = [[20,35)], B = [[10,20)], C = [[0,5)] }：

我们的 similarity 函数将支持客户端提供的标签相似度定义。 例如，假设一个二元定义：当标签相等时完全相似（值为 1），否则完全不相似（值为 0）。

由两个集合共同跨过的区间的区间相似度是其标签的相似度。 仅由其中一个集合跨过或由两个集合都不跨过的区间，其区间相似度为 0。

多区间集之间的相似度将定义为两个集合跨度的比率，因此使用标签相似度的二元定义，这两个集合之间的相似度为：

( 5×0 + 5×0 + 10×1 + 5×1 + 5×0 + 5×0 ) ÷ ( 35 - 0 ) = 15 / 35 ≈ 0.42857

（将鼠标悬停或点击单个项以突出显示上方图形的相应部分。）

但是，假设客户端改为指定 "A" 和 "C" 的相似度为 0，但 "A" 和 "B" 更接近，相似度为 ½。 使用该定义：

( 5×0 + 5×0 + 10×1 + 5×1 + 5×0.5 + 5×0 ) ÷ ( 35 - 0 ) = 17.5 / 35 = 0.5

similarity 的客户端通过提供一对标签及其之间介于 0 和 1 之间的数值相似度来定义标签相似度。 所有其他标签对之间的相似度为 1（如果它们相等）或 0（否则）。

阅读从 src/similarity.ts 生成的 similarity 的 TypeDoc 文档。

你的 similarity 代码应该仅依赖于 MultiIntervalSet 和其他 ADT 的规格，而不是任何特定实现的细节。

它应该充分利用你设计的新辅助 ADT，同样仅依赖于其规格而不依赖于其实现。

除此之外，similarity 的实现完全由你决定。

通过运行 npm test 运行所有测试。

评分

你的 ps2 总成绩将按以下方式计算：
~30% alpha 自动评分（包括在线练习）+ ~20% alpha 手动评分 + ~25% beta 自动评分 + ~25% beta 手动评分（包括代码审查）

自动评分测试用例从 alpha 到 beta 不会改变，但它们的分值会改变。 测试用例在 alpha 上可能值零分，在 beta 上可能值非零分，反之亦然。

alpha 的手动评分可能会检查你解决方案的任何部分，包括规格、测试套件、实现和你的 Git 提交历史。 beta 的手动评分可能会检查任何部分，以及你如何处理来自 alpha 的手动评分和代码审查反馈。
