引言

今天的阅读介绍了几个概念：

  • 语法，包含产生式、非终结符、终结符和运算符
  • 正则表达式
  • 解析器生成器

一些程序模块以字节序列或字符序列的形式接收输入或产生输出，当它仅存储在内存中时称为字符串（string），当它流入或流出模块时称为流（stream）。就像我们一直在开发的具有多个客户端和实现的方法一样，有许多不同的用户依赖于对这些字符串或流格式的共识；换句话说，这些序列需要一个规范。在今天的阅读中，我们讨论如何为这样的序列编写规范。具体来说，字节或字符序列可能是：

  • 一个字符串
  • 磁盘上的文件，此时规范称为文件格式
  • 通过网络发送的消息，此时规范称为通信协议
  • 用户在控制台输入的命令，此时规范称为命令行界面

对于这些类型的序列，我们引入语法（grammar）的概念，它不仅允许我们区分合法和非法的序列，还能将序列解析为程序可以处理的数据结构。从语法生成的数据结构通常是像我们在递归数据类型阅读中讨论的那样的递归数据类型。

我们还讨论了一种称为正则表达式（regular expression）的语法特殊形式。除了用于规范定义和解析之外，正则表达式还广泛用于许多字符串处理任务，如拆解字符串、从中提取信息或对其进行转换。

最后我们将讨论解析器生成器（parser generator），这是一种能将语法自动转换为该语法的解析器的工具。

语法

为了描述符号串，无论它们是字节、字符还是从固定集合中抽取的其他类型的符号，我们使用一种称为语法（grammar）的紧凑表示方法。

语法定义了一组字符串，通常称为一种语言。 为了介绍语法，在整篇阅读中，我们将探讨表示 URL 的语法。 我们用于 URL 的语法将指定 HTTP 协议中合法 URL 的字符串集合。

语法有两个主要元素：终结符和非终结符。

语法中的字面字符串称为终结符（terminal）。它们之所以被称为终结符，是因为它们不能再被进一步展开。 我们通常用引号来表示终结符，如 'http' 或 ':'。

另一方面，非终结符（nonterminal）可以被视为能够匹配一组可能字符串中某一个的变量，因此可以被进一步展开。 我们如何决定非终结符可以取什么值？ 每个语法由一组产生式（production）或规则组成，其中每个产生式用其他非终结符、运算符和终结符来定义一个非终结符。

语法中的产生式具有以下形式

nonterminal ::= expression of terminals, nonterminals, and operators

语法中的一个非终结符被指定为根（root）。 按照惯例，我们首先列出根的产生式，以使语法更容易被人类理解。 语法识别的字符串集合是那些匹配根非终结符的字符串。 这个非终结符有时被称为 root 或 start 或者简写为 S，但在下面的语法中，我们通常会为根选择更具可读性的名称，如 url、html 和 markdown。

因此，表示单例集（只允许一个特定 URL）的语法可能只有一个定义非终结符 url 的产生式，右侧有一个终结符：

url ::= 'http://mit.edu/'

语法运算符

产生式可以使用运算符来组合右侧的终结符和非终结符。 产生式表达式中最重要的三个运算符是：

重复（Repetition），用 * 表示：

x ::= y*        // x matches zero or more y

连接（Concatenation），不用符号表示，仅用空格：

x ::= y z       // x matches y followed by z

并集（Union），也称为交替（alternation），用 | 表示：

x ::= y | z     // x matches either y or z

按照惯例，后缀运算符如 * 具有最高优先级，这意味着它们最先被应用。 其次是连接运算。 交替 | 具有最低优先级，意味着它最后被应用。 括号可以用来覆盖优先级：

m ::= a (b|c) d      // m matches a, followed by either b or c, followed by d
x ::= (y z | a b)*   // x matches zero or more yz or ab pairs

让我们使用这些运算符来推广我们的 url 语法，以匹配其他一些主机名，如 http://stanford.edu/ 和 http://google.com/。

url ::= 'http://' hostname '/'
hostname ::= 'mit.edu' | 'stanford.edu' | 'google.com'

这个语法的第一条规则演示了连接运算。 url 非终结符匹配以字面字符串 http:// 开头，接着匹配 hostname 非终结符，然后是字面字符串 / 的字符串。

hostname 规则演示了并集运算。 hostname 可以匹配三个字面字符串之一：mit.edu、stanford.edu 或 google.com。

因此，这个语法表示三个字符串的集合：http://mit.edu/、http://google.com/ 和 http://stanford.edu/。

让我们更进一步，允许任何小写单词代替 mit、stanford、google、com 和 edu：

url ::= 'http://' hostname '/'
hostname ::= word '.' word
word ::= letter*
letter ::= ('a' | 'b' | 'c' | 'd' | 'e' | 'f' | 'g' | 'h' | 'i' 
                | 'j' | 'k' | 'l' | 'm' | 'n' | 'o' | 'p' | 'q' 
                | 'r' | 's' | 't' | 'u' | 'v' | 'w' | 'x' | 'y' | 'z')

新的 word 规则匹配零个或多个小写字母的字符串，因此整体语法现在也可以匹配 http://alibaba.com/ 和 http://zyxw.edu/。 不幸的是，word 也可以匹配空字符串，所以这个 url 语法也会匹配 http://./，而这不是一个合法的 URL。 下面是一种修复方法的详细写法，它要求 word 至少匹配一个字母。

word ::= letter letter*

我们将在下一节中看到一种更简单的写法来表示 word。

更多语法运算符

你还可以使用额外的运算符，它们只是语法糖（即等价于三个主要运算符的组合）。

0 次或 1 次出现用 ? 表示：

x ::= y?       // an x is a y or is the empty string
               //    equivalent to x ::=   | y
               //                        ^--- note the empty string here

1 次或多次出现用 + 表示：

x ::= y+       // an x is one or more y
               //    equivalent to  x ::= y y*

精确的出现次数用 {n} 表示，出现次数范围用 {n,m}、{n,} 或 {,m} 表示：

x ::= y{3}     // an x is three y
               //    equivalent to x ::= y y y 

x ::= y{1,3}   // an x is between one and three y
               //    equivalent to x ::= y | y y | y y y

x ::= y{,4}    // an x is at most four y
               //    equivalent to x ::=   | y | y y | y y y | y y y y
               //                        ^--- note the empty string here

x ::= y{2,}    // an x is two or more y
               //    equivalent to x ::= y y y*

字符类 [...] 表示匹配方括号中列出的任意字符的单字符字符串集合：

x ::= [aeiou]     // equivalent to  x ::= 'a' | 'e' | 'i' | 'o' | 'u'

字符范围可以使用 - 紧凑地描述：

x ::= [a-ckx-z]   // equivalent to  x ::= 'a' | 'b' | 'c' | 'k' | 'x' | 'y' | 'z'

反转字符类 [^...] 表示匹配不在括号中列出的字符的单字符字符串集合：

x ::= [^a-c]  // equivalent to  x ::= 'd' | 'e' | 'f' | ... | '0' | '1' | ... | '!' | '@'
              //                          | ... (all other possible characters)

这些额外的运算符允许 word 产生式被更紧凑地表达：

url ::= 'http://' hostname '/'
hostname ::= word '.' word
word ::= [a-z]+

语法中的递归

我们还需要怎样推广？主机名可以有两个以上的组成部分，还可以有一个可选的端口号：

http://didit.csail.mit.edu:4949/

为了处理这种字符串，现在的语法是：

url ::= 'http://' hostname (':' port)? '/' 
hostname ::= word '.' hostname | word '.' word
port ::= [0-9]+
word ::= [a-z]+

注意 hostname 现在是如何递归地以自身来定义的。 hostname 定义的哪部分是基础情况，哪部分是递归步骤？允许哪些类型的主机名？

使用重复运算符，我们也可以不用递归来写 hostname，像这样：

hostname ::= (word '.')+ word

有时可以使用这样的运算符来消除语法中的递归，但并非总是如此。

另一个需要注意的事情是，这个语法允许技术上不合法的端口号，因为端口号只能范围从 0 到 65535（216-1）。我们可以写一个更复杂的 port 定义来只匹配这些整数，但这通常不在语法中完成。相反，约束 0 ≤ port ≤ 65535 会在使用语法的程序中指定。

要更进一步，我们还需要做更多的事情：

  • 推广 http 以支持 URL 可以有的其他协议
  • 将末尾的 / 推广为以斜杠分隔的路径
  • 允许主机名使用完整的合法字符集，而不仅仅是 a-z

解析树

将语法与字符串匹配可以生成一棵解析树（parse tree），它显示字符串的各部分如何对应语法的各部分。

解析树的叶子节点用终结符标记，表示字符串中已被解析的部分。 它们没有子节点，不能再被进一步展开。 如果我们按顺序将叶子节点连接起来，就得到了原始字符串。 一个简单的例子是我们一开始使用的单行 URL 语法，其（唯一可能的）解析树如右图所示：

url ::= 'http://mit.edu/'

解析树的内部节点用非终结符标记，因为它们都有子节点。 非终结符节点的直接子节点必须遵循语法中该非终结符产生式规则的模式。 例如，在我们允许任意两部分主机名的更复杂的 URL 语法中，树中 hostname 节点的子节点必须遵循 hostname 规则的模式：word '.' word。 右图显示了将此语法与 http://mit.edu/ 匹配所产生的解析树：

url ::= 'http://' hostname '/'
hostname ::= word '.' word
word ::= [a-z]+

作为更复杂的例子，这里是递归 URL 语法的解析树。 这棵树现在具有更多的结构。 hostname 和 word 非终结符标记着树中的节点，它们的子树匹配语法中的那些规则。

url ::= 'http://' hostname (':' port)? '/' 
hostname ::= word '.' hostname | word '.' word
port ::= [0-9]+
word ::= [a-z]+

示例：Markdown 和 HTML

现在让我们来看一些文件格式的语法。我们将使用两种不同的标记语言来表示文本中的排版样式。它们如下：

Markdown:

This is _italic_.

(To learn about Markdown, see the Markdown syntax documentation or Markdown on Wikipedia.)

HTML:

Here is an <i>italic</i> word.

(To learn about HTML, see the HTML Living Standard, or HTML on Wikipedia.)

为了简单起见，我们的示例 HTML 和 Markdown 语法只指定斜体，但其他文本样式当然也是可能的。 同样为了简单起见，我们假设格式化分隔符之间的纯文本不允许使用任何格式化标点符号，如 _ 或 <。

这是我们简化版 Markdown 的语法：

markdown ::= ( normal | italic ) *
italic ::= '_' normal '_'
normal ::= text
text ::= [^_]*

这是我们简化版 HTML 的语法：

html ::= ( normal | italic ) *
italic ::= '<i>' html '</i>'
normal ::= text
text ::= [^<>]*

正则表达式

正则语法具有一个特殊性质：通过将每个非终结符（除了根非终结符）替换为其右侧，可以将其简化为根的一个单一产生式，右侧只包含终结符和运算符。

我们的 URL 语法的则是正则的。通过将非终结符替换为它们的产生式，可以简化为单一表达式：

url ::= 'http://' ([a-z]+ '.')+ [a-z]+ (':' [0-9]+)? '/'

Markdown 语法也是正则的：

markdown ::= ([^_]* | '_' [^_]* '_' )*

But our HTML grammar can’t be reduced completely. By substituting righthand sides for nonterminals, you can eventually reduce it to something like this:

html ::= ( [^<>]* | '<i>' html '</i>' )*

Unfortunately, the recursive use of html on the righthand side can’t be eliminated, and can’t be simply replaced by a repetition operator either. So the HTML grammar is not regular.

终结符和运算符的简化表达式可以写成一种更紧凑的形式，称为正则表达式（regular expression）。正则表达式去掉了终结符周围的引号以及终结符和运算符之间的空格，因此它仅由终结符字符、用于分组的括号和运算符字符组成。 例如，我们的 markdown 格式的正则表达式就是

([^_]*|_[^_]*_)*

正则表达式也简称为regex（正则表达式）。 正则表达式的可读性远不如原始语法，因为它缺乏记录每个子表达式含义的非终结符名称。 但许多编程语言都有对正则表达式的库支持（而非对语法的支持），而且正则表达式的匹配速度比语法快得多。

编程语言库中通常实现的正则表达式语法，除了我们在上面语法中使用的之外，还有几个特殊字符。 以下是一些常见的有用字符：

.   // matches any single character (but sometimes excluding newline, depending on the regex library)

\d  // matches any digit, same as [0-9]
\s  // matches any whitespace character, including space, tab, newline
\w  // matches any word character including underscore, same as [a-zA-Z_0-9]

Backslash is also used to “escape” an operator or special character so that it matches literally. Here are some of the common special characters that you need to escape:

\.  \(  \)  \*  \+  \|  \[  \]  \\

当存在可能与特殊字符混淆的终结符字符时，使用反斜杠非常重要。 因为我们的 url 正则表达式中包含作为终结符的 .，我们需要使用反斜杠来转义它：

http://([a-z]+\.)+[a-z]+(:[0-9]+)?/

另一种转义特殊字符的方法是将其放在字符类括号中。 我们可以写 [.] 而不是 \. 来匹配字面意义上的 . 字符。 在字符类括号内，大多数特殊字符失去其特殊含义，被简单地按字面意义处理。 但对字符类语法特殊的字符，如 [、]、^、- 和 \，仍然需要通过反斜杠转义才能按字面意义使用。

最后，既然我们在讨论反斜杠，正则表达式也可以包含标准的字符串转义字符，如用于表示原本不可见字符的这些代码：

\n  // matches a literal newline character
\t  // matches a literal tab character

These are the same escape characters that can be used in Python or TypeScript/JavaScript strings, and they mean a match to a single literal character, the same as if you put in A to match an uppercase A, or  (space) to match a single space character.

所以要小心：反斜杠在这里被严重重载了！它在正则表达式中用于三种不同的用途：在字符类快捷方式中（如 \s）；按字面意义匹配特殊字符（如 \.）；以及在字符串转义字符中（如 \n）。

实际使用正则表达式

正则表达式在编程中被广泛使用，你应该将它们放在你的工具箱中。

In TypeScript/JavaScript, you can use regexes for manipulating strings (see Mozilla’s guide). They’re built-in as a first-class feature of other modern scripting languages like Python and Ruby, and you can use them in many text editors for find and replace.

在一些语言（包括 TypeScript/JavaScript）中，正则表达式有自己的以正斜杠分隔的字面语法 /..../。 在其他语言（包括 Python 和 Java）中，正则表达式没有特殊的语法支持，所以你只需使用带引号的字符串。

以下是在 TypeScript 中使用正则表达式的一些示例。

将字符串 s 中所有连续的空格替换为单个空格：

const singleSpacedString = s.replace(/ +/g, " ");

Notice the g character in the example above. By default, a regex will only match the first instance in a string. Adding a g character after the regex makes this a “global” pattern which forces it to match all instances in the string.

匹配 URL：

if (s.match(/http:\/\/([a-z]+\.)+[a-z]+(:[0-9]+)?\//)) {
    // then s is a url
}

注意上面示例中的反斜杠。 我们想要匹配字面上的句点 .，所以我们必须先将其转义为 \.，以防止它被解释为正则表达式的匹配任意字符运算符。 此外，我们想要匹配字面上的正斜杠 /，所以我们还必须将它们转义为 \/，以防止它们过早地表示正则表达式字面量的结束。 频繁需要反斜杠转义使得正则表达式的可读性降低。

提取日期的各部分，如 "2020-03-18"：

const s = "2020-03-18";
const regex = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
const m = s.match(regex);
if (m) {
  assert(m.groups);
  const year = m.groups.year;
  const month = m.groups.month;
  const day = m.groups.day;
  // m.groups.name is the part of s that matched (?<name>...)
}

此示例使用命名捕获组，如 (?<year>...)，来提取匹配字符串的各部分并为它们分配名称。 (?<name>...) 语法匹配括号内的正则表达式 ...，然后将 name 分配给匹配的字符串。 注意，这里的 ? 不表示 0 或 1 次重复。 在此上下文中，在左括号之后，? 表示这些括号具有特殊含义，而不仅仅是分组。

命名捕获组可以在成功匹配后通过 groups 属性检索。 例如，如果将此正则表达式与 "2026-03-18" 匹配，那么 m.groups.year 将返回 "2026"，m.groups.month 将返回 "03"，m.groups.day 将返回 "18"。

上下文无关语法

In general, a language that can be expressed with our system of grammars is called context-free. Not all context-free languages are also regular; that is, some grammars can’t be reduced to single nonrecursive productions. Our HTML grammar is context-free but not regular.

大多数编程语言的语法也是上下文无关的。一般来说，任何具有嵌套结构（如嵌套的括号或大括号）的语言都是上下文无关的但不是正则的。这个描述适用于 TypeScript 语法，这里部分展示：

statement ::= 
  '{' statement* '}'
| 'if' '(' expression ')' statement ('else' statement)?
| 'for' '(' forinit? ';' expression? ';' forupdate? ')' statement
| 'while' '(' expression ')' statement
| 'do' statement 'while' '(' expression ')' ';'
| 'try' '{' statement* '}' ( catches | catches? 'finally' '{' statement* '}' )
| 'switch' '(' expression ')' '{' switchgroups '}'
| 'return' expression? ';'
| 'throw' expression ';' 
| 'break' label? ';'
| 'continue' label? ';'
| expression ';' 
| label ':' statement
| ';'

解析器生成器

解析器生成器是你应该添加到工具箱中的好工具。解析器生成器以语法作为输入，自动生成一个解析器，后者接收字符序列并尝试将其与语法匹配。

The parser typically produces a parse tree, which shows how grammar productions are expanded into a sentence that matches the character sequence. The root of the parse tree is the root nonterminal of the grammar. Each node of the parse tree expands into one production of the grammar. We’ll see how a parse tree actually looks later in this reading.

解析的最后一步是对这棵解析树做一些有用的事情。我们将把它转换为递归数据类型的值。递归抽象数据类型通常用于表示语言中的表达式，如 HTML、Markdown、TypeScript 或代数表达式（代数的符号语言）。表示语言表达式的递归抽象数据类型称为抽象语法树（AST）。

在 6.102 中，我们将使用 ParserLib，这是课程工作人员为 TypeScript 开发的解析器生成器。该解析器生成器在精神上与更广泛使用的解析器生成器如 Antlr 类似，但它具有更简单的接口，通常更容易使用。

ParserLib 语法

Documentation for ParserLib can be found online.

这是我们的 HTML 语法作为 ParserLib 语法时的样子：

html ::= ( italic | normal ) * ;
italic ::= '<i>' html '</i>' ;
normal ::= text ; 
text ::= [^<>]+ ;  /* represents a string of one or more characters that are not < or > */

Let’s break it down.

每个 ParserLib 规则由一个名称、一个 ::=、其定义以及一个分号终止符组成。ParserLib 语法还可以包含 TypeScript 风格的注释，包括单行和多行注释。

By convention, we use lowercase for nonterminals: html, normal, italic, text. The ParserLib library is case-insensitive with respect to nonterminal names; it canonicalizes names to all-lowercase, so even if you don’t write all your names into lowercase, you will see them as lowercase when you print your grammar.

终结符是带引号的字符串，如 '<i>'，或更一般地是正则表达式，如 [^<>]+。 然而，与普通正则表达式不同，ParserLib 语法要求字面字符必须用引号括起来或放在字符类括号中。 因此，正则表达式 (alpha|beta|[c-z])* 在 ParserLib 语法中写为 ('alpha'|'beta'|[c-z])*。

html ::= ( italic | normal ) * ;

This rule shows that ParserLib rules can have the alternation operator |, repetition operators like * (and also + and ?, even though they’re not shown in this rule), and parentheses for grouping, in the same way we’ve been using in the grammars section.

语法中的空白字符不重要（在带引号的字符串或 [...] 字符类之外）。 这里运算符周围加了空格以使它们更醒目。 将规则写为 html::=(italic|normal)*; 会有同样的效果，只是可读性较差。

The html nonterminal also happens to be the root of this grammar (also called starting symbol). The root is the nonterminal that the whole input needs to match. It’s good practice to put the rule for the root nonterminal first in the grammar, so that a human reader can take a top-down view, but it isn’t essential. When we create a parser from the grammar, we tell ParserLib which nonterminal the parse should use as the root.

italic ::= '<i>' html '</i>' ;
normal ::= text ;
text ::= [^<>]+ ;

注意 text 产生式使用了在语法章节中讨论的反转字符类 [^<>] 来表示除 < 和 > 之外的任何字符。

空白字符

考虑下面显示的语法。

expr ::= sum ;
sum ::= primary ('+' primary)* ;
primary ::= constant | '(' sum ')' ;
constant ::= [0-9]+ ;

这个语法将接受像 42+2+5 这样的表达式，但会拒绝常量与 + 号之间有任何空格的类似表达式。我们可以通过修改 sum 的产生式规则来修改语法以允许加号周围的空白字符，如下所示：

sum ::= primary (whitespace* '+' whitespace* primary)* ;
whitespace ::= [ \t\r\n]+ ;

然而，一旦语法变得更复杂，这可能会很快变得繁琐。ParserLib 允许使用简写来表示应该跳过某些类型的字符。

// the IntegerExpression grammar
@skip whitespace {
    expr ::= sum ;
    sum ::= primary ('+' primary)* ;
    primary ::= constant | '(' sum ')' ;
}
whitespace ::= [ \t\r\n]+ ;
constant ::= [0-9]+ ;

@skip whitespace 表示法表示，在 expr、sum 和 primary 右侧的每个终结符、非终结符和字符类之前和之后，应自动忽略对 whitespace 非终结符的零次或多次匹配。 因此从语法匹配的角度来看，这三条规则实际上变为：

expr ::= whitespace* sum whitespace* ;
sum ::= whitespace* primary whitespace* (whitespace* '+' whitespace* primary whitespace*)* whitespace* ;
primary ::= whitespace* constant whitespace* | whitespace* '('  whitespace* sum  whitespace* ')' whitespace* ;

关于 @skip 有几件事需要注意。 首先，whitespace 没有什么特别的。@skip 指令适用于语法中定义的任何非终结符——所以你可以用 @skip punctuation 或 @skip spacesAndComments 代替，只需为这些非终结符定义适当的规则。

其次，注意 constant 的定义是如何被有意放在 @skip 块外面的。 这是因为我们希望接受常量周围有空格的表达式，如 42 + 2，但拒绝常量内部有空格的表达式，如 4 2 + 2。 将 constant 规则放在 @skip 块内会使其实际上变为 constant ::= (whitespace* [0-9] whitespace*)+，因此它会接受内部有空格的常量。 将 primary 规则放在 @skip 块内——使其对 constant 的使用可以被空白字符包围——但将 constant 规则保留在外面，提供了所需的行为。

本阅读的其余部分将使用我们在上一节中定义的 IntegerExpression 语法作为贯穿示例。 为了在 TypeScript 中嵌入语法并保留其换行符，我们将使用反引号（也称为模板字面量）：

const grammar: string = `
  @skip whitespace {
      expr ::= sum;
      sum ::= primary ('+' primary)*;
      primary ::= constant | '(' sum ')';
  }
  constant ::= [0-9]+;
  whitespace ::= [ \\t\\r\\n]+;  // <-- note that backslashes must be escaped here, because this regex is inside a string
`;

ParserLib 解析器生成器工具将这样的语法字符串转换为解析器。为了做到这一点，你需要遵循三个步骤。首先，你需要导入 ParserLib 库：

import { Parser, ParseTree, compile } from "parserlib";

第二步是定义一个包含语法使用的所有非终结符的 enum 类型。这将告诉 ParserLib 在语法中期望哪些定义，并允许它检查是否有遗漏。

parser.ts 
enum IntegerGrammar {
  Expr, Sum, Primary, Constant, Whitespace
}

注意 ParserLib 本身不区分大小写，但按照惯例，enum 值的名称首字母大写。

在你的代码中，你可以通过调用其 compile 工厂函数来创建一个 Parser。

parser.ts 
const parser: Parser<IntegerGrammar> = compile(grammar, IntegerGrammar, IntegerGrammar.Expr);

compile 方法接收一个语法字符串、非终结符枚举以及用作语法根非终结符的非终结符。 在这种情况下，我们想要的根非终结符是 expr，所以我们传入 IntegerGrammar.Expr。

Assuming you don’t have any syntax errors in your grammar, the result will be a Parser object that can be used to parse text. Notice that the Parser is a generic type that is parameterized by the IntegerGrammar enum that you defined earlier.

调用解析器

Now that you’ve generated the parser object, you are ready to parse your own text. The parser has a method called parse that takes in the text to be parsed as a string, and returns a ParseTree. Calling it produces a parse tree:

const parseTree: ParseTree<IntegerGrammar> = parser.parse("54+(2+ 89)");

注意 ParseTree 也是一个泛型类型，由枚举类型 IntegerGrammar 参数化。

遍历解析树

So we’ve used the parser to turn a stream of characters into a parse tree, which shows how the grammar matches the stream. Next we want to do something useful with this parse tree: translating it into a value of a recursive abstract data type.

与 Parser 本身一样，ParseTree 由类型 NT 参数化，这是一个列出语法中所有非终结符的 enum 类型，像我们之前定义的 IntegerGrammar 枚举。

第一步是学习如何遍历解析树。 ParseTree 对象有四个方法你最需要熟悉。 其中三个是基本的观察器，表示为 getter 属性：

interface ParseTree<NT> {

  /**
   * The nonterminal corresponding to this node in the parse tree.
   */
  name: NT;

  /**
   * The children of this node, in order, excluding @skipped subtrees
   */
  children: ReadonlyArray<ParseTree<NT>>;

  /**
   * The substring of the original string that this subtree matched
   */
  text: string;

此外，你可以查询 ParseTree 以获取匹配特定产生式的所有子节点：

  /**
   * Get the children that correspond to a particular production rule 
   * @param name Name of the nonterminal corresponding to the desired production rule.
   * @returns children that represent matches of name's production rule.
   */
  public childrenByName(name: NT): ReadonlyArray<ParseTree<NT>>;
}

访问解析树中节点的好方法是编写递归函数。 例如，下面的递归函数以适当的缩进打印解析树中的所有节点。

/**
 * Traverse a parse tree, indenting to make it easier to read.
 * @param node   parse tree to print.
 * @param indent indentation to use.
 */
function printNodes(node: ParseTree<IntegerGrammar>, indent: string): void {
    console.log(indent + node.name + ":" + node.text);
    for (const child of node.children){
        printNodes(child, indent + "  ");
    }
}

构建抽象语法树

We need to convert the parse tree into a recursive data type. Here’s the definition of the recursive data type that we’re going to use to represent integer arithmetic expressions:

IntegerExpression = Constant(n: number)
                  + Plus(left: IntegerExpression, right: IntegerExpression)

如果这种语法看起来很神秘，请复习递归数据类型定义。

当递归数据类型以这种方式表示一种语言时，它通常被称为抽象语法树。IntegerExpression 值捕获了表达式的重要特征——它的分组和其中的整数——同时省略了创建它的字符序列的不必要细节。

By contrast, the parse tree that we just generated with the IntegerExpression parser is a concrete syntax tree. It’s called concrete, rather than abstract, because it contains more details about how the expression is represented in actual characters. For example, the strings 2+2, ((2)+(2)), and 0002+0002 would each produce a different concrete syntax tree, but these trees would all correspond to the same abstract IntegerExpression value: Plus(Constant(2), Constant(2)).

现在，我们可以创建一个递归函数来遍历 ParseTree 以生成 IntegerExpression，如下所示：

parser.ts 
/**
 * Convert a parse tree into an abstract syntax tree.
 * 
 * @param parseTree constructed according to the IntegerExpression grammar
 * @returns abstract syntax tree corresponding to parseTree
 */
function makeAbstractSyntaxTree(parseTree: ParseTree<IntegerGrammar>): IntegerExpression {
    if (parseTree.name === IntegerGrammar.Expr) {
        // expr ::= sum;
        return makeAbstractSyntaxTree(parseTree.children[0] ?? assert.fail('missing child'));

    } else if (parseTree.name === IntegerGrammar.Sum) {
        // sum ::= primary ('+' primary)*;
        const children = parseTree.childrenByName(IntegerGrammar.Primary);
        const subexprs = children.map(makeAbstractSyntaxTree);
        const expression: IntegerExpression = subexprs.reduce((result, subexpr) => new Plus(result, subexpr));
        return expression;

    } else if (parseTree.name === IntegerGrammar.Primary) {
        // primary ::= constant | '(' sum ')';
        const child: ParseTree<IntegerGrammar> = parseTree.children[0] ?? assert.fail('missing child');
        // check which alternative (constant or sum) was actually matched
        switch (child.name) {
        case IntegerGrammar.Constant:
            return makeAbstractSyntaxTree(child);
        case IntegerGrammar.Sum:
            return makeAbstractSyntaxTree(child);
            // for this parser, we do the same thing either way (and should really DRY this out)
        default:
            assert.fail(`Primary node unexpected child ${IntegerGrammar[child.name]}`);
        }

    } else if (parseTree.name === IntegerGrammar.Constant) {
        // constant ::= [0-9]+;
        const n: number = parseInt(parseTree.text);
        return new Constant(n);

    } else {
        assert.fail(`cannot make AST for ${IntegerGrammar[parseTree.name]} node`);
    }
}

The function follows the structure of the grammar, handling each rule from the grammar in turn: expr, sum, primary, and constant. The only rule we don’t need to handle here is whitespace, because the grammar uses whitespace only in a @skip block, and skipped subtrees are not returned by children so they should never appear in the traversal. Note, however, that skipped whitespace will still appear in the text field of a matched nonterminal.

注意这段代码与语法紧密相关。 如果你以重大方式更改语法的规则，这段代码也可能需要更改。

对于 sum 节点，代码使用 map 和 reduce 来避免编写循环（注意 parseTree.childrenByName 等同于对 parseTree.children 执行 filter）。

为了处理 primary 节点，这段代码使用 switch 语句。 每次使用 switch 时，记住：switch 语句的执行从匹配的 case 开始，并会贯穿到后续的 case。 我们这里的代码在每个 case 中小心地 return（或抛出错误），永远不会贯穿。

错误处理

解析时可能会出几种错误。

你的语法可能有语法错误。 在这种情况下，compile 会抛出一个 ParseError。

你尝试解析的字符串可能无法用给定的语法解析。 这可能发生在你的语法不正确，或者你的字符串不正确的情况下。 无论哪种情况，问题都会通过 parse 方法抛出 ParseError 来发出信号。

ParseError 错误包含有关错误可能位置的信息，尽管解析错误有时本质上难以定位，因为解析器无法知道你打算写什么字符串，所以你可能需要搜索一下才能找到错误的真正位置。

左递归和其他 ParserLib 限制

ParserLib 通过生成自顶向下的递归下降解析器来工作。这类解析器在可以解析的语法方面有一些限制。特别值得指出的是两个限制。

左递归。如果语法涉及左递归，递归下降解析器可能会进入无限循环。这是一种非终结符的定义将该非终结符作为其最左符号的情况。例如，下面的语法包含了左递归，因为 sum 的一个可能定义是 sum '+' number，其中 sum 是其最左符号。

sum ::= number | sum '+' number ;
number ::= [0-9]+ ;

这个左递归定义是有问题的，因为递归下降解析器需要尝试匹配 sum 的所有备选项，包括 number 和 sum '+' number。 但尝试匹配 sum '+' number 立即需要以匹配 sum 作为第一步。 解析器不断递归地尝试该规则，但在被解析的字符串上没有取得任何进展——没有像正确递归要求终止的那样归约为更小的子问题。 相比之下，像 expr = number | '(' expr ')' 这样的规则，是递归的但不是左递归的，它能够在字符串中取得进展，通过在再次递归应用 expr 规则之前先匹配 (。

左递归也可能间接发生。例如，将上面的语法改为下面的语法并不能解决问题，因为 sum 的定义仍然间接涉及一个以 sum 作为其第一个符号的符号。

sum ::= number | thing number ;
thing ::= sum '+' ;
number ::= [0-9]+ ;

如果你将任何这些语法传给 ParserLib，然后尝试使用它们来解析一个符号，ParserLib 将以 ParseError 失败，列出违规的非终结符。

有一些通用技术可以消除左递归；对于我们的目的来说，最简单的方法是用重复（*）代替左递归，所以上面的语法变为：

sum ::= (number '+')* number ;
number ::= [0-9]+ ;

贪婪性。这是一个你在这门课程中可能不会遇到的问题，但它是 ParserLib 的一个限制，你应该意识到。ParserLib 的解析器是贪婪的，即在每个点它们都尝试为当前正在考虑的任何规则匹配最大字符串。例如，考虑以下语法：

g ::= ab threeb ;
ab ::= 'a'*'b'* ;
threeb ::= 'bbb' ;

字符串 'aaaabbb' 显然应该匹配 g，但贪婪解析器无法解析它，因为它会尝试解析匹配 ab 符号的最大子字符串，然后发现无法解析 threeb，因为它已经消耗了整个字符串。与左递归（容易修复）不同，这是 ParserLib 实现的解析器类型的一个更基本的限制。

总结

机器处理的文本语言在计算机科学中无处不在。语法是描述这类语言的最流行的形式化方法，而正则表达式是语法的一个重要子类，可以在没有递归的情况下表达。

The topics of today’s reading connect to our three properties of good software as follows:

  • 免受 Bug 困扰。语法和正则表达式是字符串和流的声明性规范，可以由库和工具直接使用。这些规范通常比手写解析代码更简单、更直接，且更不容易出错。

  • 易于理解。语法以比手写解析代码更容易理解的形式捕获序列的形状。唉，正则表达式通常不容易理解，因为它们是可能更易懂的单行正则语法的简化形式。

  • 准备好应对变化。语法可以轻松编辑，但不幸的是，正则表达式更难更改，因为复杂的正则表达式是晦涩且难以理解的。
