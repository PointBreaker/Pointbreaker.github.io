学习目标

在本阅读中，我们将讨论回调（callbacks），即实现者调用由客户端提供的函数。 我们以 Promise 为背景讨论这一概念，展示 await 是如何使用回调来实现的。 我们还将探讨回调如何在图形用户界面（GUI）中使用，其中一种称为监听器（listener）的回调函数用于响应用户的输入事件。

在下节课讨论 Web 服务器时，我们将看到更多回调的实例。

回调

回调（callback）是客户端提供给模块供其调用的函数。 这与正常的控制流相反，在正常控制流中，客户端进行所有的调用：向下调用模块提供的函数。 使用回调时，客户端提供一段代码供实现者调用。

我们在函数式编程中已经见过一种回调：传递给 map、filter 或 reduce 的函数，它针对序列中的每个元素被反复调用。 这是一种同步回调，因为它仅在 map/filter/reduce 执行期间被调用，之后不再使用。 回调的使用在 map/filter/reduce 的调用和返回之间是同步的。

本阅读讨论的是异步回调，它被模块保存起来以供将来调用，在接收回调的函数已经返回之后。

这里有一个类比可以帮助理解同步和异步之间的区别。 普通的（同步）函数调用就像拿起电话拨打某个服务，比如打电话给你的银行查询账户余额。 你提供接线员查找账户所需的信息（类似于传入参数），他们在电话里向你报出账户余额（返回值），然后你挂断电话（从调用中收回控制权）。 在这个类比中，你是客户端，银行是你正在调用的模块。

有时银行回答得很慢。 你被搁置等待，直到他们为你找到答案。 这就像一个同步函数调用，等待到准备就绪才返回。 你在短时间内无法收回控制权；你被困在电话旁等待答案。

但有时任务可能需要很长时间，银行甚至不想让你等待。 然后银行会要求你提供一个回拨电话号码，并承诺在未来某个不可预测的时间给你回电告知答案。 向银行提供你的电话号码，类似于客户端向模块提供一个异步回调函数。

有时回调函数只会被调用一次（或最多一次），作为对一次性请求的响应，就像这个账户余额的例子一样。 但回调函数也可能被反复调用，每当某个特定事件发生时。 这种回调的一个类比可能是账户欺诈保护，即每当你的账户发生可疑交易时，银行会拨打你注册的电话号码。 在本阅读中，我们将看到这两种异步回调。

定时器回调

一个使用回调的简单例子是内置的 JavaScript 函数 setTimeout，它接受两个参数：一个回调函数和执行该函数之前要等待的毫秒数：

setTimeout(
    () => console.log("beep!"),
    3000
);

这里，回调函数是由 lambda 表达式 () => console.log("beep!") 创建的函数对象。

现在考虑在 TypeScript 提示符下运行以下代码的输出：

> setTimeout(() => console.log("beep!"), 3000); console.log("boop!");
boop!
>
3 秒后
beep!

注意这个回调是异步的。setTimeout() 调用本身并不会等待 3000 毫秒（3 秒）再打印 boop!。 相反，它启动一个内部定时器，存储对回调函数的引用，然后打印 boop!。三秒后内部定时器到期，回调函数才被最终调用，打印 beep!。

要查看一个定义带有回调的函数的例子，让我们来创建一个倒计时器：

/**
 * 启动一个每秒计时一次直到到期的定时器。
 * @param ticks      定时器持续时间（秒），必须是整数 >= 0
 * @param callback   回调函数，最初同步调用，
 *                   然后在定时器每次计时后再次调用，
 *                   每次传递定时器到期前剩余的秒数。
 *                   ticksLeft 必须是 [0, ticks] 范围内的整数。
 */
function countdown(ticks: number, callback: (ticksLeft: number) => void): void

仔细看 callback 参数的类型：这是一个函数类型。 在这个例子中，countdown() 期望的回调函数接受一个 number 参数并返回 void。

以下是在 TypeScript 提示符下调用它的一种方式：

> countdown(3, (n: number) => console.log(n));
3
>
一秒后
2
一秒后
1
一秒后
0

注意上面记录中 3 打印的位置：在下一个提示符 > 显示之前，因为规范指出第一次回调应该同步地调用，在 countdown() 返回之前。回调的其余调用则以异步方式发生，随着定时器倒数到零。

事件循环

这些定时器回调使我们能够揭示 TypeScript/JavaScript 编程模型的一个基本方面。JavaScript 运行时系统的核心是一个事件队列，一个先进先出的队列，用于存储从各个来源到达的事件。该队列由一个事件循环提供服务，它反复检查这个队列中是否有新到达的事件，并调用适当的回调函数。

事件的一个来源是由 setTimeout 创建的定时器。定时器到期会导致一个"定时器完成"事件被放入队列末尾，连同其回调函数一起。当事件循环最终从队列顶部检索到这个事件时，它调用回调函数，最终履行 setTimeout 契约的义务。

在本阅读的后面，我们将看到事件的另一个来源：图形用户界面。 对于在 HTML 网页中运行的 JavaScript，用户的按键、鼠标移动和点击或触摸被放入事件队列的末尾，并最终由它们注册的回调函数处理。

事件的另一个来源是文件系统和网络的输入和输出，这将在未来的阅读中介绍。

我们所有的 TypeScript/JavaScript 代码实际上都是在事件循环内部运行的——甚至程序的启动也是由事件循环发起的。 为了使程序正确运行，我们所有的代码也必须及时返回到事件循环，这样事件循环才能继续处理下一个事件，并继续处理后续的定时器到期或 GUI/文件/网络事件。

如果我们任何代码出现阻塞——占用控制流且相当长一段时间不返回给调用者——那么事件循环就会停止处理事件。 定时器回调不会触发，用户界面停止响应，网络连接停止传输数据。 如果你曾经看到鼠标指针变成了旋转的沙漏或彩色旋转球，那就是一个事件循环已被阻塞、不再处理事件的程序的征兆。 这很糟糕。

这里有一个会阻塞 JavaScript 事件循环的简单函数：

/** Wait for `milliseconds` to pass before returning. */
function busyWait(milliseconds: number): void {
    const now = new Date().getTime(); // new Date().getTime() is always the current clock time in milliseconds
    const deadline = now + milliseconds;
    while (new Date().getTime() < deadline) {
        // do nothing, just wait until the clock reaches the deadline time
    }
}

调用 busyWait(10000) 会不停地在 while 循环中旋转，监视时钟，直到 10 秒过去。 在那段时间里，事件会在事件队列中堆积，但事件循环无法处理它们，因为 busyWait() 还没有返回。 一旦 busyWait() 返回给它的调用者（然后调用者再返回给它的调用者，一直回到事件循环，事件循环是 JavaScript 中一切代码的原始调用者），事件循环终于可以取出下一个等待的事件并调用其回调函数，生活才能恢复正常。 但所有那些堆积的定时器回调都会太晚触发！

回想一下，在循环中旋转等待外部变化被称为忙等待（busy-waiting），对于像 JavaScript 这样的事件循环运行时系统来说，这是一个非常坏的代码异味。 像 busyWait() 这样的代码需要被重写。它应该使用由变化触发的回调（就像内置的 JavaScript 函数 setTimeout() 那样），或者由变化触发的 Promise（像我们的异步版本 timeout()）。

将回调与 Promise 一起使用

在 JavaScript 引入 Promise 之前，回调函数是实现异步函数行为最常见的方式，并且在 JavaScript 库生态系统中仍然有许多使用回调的场景。

事实证明，在底层，Promise 也使用回调。 让我们深入探讨 Promise 抽象数据类型，以更好地理解它的工作原理以及它与 await 和 async function 的交互方式。

抽象数据类型由其操作定义，而 Promise<T> 有一个关键操作，称为 then。 以下是 then 最简单的版本：

interface Promise<T> {
  then(callback: T => U): Promise<U>;
}

then 操作是一个 Promise 生产者。 它在期望产生类型 T 值的现有 promise 上调用，并向该 promise 附加一个回调函数。 回调函数消费 promise 最终产生的 T 值，并生成某种其他类型 U 的值（当然可能与 T 相同）。

以下是 then 实际使用的一个例子：

const promise : Promise<string> = fs.promises.readFile('account', { encoding: 'utf-8' });

const biggerPromise : Promise<number> = promise.then(function(data: string) {
  return parseInt(data);
});

这里，原始的 promise 正在将文件读取为字符串，通过 then 与将该字符串解析为数字的回调函数组合。生成的 biggerPromise 代表了整个计算——读取文件和将其解析为数字——并承诺最终产生该数字。

将 then 视为异步计算的组合操作会很有帮助。传统的函数组合接受两个函数 f 和 g，将它们组合成一个新函数 g ⚬ f，使得 (g ⚬ f)(x) = g(f(x))。如果 f: S → T 且 g: T → U，则结果组合的类型为 g ⚬ f: S → U。

非常类似地，then 将一个计算 f（由对其返回值的 promise Promise<T> 表示）与另一个计算 g（期望消费该 T 值并产生一个 U 值）组合。 组合的结果是一个组合计算，承诺最终产生该 U 值，所以其类型为 Promise<U>。

将 Promise<T> 想象为一个（最终）包含 T 值的单元素列表也可能有帮助。从这个角度来看，then(g) 就像 map(g)——一旦 T 元素到达，g 回调就在其上调用，产生一个 U 值，作为结果 Promise<U> 的唯一元素。（然而，这个类比在一个地方不适用，即 Promise<void>，因为这样的 promise 实际上永远不会有任何元素值。在 void promise 上使用 then(g) 仍然会在 promise 履行时调用 g，但不会向 g 传递任何值。）

我们需要在一个重要方面扩展这个 then 的概念。 回调函数不必返回一个已经计算好的 U 值。 它可以改为返回自己的一个 promise，类型为 Promise<U>：

interface Promise<T> {
  then(callback: T => U|Promise<U>): Promise<U>;
}

如果计算 U 值也需要在后台运行的另一长时间运行计算，则回调可能需要这样做。 网页检索提供了一个很好的例子，因为从 fetch() 调用获取 Response 只表示你已经成功连接到 Web 服务器。实际下载完整页面可能需要更长时间。 以下是该 promise 链可能的样子：

const promisedResponse: Promise<Response> = fetch('http://www.mit.edu/);

const promisedText: Promise<string> =
  promisedResponse.then(function(response: Response): Promise<string> {
    // we've made a connection, which is why the `response` object exists
    const downloadingPromise: Promise<string> = response.text();
    // but we may have to wait some more for the actual data, hence `downloadingPromise`
    return downloadingPromise;
  });

注意此示例代码中显示的多个 promise：

  • promisedResponse 代表正在与 www.mit.edu 建立初始连接的计算
  • downloadingPromise 代表在连接已建立之后下载 MIT 主页的计算
  • promisedText 代表两个计算的组合：初始连接后跟下载。promisedText 的最终值来自 downloadingPromise 的值，即网页的文本。

尽管传入 promisedResponse.then() 的回调函数没有使用 async 或 await，它仍然返回一个 promise，所以它是一个异步函数。

回到函数组合的类比，如果 promisedResponse 和 downloadingPromise 分别类似于函数 f 和 g，那么 promisedText 就类似于组合 g ⚬ f。

你可以在一个 promise 上多次调用 then，以附加可能对 promise 的值做不同处理的不同回调。

你也可以在 promise 当前处于任何状态时调用 then。 大多数情况下，promise 仍在等待中，所以 then 回调将在未来某个时间运行。 如果 promise 已经履行，then 回调会更快运行——但仍然是异步地。 回调函数永远不会被 then 同步调用。 相反，then 总是先返回，然后，在控制返回到事件循环之后，回调函数才会被调用。事件循环如何调用 promise 回调的细节不是本课程的要求，但如果你好奇，本阅读的附录提供了一些细节。

then 操作是 promise 的基本操作。then 是访问 promise 计算值的唯一方式。（await 实际上使用了 then，我们马上就会看到。）这部分是一个安全属性，因为它确保客户端代码永远无法查看 promise 内部并看到缺失的值。但更重要的是，then 是并发设计的一个特性。它允许通过一系列组合计算——一系列 then 回调——来构建并发计算，这些回调可以以受控的、可预测的方式交错执行。

解析异步函数

then 操作现在给了我们足够的能力来理解 await 和 async function 的含义，以及它们如何使用 promise 和回调来构建计算。

这里有一个 async 函数，包含一行等待 promise 的代码，然后对 promise 的结果进行一些计算：

async function getBalance(): Promise<number> {
    const promise: Promise<string> = fs.promises.readFile('account', { encoding: 'utf-8' });
    const data: string = await promise;
    const balance: number = parseInt(data);
    return balance;
}

当在这样的函数执行过程中遇到 await 时，TypeScript 会取出该函数剩余的计算部分，并将其包装成一个 then 回调。 所以这段代码：

const data: string = await promise;
const balance: number = parseInt(data);
return balance;

变成了类似这样的东西：

promise.then(function(data: string) {
  const balance: number = parseInt(data);
  return balance;
});

await 不是空转等待文件加载 promise 履行，而是创建一个组合 promise，将文件加载计算与 parseInt 计算组合在一起。然后它立即将控制权返回给调用者，连同这个组合 promise 一起。所以等价的代码，不使用 await 或 async，看起来像这样：

function getBalance(): Promise<number> {
    const promise: Promise<string> = fs.promises.readFile('account', { encoding: 'utf-8' });
    return promise.then(function(data: string) {
      const balance: number = parseInt(data);
      return balance;
    });
}

注意这个版本的 getBalance 相当简单，因为它只是直线式代码。当 await 在循环内部使用时，"函数计算剩余部分"包括循环的剩余迭代，这不能通过这样的语法转换轻松展示，因为它会将循环分割。但这个示例从语义上展示了 await 的含义。

还要注意，这个版本的 getBalance 不再有 async 关键字，因为我们正在展示 async 关键字在底层 TypeScript 代码中的含义。但这个版本的 getBalance 确实仍然是异步的，因为它返回一个表示尚未完成的并发计算的 promise。

总结一下，当你使用 async function 而不是 function 时，TypeScript/JavaScript 在内部转换函数的行为：

  • await 表达式被转换为返回一个与 then 组合的 promise；
  • return/throw 语句被转换为履行/拒绝（分别）该 promise
    • 一个通过执行到函数体末尾而返回的函数被转换为其履行 promise 之后再返回

HTML 与文档对象模型

异步回调在图形用户界面中被大量使用。 要理解其原理，我们需要从用户界面的结构开始看起，以 HTML 网页为例。

HTML 由元素组成，元素由开始标签和结束标签界定。 例如，以下是 HTML 中描述按钮的方式：

<button id='drawButton'>Draw</button>

...网页浏览器将其渲染为：

开始标签通常包含属性，比如这个 button 示例中的 id。 id 属性是元素的唯一标识符。 其他属性可以指定元素的其他属性。 例如，这是一个 256 乘 256 像素的绘图表面：

<canvas id="drawingCanvas" width="256" height="256"></canvas>

（<canvas> 元素具有我们在 ps3 中使用的 Canvas 绘图接口。）

HTML 元素嵌套在其他 HTML 元素中，形成一棵树。下面是一段 HTML 片段，使用 <div> 分组元素将两个按钮放在同一行，将 canvas 放在另一行。它在网页中可能的渲染方式显示在右侧。

<div>
    <button id="drawButton">Draw</button>
    <button id="clearButton">Clear</button>
</div>
<div>
    <canvas id="canvas" width="256" height="256">
</canvas>
</div>

当网页浏览器加载并显示这样的 HTML 文档时，每个元素都由内存中的一个对象表示，是 HTMLElement 的一个子类型的实例。这棵元素树被称为文档对象模型（DOM）。树中的每个元素占据屏幕上的某个区域，通常是一个称为其边界框的矩形区域。这棵树不仅仅是任意的层次结构，实际上是一棵空间树：子元素通常嵌套在其父元素的边界框内。

几乎每个 GUI 系统都有某种类似的视觉元素树。元素树是一个强大的结构化思想，在典型的 GUI 中承担着多项职责：

输出。元素的属性和子元素影响元素在屏幕上显示的内容。例如，按钮上的标签是其开始标签和结束标签之间找到的文本。

输入。元素可以有输入处理器，用于响应用户的鼠标和键盘输入，以及其他事件。稍后会详细介绍。

布局。DOM 控制元素在屏幕上的布局方式，即如何分配它们的边界框。自动布局算法自动计算每个元素的位置和大小，由用层叠样式表（CSS）编写的样式规则控制。CSS 布局超出了我们在 6.102 中讨论的范围；6.104 [原 6.170]、6.450 或 IAP Web.Lab 是学习它的好地方。

连接到 TypeScript

为了制作交互式用户界面，HTML 还可以包含 JavaScript 代码（或已编译为 JavaScript 的 TypeScript）。代码可以使用 getElementByIdAndType() 获取对树中元素的引用：

const drawButton: HTMLButtonElement = getElementByIdAndType('drawButton', HTMLButtonElement);

注意，我们在这里使用的 getElementByIdAndType() 函数与 JavaScript 中使用的标准 document.getElementById() 方法不完全相同，而是它的类型安全 TypeScript 版本。如果你对它的定义感兴趣，请参见完整代码。

DOM 元素是可变的，因此代码可以重新分配实例变量或调用修改器来添加和删除树中的元素，或改变它们的外观。例如，这段代码改变了按钮的标签：

drawButton.text = 'Draw Randomly';

输入处理

GUI 中的输入处理方式与典型的命令行或文本输入用户界面不同。 典型的文本 UI 有一个输入循环，显示提示符，读取用户输入的命令，进行解析，并决定如何将其引导到程序的不同模块。

如果 GUI 以这种方式编写，可能看起来像这样（伪代码）：

while (true) {
    read mouse click
    (x,y) = position of mouse click
    if (mouse was clicked on the Draw button) drawRandomShape();
    else if (mouse was clicked on the Clear button) clearCanvas();
    else if (mouse was clicked somewhere on the canvas) drawShapeAtPosition(x, y);
    ...
}

但在 GUI 中，我们不会直接编写这样的代码，因为它不够模块化。 GUI 由各种库组件组合而成——按钮、滚动条、文本框、菜单——这些组件需要是自包含的并处理自己的输入。 在图形用户界面库的深处，有一个输入循环正在从鼠标和键盘读取，并将这些输入事件传递给 GUI 的适当组件。

为了使按钮在被点击时执行某些操作，你需要为其附加一个监听器（listener）：

drawButton.addEventListener('click', (event: MouseEvent) => {
  drawRandomShape();
});

GUI 事件处理是监听器模式（Listener pattern）的一个实例。 在监听器模式中：

  • 事件源产生一系列离散事件。
  • 一个或多个其他模块订阅（或监听）事件流，提供一个在新事件发生时将被调用的函数。

在这个例子中：

  • 按钮是事件源；
  • 它的事件是按钮按下；
  • 监听器是客户端提供的函数。

事件通常包含额外的信息，这些信息可能被打包到一个事件对象中（比如这里的 MouseEvent），或作为参数传递给监听器函数。

当事件发生时，事件源通过调用其监听器回调将其分发给所有已订阅的监听器。

因此，通过图形用户界面的控制流如下进行：

  • 事件循环从鼠标和键盘读取输入。在 HTML/JavaScript 中，像大多数其他 GUI 框架一样，这个循环实际上是对你隐藏的。它深埋在 JavaScript 运行时系统内部，监听器看起来像是被神奇地调用的。
  • 每个监听器做自己的事情（可能涉及例如修改用户界面中的对象），然后立即返回事件循环。

最后一部分——监听器尽快返回事件循环——非常重要，因为它保持了用户界面的响应性。

监听器设计模式不仅仅用于按钮按下。 每个 GUI 对象都会产生事件，通常是作为输入设备发送的某些低级输入事件组合的结果，比如鼠标、键盘或触摸屏。 例如，在 HTML 中：

  • 鼠标发送低级事件 mousedown（鼠标按钮被按下）和 mouseup（按钮被释放时）
  • 键盘在按下和释放键盘键时发送类似的低级事件 keydown 和 keyup
  • 按钮（<button>）在接收到 mousedown 和 mouseup 之后发送 click 事件。
  • 下拉菜单（<select>）当用户从下拉菜单中选择不同的元素时（无论是通过鼠标还是键盘）发送 input 事件
  • 文本框（<input type=text>）当其内部的文本发生变化时发送 input 事件，这是键盘或鼠标事件的结果。

事件源

监听器模式是一个通用的编程思想，它在 TypeScript/JavaScript 编程中以两种方式出现：

  • 在网页中，正如我们刚刚看到的，可以作为事件源的对象实现了 addEventListener() 方法，它是 EventTarget 接口的一部分。

  • 在 Node 中，事件源实现了 on() 方法，它是 EventEmitter 的一部分。而 addListener() 是 on() 的同义词。

addEventListener() 和 on()/addListener() 方法具有本质上相同的参数：一个命名事件类型的字符串，以及一个在事件发生时将被调用的回调函数。

监听器中的陷阱

监听器设计模式有一些常见的陷阱，特别是在 GUI 中使用时，了解这些陷阱很重要。

监听器应该快速运行并快速返回。 如果监听器函数通过执行长时间、缓慢的计算来响应事件，那么它会阻塞用户界面。由于监听器是由 GUI 事件循环调用的，在监听器返回之前，事件循环将无法继续处理输入事件。

例如，假设绘图按钮的监听器绘制了大量的随机图形：

drawButton.addEventListener('click', (event: MouseEvent) => {
    for (let i = 0; i < 1_000_000; i++) {
        drawRandomShape();
    }
});

绘制一百万个矩形可能涉及很长的停顿。 在那段时间里，网页看起来冻结了。 鼠标点击似乎不起作用，滚动不起作用，按键似乎没有被处理。 在许多平台上，操作系统会将鼠标指针变为沙漏或彩色旋转球，以显示用户界面已卡住。

一旦一百万个矩形最终全部绘制完成，监听器函数返回，事件循环就会恢复处理。 当你卡住时尝试的所有输入事件都被存储在队列中，所以它最终会赶上。

这里的教训是：在图形用户界面中，监听器函数必须快速运行并快速返回，通常在几毫秒内。

如果监听器需要执行长时间运行的计算，它应该使用我们在之前课上讨论过的并发。

注意循环。 有时需要有两个相互依赖的 GUI 元素，比如下面代码中的文本框和滑块：

Size: 
<div>
    Size:
    <input type="number" id="sizeTextbox" value="10" min="1" max="50" maxlength="2">
    <input type="range" id="sizeSlider" value="10" min="1" max="50">
</div>

在这个设计中，用户应该能够通过在框中输入数字或拖动滑块来改变大小。 无论哪种方式都应该更新另一个元素，使它们保持一致。 因此，很容易想附加这样的监听器，将值从文本框传播到滑块，反之亦然：

sizeTextbox.addEventListener('input', (event: ChangeEvent) => {
    // make the slider match the updated textbox
    sizeSlider.value = sizeTextbox.value;
});
sizeSlider.addEventListener('input', (event: ChangeEvent) => {
    // make the textbox match the updated slider
    sizeTextbox.value = sizeSlider.value;
});

这创建了一个监听器循环。 如果文本框发生变化，它的监听器通过修改滑块来响应，这反过来可能触发滑块的监听器，滑块监听器修改文本框，然后可能再次触发文本框监听器。 存在无限循环的风险。

在这个例子中，循环被规范打破了：input 事件被指定为仅在用户使用鼠标或键盘输入更改文本框或滑块的值时发送。由代码引起的值修改不会触发事件。所以在这种情况下没有无限循环，但你应该注意一般情况下的可能性。

最后，不要忘记清理。 你可能会在程序中到达一个想要停止监听的时刻。EventTarget 的 addEventListener() 和 EventEmitter 的 on()/addListener() 方法有对应的方法 removeEventListener() 和 off()/removeListener()。 在不再需要监听器时未能移除它们可能会减慢你的用户界面或导致 bug。

总结

  • 回调是一等函数的另一个例子，我们将函数视为数据对待：将它们传递给其他函数和从其他函数返回，并存储起来供以后调用。
    • 它们可以是同步的或异步的
  • TypeScript/JavaScript 使用事件循环和事件队列来存储事件和执行异步回调代码。
  • GUI 事件处理（例如 HTML）使用监听器模式，其中模块可以监听不同的事件并提供回调函数。
    • 监听器必须快速返回以将控制权交还给事件循环，并且不应与另一个监听器形成循环。

这些思想与我们优秀软件的三个关键属性关联如下：

  • 回调使代码更加为变更做好准备，因为它允许客户端提供自己的代码在事件运行时执行，这样行为就不必被预先硬编码到实现中。

  • 编写一个单一的巨型输入循环来处理大型系统中每个可能的事件，既不安全也不易理解：那一段代码变成了一个无所不知、无所不控的庞然大物。回调允许系统中的每个模块负责自己的事件。
