Hailstone 序列

作为一个贯穿始终的示例，我们将探索 Hailstone 序列，其定义如下： 从一个数字 n 开始，序列中的下一个数字是 n/2（如果 n 是偶数），或者 3n+1（如果 n 是奇数）。 当序列到达 1 时结束。 以下是一些示例：

2, 1
3, 10, 5, 16, 8, 4, 2, 1
4, 2, 1
2n, 2n-1 , … , 4, 2, 1
5, 16, 8, 4, 2, 1
7, 22, 11, 34, 17, 52, 26, 13, 40, …? （这个序列在哪里停止？）

由于奇数规则，序列在递减到 1 之前可能会上下波动。 人们推测所有的 Hailstone 最终都会落地——即对于所有起始值 n，Hailstone 序列都会到达 1——但这仍然是一个未解决的问题。 为什么叫 Hailstone 序列？ 因为冰雹在云层中形成时，会上下翻滚，直到最终积累足够的重量落到地面。

计算 Hailstone

下面是一些用于计算和打印 Hailstone 序列的代码，对于给定的起始值 n。 我们将同时编写 JavaScript 和 Python 版本的代码进行比较：

# Python
n = 3
while n != 1:
    print(n)
    if n % 2 == 0:
        n = n / 2
    else:
        n = 3 * n + 1


print(n)
// JavaScript（或 TypeScript，这段代码在两种语言中都能运行）
let n = 3;
while (n !== 1) {
    console.log(n);
    if (n % 2 === 0) {
        n = n / 2;
    } else {
        n = 3 * n + 1;
    }
}
console.log(n);

JavaScript 中表达式和语句的基本语义与 Python 非常相似。例如，while 和 if 关键字的行为是相同的。

这里有几个语法要点值得注意：

  • JavaScript 要求在 if 和 while 的条件周围加上括号。

  • JavaScript 语句以分号结尾。 这在技术上是可选的，因为 JavaScript 有在行尾自动插入分号的规则。但这些规则存在一些隐蔽的陷阱，可能导致意外的行为和错误，因此始终使用分号是一个好习惯。

  • JavaScript 使用花括号来包围代码块，而不是使用缩进。 但你仍然应该始终缩进代码块，即使 JavaScript 不会关注你额外的空格。编程是一种交流形式，你不仅要与编译器交流，还要与人类交流。人类需要那些缩进。我们稍后会回到这个话题。

你可能还会注意到，JavaScript 版本使用 === 和 !==，而 Python 使用 == 和 !=。 这是因为 JavaScript 中的 == 和 != 会进行各种自动类型转换，试图使左侧和右侧的值可以相互比较。 例如，0 == "" 在 JavaScript 中为 true，这令人惊讶且困惑。 这些操作符的三等号版本更安全、更可预测：0 === "" 为 false。 优秀的 JavaScript 程序员只会使用 === 和 !==。 这是从 Python 迁移时的一个潜在陷阱。

类型

但严格来说，我们在这门课中并没有使用 JavaScript。 我们使用的是 TypeScript，它扩展了 JavaScript，增加了在程序中声明类型的能力。 在这个例子中，我们可以指定变量 n 的类型为 number：

let n: number = 3;

一个 类型是一组值以及可以在这些值上执行的操作。

TypeScript 有几种内置类型，包括：

  • number，表示整数和浮点数
  • boolean，表示真或假
  • string，表示字符序列

操作是接收输入并产生输出的函数（有时也会更改输入值本身）。操作的语法各不相同，但无论它们如何书写，我们仍然将其视为函数。以下是 Python 或 TypeScript 中一个操作的几种不同语法：

  • 作为操作符。例如，a + b 调用操作 + : number × number → number。 （在这种表示法中：+ 是操作名称，箭头前面的 number × number 给出两个输入的类型，箭头后面的 number 给出输出的类型。）

  • 作为函数。例如，Math.sin(theta) 调用操作 sin: number → number。这里，Math 不是一个对象，而是包含 sin 函数的类。

  • 作为对象的方法。例如，str1.concat(str2) 调用操作 concat: string × string → string。

  • 作为对象的属性。例如，str.length 调用操作 length: string → number。注意 str.length 后面没有括号。

将 TypeScript 的 str.length 与 Python 的 len(str) 进行比较。在两种语言中，这是同一个操作——接收一个字符串并返回其长度——但它使用了不同的语法。

有些操作是重载的，这意味着相同的操作名称用于接收不同类型参数的函数。 操作符 + 在 TypeScript 中是重载的。 对于数字，5 + 3 自然产生 8。 但当 + 用于字符串时，它执行的是字符串拼接，因此 "5" + "3" 产生 "53"。 重载不仅限于 + 这样的操作符；方法和函数也可以被重载 （至少在某些编程语言中，包括 TypeScript）。

静态类型

TypeScript 是一种静态类型语言。变量可以在编译时（程序运行之前）被赋予一个类型，因此编译器可以推导出使用这些变量的表达式的类型。如果 a 和 b 被声明为 number，那么编译器会得出结论 a+b 也是 number。事实上，VS Code 环境在你编写代码时就会这样做，所以你可以在输入时看到所有相关的错误。

相比之下，JavaScript 和 Python 是动态类型语言，因为这种检查被延迟到运行时（程序运行时）。

静态类型是一种特殊类型的静态检查，即在编译时检查错误。错误是编程的祸害。本课程中的许多思想都旨在消除代码中的错误，而静态检查是我们为此看到的第一个思想。静态类型防止了大量错误感染你的程序：确切地说，是由将操作应用于错误类型的参数引起的错误。如果你写了一行像下面这样的错误代码：

"5" * "6"

试图将两个字符串相乘，那么静态检查会在你编程时捕获这个错误，而不是等到执行时才被发现。

编译时的静态类型，运行时的动态类型

静态类型声明在编译时用于执行静态检查。 添加静态类型不会改变这样一个事实：我们程序在运行时的行为由实际值驱动。 在 Hailstone 程序中，如果我们声明 let n: number = 3; 来指定 n 的静态类型，运行时的初始值仍然是 3，而不是其他任何 number。 当我们声明的静态类型包含多种可能的运行时类型时，我们需要记住这个区别：一个静态类型为 Animal 的变量（让我们想象一下）在运行时实际上可能是 Dog、Fish 或 SpottedOwl。

事实上，TypeScript——像许多静态类型语言一样——在编译后会丢弃静态类型信息。 TypeScript 编译器生成的是什么？JavaScript！ 下面是一段类型良好的 TypeScript 代码，以及生成的 JavaScript：

// 待编译的 TypeScript
function hello(name: string): string {
    return 'Hi, ' + name;
}
let greeting: string = hello('types');
// 生成的 JavaScript
function hello(name) {
    return 'Hi, ' + name;
}
let greeting = hello('types');      

动态类型语言中对静态类型的支持

正如 TypeScript 为动态类型的 JavaScript 语言添加了静态类型一样，Python 也有支持静态类型的扩展。 Python 3.5 及更高版本允许你在代码中声明类型提示，例如：

# 使用类型提示声明的 Python 函数
def hello(name: str) -> str:
    return 'Hi, ' + name

声明的类型可以被 Mypy 或 Pyright 等检查器使用，以在无需运行代码的情况下静态地查找类型错误。

为 Python 和 JavaScript 等动态类型语言添加静态类型，反映了软件工程师中普遍存在的信念，即使用静态类型对于构建和维护大型软件系统至关重要。 本阅读材料的其余部分，实际上整个课程，都将展示这一信念的理由。

为动态类型语言添加静态类型实现了一种称为渐进类型的编程方法，其中代码的某些部分有静态类型声明，而其他部分则省略了它们。 渐进类型可以为小型实验性原型成长为大型、稳定、可维护的系统提供更平滑的路径。

静态检查、动态检查、不检查

思考语言可以提供的三种自动检查是很有用的：

  • 静态检查：在程序运行之前自动发现错误。
  • 动态检查：在执行过程中自动发现错误。
  • 不检查：语言根本不帮助你发现错误。你必须自己留意，或者最终得到错误的答案。

不用说，静态捕获错误比动态捕获更好，而动态捕获又比根本不捕获要好。

以下是一些关于在每个阶段可以预期捕获哪些错误的经验法则。

静态检查可以捕获：

  • 语法错误，如多余的标点符号或无关的词语。即使是 Python 这样的动态类型语言也会进行这种静态检查。如果你的 Python 程序中有缩进错误，你会在程序开始运行之前就发现。
  • 拼写错误的名称，如 Math.sine(2)。（正确的拼写是 sin。）
  • 参数数量错误，如 Math.sin(30, 20)。
  • 参数类型错误，如 Math.sin("30")。
  • 返回类型错误，如从声明为返回 number 的函数中 return "30";。

一般来说，静态检查可以检测与变量的类型相关的错误——即它允许拥有的值集，在 TypeScript 等静态类型语言中，这在编译时是已知的——但通常无法发现与该类型中特定值相关的错误。

动态检查可以捕获，例如：

  • 特定的非法参数值。例如，当 y 为零时，表达式 x/y 是错误的，但对于 y 的其他值则是定义良好的。因此除零不是静态错误，因为在运行时之前你无法知道 y 是否确实为零。但除零可以作为动态错误被捕获；Python 会在发生除零时抛出 ZeroDivisionError。
  • 非法转换，即当特定值无法转换为目标类型或无法在目标类型中表示时。 例如，在 Python 中，int("hello") 抛出 ValueError，因为字符串 "hello" 无法解析为十进制整数。
  • 越界索引或缺失的键，例如对字符串或数组使用过大的索引。 在 Python 中，"hello"[13] 抛出 IndexError，{'a': 1}['b'] 抛出 KeyError。

但你可能已经注意到，上面的动态检查示例都来自 Python。 那 TypeScript 中的动态检查呢？ TypeScript 进行静态检查，但其运行时行为完全由 JavaScript 提供，而 JavaScript 的设计者决定对许多情况不进行检查。 因此，例如，当字符串或数组索引越界，或者在映射中找不到键时，JavaScript 返回特殊值 undefined，而不是像 Python 那样抛出错误。 当除以零时，JavaScript 返回表示无穷大的特殊值，而不是抛出错误。 不检查使得错误比本来更难发现，因为这些特殊值可以通过进一步的计算传播，直到最终在离代码中原始错误很远的地方才发生故障。

意外发现：number 不是真正的数字

TypeScript 中的另一个陷阱——许多其他编程语言也有同样的陷阱——是其数字类型具有一些不像我们习惯的整数和实数的边界情况。因此，一些确实应该被动态检查的错误根本没有被检查。以下是隐藏在 TypeScript 中的一些陷阱：

  • 整数的精度有限。TypeScript 中的所有数字都是浮点数，这意味着大数值的整数只能被近似表示。-253 到 253 之间（不含）的整数可以被精确表示，但超出该范围后，浮点表示只保留数字的最高有效二进制位。 如果你有比如说 260 并尝试将其加 1，会发生什么？你会得到相同的数字：在 TypeScript 中，2**60 + 1 === 2**60。 所以这是一个例子，说明我们可能希望是动态错误的情况（因为我们编写的计算无法被正确表示）反而产生了错误的答案。

    这些可表示整数的限制可以作为内置常量使用：

    • Number.MAX_SAFE_INTEGER（大约 253 或 1016）是最大可精确表示的整数
    • Number.MIN_SAFE_INTEGER（大约 -253 或 -1016）是最小可精确表示的整数


    在这些安全范围内的整数运算保证保持精确。

  • 特殊值。number 类型有几个不是实数的特殊值：

    • Number.NaN（表示"不是一个数字"）
    • Number.POSITIVE_INFINITY（打印为 "Infinity"）
    • Number.NEGATIVE_INFINITY（打印为 "-Infinity"）


    当你对 number 应用某些你期望会产生动态错误的操作时，比如除以零或对负数取平方根，你会得到这些特殊值之一。如果你继续用它计算，你最终会得到错误的最终答案。

  • 上溢和下溢。TypeScript 也无法表示太大（远离零）或太小（接近零）的数字：

    • Number.MAX_VALUE（大约 10308）是能够安全表示的最大数字
    • Number.MIN_VALUE（大约 10-324）是能够安全表示的最小正数


    当你进行一个计算，其答案太大或太小而无法容纳在该有限范围内时，会发生什么？计算会静默地上溢（变为 POSITIVE_INFINITY 或 NEGATIVE_INFINITY）或下溢（变为零）。

这些特殊的常量值以大写的 Number 开头，它是 number 的类包装器。 不要将 Number 用作类型——只使用它来访问这些常量。 当你声明类型时，始终使用小写的 number。

数组

让我们修改 Hailstone 计算，使其将序列存储在数据结构中，而不仅仅是打印出来。

为此，我们可以使用数组类型。数组是另一种类型的可变长度序列，类似于 Python 列表。以下是如何声明一个数字数组并创建一个空数组值：

let array: Array<number> = [];

下面是使用数组编写的 Hailstone 代码：

let array: Array<number> = [];
let n: number = 3;
while (n !== 1) {
    array.push(n);
    if (n % 2 === 0) {
        n = n / 2;
    } else {
        n = 3 * n + 1;
    }
}
array.push(n);

函数

如果我们想将这段代码包装成可重用的模块，我们可以编写一个函数：

/**
 * 计算 Hailstone 序列。
 * @param n  序列的起始数字。假设 n > 0。
 * @returns 以 n 开始、以 1 结束的 Hailstone 序列。
 */
function hailstoneSequence(n: number): Array<number> {
    let array: Array<number> = [];
    while (n !== 1) {
        array.push(n);
        if (n % 2 === 0) {
            n = n / 2;
        } else {
            n = 3 * n + 1;
        }
    }
    array.push(n);
    return array;
}

请注意函数前面的 /** ... */ 注释，因为它非常重要。这个注释是函数的规范，描述了操作的输入和输出。规范应该简洁、清晰、精确。注释提供了函数类型中尚未明确的信息。例如，它没有说返回值是一个数字数组，因为下面的 Array<number> 返回类型声明已经说明了这一点。但它确实说明了序列以 n 开始并以 1 结束，这是类型声明没有涵盖但对调用者来说很重要的信息。

我们将在接下来的几节课中详细讨论如何编写好的规范，但你现在就需要开始阅读和使用它们。

更改变量值 vs. 重新赋值变量

变化是必要的邪恶。 但优秀的程序员尽量避免变化的事物，因为它们可能会发生意外的改变。 不可变性——有意禁止某些事物在运行时发生变化——将是本课程中的一个重要设计原则。

不可变性有两个方面：值是可变的还是不可变的，以及引用（如变量）是否可以被重新赋值。

变更（Mutation）指的是改变值的内容。 不可变类型是指其值一旦创建就永远不能改变的类型。 字符串类型在 Python 和 TypeScript 中都是不可变的。 一旦创建了字符串，你就不能使其变短、变长或替换其中的任何字符。 你必须创建一个包含你想要更改的新字符串。

相比之下，数组类型在 TypeScript 中是可变的，就像列表在 Python 中是可变的样。 你可以更改数组或列表的内容——添加元素、删除元素或替换元素。

Python 也有不可变序列，即 元组（tuple），一旦创建就不能更改。 TypeScript 没有不可变元组，但它有 ReadonlyArray，这是一种省略了变更操作的数组类型。 当你在代码中使用 ReadonlyArray 作为类型时，你不能调用 push() 来添加元素，也不能调用 splice() 来删除元素，也不能像 arr[i] = ... 那样重新赋值元素。 TypeScript 会报告编译器错误，因为它在 ReadonlyArray 类型中找不到这些操作。

重新赋值（Reassignment）指的是改变变量指向的位置。 Python 允许任何变量被重新赋值，但 TypeScript 允许我们声明常量，即不可重新赋值的变量：只被赋值一次，之后永远不能被重新赋值。为了使引用不可重新赋值，使用关键字 const 而不是 let 来声明：

const n: number = 5;

如果 TypeScript 编译器不相信你的 const 变量在运行时只会被赋值一次，那么它会产生编译器错误。因此，const 为你提供了对不可重新赋值引用的静态检查。

尽可能使用 const 是一个好习惯。与变量的类型一样，这些声明是重要的文档，对代码的读者有用，并由编译器进行静态检查。

记录假设

写下变量的类型记录了一个关于它的假设：例如，变量 n 将始终引用一个数字。TypeScript 实际上会在编译时检查这个假设，并保证在你的程序中没有违反这个假设的地方。

将变量声明为 const 也是一种文档形式：一个声明该变量在初始赋值后永远不会被重新赋值的声明。TypeScript 也会静态地检查这一点。

我们记录了另一个 TypeScript（不幸的是）不会自动检查的假设：n 必须为正数。

为什么我们需要写下我们的假设？因为编程充满了假设，如果我们不写下来，我们就会忘记它们，其他将来需要阅读或修改我们程序的人也不会知道它们。他们将不得不猜测。

编写程序必须牢记两个目标：

  • 与计算机交流。首先说服编译器你的程序是合理的——语法正确且类型正确。然后确保逻辑正确，以便在运行时产生正确的结果。
  • 与其他人交流。使程序易于理解，以便当某人（可能是你自己）将来必须修复、改进或调整它时，他们能够做到。

黑客行为 vs. 工程实践

我们在本阅读材料中写了一些粗糙的代码。黑客行为通常以无节制的乐观为特征：

  • 不好：在测试任何代码之前编写大量代码。
  • 不好：把所有细节都记在脑子里，假设你（以及每个使用你代码的人）会永远记住它们，而不是把它们写在代码中。
  • 不好：假设错误不存在，或者即使存在也很容易发现和修复。

但软件工程不是黑客行为。工程师是悲观主义者：

  • 好：一次写一点，边写边测试。在以后的课程中，我们将讨论测试优先编程。
  • 好：记录你的代码所依赖的假设。
  • 好：保护你的代码免受愚蠢行为的侵害——尤其是我们自己的愚蠢！静态检查在这方面有帮助。

6.102 的目标

我们在这门课程中的主要目标是学习如何生产具有以下特性的软件：

  • 免受错误影响。正确性（当前的正确行为）和防御性（未来的正确行为）是我们构建的任何软件所必需的。
  • 易于理解。代码必须能够与需要理解它并进行更改的未来程序员交流（修复错误或添加新功能）。那个未来的程序员可能是几个月或几年后的你。如果你不写下来，你会惊讶于自己会忘记这么多，而一个好的设计对你自己的未来帮助有多大。
  • 适应变化。软件总是在变化。一些设计使更改变得容易；另一些则需要抛弃并重写大量代码。

软件还有其他重要属性（如性能、可用性、安全性），它们可能与这三个属性存在权衡。但这些都是我们在 6.102 中关注的三大属性，也是软件开发人员在构建软件实践中最重视的。值得思考我们在本课程中学习的每种语言特性、每种编程实践、每种设计模式，并理解它们与这三大属性的关系。

为什么我们在这门课中使用 TypeScript

由于你已经学过 6.101 [原 6.009]，我们假设你对 Python 感到舒适。那么我们为什么在这门课中不使用 Python 呢？为什么我们在 6.102 中使用 TypeScript/JavaScript？

安全性是第一个原因。TypeScript 具有静态检查（主要是类型检查，但也有其他类型的静态检查，比如检查你的代码是否从声明为返回值的函数中返回了值）。我们在这门课程中学习软件工程，而免受错误影响是该方法的核心原则。TypeScript 将安全性调到了很高的水平，这使它成为学习良好软件工程实践的好语言。当然，在 Python 或 JavaScript 等动态语言中编写安全代码也是可能的，但如果你在安全的、静态检查的语言中学习需要做什么，就会更容易理解。

普遍性是另一个原因。TypeScript 编译成纯 JavaScript，后者在研究、教育和行业中广泛使用。JavaScript 可以在许多平台上运行，不仅限于最初广泛使用的网络浏览器，现在还可以在网络服务器甚至 Windows/Mac/Linux 的桌面应用程序中运行。

与 Java 相比，TypeScript 具有更丰富的类型系统，编写程序需要更少的样板代码，并且是创建现代用户界面和 Web 应用程序的更好选择。事实上，TypeScript 的类型系统相当先进，使用它能够创建出令人意料的程序（其中一些相当非凡）。

无论如何，优秀的程序员必须是多语言的。编程语言是工具，你必须为工作使用正确的工具。在你完成 MIT 的学业之前，你很可能会因为课程、实习或 UROPs 而不得不学习其他编程语言（如 Java、C/C++、Scheme、Ruby 或 Haskell），所以我们现在让你开始学习第二门语言。

由于其普遍性，JavaScript 拥有大量有趣且有用的库和优秀的免费开发工具（如 VS Code 等 IDE、编辑器、编译器、测试框架、分析器、代码覆盖率工具、代码风格检查器）。JavaScript 和 Python 在生态系统丰富度方面是势均力敌的竞争者，而 TypeScript 可以充分利用 JavaScript 库。

使用 JavaScript 有一些令人遗憾的原因。它很庞大，在最初设计以来的几十年里积累了许多功能。它背负着 C/C++ 等较旧语言的包袱——switch 语句是从 C 继承的过时且不安全的语言结构的一个很好的例子。JavaScript 本身也有一些糟糕的设计决策，包括使 0 == "" 返回 true 和 [] + [] 以某种方式产生空字符串 的类型转换规则，以及比其他语言更少的动态检查。 TypeScript 修复了 JavaScript 中的一些缺陷，但不是全部。 JavaScript 中有许多部分现在已被弃用，程序员避免使用它们，因为它们使用起来有风险。

但总体而言，TypeScript 是目前学习如何编写免受错误影响、易于理解和适应变化的代码的合理选择。这就是我们的目标。

你从这门课程中获得的真正技能不是特定于某种语言的，而是可以迁移到你可能编程的任何语言中。这门课程最重要的经验教训将经受住语言潮流的考验：安全性、清晰性、抽象能力、工程直觉。

总结

我们今天介绍的主要思想是静态检查。以下是这个思想与课程目标的关系：

  • 免受错误影响。 静态检查通过在运行时之前捕获类型错误和其他错误来帮助提高安全性。

  • 易于理解。 它有助于理解，因为类型在代码中被明确说明。

  • 适应变化。 静态检查通过识别需要同时更改的其他位置，使更改代码变得更容易。
