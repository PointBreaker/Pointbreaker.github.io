6.101: 递归

引言

从某种意义上说，本周的阅读材料代表了一个关注点的轻微转变，因为我们即将进入一个新的主题。当然，我们目前为止讨论的那些概念并不会消失，但在接下来的几周里，我们将有一个不同的核心关注点：递归。

我们期望递归是大家在本课程先修课程中就应该接触过的内容，但在积累了一定的使用经验并理解其工作原理之前，递归可能会让人感到有些奇怪和不自在。因此，我们将在接下来的几周里花相当多的时间，以这个目标为导向：培养使用递归的熟练度和自信心，并加深对递归的理解。像往常一样，我们将从几个不同的角度来探讨这个问题——我们当然会研究如何在自己的程序中使用递归，但我们也会关注递归在幕后是如何工作的（从我们的环境模型的角度），同时讨论如何判断递归解决方案是否适合某个给定问题（或者是否其他方法可能更好）。

如果递归让你感到奇怪或不自在，也不必担心；这是一种很自然的第一反应，随着时间的推移和实践（我们计划在接下来的几次阅读、习题课和实验中提供这些），这个概念将不再那么令人望而生畏，并开始成为我们可以在自己程序中使用的真正强大的工具。

编程

事实证明，Python允许我们以递归方式定义函数（也就是说，我们可以用函数自身来定义函数）。作为一个例子，下面是上面阶乘定义的Python实现（注意它几乎是一个逐字翻译）：

def factorial(n):
    if n == 0:
        return 1
    else:
        return n * factorial(n-1)

我们可以尝试写得更简洁一些，但这个形式很好，可以展示这个定义与上面的数学定义之间的对应关系。这里有一些关键的要点需要注意：

  • 这是一个递归定义，因为计算 factorial 依赖于 factorial （也就是说，在某些情况下，函数在计算结果的过程中会调用自身）。

  • 我们有一个基准情况。当 n == 0, 时，我们可以在不进行任何递归的情况下计算出结果。

  • 我们有一个递归情况，它逐步向基准情况递减。

在我们继续讨论这在Python中如何工作之前，值得再次提及，根据你之前接触这些思想的程度不同，写这样一个函数可能会让你感到不自在。这里的怪异感的一个重要来源是，当我们在编写 factorial 时，我们在函数体中使用了 factorial，尽管 我们还没写完 factorial ！ 但是，正确的策略是在你已经拥有了一个完整、可工作的函数版本的假设下来编写你的递归情况，然后思考，在这些条件下，我该如何将那次递归调用的结果与其他东西结合起来，生成我感兴趣的结果？我们在这里不需要盲目自信；如果我们设计得当，已经设置好了基准情况，并且我们的递归调用正逐步向其中一个基准情况靠拢，那么一切都会顺利解决。

这里的另一个怪异感的来源是，在计算对 factorial, 的调用过程中，我需要再次调用 factorial ，而且可能调用很多次；每次调用都有自己独立的 n. 那么，我们如何确保Python能将这些东西分开处理而不混淆呢？

递归的实际应用

为了强化某些问题是天然递归的这一思想，让我们来看一个来自一个非常实用的程序的快速示例：CAT-SOOP，也就是正在运行你现在所浏览的这个网站的软件。CAT-SOOP是用Python编写的。它的任务之一是存储关于提交的以及使用过程中发生的其他事件的信息，因此它有一个 log 的概念，用于在磁盘上记录有关这些事件的信息。

我们不想过多地讨论CAT-SOOP如何进行日志记录，但系统中有一个与我们的讨论特别相关的部分：一个测试某个任意的Python值是否可以被存储在日志中的函数。

def can_log(x):
    """
    Checks whether a given value can be a log entry.
    Valid log entries are strings, ints, floats, complex numbers, bytestrings, None, or Booleans;
    _or_ lists, tuples, sets, frozensets, dicts, or OrderedDicts containing only valid log entries.
    """

看看这个函数的文档字符串（docstring）：它很好地描述了哪些值可以是有效的日志条目。 这个描述的哪些方面表明递归可能是实现这个函数的最佳方式？

文档字符串定义了什么是"有效日志条目"，而其定义方式依赖于有效日志条目的定义！

有效的日志条目是字符串、整数、浮点数等， 或者仅包含有效日志条目的列表、元组、集合等。

这样的定义在编程、数据表示以及整个软件系统中都是极其常见的。

我们该如何递归地实现它呢？首先注意到这个定义有一个基准情况：

    if isinstance(x, (str, bytes, int, float, complex, bytes, NoneType, bool)):
        return True

If x 是这些类型之一，那么我们就完成了，完全不需要再进行任何递归。

但是，我们还有这些递归情况：如果 x 是集合类型之一，比如列表、元组或集合，那么

    elif isinstance(x, (list, tuple, set, frozenset)):
        return all(can_log(v) for v in x)

注意，对 can_log 的递归调用被应用于集合中的每个元素。 （内置函数 all 测试一个可迭代对象的每个元素是否为真，因此它实际上是将所有这些递归调用的结果 ands 在一起。） 最重要的是，尽管集合中的那些元素 可能是简单的字符串或整数（基准情况），但它们也可能是列表、集合或其他集合本身，因此需要进一步的递归。无论嵌套多么复杂，递归实现都能自动处理。

我们还需要处理字典，每个（键,值）对需要两次递归调用：

    elif isinstance(x, (dict, OrderedDict)):
        return all((can_log(k) and can_log(v)) for k,v in x.items())

最后，还有第二个基准情况，即如果 x 不具备我们所检查的任何类型，那么它就不是一个有效的日志条目，因此我们需要返回 False. 这是完整的函数：

def can_log(x):
    """
    Checks whether a given value can be a log entry.
    Valid log entries are strings, ints, floats, complex numbers, bytestrings,
    None, or Booleans; _or_ lists, tuples, sets, frozensets, dicts, or
    OrderedDicts containing only valid log entries.
    """
    if isinstance(x, (str, bytes, int, float, complex, NoneType, bool)):
        return True
    elif isinstance(x, (list, tuple, set, frozenset)):
        return all(can_log(v) for v in x)
    elif isinstance(x, (dict, OrderedDict)):
        return all((can_log(k) and can_log(v)) for k,v in x.items())
    return False

这个函数的细节不如整体框架重要：这是一个实际问题，其问题结构使得递归解决方案自然而然地成为最简单、最合适的实现方式。

对列表求和

让我们深入研究另一个例子：对一组数字列表求和：

def sum_list(x):
    """
    Compute the sum of a list of numbers, recursively.

    pass

当然，我们可以使用内置函数 sum() 来做这个，或者我们可以写一个迭代解决方案，这也是 sum() 在底层做的事情：

def sum_list(x):
    out = 0
    for num in x:
        out += num
    return out

我们将在下一篇阅读材料中更多地讨论迭代与递归之间的权衡。 不过，现在让我们尝试用递归来完成所有事情。 从这些简单例子中获得的直觉将有助于处理更复杂的情况，即内置函数不存在或迭代解决方案不是最佳方法的情况。

我们可以在文档字符串中放入任意数量的文档测试，让我们再添加一个，看看当我们对一个空列表求和时会发生什么：

def sum_list(x):
    """
    Compute the sum of a list of numbers, recursively.

    >>> sum_list([1,2,3,4,5])
    15
    >>> sum_list([])
    0
    """
    if len(x) == 1:
        return x[0]
    else:
        return x[0] + sum_list(x[1:])

糟糕！我们遇到了一次失败。你能看出为什么出了问题吗？我们将在下一节中看看如何修复它。

关于文档测试有一个重要的警告：它通过检查打印输出来工作，而不是使用 == 来比较预期值和实际值（这是我们在其他类型的测试中使用 assert 时所做的事情）。这有两个不幸的影响：

  • 如果你在代码中放入任何 print 语句来调试代码，那些打印语句会导致文档测试失败，因为文档字符串中不会将它们列为预期输出。为了使测试再次通过，你必须移除或注释掉所有调试用的打印语句。
  • 如果输出中存在任何无害的差异——例如，集合或字典的打印顺序——那么测试也会失败，即使集合或字典实际上是正确的。我们将在下面看到一种处理这个问题的方法。

话虽如此，在函数的文档中直接包含可执行测试用例的便利性和可理解性可能是一个很大的优势。

正确处理基准情况

让我们添加一个基准情况来处理空列表：

def sum_list(x):
    if len(x) == 0:
        return 0
    elif len(x) == 1:
        return x[0]
    else:
        return x[0] + sum_list(x[1:])

现在代码可以工作了，但是，如果我们再仔细思考一下，我们是否需要 both 这些基准情况呢？不需要！既然我们已经正确处理了长度为0的列表，那么长度为1的基准情况就与递归情况冗余了。 为了更清楚地看到这一点，我们可以想象为长度2、长度3等等都设置基准情况：

def sum_list(x):
    if len(x) == 0:
        return 0
    elif len(x) == 1:
        return x[0]
    elif len(x) == 2:
        return x[0] + x[1]
    elif len(x) == 3:
        return x[0] + x[1] + x[1]
    else:
        return x[0] + sum_list(x[1:])

这段代码不够DRY（也就是说，它没有遵循"不要重复自己"的原则）。冗余的基准情况越多，bug可以隐藏的地方就越多。（事实上，这个例子中 is 确实隐藏着一个bug——你能看出来吗？）

因此，让我们将基准情况和递归情况简化到最少。我们还会用更具Python风格的方式来编写空列表测试，因为空列表是假值（falsy）：

def sum_list(x):
    if not x:
        return 0
    else:
        return x[0] + sum_list(x[1:])

对嵌套列表求和

现在让我们思考一个稍微不同的问题：对一组数字列表求和，其中数字可能嵌套在子列表中，深度可以是任意的：

def sum_nested(x):
    """
    >>> sum_nested([[1, 2], [3, [4, 5]], [[[[[6]]]]]])
    21
    """
    pass

子列表可以深入到任意深度这一事实使得这个问题感觉很难。 幸运的是，空列表仍然是我们的基准情况：

if not x:
    return 0

但是递归情况呢？从 sum_list, 改编的递归情况——即剥离第一个元素，然后将其加到剩余元素的递归和中——在这里行不通：

return x[0] + sum_nested(x[1:])

它行不通的原因是第一个元素 x[0] 不仅仅是一个数字；它可能是一个列表。如果它是一个列表，我们需要做不同的事情，将子列表 x[0] 转换成一个可以加到从 sum_nested(x[1:]) 得到的数字上的数字。

因此，让我们尝试用另一个 if 测试来区分这两种情况：

if isinstance(x[0], list):
    return SOMETHING + sum_nested(x[1:])
else:
    return x[0] + sum_nested(x[1:])

现在，我们有两个递归情况：一个在第一个元素是列表时使用，另一个在第一个元素只是一个数字时使用。 第二种情况我们可以像以前一样处理。但是，当 SOMETHING be, when x[0] 是一个子列表时，SOMETHING 应该是什么？我们可能尝试提取那个子列表的元素：

if isinstance(x[0], list):
    return x[0][0] + sum_nested(x[1:])

但如果子列表包含多个元素（或少于1个元素），这就不正确了！ 我们可能会退回到迭代方式：

if isinstance(x[0], list):
    subtotal = 0
    for x in x[0]:
        subtotal += x
    return subtotal + sum_nested(x[1:])

但我们正在尝试递归地解决这个问题，更糟糕的是，这也不行！ x 在这里能保证是一个数字吗？不能，它本身可能是另一个子列表。 x[0] 可能在其内部包含任意深度的子列表！

让我们退一步。我们已经有一种方法来对 x[0] 求和，如果它是一个任意深度的列表列表的话。那个方法就是 sum_nested 本身！我们只需要全身心投入并信任递归：

if isinstance(x[0], list):
    return sum_nested(x[0]) + sum_nested(x[1:])

同样，这似乎很神奇。我们现在在同一行中使用了两次 sum_nested ！为什么这不会导致无限地调用自身而永远不返回呢？关键是要注意到，每次对 sum_nested 的递归调用所使用的列表在某个方面严格地 smaller or simpler in some respect, 朝着由基准情况所代表的最小值前进。在这里，我们将原始的嵌套列表拆成了两个部分， x[0] and x[1:], 两者都更小。

这是完整的代码：

def sum_nested(x):
    """
    >>> sum_nested([[1, 2], [3, [4, 5]], [[[[[6]]]]]])
    21
    """
    if not x:
        return 0
    elif isinstance(x[0], list):
        return sum_nested(x[0]) + sum_nested(x[1:])
    else:
        return x[0] + sum_nested(x[1:])

为问题选择正确的拆分方式

找到将问题分解为更小的步骤的正确方法是编程的一个重要组成部分，而对于某些问题来说，递归是一种优雅而简单的分解方式。假设我们想要实现这个函数：

def subsequences(seq):
    """
    Given a tuple or list or other iterable, returns a set of tuples
    consisting of all its subsequences.
    A subsequence is a sequence of elements from seq that are in the same
    order as in seq but not necessarily adjacent.

    >>> subsequences([4,2,3])
    {(4, 2, 3), (4, 2), (4, 3), (2, 3), (4,), (2,), (3,), ()}
    """
    pass

{(4,2,3), (4,2), (4,3), (2,3), (4,), (2,), (3,), ()}
{(4,), (4,2), (4,3), (4,2,3), (2,), (2,3), (3,), ()}
{(), (2,), (2,3), (3,), (4,), (4,2), (4,2,3), (4,3)}

……但只有第一个能通过我们编写的文档测试。因此，让我们做一个小改动，将输出放入 canonical 形式中，在这个例子中就是将元组按排序顺序放置。为此，我们必须打印一个列表而不是一个集合：

def subsequences(seq):
    """
    ...
    >>> sorted(subsequences([4,2,3]))
    [(), (2,), (2, 3), (3,), (4,), (4, 2), (4, 2, 3), (4, 3)]
    """
    pass

注意，元组是按字典序排序的，即一次比较一个元素，一旦某个元素不同或者某个元组没有更多元素时就停止（在这种情况下，较短的元组胜出）。

这个例子表明，文档测试不一定只能是对函数的单一调用——它也可以做其他一些工作，以使测试对无害的差异更加宽容。

但是，请记住，尽管我们的文档测试为了打印的一致性将集合转换为排序后的列表， subsequences 函数本身仍然只是在处理集合。

实现子序列的一种方法

The subsequences 问题适合一种优雅的递归分解。考虑 seq 的第一个元素。我们可以形成一组跳过该元素的子序列，以及另一组 skip 包含该元素的子序列，使用后剩余元素的子序列。这两组生成了原始输入的所有可能子序列：

def subsequences(seq):
    if not seq:
        # base case
        return {()}
    else:
        # recursive case
        first = seq[0]
        rest = seq[1:]
        result = set()
        for subseq in subsequences(rest):
            result.add((first,) + subseq)
            result.add(subseq)
        return result

我们可能尝试用一行来编写 result 集合的计算，像这样：

result = ({(first,) + subseq for subseq in subsequences(rest)} | 
            {subseq for subseq in subsequences(rest)})
return result

选择正确的递归子问题

让我们再看另一个例子。假设我们想要将一个整数转换为给定进制下的字符串表示，遵循以下规范：

def number_to_string(n, b):
    """
    Given an integer n and base b (where 2 <= b <= 10),
    returns n represented as a string in base-b notation,
    without any unnecessary leading zeroes.

    >>> number_to_string(-829, 10)
    "-829"
    >>> number_to_string(5, 2)
    "101"
    >>> number_to_string(0, 10)
    "0"
    """

让我们开发这个函数的递归实现。这里有一个递归情况是简单的——我们可以通过递归调用处理对应正整数的表示来简单地处理负整数：

if n < 0:
    return "-" + number_to_string(-n, b)

这表明，递归子问题可以以比仅仅是数值参数的值或列表参数的大小更微妙的方式变得更小或更简单。我们仍然有效地缩小了问题的范围，将其从所有可能的整数缩小到了仅正整数。

下一个问题是，假设我们有一个正 n, say n = 829 in base 10, ，我们应该如何将其分解为一个递归子问题？像我们在纸上写数字那样来思考这个数字，我们可以从8（最左边或最高位的数字）开始，也可以从9（最右边或最低位的数字）开始。从左端开始似乎很自然，因为那是我们书写的方向，但在这种情况下更难，因为我们需要首先找出数字的位数，以便确定如何提取最左边的数字。相反，分解 n 的更好方法是取它对 b (which gives the rightmost 数字），同时除以 b （这给出了子问题，即剩余的高位数字）：

digits = "0123456789"
return number_to_string(n // b, b) + digits[n % b]

一般来说，思考几种分解问题的方法，并尝试编写递归情况。你想要找到能产生最简单、最自然递归情况的那个。

接下来需要确定基准情况是什么，并包含一个 if 语句来区分基准情况和这个递归情况。这就是该函数：

def number_to_string(n, b):
    """
    Given an integer n and base b (where 2 <= b <= 10),
    returns n represented as a string in base-b notation.

    >>> number_to_string(-829, 10)
    "-829"
    >>> number_to_string(5, 2)
    "101"
    >>> number_to_string(0, 10)
    "0"
    """
    digits = "0123456789"
    if n < 0:
        return "-" + number_to_string(-n, b)
    elif IS_BASE_CASE:
        BASE_CASE
    else:
        return number_to_string(n // b, b) + digits[n % b]

总结

我们在这里研究了几个函数，并展示了如何用递归方式编写它们，有时以不同的方式。 在这个过程中，我们了解到：

  • 每个递归函数都需要一个或多个基准情况和一个或多个递归情况
  • 递归情况应该以某种方式使问题变得更小或更简单

在这篇阅读材料中，我们紧密关注递归，目标是用递归来编写每个函数，即使存在 iterative 的方法时也是如此。 下周的阅读材料将更深入地探讨递归与迭代的问题，展示它们是可以互换的（每个迭代算法都可以改写为递归，反之亦然），并讨论何时使用一种或另一种更为自然。
