学习目标

本阅读材料讨论使用 promise 进行并发计算。

我们从最高层的抽象开始，即 promise 抽象，以及 await 操作符和 async 函数声明，它们使得 TypeScript 中的并发计算以非常接近熟悉的同步编程的方式运行。

接下来我们将深入底层，进一步了解 Promise、await 和 async 的工作原理。

Promises

Promise 表示一个已经启动但其结果可能尚未就绪的并发计算。 这个名称来源于这样一个概念：它承诺在未来的某个时刻完成计算并提供一个结果。

TypeScript 中的 Promise 类型是泛型的：Promise<T> 表示一个并发计算，它应在某个时刻产生一个类型为 T 的值。

以下是使用 promise 进行并发计算的示例。（其中一些是 Node 包实际提供的函数；另一些目前不作为库函数存在，但可以轻松实现。）

  • readFile(pathname: string, ...) 返回一个 Promise<string>。文件被并发加载，它最终承诺产生的值就是文件的内容。
  • diskSpace(folder: string) 返回一个 Promise<number>。文件系统中的文件夹树在后台被遍历，其所有文件的大小被累加，得到的字节数就是承诺的结果。
  • fetch(url: string) 返回一个 Promise<Response>。URL 在后台被打开，承诺的结果是一个 HTTP Response 对象。
  • timeout(milliseconds: number) 返回一个 Promise<void>。一个计时器运行给定的毫秒数，承诺的结果类型为 void（与不返回结果的函数相同）。这看起来可能像一个空的 promise（哈），但我们马上就会看到，即使是空的 promise 也很有用，因为我们可以在 timeout 计算完成时触发额外的计算。

重要的是，这些函数中的每一个都会几乎立即返回其 promise。 函数启动一个长时间运行的计算，比如加载网页或扫描文件系统，但不会等待该计算完成。 它不返回计算得到的值，而是返回与其启动的并发计算相关联的 promise。 当计算完成时，其结果将通过该 promise 可访问。

这让我们能做什么？我们能从 promise 中获得的一个好处是并发性：通过启动多个计算并收集每个计算的 promise，这些计算可以彼此并发地进行：

const promise1 = fetch('http://www.mit.edu/');
const promise2 = fetch('http://www.harvard.edu/');
const promise3 = fetch('http://www.tufts.edu/');
// 我们现在已经开始并发地尝试联系所有三个 Web 服务器

更具体地说，Promise<T> 是一个具有三种状态的可变值：

  • pending（待定）：与该 promise 关联的计算尚未完成。
  • fulfilled（已兑现）：计算已完成，promise 现在持有计算产生的类型为 T 的值。
  • rejected（已拒绝）：计算因某种原因失败，promise 现在持有描述该失败的 Error 对象。

Promise 起始于 pending 状态，最终转变为 fulfilled（如果计算完成）或 rejected（如果计算抛出异常）。 它也可能永远保持在 pending 状态（例如，如果计算正在等待一个永远不会发生的事件）。 一旦 promise 变为 fulfilled 或 rejected，它将保持在该状态；无法将 promise 重置回 pending 状态。

如果你为了调试目的打印一个 promise，你会看到它的状态以及存储在其中的结果（如果它不再是 pending 状态）。 例如，在 npx ts-node TypeScript 提示符下，你可以立即打印一个 promise 来查看它的 pending 状态：

> const promise = fs.promises.readFile('account', { encoding: 'utf-8' }); console.log(promise);
Promise { <pending> }

假设文件 account 包含 200（代表一个有 $200 的银行账户），那么你的下一条命令应该会看到 promise 已被 fulfilled（因为相对于你的打字速度，加载文件所需的时间非常短）：

> console.log(promise);
Promise { '200' }

另一方面，如果文件 account 不存在，你会看到 promise 已被 rejected。通常会被抛出的异常对象被存储在 promise 中：

> console.log(promise);
Promise {
  <rejected> [Error: ENOENT: no such file or directory, open 'account'] { ... }
}

Await

我们已经了解了如何启动并发计算并获取与之关联的 Promise 值。 那么我们如何与这些计算产生的最终值进行交互呢？ 一种简单的方式是使用 await 关键字：

const promise: Promise<string> = fs.promises.readFile('account', { encoding: 'utf-8' });
const data: string = await promise;
// data 现在是 '200'

await 关键字是一个内置操作符，将类型为 Promise<T> 的值转换为类型为 T 的值。 它会等待直到 promise 被 fulfilled，然后解包 promise 以提取承诺的值。 如果 promise 被 rejected，则 await 会抛出异常，使用计算存储在 promise 中的 Error 对象。

请注意，await 并不是在触发 promise 所代表的计算。 计算已经在进行中！ 它是由最初产生该 promise 的函数启动的。 当执行到达 await 时，计算可能已经取得了一些进展，甚至可能已经完成。

对 await 更好的心智模型是：它在处理产生 promise 的函数的一个延迟返回。 await 等待计算完成，然后提供其返回值，或者抛出的异常，就像正常函数调用的结果一样。

使用 await，现在我们可以获取我们启动的并发计算的结果了：

const promise1: Promise<Response> = fetch('http://www.mit.edu/');
const promise2: Promise<Response> = fetch('http://www.harvard.edu/');
const promise3: Promise<Response> = fetch('http://www.tufts.edu/');
// 我们现在已经开始并发地尝试联系所有三个 Web 服务器

const response1: Response = await promise1;
const response2: Response = await promise2;
const response3: Response = await promise3;
// 我们现在已收到所有三个服务器的初始响应
// （除非其中一个失败并抛出了异常）

请注意，有一种更好的方式来处理等待多个 promise 的情况，即使用 Promise.all()，我们将在本阅读材料的后面讨论。

现在我们明白了为什么即使是空的 promise 也很有用，就像返回值为 void 的函数一样：

const promise: Promise<void> = timeout(2000);
// 启动了一个 2000 毫秒的计时器

await promise;
// 没有有用的返回值，但是——现在我们知道确实已经过去了 2000 毫秒

请注意，void 是与 undefined 不同的类型，我们一直在其他上下文中使用 undefined 来表示"没有有用的值"的概念。void 类型被设计为不返回任何内容的函数的返回类型。这就是为什么我们对不会产生值的计算使用 Promise<void>，它们只是为了某种副作用而运行（比如计时器延迟）。相比之下，undefined 表示值的缺失，区别在于 void 告诉其他程序员该函数不应该被用于其返回值，而 undefined 告诉其他程序员值的缺失是重要的。

异步函数

我们一直在使用的返回 promise 的函数——readFile、fetch、timeout——都是异步函数的例子。 异步函数是在其计算完成之前就将控制权返回给调用者的函数。

与之对比，更熟悉的同步函数在其计算完成后才返回控制权，此时其返回值已经可知。 到目前为止，我们在课程中使用的几乎每个函数都是这样的同步函数。

在现代 TS/JS 编程中，使用 promise 时，异步函数可以使用 async 关键字声明，且必须具有返回类型 Promise：

async function getBalance(): Promise<number> {
    const data: string = await fs.promises.readFile('account', { encoding: 'utf-8' });
    const balance: number = parseInt(data);
    if ( isNaN(balance) ) throw new Error('account does not contain a number')
    return balance;
}

请注意，async 函数的主体可以像同步函数一样使用 return 和 throw 语句。 这些会自动转换为对函数 promise 的影响。 return balance 语句用 balance 的值来兑现 promise，而 throw 语句则用给定的 Error 对象来拒绝 promise。

由于 getBalance() 是一个返回 promise 的异步函数，getBalance() 的调用者需要适当地与 promise 进行交互，即使用 await：

const myBalance = await getBalance();

请注意，await 不能在同步函数内部使用（即未声明为 async 的函数）。 TypeScript 会静态检查此要求。 如果 await 出现在非 async 函数内部，它将产生一个静态错误。

顶层 await

我们上面已经看到，await 不能在同步函数中使用；函数必须声明为 async 才能使用 await。

但是顶层代码，即在任何函数之外的代码呢？考虑之前的练习，我们不得不将同步函数从 g 到 f 一直到入口函数 main 都改为 async 函数。但在顶层代码的某个地方，我们需要有一个对 main 的调用作为启动的起点：

async function main(): Promise<void> { ... }
...
main();  // 我们如何处理 main() 返回的 promise？

当周围没有函数可以标记为 async 时，我们能否将这行改为 await main()？

不幸的是，答案取决于代码将运行在哪种 JavaScript 上下文中。 在作为现代 JavaScript 模块（也称为"ECMAScript 6 模块"或"ES6 模块"，以引入模块的 JavaScript 标准版本命名）编译和运行的代码中，你可以在顶层代码中使用 await，其行为与在 async 函数内部完全一样：

async function main(): Promise<void> { ... }
...
await main();  // 等待 main() 完成后再继续——适用于现代 ES6 模块上下文

我们在 6.102 中的代码尽可能地使用这些新模块，因此 await 在顶层是有效的。

不幸的是，在较旧的 JavaScript 上下文中，顶层脚本是同步运行的，不允许使用 await，因此 await main() 会产生错误。 如果你发现自己处于那种上下文中，最好的做法是将所有顶层代码放在一个异步 main 函数内部（我们在这里已经这样做了），并在不等待其 promise 的情况下调用它。 这是否意味着程序会立即退出，在 promise 被 fulfilled 之前？ 不会——事实证明 node 本身会跟踪未完成的 promise，进程在 main() 返回的 promise 被 fulfilled 或 rejected 之前不会退出。因此，如果你只是在顶层调用一个函数，await 不是必需的。

根据你的配置，你可能在编译时仍然会收到一个警告，提示你没有处理 promise 的返回值，因此你可以通过在调用前加上 void 操作符来声明你不打算处理它：

async function main(): Promise<void> { ... }
...
void main();  // 调用 main() 但不等待其完成——适用于所有 JavaScript 上下文

并发模型

让我们更深入地了解异步函数是如何被 JavaScript 运行时系统执行的，运行时系统是运行 JavaScript 代码和管理 JavaScript 环境的解释器。（在本课程中，我们主要使用 Node 作为运行时系统，但也存在其他运行时，如 Deno、Bun，或者你正在查看本阅读材料的 Web 浏览器。）

JavaScript 每个全局环境只有一个控制线程。（虽然 Worker 会创建一个新线程，正如我们在之前的阅读材料中看到的，但每个 worker 获得一个全新的全局环境，通常通过消息传递与其他 worker 或主程序通信，而不是通过在内存中直接共享可变对象。）

这引发了一些问题：如果 JavaScript 环境中只有一个线程，那么同时有多个异步函数在进行意味着什么？在异步函数将 promise 返回给其调用者之后、在其计算完成之前，它何时以及如何重新获得控制权，以便它能够继续计算并最终兑现或拒绝 promise？

让我们通过一个示例来看看这是如何工作的，该示例从两个银行账户获取余额并将它们相加：

async function totalBalance(): Promise<number> {
    const checkingPromise = getBalance('checking');
    const savingsPromise = getBalance('savings');
    return (await checkingPromise) + (await savingsPromise);
}

async function getBalance(account: string): Promise<number> {
    const data: string = await fs.promises.readFile(account, { encoding: 'utf-8' });
    return parseInt(data);
}

假设客户端调用 totalBalance()。 以下是发生的事情。 （你可以将鼠标悬停在下面文本的每个步骤上，查看右侧对应的代码高亮。）

  1. totalBalance 调用 getBalance('checking')，后者调用 readFile，readFile 开始读取文件并立即返回一个 Promise<string> 用于文件内容。
  2. getBalance('checking') 到达该文件 promise 的 await，这意味着它必须放弃控制权。它为自己的结果构造一个新的 Promise<number>，并将该 promise 返回给其调用者 totalBalance。
  3. totalBalance 暂时没有等待那个 promise，而是将其存储在 checkingPromise 中，继续调用 getBalance('savings')。
  4. getBalance('savings') 以同样的方式演进，到达其 await 并返回一个储蓄账户余额的 promise，totalBalance 将其存储在 savingsPromise 中。
    • 请注意，totalBalance 现在已经创建了两个并发计算，一个加载支票账户，另一个加载储蓄账户。通过持有它们的 promise 并将 await 留到后面，它允许计算独立运行，而不是强制一个在另一个开始之前就完成。这就是基于 promise 的并发的本质。
  5. totalBalance 必须 await 每个 promise 才能计算最终的总和。TypeScript/JavaScript 从左到右计算表达式（并非所有语言都如此……），所以 await checkingPromise 会先发生。由于 checkingPromise 仍然是 pending 状态，这意味着 totalBalance 为自己的最终结果构造一个新的 Promise<number>，并将该 promise 返回给原始调用者。
  6. 原始调用者（未显示）继续执行。为了使 JavaScript 的并发模型正确工作，我们依赖调用者最终将控制权交还给 JavaScript 运行时系统（我们代码起始点的原始调用者）。运行时系统处理底层操作，如文件加载。
  7. 假设储蓄文件先完成加载，其 promise 以字符串 "200" 兑现。然后 JavaScript 运行时系统将控制权交给 getBalance('savings')，它一直在等待该 promise，执行以 await 求值为 "200" 恢复。getBalance('savings') 完成执行，用数字 200 兑现 savingsPromise，并将控制权交还给运行时系统。但 totalBalance 没有在等待 savingsPromise（暂时没有），所以没有进一步的事情发生。
  8. 支票文件完成加载，以字符串 "50" 兑现。运行时系统将控制权交给 getBalance('checking')，后者用数字 50 兑现 checkingPromise，并将控制权交还给运行时系统。
  9. 由于 totalBalance 一直在等待 checkingPromise，运行时系统以值 50 将控制权交给 totalBalance。然后 totalBalance 执行 await savingsPromise，所以它再次将控制权交给运行时系统。但因为 savingsPromise 已经以值 200 兑现，运行时系统会很快（可能立即）再次交还控制权。totalBalance 继续自己的计算，最终以总和 250 兑现自己的 promise。

这个示例揭示了关于控制流的一些高层次要点：

  • 每个 await 都是异步函数放弃控制权的地方。
  • 对于异步函数中的第一个 await，"放弃控制权"意味着将函数自己的 promise 返回给其调用者。后续的 await 直接将控制权交还给运行时系统。
  • 当 await 恢复时，控制权从运行时系统返回。
  • 异步函数实际上被分割成 await 之间的计算片段，这些片段可以与其他异步函数调用的片段交错执行。

这种并发模型被称为协作式或非抢占式。 只有一个控制线程，并发计算必须协作在明确定义的点（如 await 和 return）相互释放控制权。

请注意，await 总是放弃控制权，即使它要等待的 promise 已经被 fulfilled。 在这种情况下，它可能几乎立即重新获得控制权，但首先它给了其他并发计算继续执行的机会。

这是一个好时机来观察异步函数中的 await 与生成器函数中的 yield 在行为上的相似性。两者都放弃控制权（即，暂时暂停运行该函数），但准备好在某个事件发生时立即恢复函数。对于使用 await 的异步函数，函数在其等待的 promise 被 fulfilled 后恢复运行。对于使用 yield 的生成器函数，函数在其调用者请求序列中的下一个值时（例如通过调用 next()，或通过 for 循环循环）恢复运行。异步函数和生成器函数都被视为协作式并发的例子。

还值得澄清的是，"一个控制线程"意味着只有一个线程在运行我们的 TypeScript/JavaScript 代码。但是 JavaScript 运行时系统内部可能使用其他线程来处理网络连接、渲染网页、读写文件系统等。这些其他线程可能导致 promise 被 fulfilled（例如 readFile() 或 fetch() 返回的 promise），但等待那些 promise 的代码直到单个 JavaScript 执行线程准备好关注它们时才会恢复运行。

聚合 Promise

当运行多个并发计算时，通常需要使用类似 AND 和 OR 的操作来组合它们的 promise。

Promise.all() 类似于逻辑 AND——它将一个可迭代的 promise 集合组合成一个单一的 promise，等待所有 promise 都被 fulfilled，并返回它们结果的数组：

const allResponses: Array<Response> =
  await Promise.all( [ fetch('http://www.mit.edu/'),
                       fetch('http://www.harvard.edu/'),
                       fetch('http://www.tufts.edu/') ] );

但如果任何一个单独的 promise 失败，整个 Promise.all() 也会失败。

对于逻辑 OR，Promise.any() 产生一个 promise，等待任何一个单独的 promise 成功 fulfilled（并返回该 promise 的结果），只有在所有 promise 都失败时才失败。 你可以用它来运行可能独立失败的冗余计算：

const firstResponse: Response =
  await Promise.any( [ fetch('http://www.mit1.edu/'),
                       fetch('http://www.mit2.edu/'),
                       fetch('http://www.mit3.edu/') ] );

Promise.race() 是一个逻辑 OR，等待任何一个单独的 promise fulfilled 或 rejected，并以同样的方式立即 fulfilled 或 rejected。 Promise.race() 的一个用途是为操作设置超时：

const responseOrTimeout: Response|void =
  await Promise.race( [ fetch('http://www.mit.edu/'),
                        timeout(5000) ] );

永远不要忙等待

我们已经看到 Promise 有一个观察者操作 await，它让客户端获取 promise 的值（并且总是放弃控制权，必要时等待 promise 被 fulfilled）。

但是没有方法可以直接查询 promise 的状态（"你还在 pending 吗？"），或者在不放弃控制权的情况下提取其值。

这些操作没有被提供是有充分理由的。 如果提供了这些操作，promise 的客户端可能会忍不住忙等待，等待 promise 被 fulfilled。 忙等待意味着坐在一个紧密的循环中等待某个事件发生，而不放弃控制权。 例如，这是一个忙等待计时器：

async function busyWait(milliseconds: number): Promise<void> {
    const now = new Date().getTime(); // new Date().getTime() 始终是当前时钟时间（毫秒）
    const deadline = now + milliseconds;
    while (new Date().getTime() < deadline) {
        // 什么都不做，只是忙等待直到系统时钟时间达到 deadline
    }
}

从狭义上讲，这段代码是有效的，调用 busyWait(500) 确实会等待 500 毫秒，其 promise 会在该时间过后被 fulfilled。 但因为 busyWait 在这段时间内从未释放控制权——注意它的循环体中完全没有 await——程序中没有其他异步函数会在这段时间内有机会运行。 我们永远不会回到 JavaScript 运行时系统来将控制权交给它们。 程序将简单地冻结，直到 busyWait() 的整个函数体完成并返回。 所以 busyWait() 作为异步函数是相当无用的——它不能与任何其他异步代码并发运行。

如果 Promise 提供了 await 以外的观察者，那么程序员会忍不住写出这样的忙等待代码：

const promise = readFile('account', { encoding: 'utf-8' });
while ( promise.isPending() ) { // 假设的，isPending() 不存在
  // 忙等待！坏主意
}
const data: string = promise.get() // 假设的，get() 不存在

这段代码不仅会冻结程序，甚至不能完成程序员想要做的事情。 忙等待循环从不放弃控制权，这意味着我们从不回到处理文件输入/输出的顶层运行时系统。 所以 readFile() 永远不会将其 promise 标记为 fulfilled，假设的 promise.isPending() 操作永远不会返回 false，我们永远无法退出忙等待循环。

忙等待在并发编程中通常是一个坏主意（除了少数罕见的例外，如自旋锁），但它对 promise 和 async/await 代码尤其致命。 相反，应该使用 await 来操作 promise 的值，或对其从 pending 到 fulfilled 的状态转换做出反应。

Promise 与异常处理

本阅读材料的大部分内容集中在正常情况上：async 函数返回一个值，该值被存储在（并兑现）其关联的 promise 中，然后返回值由等待该 promise 的 await 表达式产生。

但理解异步编程中错误是如何处理的也很重要：

  • 当 async 函数抛出异常时，promise 变为 rejected 状态，异常对象被存储在关联的 promise 中。
  • 等待该 promise 的 await 表达式现在能够继续执行，但它不是提供值，而是继续抛出该异常。

一种理解方式是，await 提供异步函数的结果，无论该结果是返回值还是抛出的异常。 因此，在同步函数调用中，调用和结果发生在同一行，包括任何异常处理：

try {
  // fs.readFileSync() *不是* 异步的：它被调用，运行完成，然后在这里返回文件内容或抛出异常
  fileContents = fs.readFileSync('account', { encoding: 'utf-8' });
} catch (e) {
  // 捕获 fs.readFileSync() 抛出的异常
  console.error("can't read account file");
}

……对异步函数的调用将调用与其结果分开，这也意味着推迟任何异常处理：

// fs.promises.readFile() *是* 异步的；它返回一个 promise 但*绝不*在这里抛出异常
promise = fs.promises.readFile('account', { encoding: 'utf-8' });
...
// 程序中的其他地方等待 promise 并处理异常（如果有的话）
try {
  fileContents = await promise;
} catch (e) {
  // 捕获 fs.promises.readFile() 抛出的异常
  console.error("can't read account file");
}

当你编写异步函数（而不是调用它）时，拒绝 promise 的正确方式是直接抛出异常。 例如：

async function getBalance(account: string): Promise<number> {
    const data: string = await fs.promises.readFile(account, { encoding: 'utf-8' });
    const balance: number = parseInt(data);
    if (Number.isNaN(balance)) {
      throw new Error('account balance is not an integer'); // 抛出此异常会拒绝 promise
    }
    return balance;
}

你不需要使用 Promise.reject() 来创建被拒绝的 promise。只需用异常对象使用 throw，就像你用 return 来用返回值兑现 promise 一样。

总结

本阅读材料讨论了返回 promise 的异步函数。

  • Promise 是一个已经启动但可能尚未完成的并发计算，其结果可能尚未就绪。
    • Promise 允许我们编写永不忙等待的并发代码。
  • await 等待并访问 promise 计算的值。
  • Promise.all()、Promise.any()、Promise.race() 是将多个 promise 聚合在一起的方式。
  • 返回 promise 的函数是异步的。
    • 这些函数将控制权交给其调用者或 JavaScript 运行时系统。
    • 通过使用 async 和 await 关键字并返回 promise 类型，可以将普通函数转换为异步函数。

这些思想与我们优秀软件的三个关键属性之间的联系如下：

  • 免于 Bug。 对 promise 类型的静态检查，以及必须使用 await 将 promise 转换为值的要求，确保依赖异步计算的代码在所需值就绪之前不能继续执行。

  • 易于理解。 使用 await 将 promise 转换为值使得异步代码读起来非常像直线式的同步代码。但与所有并发一样，promise 和异步函数可能很微妙，产生令人惊讶的效果。

  • 拥抱变化。 Promise 可以以其他并发技术（如线程和 worker）不易支持的方式组合和合并。
