代码审查

在本课程中，你将阅读同学的代码并对其发表评论。 本文档描述了 6.102 代码审查流程的原因和方式。

不学会阅读，就无法学会写作——编程也不例外。 代码审查在软件开发中被广泛使用，无论是在工业界还是开源项目中。 许多公司已将提交前审查作为一项强制政策。 例如，除非另一位 Google 工程师阅读了代码、给出了反馈并签收了，否则你无法将一行代码提交到 Google 源代码仓库。

代码审查在实践中有多方面的好处。 审查以与其他技术（如静态检查、测试、断言和推理）互补的方式帮助发现 bug。 审查能发现难以理解、文档不完善、不安全或未准备好进行维护或未来变更的代码。 审查还能在组织内传播知识，让开发者通过明确的反馈和示例互相学习。 因此，代码审查不仅是一项你在现实世界中需要的实用且重要的技能，也是一个学习机会。

关注要点

虽然你可以对任何你认为相关的方面发表评论，但本课程的主要目标是学会编写免受 bug 困扰（SFB）、易于理解（ETU）和为变更做好准备（RFC）的代码。 请以这些原则为导向阅读代码。以下是一些具体的问题示例：

Bug 或潜在的 bug。

  • 重复代码（记住 DRY，Don't Repeat Yourself，不要重复你自己）。
  • 代码与规格说明不一致。
  • 差一错误。
  • 全局变量和其他过大的变量作用域。
  • 魔法数字。
  • 本可以编写得更防御性或更快失败的代码。
  • 等…

不清晰、凌乱的代码。

  • 糟糕的变量名或方法名。
  • 缩进不一致。
  • 可以简化的复杂控制流（if 和 while 语句）。
  • 在一行代码或一个方法中塞入过多内容。
  • 未能为晦涩的代码添加注释。
  • 有太多与代码简单重复的琐碎注释。
  • 用于多个目的的变量。
  • 等…

对编程语言的误解。

  • 使用 == 而非 ===。
  • 使用 var 而非 let。
  • 使用 for ... in 而非 for ... of。
  • 等…

误用（或未使用）我们在课堂上已讨论过的基本设计概念。 （如果你不确定其中某些概念的含义，可以在主题与术语中查阅，有些概念我们可能尚未在课堂上讨论过。）

  • 方法或类的规格说明不完整或不正确。
  • 数据抽象的表示暴露。
  • 易变数据类型暴露自身供修改。
  • 实际上不是不变量的不变量，或甚至未声明的不变量。
  • 测试策略中记录不充分的分区。
  • 记录不充分的测试用例分区覆盖。
  • 包含非法输入的分区。
  • 不是规格说明的合法客户端的测试用例。
  • 等…

正面评论也是很好的做法。 不要害怕对你真正喜欢的内容发表评论，例如：

  • 特别优雅的代码。
  • 很好的命名选择。
  • 有创意的解法。
  • 出色的设计。
  • 等…

流程

我们将使用一个名为 Caesar 的基于 Web 的代码审查系统，它是在 MIT 本地构建的。 Caesar 与其他代码审查工具（如 GitHub、Rietveld 和 Review Board）有几个不同之处。 它设计用于审查整个程序，而非变更集。 它将程序分成若干部分，分配给多个审查者，并通过线程评论和上下投票支持基于讨论的审查。 它自动忽略广泛重复的代码，如样板代码或库代码，以便将注意力集中在值得审查者花时间的代码上。 使用这个系统，你将阅读其他几个学生编写的小段代码，其他许多学生也将各自阅读你的一小段代码。

以下是流程的典型进行方式。 只对习题集代码进行审查。 团队项目不会经过这个流程。

习题集截止日期：习题集的第一轮迭代（alpha）到期。

截止日次日上午：提交的代码被加载到 Caesar 中，审查流程开放的通知通过电子邮件发送给所有审查者。

如果你在截止日期使用了宽限日：你必须等到截止日次日上午才能开始代码审查。

在代码审查期间：你应该访问 Caesar，阅读分配给你的代码，并对其发表评论。 对于你审查的每段代码，你可以：

  • 发表评论
    通过点击一行代码或选择一行范围，然后输入你的评论。

  • 回复其他评论
    通过点击回复。 你可以用此来澄清、扩展或反驳其他审查者发表的评论。

  • 赞同评论
    通过点击竖起大拇指图标。 用此来表示你同意另一位审查者发表的评论。

  • 反对评论
    通过点击大拇指向下图标。 如果你在反驳别人的观点，那么回复以解释原因是礼貌且有益的做法。

课程工作人员（TA、LA、讲师）将审查这些评论：视情况进行赞同、反对、回复和评论。

代码审查截止后：查看对你自己代码的评论，开始为你的 beta 提交修改代码。

我应该如何回应我的代码审查？

你的 beta 提交必须回应你收到的所有代码审查——所有人工评论以及所有标记为 #important 的自动 checkstyle 评论。

通过在 Caesar 中回复评论来回应每个人工评论，解释你如何修改代码以回应审查，或者解释为什么没有修改代码。 你必须在 Caesar 中提交回复；仅仅修改代码是不够的。

通过从代码中消除来回应每个 #important checkstyle 评论。 如果 checkstyle 评论确实因某种原因是错误的，你可以通过在源代码中出现的位置写一条评论来解释为什么无法消除它。但这种情况非常罕见——你应该努力消除所有 #important 问题。

评分人将检查你的 beta 提交，如果未能很好地回应代码审查，将扣除分数。

不用说，如果你没有收到任何代码审查评论——这种情况有时会发生——那么你不需要回应任何代码审查评论。 正面评论也不需要回应。

我如何查看自己是否已修复 Checkstyle 评论？

你可以使用与 Caesar 上的代码审查 checkstyle 机器人相同的规则，在本地笔记本电脑上运行 ESLint。 说明将在 ps0 的附录中提供。 请注意，Caesar 上的 #important 标签不会出现在你笔记本电脑上的 ESLint 消息中。 取而代之的是，在 Caesar 上会是 #important 的问题在 ESLint 工具中报告为错误，其他问题报告为警告。

隐私与可见性

作为代码作者，你是匿名的。 系统不会在你编写的任何代码旁显示你的名字。 请不要在你的源代码中放入你的全名、用户名、电子邮件地址或其他身份信息。 我们尝试在出现时去除你的名字和用户名，但这个过程并不完美，特别是因为你们中有些人的名字在源代码中很常见。 是的，我说的就是你，小 Bobby Tables。

作为审查者，你是完全公开的。 系统会在你负责的每条评论、回复、赞同或反对旁显示你的用户名和全名。 所有注册用户都能看到你的名字和你写的内容。

所有审查者、所有代码和所有评论对注册用户均可见。 "所有用户"链接显示所有用户的列表，每个用户都有一个个人资料页面，显示他们发表的所有评论。 任何登录 Caesar 的人都可以查看某段代码或某条评论的 URL，无论他们是否被分配为该段的审查者。

Caesar 仅对注册用户开放。 系统不对互联网开放，也不被 Google 索引。 它仅对使用过它的 MIT 课程成员可见。

尊重

要有礼貌。 讽刺、侮辱和贬低的话语在代码审查中没有容身之地。 无论你在谈论一个人（ fellow 审查者或代码作者）还是代码本身，都无关紧要。 不要说代码"愚蠢"，因为这太容易转移到代码作者身上，无论你是否有意。

要有建设性。 不要只是批评，要提供帮助：指出解决的方向。 "无望的混乱"不是建设性的评论；"变量命名应更具描述性，例如 tmp1 不是个好名字"则更具建设性。

作为审查者，你应该对他人发表的没有建设性或粗鲁的评论投反对票，严重问题应提交给教学工作人员。

作为代码作者，你应该仔细阅读你的反馈，并保持开放的心态。 不要产生防御心理。 如果你的审查者——他们是MIT 的同学——发现你的代码令人困惑，那么你应该思考这对它在现实世界中的清晰度和可维护性意味着什么。

审查者常见问题

审查会影响我的成绩吗？

你会因为参与代码审查而获得成绩，基于你发表审查评论的数量和质量。

我的审查会影响其他人的成绩吗？

不会直接影响。 正面或负面的代码审查不会计入代码作者的成绩，赞同和反对也不会影响其他审查者的参与成绩。 但你的审查有望帮助其他学生成为更好的程序员，更好地理解课程，从而间接提高他们的成绩。

我需要审查多少文件，每个文件我需要做多少？

分配给你的数量取决于习题集的大小，但不会超过 10 个文件。

Caesar 系统会期望你对每个分配给你的文件至少做一件事——发表评论、回复评论、赞同或反对——之后系统就认为该段代码"已审查"。

然而，要获得代码审查的完整参与分，你应该对每个文件发表多个实质性的、具体的评论，而不仅仅是赞同或反对别人发表的评论。

我觉得自己什么都不懂。我怎么可能审查别人的代码？

你知道的比你想象的多。 你可以检查清晰度，评论代码令人困惑的地方，寻找我们在课堂上读过或讨论过的问题等。

如果我没有发现任何问题怎么办？

你可以写具体的正面评论，将代码的良好特性与我们在课程中讨论的概念联系起来。

如果我认为某条 Checkstyle 评论是错误的或不相关的怎么办？

Checkstyle 机器人的审查评论是由名为 ESLint 的风格检查器自动生成的。 其中一些评论可能对该情境下是错误的或不合适的，因此请使用赞同和反对来审查 Checkstyle。

我需要尝试理解整个程序的多少？

Caesar 将每个文件孤立呈现，只要求你对该文件发表评论。 我们不期望你去查看任何其他内容，也不期望你花时间纠结于判断它是否正确。

我怎么能查出是谁写了这段代码？

代码作者是匿名的。 如果出现需要查明代码作者身份的严重情况——例如潜在的抄袭案例——请将其提交给教学工作人员。

代码作者常见问题

有人能用我的代码在课程中作弊吗？

在你提交习题集（alpha 版本）之前，无法参与代码审查。

在为 beta 修改时，抄袭代码审查中看到的代码将严重违反协作政策。 请参阅 通用信息中关于习题集、迭代和宽限日的部分以及 协作、分享与 AI 工具中关于个人作业的部分。
