概述

表情包很有趣。 如果我们能用编程方式制作它们，那会更有趣。 在本问题集中，我们将实现一种生成带标题图像表情包的语言！

该语言中一个表达式的含义是一张生成的图像，即一个具有特定宽度和高度的二维像素数组。 该语言中所有的宽度和高度都是正整数。

该语言的两个基本元素是图像文件，由文件名表示，例如：

myroom.jpg
portrait.png
image-file_3

以及标题，由带引号的字符串表示，例如：

"This is my room"
"~:┐)"
"it's a secret"

图像文件名从以文件形式存储的图像库中加载指定名称的图像。 尽管操作系统允许文件名中包含多种字符，但在本语言中，文件名只能由字母、数字或句点组成，还可以包含连字符 - 和下划线 _，只要它们不是文件名的第一个字符。 图像文件格式可以是Web 浏览器广泛支持的任何格式。 如果文件中的图像宽度为零或高度为零（大多数图像格式实际上禁止这种情况），则行为未定义。

标题生成一张图像，将给定文本显示为单行，不进行自动换行。 标题可以包含除换行符和双引号之外的任何字符（尽管字体实际显示表情符号等特殊字符的方式未规定）。 文本的字体、颜色和大小未规定，但必须具有合理的可读性。 （如果你选择使用默认字体以外的字体，请确保所有公开测试在 Didit 上都能正确渲染。） 宽度和高度必须为正数，并且足够大以不裁剪任何文本。 允许有额外的边距或内边距，但未作规定。 标题的背景应该是透明的，以便在需要时可以放置在其他图像之上。

该语言包含若干用于并置、叠加和调整图像大小的运算符，下文将逐一描述。

| 运算符将图像左右拼接在一起，例如：

A.jpg | B.jpg | C.jpg

生成一个水平的三格漫画条。

--- 运算符将图像上下拼接在一起，例如：

1.jpg --- 2.jpg --- 3.jpg

生成一个垂直的三格条。

符号周围的空格、制表符、回车符和换行符无关紧要，会被忽略，任何至少包含 3 个 - 字符的字符串都可以用来表示单个 --- 运算符，所以上例也可以写成：

1.jpg
--------
2.jpg
------
3.jpg

左右拼接的优先级高于上下拼接。 例如：

A1.jpg  |  B1.jpg  |  C1.jpg
-----------------------------
A2.jpg  |  B2.jpg  |  C2.jpg

生成一个 6 格漫画，排列为 2 行，每行 3 张图像。 可以使用括号对表达式进行分组并覆盖优先级，因此如果六个图像文件大小都相同，下面是书写相同布局的另一种方式：

(A1.jpg --- A2.jpg) | (B1.jpg --- B2.jpg) | (C1.jpg --- C2.jpg)

当不同大小的图像左右拼接时，较短的图像相对于较高的图像垂直居中，所得组合的高度等于较高图像的高度。 类似地，当不同大小的图像上下拼接时，较窄的图像相对于较宽的图像水平居中。 在两种情况下，如果将较小的图像居中需要将其放置在分数像素位置，则可以将其放置在 ±1 像素范围内的整数位置。 较小图像周围的"空白区域"应该是透明的。

该语言还有两个组合运算符，用于将一张图像叠加到另一张图像上。 插入符 ^ 将其第二个参数放置在第一个参数的上部，使得两张图像的顶部对齐，如下所示：

boromir.jpg ^ "One does not simply"

类似地，下划线 _ 将其第二个参数放置在第一个参数的下部，使得底部对齐：

boromir.jpg _ "walk into Mordor"

^ 和 _ 的参数当然可以是任何表达式，尽管它们最常与标题一起使用。 对于这两个运算符，如果两张图像的宽度不同，则较窄的图像相对于较宽的图像水平居中，分数像素的处理规则与上述相同。 所得图像的宽度是两张图像宽度的最大值，高度同理。

最后，可以使用 @ 运算符显式地调整任何表达式的大小：

red.jpg @ 300x200

这将重新缩放图像（即拉伸或缩小），使其宽度为 300 像素，高度为 200 像素。 宽度和高度必须是正整数，或者是 ?，表示对应的维度应是一个合法的宽度或高度，尽可能保持图像的宽高比。 例如：

boromir.jpg @ 100x?

此表达式将 boromir.jpg 从其原始尺寸 550x325 调整为 100x59，因为所得的宽高比 100/59 ≅ 1.6949 尽可能接近原始宽高比 550/325 ≅ 1.6923。 如果宽度和高度都是 ?，则该表达式无效，应产生语法错误。 保持宽高比的 ? 对于标题特别有用，例如：

boromir.jpg ^ ( "One does not simply" @ 550x? )

此表达式调整标题的大小以填充 boromir.jpg 的宽度，而不会使文本看起来被拉伸或挤压。

运算符的优先级顺序为：@ ^ _ | ---。 调整大小的 @ 运算符优先级最高，最先应用。 顶部叠加运算符 ^ 的优先级次之，其次是底部叠加运算符 _，因此 A _ B ^ C 等价于 A _ (B ^ C)。 然后应用左右拼接运算符 |code>，最后上下拼接运算符 --- 优先级最低。 优先级可以通过括号覆盖。

请注意，字符 _ 和 - 也可能出现在文件名内部。 为了在文件名后立即使用 _ 和 --- 等运算符，运算符必须与文件名用括号分隔，如 (cat.jpg)_"meow"，或用空白字符分隔，如 cat.jpg _ "meow"。 如果没有这样的分隔，_ 和 - 字符将被视为文件名的一部分。

定义一个不可变的、递归的抽象数据类型，用于将表达式表示为抽象语法树。

1.2 toString()

按照规格说明/测试/代码的步骤，为 MemeExpression 定义 toString() 操作。

输出字符串必须是上文定义的有效表达式。 你可以自由决定如何使用空白字符和括号来格式化输出以提高可读性，但该表达式必须具有与图像相同的含义。 toString() 所需的加强规格说明已在 expression.ts 中给出。 如果你愿意，可以进一步加强规格说明，但规格说明不一定是确定性的。

1.3 equalValue()

为你的 AST 定义 equalValue() 操作以实现结构相等。 equalValue() 所需的规格说明已在 expression.ts 中给出。 如果你愿意，可以进一步加强。

结构相等将两个表达式定义为相等，当且仅当：

  1. 表达式包含相同的文件名、标题、尺寸（数字和 ?）和运算符；
  2. 这些文件名、标题、尺寸和运算符从左到右的读取顺序相同；
  3. 并且它们的分组方式相同。

例如，a.jpg ^ "title" 的 AST 不等于 "title" ^ a.jpg 的 AST，但它等于 a.jpg^"title"、(a.jpg ^ "title") 和 (a.jpg) ^ ("title") 的 AST。 (A | B) --- (C | D) 的 AST 不等于 (A --- C) | (B --- D) 的 AST，尽管它们可能生成相同的 2×2 格表情包。

对于 n 元分组，其中 n 大于 2：

  • 这样的表达式必须等于其自身。 例如，A | B | C 和 (A | B | C) 的 AST 必须相等。
  • 然而，它们与具有相同图像含义的不同分组是否相等并未作规定，你应该为你的 AST 选择合适的规格说明和实现。 例如，你需要确定 (A | B) | C 和 A | (B | C) 的 AST 是否相等。

记住：具体语法，包括括号，不应在你的 AST 中表示。 例如，分组应该反映在 AST 的结构中。

确保根据此定义和根据 equalValue() 被认为相等的 AST 实例也满足观察相等性。

你的 equalValue() 必须是递归的，并且它应该使用 instanceof 来测试它所比较的表达式的变体：参见《递归数据类型》中"相等性"一节。

4.4 运行 Web 界面

到目前为止，我们一直在 Node.js 中运行图像表情包系统，通过运行控制台界面和测试。 但是，TypeScript 编译器生成的 JavaScript 也可以在 Web 浏览器中运行。

首先，使用 npm run web 启动所提供的 Web 服务器。 这个小型 Node.js Web 服务器会将代码和图像文件发送到你的浏览器。 它不会运行代码：所有的解析和图像生成都将由浏览器的 JavaScript 引擎完成。

然后，在浏览器中导航到 localhost:8080。 输入一个表达式，然后点击 Generate 查看结果。

当你更改代码时，不需要重启 Web 服务器。 当然，你需要将 TypeScript 重新编译为 JavaScript（例如 npm run compile），但完成后你可以重新加载网页来使用更新后的代码。 如果你不想每次手动重新编译，可以在另一个终端中运行 npm run watch。 该命令将持续运行，当你编辑并保存 .ts 文件时自动重新编译你的代码。

（如果你直接导入了 canvas、fs 或其他模块，你的代码可能在 Web 界面中无法工作。 请确保你只使用 imagelibrary.ts 的导出。）

评分

你的 ps3 总评成绩将大致按以下方式计算：
~30% alpha 自动评分（包括在线练习）+ ~20% alpha 手动评分 + ~25% beta 自动评分 + ~25% beta 手动评分（包括代码审查）

从 alpha 到 beta 将使用相同的自动评分测试用例，但它们的分值会有所不同。 为了鼓励增量开发，alpha 自动评分将把大部分权重放在仅使用文件名、| 和使用数字（而非 ?）的 @ 的测试上，而对使用语言其他特性（标题、使用 ? 的 @、---、^ 和 _）的测试给予较少权重。 在 beta 中，自动评分将把权重均匀分布在整个语言上。

alpha 的手动评分将检查你的表达式操作的规格说明、表达式数据类型的内部文档（数据类型定义、AF、RI 等），以及表达式变体的实现。 beta 的手动评分可能检查任何部分，包括重新检查 ADT 实现，以及你如何处理代码审查反馈。
