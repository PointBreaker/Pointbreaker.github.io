项目测试

自动化测试

从作业 0 开始，你一直在使用 Didit 系统进行自动化构建和测试：每次你将提交推送到 GitHub 时，Didit 构建服务器就会拉取你代码的一份副本，尝试编译它，并运行测试。

这种自动化在专业软件开发中非常常见，对于协调开发者团队非常有用。 代码能否编译没有任何歧义：如果在构建服务器上编译不了，那就是编译不了。 测试是否通过也没有歧义：如果在构建服务器上测试不通过，那就是不通过。

限制条件

除了所提供的 package.json 中包含的包之外，你不可以使用其他包。

你的测试不能使用不合理的空间量（例如大型图片）或时间（例如缓慢的并发测试）。

你的代码应使用 localhost 的 8700—8799 端口在服务器和客户端之间通信。

一如既往，不要尝试运行除项目测试以外的任何东西。

排除测试

你可能有一些 Didit 无法运行的测试。 不要让 Didit 的限制阻止你编写这样的测试。

相反，任何在名称中任何地方提到“Didit”的测试都将被排除在 Didit 的运行之外。

不幸的是，这些测试将完全不会出现在构建结果页面上。 请确保你和你的队友手动运行这些被跳过的测试！

如何测试：canvas 绘图

在浏览器中，HTMLCanvasElement 对象指的是页面上的 <canvas> HTML 元素。

要测试主要用于在浏览器 <canvas> 元素上绘图的代码，你可能想编写在 Node.js 中运行的 Mocha 测试，就像你在作业 3 中所做的那样。

下面是一种管理方法。 在浏览器中运行的代码中，定义辅助类型：

// 仅从 'canvas' 导入类型，而非实现
import type { Canvas, CanvasRenderingContext2D as NodeCanvasRenderingContext2D } from 'canvas';

/**
 * 两者之一：Web 浏览器中的 CanvasRenderingContext2D，
 *      或 Node 中的 NodeCanvasRenderingContext2D（用于测试）
 */
type WebOrNodeCanvasRenderingContext2D = CanvasRenderingContext2D | NodeCanvasRenderingContext2D;

/**
 * 两者之一：表示网页上 `<canvas>` 的 HTMLCanvasElement，
 *      或表示 Node 中 canvas 的 Canvas（用于测试）
 */
type WebOrNodeCanvas = Omit<HTMLCanvasElement | Canvas, 'getContext'> & {
    getContext(contextId: '2d'): WebOrNodeCanvasRenderingContext2D | null;
};

上面的 WebOrNodeCanvas 类型定义解决了 getContext(..) 的一个问题，该问题使我们无法使用简单的联合类型。

如果你有接收 HTMLCanvasElement 进行绘图的函数（或方法、构造函数等），将它们改为接收 WebOrNodeCanvas。 修改之后，你的代码应该能够继续在浏览器中编译、打包和运行。

在你的 Mocha 测试代码中，从 canvas 包中导入 createCanvas(..) 并用它来创建 Canvas 实例。 然后你可以像在 PS3 中那样检查这些 Canvas 对象的图像数据。

如果你的函数（或方法、构造函数等）接收的是渲染上下文，你可以使用上面的 WebOrNodeCanvas­Rendering­Context2D 联合类型。

如果你想使用 drawImage，上面的定义是不够的。 你可以添加这段类型处理代码：

import type { Image } from 'canvas'; // 同时导入 Image 类型

declare global {
    // 断言浏览器的 drawImage 与 Image 兼容
    interface CanvasDrawImage {
        drawImage(image: Image, dx: number, dy: number): void;
        // ... 如需可添加其他重载 ...
    }
}

然后在 Node 和浏览器中都使用 loadImage：

import { loadImage } from 'canvas';

const context: WebOrNodeCanvasRenderingContext2D = ...;
const image = await loadImage('my-cool-image.png');
context.drawImage(image, 0, 0);

无浏览器依赖

请记住：在 Node 中运行的代码不能使用 DOM API。

以下代码不会正常工作：

test/drawing.test.ts

import { createCanvas } from 'canvas';
import { draw } from '../src/starb-client.ts';  // 哎呀！

describe('draw', function() {
    it('should work', function() {
        // 用 createCanvas(..) 创建一个 canvas
        // 调用 draw(..)
    });
});

src/starb-client.ts

// ... 导入和类型定义 ...

export function draw(canvas: WebOrNodeCanvas): void {
    // 在 canvas 上绘图，不使用 `document`
}

function main(): void {
    // 使用 `document.getElementById` 获取 canvas
    // 调用 draw(..)
}

main();

导入 starb-client.ts 会运行文件最后一行的 main()。 由于 drawing.test 导入了 starb-client，尝试运行测试会立即失败，报错：

ReferenceError: document is not defined

这里有一个快速修复方法。 考虑一下在你们组的设计中实现相同目标的最佳方式，这可能涉及额外的模块：

test/drawing.test.ts

import { createCanvas } from 'canvas';
import { draw } from '../src/coolgraphics.ts'; // 没问题！  

describe('draw', function() {
    it('should work', function() {
        // 用 createCanvas(..) 创建一个 canvas
        // 调用 draw(..)
    });
});

src/coolgraphics.ts

// ... 导入和类型定义 ...

export function draw(canvas: WebOrNodeCanvas): void {
    // 在 canvas 上绘图，不使用 `document`
}

src/starb-client.ts

import { draw } from './coolgraphics.ts';

function main(): void {
    // 使用 `document.getElementById` 获取 canvas
    // 调用 draw(..)
}

main();

如何测试：Web 服务器

测试 Web 服务器与你到目前为止在课程中编写的测试略有不同。 特别是，你可能需要使用 fetch() 来模拟客户端/服务器交互。

参见 Fetch API 文档。 Node 的 fetch 实现了相同的规范。

下面是一个如何测试 Web 服务器的示例：

import assert from 'assert';
import { WebServer } from '../src/web-server.ts';
import { StatusCodes } from 'http-status-codes';

describe('server', function () {

    it('covers /hello with valid greeting', async function () {
        const server = new WebServer();
        await server.start();

        const url = `http://localhost:${server.port}/hello/w0rld`;

        // 在这个测试中，我们只断言服务器输出的正确性
        const response = await fetch(url);
        assert.strictEqual(await response.text(), "Hello, w0rld!");

        server.stop();
    });

    it('covers /hello with invalid greeting', async function () {
        const server = new WebServer();
        await server.start();

        const url = `http://localhost:${server.port}/hello/world!`;

        // 在这个测试中，我们只断言响应状态码的正确性
        const response = await fetch(url);
        assert.strictEqual(response.status, StatusCodes.NOT_FOUND);

        server.stop();
    });

});
