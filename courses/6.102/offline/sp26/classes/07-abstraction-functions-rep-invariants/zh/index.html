目标

今天的阅读引入了几个概念：

  • 不变量
  • 表示暴露
  • 抽象函数
  • 表示不变量

在本次阅读中，我们通过抽象函数和表示不变量的概念，来研究一个类如何实现一个 ADT 的更形式化的数学定义。 这些数学概念在软件设计中具有极强的实用性。 抽象函数为我们提供了一种清晰定义抽象数据类型相等性操作的方式（我们将在未来的课堂上更深入地讨论这一点）。 表示不变量使我们更容易捕获因数据结构损坏而导致的 bug。

不变量

继续我们关于什么是好的抽象数据类型的讨论，一个好的抽象数据类型的最后一个（也可能是最重要的）性质是它保持其自身的不变量。 一个不变量是程序的一个性质，在程序开始时为真的前提下，对于程序每一个可能的运行时状态都始终为真。你可能从 6.1200 [原 6.042] 中回忆起这个被保持的不变量的概念。 不可变性是我们已经遇到过的一个关键不变量：一旦创建，一个不可变对象在其整个生命周期中应始终表示相同的值。 但还有许多其他种类的不变量，包括变量的类型（i: number 表示 i 始终是一个数），或者变量之间的关系（例如，当 i 用于遍历数组的索引时，那么 0 <= i < array.length 就是循环体内的一个不变量）。

说 ADT 保持其自身的不变量，意思是 ADT 负责确保其自身的不变量成立。 这是通过隐藏或保护参与不变量的变量（例如，使用 private 等语言特性），并且只允许通过具有良好定义契约的操作进行访问来实现的。

当一个 ADT 保持其自身的不变量时，对代码进行推理就变得容易得多。 例如，如果你可以依赖字符串是不可变的这一事实，那么你在调试使用字符串的代码时，就可以排除字符串被修改的可能性——或者在你试图为另一个使用字符串的 ADT 建立不变量时也可以如此。 与之形成对比的是可变字符串类型，任何能够访问它的代码都可以修改它。 要推理涉及可变字符串的 bug 或不变量，你就必须检查代码中该字符串可能可被访问的所有位置。

这一论点适用于所有情况，即使是你独自编程时也是如此。但当你在团队中编程，或编写供团队外开发者使用的软件时，保持自身不变量的 ADT 在免受 bug 困扰方面也更为安全。 公司中其他团队误用你代码的可能性，或者真实用户意外破坏你软件的可能性都会低得多。

不可变性

在本次阅读的后面，我们将会看到许多有趣的不变量。 现在让我们聚焦于不可变性。这里有一个具体的例子：

/**
 * This immutable data type represents a post on a forum.
 */
class Post {

    public author: string;
    public text: string;
    public timestamp: Date;

    /**
     * Make a Post.
     * @param author    user who wrote the post
     * @param text      text of the post
     * @param timestamp date/time when the post was sent
     */
    public constructor(author: string, text: string, timestamp: Date) {
        this.author = author;
        this.text = text;
        this.timestamp = timestamp;
    }
}

我们如何保证这些 Post 对象是不可变的——即，一旦一个帖子被创建，其作者、消息和日期就永远不能被改变？

对不可变性的第一个威胁来自于客户端可以——事实上必须——直接访问其字段这一事实。所以没有什么能阻止我们编写像这样的代码：

let post: Post = new Post("justinbieber",
                    "Thanks to all those beliebers out there inspiring me every day",
                    new Date());
post.author = "rbmllr";

这是一个表示暴露的简单例子，意思是类外部的代码可以直接修改表示。这样的表示暴露不仅威胁到不变量，还威胁到表示独立性。 如果所有直接访问这些字段的客户端都受到影响，我们就无法更改 Post 的实现。

幸运的是，TypeScript 为我们提供了处理这类表示暴露的语言机制：

class Post {

    private readonly author: string;
    private readonly text: string;
    private readonly timestamp: Date;

    public constructor(author: string, text: string, timestamp: Date) {
        this.author = author;
        this.text = text;
        this.timestamp = timestamp;

    }

    /**
     * @returns user who wrote the post
     */
    public getAuthor(): string {
        return this.author;
    }

    /**
     * @returns text of the post
     */
    public getText(): string {
        return this.text;
    }

    /**
     * @returns date/time when the post was sent
     */
    public getTimestamp(): Date {
        return this.timestamp;
    }

}

private 和 public 关键字用于表示哪些字段和方法只能在类内部访问，哪些可以从类外部访问。 private 用于对象的内部状态和内部辅助方法，而 public 用于面向类客户端的方法和构造函数。 观察器 getAuthor()、getText() 和 getTimestamp() 允许客户端仍然能够访问 Post 对象的属性。

readonly 用于表示对象的哪些实例变量可以重新赋值，哪些不可以。 请注意，TypeScript 仅将 readonly 用于实例变量，而仅将 const 用于局部变量和全局变量，但 readonly 和 const 都表示相同的含义：不可重新赋值。

但这并不是故事的结局：表示仍然被暴露着！考虑这段完全合理的、使用 Post 的客户端代码：

/**
 * @returns a post that reposts t, one hour later
 */
function repostLater(post: Post): Post {
    const d: Date = post.getTimestamp();
    d.setHours(d.getHours()+1);
    return new Post("rbmllr", t.getText(), d);
}

repostLater 接收一个帖子，并应返回另一个具有相同消息（称为 repost，即转发）但晚一小时发送的帖子。repostLater 方法可能是自动转发重要消息的系统的一部分。

这里的问题是什么？getTimestamp 调用返回的是对 post 所引用的同一个 Date 对象的引用。 post.timestamp 和 d 是同一个可变对象的别名。因此，当那个日期对象被 d.setHours() 修改时，post 中的日期也会受到影响，如图所示的快照图所示。

Post 的不可变性不变量已被破坏。问题在于 Post 泄露了一个对其不可变性所依赖的可变对象的引用。我们暴露了表示，使得 Post 不再能够保证其对象是不可变的。一段完全合理的客户端代码制造了一个微妙的 bug。

我们可以通过使用防御性拷贝来修补这类表示暴露，这是一种我们之前见过的策略：拷贝一个可变对象，以避免泄露对表示的引用。代码如下：

public getTimestamp(): Date {
    return new Date(this.timestamp.getTime());
}

可变类型通常都有一个拷贝构造函数，允许你创建一个复制了现有实例值的新实例。 在这种情况下，Date 的拷贝构造函数使用时间戳值（以自 1970 年 1 月 1 日起的毫秒数来衡量）。再举个例子，Map 的拷贝构造函数接收一个键值对数组，可以通过调用 entries() 从你想拷贝的 map 中提取。

所以我们在 getTimestamp 的返回值中做了一些防御性拷贝。 但我们还没有完成！仍然存在表示暴露。考虑这段（同样完全合理的）客户端代码：

/**
 * @returns an array of 24 inspiring posts, one per hour today
 */
function postEveryHourToday(): Array<Post> {
    const array: Array<Post> = [];
    const date: Date = new Date();
    for (let i = 0; i < 24; i++) {
        date.setHours(i);
        array.push(new Post("rbmllr", "keep it up! you can do it", date));
    }
    return array;
}

这段代码打算让单个 Date 对象推进一天中的 24 个小时，每小时创建一个帖子。 但请注意，Post 的构造函数保存了传入的引用，所以所有 24 个 Post 对象最终都具有相同的时间，如图所示的快照图所示。

同样，Post 的不可变性被违反了。我们也可以通过审慎地使用防御性拷贝来修复这个问题，这次是在构造函数中：

public constructor(author: string, text: string, timestamp: Date) {
    this.author = author;
    this.text = text;
    this.timestamp = new Date(timestamp.getTime());
}

一般来说，你应该仔细地检查你的所有 ADT 操作的参数类型和返回类型。 如果其中任何类型是可变的，请确保你的实现不会返回对其表示的直接引用。 返回一个对可变表示对象的引用会导致表示暴露。

你可能会反对说这似乎很浪费。为什么要拷贝这么多日期？我们为什么不能像这样通过精心编写的规范来简单地解决这个问题？

/**
 * Make a Post.
 * @param author    user who wrote the post
 * @param text      text of the post
 * @param timestamp date/time when the post was sent. Caller must never
 *                   mutate this Date object again!
 */
public constructor(author: string, text: string, timestamp: Date) {

当没有其他合理替代方案时，有时会采用这种方法——例如，当可变对象太大而无法高效拷贝时。但这对你推理程序的能力以及避免 bug 的能力所造成的代价是巨大的。 在没有令人信服的反面论据的情况下，抽象数据类型保证其自身的不变量几乎总是值得的，而防止表示暴露对此至关重要。 我们在讨论设计规范时也使用了类似的推理。

一个更好的解决方案是优先使用不可变类型。 如果 Date 是一个不可变类型，那么我们在讨论了 public 和 private 之后就可以结束本节了。 就不会再有可能的表示暴露了。

表示不变量与抽象函数

我们现在更深入地研究抽象数据类型背后的理论。这个理论不仅本身优雅而有趣；它还对抽象类型的设计和实现有着直接的实际应用。如果你深刻地理解了这个理论，你将能够构建更好的抽象类型，并且不太可能掉入微妙的陷阱。

在思考一个抽象类型时，考虑两个值空间之间的关系是有帮助的。

抽象值空间由该类型设计所支持的值组成，从客户端的角度来看。 例如，一个用于无界整数的抽象类型，比如 TypeScript 的 BigInt，会以数学上的整数作为其抽象值空间。

表示值空间（或简称 rep 值）由实际实现抽象值的对象组成。 例如，一个 BigInt 值可以使用一个数字数组来实现，数字表示为 number 值。 那么 rep 空间就是所有这样的数组的集合。

在简单的情况下，一个抽象类型会被实现为单个对象，但更常见的是需要一小部分对象组成的网络。 例如，Array 的一个 rep 值可能是一个一个链表，一组通过 next 和 previous 指针链接在一起的对象。 所以一个 rep 值不一定是单个对象，而常常是相当复杂的东西。

当然，现在抽象类型的实现者必须对表示值感兴趣，因为实现者的工作就是使用 rep 值空间来实现抽象值空间的幻象。

例如，假设我们选择使用一个字符串来表示一组字符：

class CharSet {
    private s: string;
    ...
}

那么表示空间 R 包含字符串，而抽象空间 A 是数学上的字符集合。 我们可以用图形来展示这两个值空间，用一个箭头从 rep 值指向它所表示的抽象值。

R 和 A 之间一种可能的关系如右图所示。 关于这幅图有几件事需要注意：

  • 每个抽象值都有某个 rep 值映射到它。实现抽象类型的目的是支持对抽象值上的操作。因此，我们将需要能够创建和操纵所有可能的抽象值，因此它们必须是可表示的。
  • 多个 rep 值可以映射到同一个抽象值。这种情况的发生是因为这种表示不是一种紧凑的编码。将一个无序的字符集表示为字符串有不止一种方式。
  • 并非所有的 rep 值都映射到一个抽象值。在这种情况下，字符串 "abbc" 不映射到任何东西，因为我们决定 rep 字符串不应包含重复字符。这将允许我们在遇到某个特定字符的第一个实例时终止 remove 方法，因为我们知道最多只能有一个。

在实践中，我们只能图示两个空间及其关系的一小部分；整个图是无限的。所以我们通过给出两件事来描述它：

1. 一个抽象函数，它将 rep 值映射到它们所表示的抽象值：

AF : R → A

上面图中的箭头表示抽象函数。用函数的术语来说，我们上面讨论的性质可以表述为该函数是满射的（也称为到上的），不一定是单射的（一对一的），因此也不一定是双射的，而且通常是偏函数。

2. 一个表示不变量，它将 rep 值映射到布尔值：

RI : R → boolean

表示不变量是 rep 值上的一个谓词。

对于一个 rep 值 r，当且仅当 r 被 AF 映射时，RI(r) 为真。换句话说，RI 告诉我们一个给定的 rep 值是否格式良好。 或者，你可以把 RI 看作一个集合：它是 AF 有定义的那些 rep 值的子集。

例如，右边的图展示了一个禁止重复字符的 CharSet 表示：

  • RI("a") = true
  • RI("ac") = true
  • RI("acb") = true

但是

  • RI("aa") = false
  • RI("abbc") = false

遵守表示不变量的 rep 值显示在 R 空间的绿色部分，并且必须映射到 A 空间中的一个抽象值。 违反表示不变量的 rep 值显示在红色区域，在 A 空间中没有等价的抽象值。

表示不变量和抽象函数都应该被记录在代码中，紧挨着表示本身的声明旁边：

class CharSet {
    private s: string;
    // Rep invariant:
    //   s contains no repeated characters
    // Abstraction function:
    //   AF(s) = {s[i] | 0 <= i < s.length}
    ...
}

关于抽象函数和表示不变量的一个常见混淆是，认为抽象值空间 A 和 rep 空间 R 的选择，或者甚至仅抽象值空间的选择，就自动决定了 AF 和 RI。 如果是这样的话，AF 和 RI 就多余了。

但仅凭抽象值空间并不能决定 AF 或 RI：同一个抽象类型可以有多种表示。一组字符既可以如上所述表示为字符串，也可以等价地表示为位向量，每个可能的字符对应一个位。显然，我们需要两个不同的抽象函数来映射这两个不同的 rep 值空间。

为什么两个空间的选择并不能决定 AF 和 RI，这一点就不那么明显了。关键在于，为 rep 定义一个类型，从而为 rep 值空间选择值，并不能决定哪些 rep 值会被认为是合法的，以及在那些合法的 rep 值中，它们将如何被解释。与我们上面决定字符串不重复不同，我们也可以改为允许重复，但同时要求字符按非递减顺序排序。这将允许我们在字符串上执行二进制搜索，从而以线性时间而非对数时间来检查成员关系。同样的 rep 值空间——不同的表示不变量：

class CharSet {
    private s: string;
    // Rep invariant:
    //   s[0] <= s[1] <= ... <= s[s.length-1]
    // Abstraction function:
    //   AF(s) = {s[i] | 0 <= i < s.length}
    ...
}

即使 rep 值空间的类型相同且表示不变量也相同，我们仍可能通过使用不同的抽象函数来以不同的方式解释 rep。 假设表示不变量允许任意的字符串。 那么我们就可以如上定义抽象函数，将数组的元素解释为集合的元素。 但没有先验的理由让 rep 来决定解释方式。 也许我们将把连续的字符对解释为子范围，这样字符串 rep "acgg" 就被解释为两个范围对，[a-c] 和 [g-g]，因此表示集合 {a,b,c,g}。 下面是那种表示对应的 AF 和 RI：

class CharSet {
    private s: string;
    // Rep invariant:
    //   s[0] <= s[1] <= ... <= s[s.length-1]
    // Abstraction function:
    //   AF(s) = union of { c | s[2i] <= c <= s[2i+1] }
    //           for all 0 <= i < s.length/2
    ...
}

（当 s.length 为奇数时，即字符串末尾有一个未配对的字符时，这个抽象函数会做什么？）

关键点是，实现一个抽象类型意味着不仅要选择两个空间——用于规范的抽象值空间和用于实现的 rep 值空间——还要决定哪些 rep 值是合法的，以及如何将它们解释为抽象值。

至关重要的是，要把这些假设写在代码中，正如我们上面所做的，以便未来的程序员（以及未来的你自己）知道表示的真正含义。为什么？如果不同的实现者对 rep 的含义有分歧会怎样？

    //   s.length is even
    //   s[0] <= s[1] <= ... <= s[s.length-1]

示例：有理数

这里有一个任意精度有理数抽象数据类型的一个例子，在表示中使用 BigInt 实现。 仔细看它的表示不变量和抽象函数。 设计这个 ADT 的另一种实现、使用一个更宽松的 RI，也是完全合理的。 做了这样的改动后，某些操作可能执行起来更昂贵，而另一些则更便宜。

class RatNum {

    private readonly numerator: bigint;
    private readonly denominator: bigint;

    // Rep invariant:
    //   denominator > 0
    //   numerator/denominator is in reduced form,
    //       i.e. gcd(|numerator|,denominator) = 1

    // Abstraction function:
    //   AF(numerator, denominator) = numerator/denominator

    /**
     * Make a new RatNum = (n / d).
     * @param n numerator
     * @param d denominator
     * @throws Error if d = 0
     */
    public constructor(n: bigint, d: bigint) {
        // reduce ratio to lowest terms
        const g = gcd(BigInt(n), BigInt(d));
        const reducedNumerator = n / g;
        const reducedDenominator = d / g;

        // make denominator positive
        if (d < 0n) {
            this.numerator = -reducedNumerator;
            this.denominator = -reducedDenominator;
        } else if (d > 0n) {
            this.numerator = reducedNumerator;
            this.denominator = reducedDenominator;
        } else {
            throw new Error('denominator is zero');
        }
        this.checkRep();
    }

}

检查表示不变量

表示不变量不仅仅是一个巧妙的数学想法。如果你的实现在运行时断言表示不变量，那么你就可以尽早捕获 bug。我们可以在一个名为 checkRep() 的私有方法中断言表示不变量。下面是它对 RatNum 可能的样子：

// assert the rep invariant
private checkRep(): void {
    assert(this.denominator > 0n);
    assert(gcd(abs(this.numerator), this.denominator) === 1n);
}

你当然应该在每个创建或变更 rep 的操作末尾调用 checkRep() 来断言表示不变量——换句话说，创建者、生产者和变更者。回头看看上面的 RatNum 代码，你会看到它在构造函数的末尾调用了 checkRep()。

观察器方法通常不需要调用 checkRep()，但这样做是良好的防御性实践。为什么？在每个方法中（包括观察器）调用 checkRep() 意味着你更有可能捕获到因表示暴露而导致的表示不变量违反。

为什么 checkRep 是私人的？谁应该负责检查和执行表示不变量——客户端，还是实现本身？

表示中不允许空值

回顾规范阅读材料，null 和 undefined 值是麻烦且不安全的，以至于我们试图完全将它们从我们的编程中移除。 前置条件和后置条件隐式地要求对象是非空的。 在 TypeScript 中开启严格空检查会通过静态类型检查来强制执行这一点。

我们将这种禁止扩展到抽象数据类型的表示。 表示不变量隐式地包含了 x !== null 和 x !== undefined，对于表示中的每个引用 x，包括数组、map 等内部的引用。 所以如果你的 rep 是：

class CharSet {
    s: string;
}

那么它的表示不变量自动包含 s !== null && s !== undefined，你不需要在表示不变量注释中声明这一点。 如果你启用了严格空检查（这是 6.102 的 TypeScript 配置），静态类型检查器会保证这一点。

如果表示中的某个字段允许为 null，那么它的类型应该明确说明这一点。 联合类型，比如 string|undefined，就是这样做的一个例子。 但在设计这样的表示之前要三思，因为允许 null 和 undefined 泄漏到你的代码中会在日后导致头痛。

良性副作用

回顾一下，一个类型是不可变的，当且仅当该类型的值在创建之后永不改变。 凭借我们对抽象空间 A 和 rep 空间 R 的新理解，我们可以完善这个定义：抽象值应永不改变。 但只要 rep 值继续映射到相同的抽象值，实现就可以自由地变更rep 值，使得该变化对客户端不可见。 这种变化被称为良性副作用。

这里有一个简单的例子，使用我们之前看到的 RatNum 类型的一种替代 rep。 这个 rep 具有更弱的表示不变量，不要求分子和分母必须以最简形式存储：

class RatNum {

    private numerator: bigint;
    private denominator: bigint;

    // Rep invariant:
    //   denominator != 0

    // Abstraction function:
    //   AF(numerator, denominator) = numerator/denominator

    /**
     * Make a new RatNum = (n / d).
     * @param n numerator
     * @param d denominator
     * @throws Error if d = 0
     */
    public constructor(n: bigint, d: bigint) {
        if (d === 0n) throw new Error("denominator is zero");
        this.numerator = n;
        this.denominator = d;
        checkRep();
    }

    ...
}

这个更弱的表示不变量允许一系列 RatNum 算术运算直接省略将结果约简为最简形式。 但是当需要向人类显示结果时，我们先将其化简：

    /**
     * @returns a string representation of this rational number
     */
    public toString(): string {
        const g = gcd(this.numerator, this.denominator);
        this.numerator /= g;
        this.denominator /= g;
        if (this.denominator < 0n) {
            this.numerator = -this.numerator;
            this.denominator = -this.denominator;
        }
        checkRep();
        return (this.denominator > 1n) ? (this.numerator + "/" + this.denominator)
                                 : (this.numerator + "");
    }

注意这个 toString 实现重新赋值了私有字段 numerator 和 denominator，变更了表示——尽管它是不可变类型上的一个观察器方法！ 但关键的是，这种变更并没有改变抽象值。 将分子和分母同时除以相同的公因数，或同时乘以 -1，对抽象函数 AF(numerator, denominator) = numerator/denominator 的结果没有影响。 另一种理解方式是，AF 是一个多对一函数，rep 值变成了另一个仍然映射到相同抽象值的 rep 值。 所以这种变更是无害的，或者说良性的。

我们将在未来的阅读中看到良性副作用的其他例子。 这种实现者自由通常允许诸如缓存、数据结构重平衡和延迟清理之类的性能改进。

记录 AF、RI 以及防止表示暴露的安全性

在类中记录抽象函数和表示不变量是良好的做法，就在声明 rep 私有字段的旁边使用注释。 我们上面一直在这样做。

当你描述表示不变量和抽象函数时，你必须精确。

RI 仅仅是一个泛泛的陈述，比如“所有字段都是有效的”，是不够的。 表示不变量的职责是精确地解释是什么使字段值有效或无效。

作为一个函数，如果我们取记录下来的 RI 并代入实际的字段值（无论合法与否），我们应该得到一个布尔结果。 请注意，如果我们在 RI 中试图引用抽象值，那就是本末倒置了：非法的 rep 值没有抽象值，我们需要通过只谈论 rep 值来在 RI 中拒绝它们。

AF 仅仅提供一个泛泛的解释，比如“表示一组字符”，是不够的。 抽象函数的职责是精确定义具体的字段值是如何被解释的。

作为一个函数，如果我们取记录下来的 AF 并代入实际的合法字段值，我们应该得到对所表示的那个单一抽象值的完整描述。 例如，对于 CharSet 抽象函数 AF(s) = {s[i] | 0 <= i < s.length}，我们可以代入一个具体的（合法的）rep 值，比如 s="abbc"，得到：
AF("abbc") = { "abbc"[i] | 0 <= i < "abbc".length } = { 'a', 'b', 'c' }。

但如果我们取而代之的是一个模糊且定义不清的抽象函数，比如 AF(s) = a set of characters，那么代入 s 根本不会影响等式的右边。 这个定义并没有精确地说明哪个抽象字符集对应于 rep 值 s="abbc"。

精确的陈述既可以用符号形式（如 {s[i] | 0 <= i < s.length}），也可以用英语（如“在 s 中找到的所有字符的集合”）来表达。你在数学课上都写过这两种形式的陈述，在这里你也应该采取同样的数学视角。符号表达式可能看起来更精确，而英语可能看起来更模糊，但这只是感知问题：两种方法都可以做得既认真也可以做得马虎。作为经验法则，当符号表达式简洁明了时使用它们，而当需要表达复杂内容时使用英语，但在两种情况下，都要以精确为目标。

6.102 要求你编写的另一个文档是一个表示暴露安全性论证。这是一个注释，它检查表示的每个部分，查看处理该部分表示的代码（特别是关于来自客户端的参数和返回值，因为表示暴露就发生在那里），并给出代码没有暴露表示的原因。

下面是 Post 的一个例子，其表示不变量、抽象函数以及防止表示暴露的安全性都被完整地记录了下来：

// Immutable type representing a post.
class Post {

    private readonly author: string;
    private readonly text: string;
    private readonly timestamp: Date;

    // Rep invariant:
    //   author is a forum username (a nonempty string of letters, digits, underscores)
    //   text.length <= 280
    // Abstraction function:
    //   AF(author, text, timestamp) = a post posted by author, with content text,
    //                                 at time timestamp
    // Safety from rep exposure:
    //   All fields are private;
    //   author and text are Strings, so are guaranteed immutable;
    //   timestamp is a mutable Date, so Post() constructor and getTimestamp()
    //        make defensive copies to avoid sharing the rep's Date object with clients.

    // Operations (specs and method bodies omitted to save space)
    public constructor(author: string, text: string, timestamp: Date) { ... }
    public getAuthor(): string { ... }
    public getText(): string { ... }
    public getTimestamp(): Date { ... }
}

注意，我们对 timestamp 没有任何显式的表示不变量条件（除了通常的假设，即 timestamp 不为 null，这对所有对象引用都成立）。但我们仍然需要在表示暴露安全性论证中包含 timestamp，因为整个类型的不可变性取决于抽象值保持不变，而抽象函数使用 timestamp 来映射到抽象值。 该论证不仅包括 TypeScript 可以静态检查的内容（私有字段和类型），还引用了实现者为了执行表示不变量而主动做的事情。

ADT 规范可以谈论什么

既然我们刚刚讨论了在哪里记录表示不变量和抽象函数，现在是更新我们对规范可以谈论什么的认识的好时机。

抽象类型 T 的规范——由其操作的规范组成——应该只谈论客户端可见的内容。 这包括参数、返回值以及其操作抛出的异常。 每当规范需要引用类型 T 的值时，它应该将该值描述为一个抽象值，即抽象空间 A 中的数学值。

规范不应该谈论表示的细节，或 rep 空间 R 的元素。 它应该将表示本身（私有字段）视为对客户端不可见的，就像方法体及其局部变量被视为不可见一样。 这就是为什么我们将表示不变量和抽象函数写成类体内的普通注释，而不是类上方的 TypeDoc 注释。 将它们写成 TypeDoc 注释会将它们固化为类型规范中公开的部分，这会干扰表示独立性和信息隐藏。

ADT 不变量取代前置条件

现在让我们把很多内容综合起来。一个设计良好的抽象数据类型的一个巨大优势是，它封装并强制实施了那些我们否则不得不在前置条件中规定的性质。例如，与其使用像这样带有繁琐前置条件的规范：

/**
 * @param set1 is a sorted set of characters with no repeats
 * @param set2 is likewise
 * @returns characters that appear in one set but not the other,
 *  in sorted order with no repeats
 */
static exclusiveOr(set1: string, set2: string): string;

我们可能会改为使用一个捕获所需性质的 ADT：

/**
 * @returns characters that appear in one set but not the other
 */
static exclusiveOr(set1: SortedCharSet, set2: SortedCharSet): SortedCharSet;

这达到了我们的所有目标：

  • 它更免受 bug 困扰，因为所要求的条件（已排序且无重复）可以在唯一的一个地方，即 SortedCharSet 类型中，被强制执行，而且因为静态检查开始起作用，从根本上防止不满足该条件的值被使用，并在编译时给出错误。

  • 它更易于理解，因为它更简单，而且名称 SortedCharSet 传达了程序员需要知道的内容。

  • 它更便于修改，因为 SortedCharSet 的表示现在可以更改，而无需更改 exclusiveOr 或它的任何客户端。

我们课程早期使用前置条件的许多地方，如果改用自定义的 ADT 都会受益。

如何建立不变量

不变量是对整个程序为真的性质——在关于对象的不变量的情况下，这简化为对象的整个生命周期。

为了使不变量成立，我们需要：

  • 在对象的初始状态下使不变量为真；以及
  • 确保对对象的所有改变都保持不变量为真。

用 ADT 操作的类型来翻译，这意味着：

  • 创建者和生产者必须为新对象实例建立不变量；以及
  • 变更者、观察器和生产者必须为现有对象实例保持不变量。

表示暴露的风险使情况变得更加复杂。 如果表示被暴露，那么对象可能在程序的任何地方被改变，而不仅仅是在 ADT 的操作中，而且我们无法保证在这些任意改变之后不变量仍然成立。

所以证明不变量的完整规则如下：

如果一个抽象数据类型的不变量

  1. 由创建者和生产者建立；
  2. 由变更者、观察者和生产者保持；以及
  3. 没有表示暴露发生，

那么该不变量对该抽象数据类型的所有实例都成立。

这个规则适用于抽象数据类型上的结构归纳法。

结构归纳法

回顾本次阅读第一个练习中的这个数据类型，现在它有了不同的 rep（以及新的 bug）：

/** Represents an immutable right triangle. */
class RightTriangle {
    private sides: number[];

    // Rep invariant:
    //   sides.length = 3
    //   sides[i] > 0 for all i
    //   sides[0]^2 + sides[1]^2 = sides[2]^2 (within the error tolerance of double arithmetic)

    // Abstraction function:
    //   AF(sides) = the right triangle with legs sides[0] and sides[1], and hypotenuse sides[2]


    /**
     * Make a right triangle.
     * @param legA, legB  the two legs of the triangle, must be positive
     * @param hypotenuse  the hypotenuse of the triangle, also positive,
     *           requires hypotenuse^2 = legA^2 + legB^2
     *           (within the error tolerance of double arithmetic)
     */
    public constructor(legA: number, legB: number, hypotenuse: number) {
        this.sides = new Array<number>(legA, legB, hypotenuse);
    }

    /**
     * Get all the sides of the triangle.
     * @returns three-element array with the triangle's side lengths
     */
    public getAllSides(): Array<number> {
        return this.sides;
    }

    /**
     * @returns length of the triangle's hypotenuse
     */
    public getHypotenuse(): number {
        return this.sides[2];
    }

    /**
     * @param factor to multiply the sides by, must be >0
     * @returns a triangle made from this triangle by
     * multiplying all side lengths by factor.
     */
    public scale(factor: number): RightTriangle {
        return new RightTriangle(this.sides[0]*factor, this.sides[1]*factor, this.sides[2]*factor);
    }

    /**
     * @returns a regular triangle made from this triangle.
     * A regular right triangle is one in which
     * both legs have the same length.
     */
    public regularize(): RightTriangle {
        const bigLeg: number = Math.max(this.sides[0], this.sides[1]);
        return new RightTriangle(bigLeg, bigLeg, this.sides[2]);
    }

}

这个数据类型有一个重要的不变量：直角边和斜边之间的关系，正如勾股定理所述。

编程食谱

抽象数据类型是软件构造的核心，关乎正确性、清晰性和可变性。

回顾测试优先编程方法：

编写一个方法

  1. 规范。 编写规范，包括方法签名（名称、参数类型、返回类型、异常），以及作为文档注释的前置条件和后置条件。
  2. 测试。 创建系统的测试用例，并把它们放入测试文件中，这样你就可以自动运行它们。
    1. 当你开始编写测试用例时，你可能不得不回头修改你的规范。 仅仅是编写测试用例的过程就会给你的规范带来压力，因为你在思考客户端会如何调用这个方法。 所以步骤 1 和步骤 2 会反复迭代，直到你有了更好的规范和一些好的测试用例。
    2. 确保你的至少一些测试一开始是失败的。 一个即使在你还没有实现该方法时也能通过所有测试的测试套件，并不是一个能发现 bug 的好测试套件。
  3. 实现。 编写方法体。 当所有测试都通过时，你就完成了。
    1. 实现该方法会给测试和规范都带来压力，你可能会发现必须回头修复的 bug。 所以完成该方法可能需要修改实现、测试和规范，并在它们之间来回切换。

让我们把它扩展为一个用于以下方面的食谱：

编写一个抽象数据类型

  1. 规范。 为数据类型的操作编写规范，包括方法签名、前置条件和后置条件。
    1. 这包括定义抽象值空间，但不包括抽象函数（因为我们还没有 rep）。
  2. 测试。 为 ADT 的操作编写测试用例。
    1. 同样，这会给规范带来压力。 你可能会发现你需要你之前没有预料到的操作，所以你必须把它们添加到规范中。
  3. 实现。 对于一个 ADT，这部分扩展为：
    1. 选择 rep。 写下类的私有字段（或者，正如我们在未来的阅读中将看到的，选择并定义一种不同类型的 rep）。 将表示不变量和抽象函数作为一个注释写下来。
    2. 断言表示不变量。 实现一个 checkRep() 方法来强制执行表示不变量。 如果表示不变量是非平凡的，这是至关重要的，因为它会早得多地捕获 bug。
    3. 实现操作。 编写操作的方法体，确保在其中调用 checkRep()。 当所有测试都通过时，你就完成了。

让我们把它进一步扩展为一个用于以下方面的食谱：

编写一个程序

（由 ADT 和函数组成）

  1. 选择数据类型。 决定哪些将是可变的，哪些是不可变的。
  2. 选择函数。 编写你的顶层 main 函数，并将其分解为更小的步骤。
  3. 规范。 为 ADT 和函数制定规范。 开始时保持 ADT 操作简单且数量少。 只在需要时才添加复杂的操作。
  4. 测试。 为每个单元（ADT 或函数）编写测试用例。
  5. 先简单地实现。 选择简单的、暴力破解的表示。 这里的重点是对规范和测试施加压力，并尽快把你的整个程序组合起来。 先让整个程序正确地工作。 暂时跳过高级特性。 暂时跳过性能优化。 暂时跳过边界情况。 保留一份你必须重新处理的事项的待办清单。
  6. 迭代。 现在一切都在工作了，让它工作得更好。 如果需要，重新实现、优化、重新设计。

小结

  • 一个不变量是对一个 ADT 对象实例始终为真的性质，贯穿该对象的整个生命周期。
  • 一个好的 ADT 保持其自身的不变量。不变量必须由创建者和生产者建立，并由观察器和变更者保持。
  • 表示不变量规定了表示的合法值，并应在运行时通过 checkRep() 进行检查。
  • 抽象函数将具体的表示映射到它所表示的抽象值。
  • 一个不可变 ADT 的表示可以改变，只要它所表示的抽象值不改变。
  • 表示暴露同时威胁到表示独立性和不变量的保持。
  • 一个不变量应该被记录下来，通过注释，或者更好的是通过像 checkRep() 这样的断言，否则该不变量在免受 bug 困扰方面是不安全的。

今天阅读的主题与我们优秀软件的三个性质之间的联系如下：

  • 免受 bug 困扰。 一个好的 ADT 保持其自身的不变量，使得这些不变量不易受到 ADT 客户端中 bug 的影响，并且不变量的违反可以更容易地在 ADT 本身的实现内部被隔离。明确陈述表示不变量，并在运行时通过 checkRep() 进行检查，能更早地发现误解和 bug，而不是继续带着一个损坏的数据结构往下走。

  • 易于理解。 表示不变量和抽象函数阐明了数据类型表示的含义，以及它与其抽象之间的关系。

  • 便于修改。 抽象数据类型将抽象与具体表示分离开来，使得在不更改客户端代码的情况下更改表示成为可能。
