6.102 网络应用

我无法登录某个 6.102 网络应用。

有几种可能的解决方法，请按以下顺序依次尝试：

  1. 请确保你在校园里没有使用 MIT GUEST Wi-Fi 网络，因为它的互联网访问非常有限。请将 MIT GUEST 从你电脑的已批准网络列表中移除，并优先使用MIT SECURE。

  2. 确保你使用的是安全的 https:// URL，而不是 http://。

  3. 尝试重启浏览器；如果不起作用，请尝试使用其他网页浏览器：Chrome、Firefox、Safari。

  4. 尝试删除浏览器中与你尝试登录的网站相关的 cookies。

  5. 6.102 的系统使用 Touchstone 进行登录。如果你无法登录，首先检查你是否能够登录其他使用 Touchstone 认证的网站，例如 MIT WebSIS。

  6. 你是否正在使用 Windows 并开启了杀毒软件检查？有时杀毒软件会干扰 SSL 连接，导致每个浏览器都出现 SSL_PROTOCOL_ERROR。尝试暂时关闭杀毒软件检查，看看是否能解决问题。如果可以，请在杀毒软件配置中找到将网络服务器添加到“允许”列表的方法。

如果以上方法都无效，请在 Piazza 上发帖，并附上你尝试访问的 URL、你是否能够通过双因素认证登录，以及任何错误信息。

构建与运行

我无法编译或运行问题集上的测试。

请确保你已经在问题集文件夹中运行了 npm install。

npm test 或 npm run 或其他 npm 命令产生奇怪的错误。

这有时是由于 node_modules 文件夹损坏造成的，该文件夹由 npm install 创建和维护。

要查看是否是这个原因，请进入你的问题集文件夹，找到并删除 node_modules 文件夹，然后再次运行 npm install。

npm test 或 npm run ... 产生错误 sh: ... command not found。

使用 pwd 查看问题集文件夹的完整路径。如果路径中的任何文件夹包含任何不寻常的字符（例如，空格、除下划线或连字符以外的标点符号、非英语字符），请尝试将你的问题集文件夹移动到仅使用字母、数字、连字符和下划线的路径。

使用 Git

我在使用 Windows，运行 git 时出现“permission denied”，或者在做 gitstream 练习时无法运行 go.sh。

请确保你使用的是 Git Bash 作为终端，而不是 Windows 命令提示符或 Windows Subsystem for Linux。

当我执行 git push origin main 时，出现 error: failed to push some refs ...

你可能需要更新到最新版本的 git。请使用 git --version 并确保你的版本是 2.34 或更高版本。如有必要，请更新或重新安装 Git。

不过这个警告是无害的。只要你的提交仍然显示在 Didit 上，那么这个错误可以安全地忽略。

使用 VS Code

我无法从命令行使用 VS Code。

如果你在终端中输入 code（或 codium），但 VS Code（或 VSCodium）没有启动，请改用图形用户界面启动 VS Code 或 VSCodium，将其配置为从命令行启动，关闭并重新打开终端，然后再次尝试运行 code 或 codium。

当我在 VS Code 中看到变量、方法或类的名称时，如何直接跳转到它的定义？

在名称上执行 Command+Click（Mac）或 Control+Click（Windows & Linux）即可跳转到其定义。右键单击并选择 Go to Definition 也可以达到同样的效果。

如何快速注释和取消注释我的部分代码？

使用 Edit → Toggle Line Comment 可以快速切换某些代码行的注释状态。键盘快捷键是 Command+/（Mac）或 Control+/（Windows & Linux）。

如何在 VS Code 中快速调出命令面板？

按 Command+Shift+P（Mac）或 Control+Shift+P（Windows & Linux）即可调出命令面板。从中你可以搜索任何 VS Code 命令。例如，尝试输入“focus”来查找打开特定视图并将键盘焦点置于其上的命令。然后输入“tutor”来查找将 Tutor 视图置于焦点的命令（例如类似“Explorer: Focus on Praxis Tutor View”的命令）。
