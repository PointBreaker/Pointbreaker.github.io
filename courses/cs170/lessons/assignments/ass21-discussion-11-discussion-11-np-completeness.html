1NP 问题的运行时间题目 · 提示 · 答案
官方题面翻译可离线作答官方解答已收录

完整题面

判断正误（并给出简要证明）：假设我们能证明，对于某个固定的常数 \(k\)，某个 NP-完全问题 \(P\) 存在时间复杂度为 \(O(n^k)\) 的算法。那么 NP 中的每个问题都存在时间复杂度为 \(O(n^k)\) 的算法。

查看解题提示

注意从任意问题 \(L \in \text{NP}\) 到 \(P\) 的多项式归约会引入「规模膨胀」：归约本身的运行时间是输入规模 \(n\) 的某个多项式，归约后实例的大小也是 \(n\) 的某个多项式，但这些多项式的次数可能彼此不同，也可能与 \(k\) 不同。尝试构造一种情形，使得归约后实例的规模是原规模的二次（或更高次）多项式。

展开官方参考解答

False。

从任意问题 \(L \in \text{NP}\) 到 \(P\) 的归约 \(f_L\) 保证在时间 \(O(n^{c_L})\) 内运行，并产生一个大小为 \(O(n^{c'_L})\) 的 \(P\) 的实例，其中 \(c_L\) 与 \(c'_L\) 是常数。然而，这两个常数可以任意地大于 \(k\)。

例如，如果从某个 NP 问题 \(L\) 到 \(P\) 的归约耗时 \(O(n^2)\)，而 \(P\) 有一个 \(O(n)\) 的算法，那么我们为 \(L\) 得到的算法将至少需要 \(\Omega(n^2)\) 的时间，而不是 \(O(n)\)。因此，仅凭「某个 NP-完全问题有 \(O(n^k)\) 算法」不能推出「NP 中所有问题都有 \(O(n^k)\) 算法」。

2归约热身：无向 Rudrata 路径到 DAG 最长路径题目 · 提示 · 答案
官方题面翻译可离线作答官方解答已收录

完整题面

在无向 Rudrata 路径问题（Undirected Rudrata Path，即哈密顿路径问题 Hamiltonian Path Problem）中，给定一个具有无向边的图 \(G\) 作为输入，目标是判断 \(G\) 中是否存在一条恰好经过每个顶点一次的路径。

在 DAG 最长路径问题（Longest Path in a DAG）中，给定一个有向无环图（DAG）和一个变量 \(k\) 作为输入，目标是判断该 DAG 中是否存在长度至少为 \(k\) 的路径。

下面的归约是否正确？如果正确，给出一个简明的证明；如果不正确，说明理由并给出一个反例。

「无向 Rudrata 路径可以归约到 DAG 最长路径。对于给定的无向图 \(G\)，我们使用深度优先搜索（DFS）找到 \(G\) 的一种遍历，并根据该遍历为 \(G\) 中的所有边指定方向：边的指向与它们被首次遍历的方向一致，回边（back edges）被省略，从而得到一个 DAG。如果该 DAG 中最长路径包含 \(|V|-1\) 条边，那么 \(G\) 中必定存在一条 Rudrata 路径，因为任何具有 \(|V|-1\) 条边的简单路径都必须经过每个顶点；若这一点成立，我们就可以说原图中存在一条 Rudrata 路径。由于运行 DFS 耗时多项式时间 \(O(|V|+|E|)\)，该归约是合法的。」

图表条件 · 反例图：左侧为原无向图（4 个顶点 A-B-C-D 构成的路径，含弦边 A-C），右侧为按特定 DFS 序定向后得到的 DAG（A→C, C→B, C→D），展示最长路径长度从 3 降为 2

原无向图 G：顶点 {A,B,C,D}，边 {A-B, B-C, C-D, A-C}（或等价结构，使得存在 Rudrata 路径 A-B-C-D） DFS 定向后的 DAG：有向边 {A→C, C→B, C→D}，最长路径长度 = 2（如 A→C→B 或 A→C→D）

来源：dis11-sol.pdf · 2

查看解题提示

一个正确的归约必须证明「双向性」：原实例有解 当且仅当 变换后的实例有解。题目中的论述只证明了「DAG 有长度为 \(|V|-1\) 的路径 \(\Rightarrow\) 原图有 Rudrata 路径」这一个方向。试着思考：如果原图 \(G\) 确实有一条 Rudrata 路径，按照上述 DFS 定向方式，得到的 DAG 是否一定也存在长度为 \(|V|-1\) 的路径？构造一个 4 个顶点的图，使得 DFS 访问顶点的顺序「打乱」了原 Rudrata 路径上边的方向。

展开官方参考解答

该归约不正确。

论述中确实证明了：如果 DAG 中最长路径的长度为 \(|V|-1\)，那么 \(G\) 中存在 Rudrata 路径。然而，要证明一个归约正确，必须证明双向性——即若通过变换把问题 A 的实例 \(I\) 变成问题 B 的实例 \(I'\)，则 \(I\) 有解 当且仅当 \(I'\) 有解。在上述「归约」中，有一个方向不成立：如果 \(G\) 有 Rudrata 路径，我们产生的 DAG 不一定 存在长度为 \(|V|-1\) 的路径——这取决于我们为边选择方向的方式（即 DFS 的遍历顺序）。

具体反例：考虑一个 4 个顶点的图，其顶点为 \(A, B, C, D\)，原图中存在一条 Rudrata 路径。在该图上执行 DFS 时，有可能先访问节点 \(C\) 再访问节点 \(B\)（例如因为存在边 \(A\text{--}C\) 且 DFS 优先走了这条边），于是生成的 DAG 中各边的方向为 \(A \to C\)、\(C \to B\)、\(C \to D\)（或等价定向），其最长路径长度为 2，而不是 3。尽管原图确实存在 Rudrata 路径，但得到的 DAG 中不存在长度为 3 的路径，因此该归约在「仅当」方向上失败。

3是不是 NP：复杂度分类选择题题目 · 提示 · 答案
官方题面翻译可离线作答官方解答已收录

完整题面

对于下列每个陈述，选出（唯一的）使该陈述成立的条件。

(a) 如果 \(B\) 是 NP-完全的（NP-complete），那么对于任意问题 \(A \in \text{NP}\)，存在从 \(A\) 到 \(B\) 的多项式时间归约。

  • 总是成立（Always True）

  • 当且仅当 \(\text{P} = \text{NP}\) 时成立

  • 当且仅当 \(\text{P} \neq \text{NP}\) 时成立

  • 总是不成立（Always False）

(b) 如果 \(B\) 属于 NP，那么对于任意问题 \(A \in \text{P}\)，存在从 \(A\) 到 \(B\) 的多项式时间归约。

  • 总是成立（Always True）

  • 当且仅当 \(\text{P} = \text{NP}\) 时成立

  • 当且仅当 \(\text{P} \neq \text{NP}\) 时成立

  • 总是不成立（Always False）

(c) 2-SAT 是 NP-完全的。

  • 总是成立（Always True）

  • 当且仅当 \(\text{P} = \text{NP}\) 时成立

  • 当且仅当 \(\text{P} \neq \text{NP}\) 时成立

  • 总是不成立（Always False）

(d) 最小生成树（Minimum Spanning Tree）属于 NP。

  • 总是成立（Always True）

  • 当且仅当 \(\text{P} = \text{NP}\) 时成立

  • 当且仅当 \(\text{P} \neq \text{NP}\) 时成立

  • 总是不成立（Always False）

查看解题提示

(a) 回顾 NP-完全的定义：一个问题若属于 NP，且 NP 中所有问题都能归约到它，则它是 NP-完全的。(b) 如果 \(A\) 已经能在多项式时间内求解，那么在归约过程中我们是否还有「额外时间」直接解出 \(A\) 的答案？(c) 2-SAT 是否已知有多项式时间算法？如果 \(\text{P} \neq \text{NP}\)，NP-完全问题（如 3-SAT）能否归约到它？(d) 如果一个问题的解能在多项式时间内验证，它就属于 NP。MST 的判定版本（是否存在代价不超过预算 \(b\) 的生成树）能否在多项式时间内验证？

展开官方参考解答

(a) 总是成立（Always True）。

这正是 NP-难（NP-hard）的定义，而所有 NP-完全问题都是 NP-难的。

(b) 总是成立（Always True）。

由于归约本身允许多项式时间，我们完全可以在归约过程中直接求解任意 \(A\) 的实例（因为 \(A \in \text{P}\)），然后根据答案映射到 \(B\) 的某个有解或无解的固定实例。

(c) 当且仅当 \(\text{P} = \text{NP}\) 时成立。

根据定义，一个 NP-完全问题必须属于 NP，且 NP 中所有问题都存在到它的多项式归约。

  • 如果 \(\text{P} \neq \text{NP}\)，则不可能存在从 3-SAT 这类 NP-完全问题到 2-SAT 的多项式时间归约（否则 2-SAT 将是 NP-难的，与它已在 P 中矛盾）。

  • 如果 \(\text{P} = \text{NP}\)，则存在如下多项式归约：由于 \(\text{P} = \text{NP}\)，存在多项式时间算法求解 3-SAT。归约时先求解 3-SAT 实例——若有解，则映射到一个可满足的 2-SAT 实例；若无解，则映射到一个不可满足的 2-SAT 实例。于是 NP 中所有问题（均可归约到 3-SAT）都多项式归约到 2-SAT。

(d) 总是成立（Always True）。

MST 可在多项式时间内求解，因此也可在多项式时间内验证。其判定版本为：「是否存在一棵总代价不超过预算 \(b\) 的生成树？」给定一个候选生成树，可在多项式时间内验证其合法性与总代价。

4California Cycle（加州环）题目 · 提示 · 答案
官方题面翻译可离线作答官方解答已收录

完整题面

证明下面的问题是 NP-难的（NP-hard）。

  • 输入：一张有向图 \(G = (V, E)\)，其中每个顶点被染成蓝色或金色，即 \(V = V_{\text{blue}} \cup V_{\text{gold}}\)。

  • 目标：找出一个「加州环」（Californian cycle），即一条经过 \(G\) 中所有顶点的有向环，且环上顶点颜色必须蓝、金交替出现。

提示：使用 Directed Rudrata Cycle（有向 Rudrata 环）进行归约。

图表条件 · California Cycle 归约构造示意图：展示原图 G 中的一个顶点 v 如何被拆为蓝色 v_b 与金色 v_g，原边 (u,v) 如何变为 u_g→v_b，以及 v_b→v_g 的蓝金边

原图 G：有向边 (u, v) 新图 G'：

  • 顶点：{u_b, u_g, v_b, v_g}

  • 蓝金边：u_b→u_g, v_b→v_g

  • 原边对应：u_g→v_b 展示一个 3 顶点有向环如何映射为蓝金交替的 California Cycle

来源：dis11-sol.pdf · 3

查看解题提示

关键观察：在 California Cycle 中，每个顶点必须恰好有一条入边和一条出边被使用，且颜色必须交替。考虑把原图 \(G\) 的每个顶点 \(v\) 拆成两个顶点：一个蓝色副本 \(v_b\) 和一个金色副本 \(v_g\)。原图中的每条有向边 \((u, v)\) 应该如何对应到新图中连接蓝/金副本的边？思考如何让任意一个有向环都自然地变成蓝金交替的环。

展开官方参考解答

我们通过将 Directed Rudrata Cycle 归约到 Californian Cycle 来证明后者的 NP-难性。

给定一个有向图 \(G = (V, E)\)，构造新图 \(G' = (V', E')\) 如下：

  • \(V'\) 包含顶点集 \(V\) 的两个副本：对每个 \(v \in V\)，有一个蓝色节点 \(v_b\) 和一个金色节点 \(v_g\)。

  • 对每个 \(v \in V\)，在 \(G'\) 中加一条从 \(v_b\) 到 \(v_g\) 的边。

  • 对每条 \((u, v) \in E\)，在 \(G'\) 中加一条从 \(u_g\) 到 \(v_b\) 的边。

另一种理解方式是：对每个节点 \(v \in V\)，我们将其所有入边重定向到 \(v_g\)，所有出边都从 \(v_b\) 出发（在 \(G'\) 中）。

正确性说明：

  • \(G\) 中的任意一个环都对应 \(G'\) 中一个蓝金交替的环：原环上每条边 \((u, v)\) 变成 \(u_g \to v_b\)，再经蓝金边 \(v_b \to v_g\) 回到下一个起点。因此若 \(G\) 包含 Rudrata 环，则 \(G'\) 包含 California Cycle。

  • 反之，\(G'\) 中每条从蓝节点到金节点的边的两个端点都对应 \(G\) 中同一个顶点。因此若 \(G'\) 有 California Cycle，只需忽略该环中所有蓝金边（\(v_b \to v_g\)），就能得到 \(G\) 中的一个 Rudrata 环。

该构造可在多项式时间内完成，因此 Directed Rudrata Cycle \(\leq_P\) California Cycle，California Cycle 是 NP-难的。

5破解加密题目 · 提示 · 答案
官方题面翻译可离线作答官方解答已收录

完整题面

经过多年的研究，Horizon Wireless 发布了一种加密算法 \(E\)，它能在 \(O(n^2)\) 时间内加密一个 \(n\) 比特的消息。证明：如果 \(\text{P} = \text{NP}\)，那么该加密算法可以在多项式时间内被破解。更准确地说，论证如果 \(\text{P} = \text{NP}\)，下面的解密问题可以在多项式时间内求解。

Decrypt：

  • 输入：一条加密消息 \(M\)（使用算法 \(E\) 加密得到）

  • 目标：对 \(M\) 进行解密。

查看解题提示

要说明一个问题是 NP 问题，需要给出一个多项式时间的验证器（verifier）：给定一个候选解，如何在多项式时间内验证它是正确的解密结果？验证过程需要调用加密算法 \(E\)，而 \(E\) 的运行时间是已知的。然后思考：若 \(\text{P} = \text{NP}\)，一个 NP 问题会落到哪个复杂度类中？

展开官方参考解答

首先注意到 \(\text{Decrypt} \in \text{NP}\)。这是因为：给定加密消息 \(M\) 的一个候选解密结果 \(x\)，我们可以运行 \(E(x)\) 并检查它是否输出 \(M\)。由于 \(E(x)\) 有一个 \(O(N^2)\) 的算法，我们可以在多项式时间内完成这一检查。因此，Decrypt 是一个 NP 问题。

现在，如果 \(\text{P} = \text{NP}\)，那么 Decrypt 也将在 P 中。这意味着 Decrypt 可以在多项式时间内求解——即我们可以在多项式时间内恢复出任意密文 \(M\) 对应的明文，从而「破解」该加密算法。
