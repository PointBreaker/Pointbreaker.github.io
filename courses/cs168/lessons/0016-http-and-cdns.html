本章核心问题

同一网页有几十个对象时，握手、依赖、缓存与队头阻塞怎样共同决定首屏时间？

30 秒心智模型

HTTP 定义请求/响应语义，传输层负责字节交付。缓存减少必须跨网传输的对象，CDN 把副本放近用户，版本协议改善并发调度。

1 · 请求与响应契约

请求包含 method、target、headers 和可选 body；响应包含 status、headers 与 body。GET 通常是安全且幂等的读取，POST 常用于提交状态变化，但最终语义由服务定义。

Host/:authority 让同一 IP 承载多个站点。Content-Length、chunked framing 或协议帧界定对象边界，不能依赖 TCP 的 recv 次数。

2 · 连接与并发

HTTP/1.1 persistent connection 避免为每个对象重复 TCP 握手，但单连接按序处理会受 head-of-line blocking。浏览器常开多个连接或用 pipelining 的有限变体。

HTTP/2 在一条 TCP 上多路复用 stream，消除应用层队头，却仍受 TCP 丢包影响；HTTP/3 基于 QUIC，让不同 stream 的丢失恢复更独立。协议升级改变的是阻塞边界，而非光速。

3 · 缓存正确性

Cache-Control 指定 freshness 与共享规则，ETag/Last-Modified 支持条件请求。命中 fresh 对象可直接返回；stale 对象可用 If-None-Match 验证，304 响应避免重传 body。

缓存 key 若遗漏 Vary 指定的请求维度，会把错误版本交给用户；若把用户私有响应放入共享缓存，则可能泄露数据。性能优化必须服从语义隔离。

4 · CDN 的两次选择

权威 DNS 可把用户引向合适的边缘站点，BGP/anycast 再把地址流量送往拓扑上可达的实例。选择可能考虑地理/网络距离、负载、故障与内容是否已缓存。

边缘 miss 会回源并填充缓存。评估 CDN 不能只看 hit ratio，还要按对象大小、流行度和回源成本加权。

纠错：最容易带走的错误模型

HTTP/2 多路复用不代表完全没有队头阻塞；所有 stream 共用一条 TCP 时，一个丢失 segment 仍会挡住后续字节交付。
