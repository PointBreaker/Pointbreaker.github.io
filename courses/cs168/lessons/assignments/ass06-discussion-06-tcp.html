Prediction → Work → Evidence

1 · Prediction

在每个 segment 后画发送窗口：[已确认 | 在途 | 可发送 | 窗口外]，同时记录接收端连续前缀。

2 · Work

每小问先写已知状态和允许发生的事件，再写公式/表项变化；答案旁标出使用了哪个不变量。不要从 solution 反推过程。

3 · Evidence

数值题保留单位，协议题保留事件顺序，图题保留每条边/表项来源。随后用官方 solution 逐行对照，错误归类为概念、状态、算术或边界。

失败签名与调试梯子

  • 按“包编号”而非字节编号计算 ACK
  • 忘记 SYN/FIN 各占一个序号
  • 乱序到达就直接交付应用
Hint 1 · Concept

把 payload 写成半开区间 [seq, seq+len)。ACK 指向尚未连续收到的第一个字节。

Hint 2 · Invariant

把题目当前时刻必须成立的一条关系写在纸顶；每一步更新后重新检查，而不是只看最终答案像不像。

Hint 3 · Debug strategy

缩到最小拓扑/最少包/最短时间线，固定 tie-break，并把一次事件拆成“输入 → 局部状态 → 输出”。

能力门

在丢包、超时、重复 ACK、窗口变化的时序图上，能逐事件更新双方控制块。

通过标准：Correct 与 solution 一致；Understand 能说明每一步因果；Evidence 保留可复查的表、图或单位。
