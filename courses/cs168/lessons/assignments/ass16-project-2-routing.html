距离向量路由器：当前 spec × 历史实现复盘

实现能安装直连路由、转发数据、交换距离向量、处理超时/链路变化，并用 split horizon、poison reverse、route poisoning 与增量触发更新控制环路和流量的路由器。

状态：Fall 2026 当前 spec；历史代码来自 PointBreaker/routing。提交所需的精确接口、测试与限制始终以当前官方 spec 为准。

工程合同

What you build
实现能安装直连路由、转发数据、交换距离向量、处理超时/链路变化，并用 split horizon、poison reverse、route poisoning 与增量触发更新控制环路和流量的路由器。
核心不变量
表项是当前本地决策，history 是每个邻居已看到的投影；两者不能共用一个一维 destination 状态。
Definition of Done
Correct：当前适用测试通过；Understand：能从事件解释状态变化；Evidence：保留最小 trace、失败注入和边界测试。
禁止捷径
不读取模拟器隐藏全局状态，不修改框架绕过协议，不把本教材伪装成提交实现。

依赖优先的实现路径

1 · 数据平面地基（官方 Stage 1–2）

Build
静态 host 路线使用 port latency 和 FOREVER；只有表中存在且 metric < INFINITY 才转发。
Evidence
add_static_route / handle_data_packet 的最小表项与 drop contract。

2 · 基础 DV（Stage 3–4）

Build
广告值加本地 port latency 并截断到 INFINITY；目的不存在、来自当前 next hop、或候选更优时更新。
Evidence
在三节点线形拓扑按事件记录 table diff 与 triggered update。

3 · 新鲜度（Stage 5、9）

Build
动态路线写 expire_time；过期可删除或先毒化一个 TTL。直连路线永不过期。遍历时避免改变字典大小。
Evidence
时间刚小于/等于/大于 expire_time 的边界测试。

4 · 环路抑制（Stage 6–8）

Build
split horizon 对 next-hop 邻居沉默；poison reverse 对它发送 INFINITY；有限 INFINITY 截断 count-to-infinity。
Evidence
两节点与三节点环路对照轨迹，说明保护边界。

5 · 增量与链路事件（Stage 10A–10B）

Build
发送历史按 (dst, port) 记录“该邻居实际看到的 metric”；link up 只向新端口同步，link down 统一毒化受影响路线再触发更新。
Evidence
force / single_port / incremental 三维组合测试。

最小 sanity check

先构造只含两个端点和一个可控故障的最小场景。预测每条消息、字段和状态变化，再运行一次；任何额外消息、无法解释的表项或越界状态都视为失败，即使最终输出碰巧正确。

以下结论来自你提供的公开仓库与提交历史。它们服务于复盘，不复制完整实现，也不声称旧代码满足当前未发布/已变化的 spec。

  1. 2023-11-08：从 skeleton 到 Stage 4，再到 Stage 8、route poisoning 与 Stage 10 调试。
  2. 2023-11-09：提交信息标记全部测试完成；最终实现引入 history[(dst, port)]。
  3. 复盘点：single_port 分支完成指定端口发送后仍继续进入普通增量循环。当前 spec 明确 single_port 非空时不得发送其他端口，应用 spy/mock 记录 send_route 调用验证。
  4. 重构方向：先用纯函数 effective_metric(entry, out_port) 统一 split horizon/poison reverse，再由一个循环处理 force、history 与发送。

失败签名

  • 按 destination 而非 (destination, port) 保存历史
  • 忽略同 next-hop 的更差更新
  • link down 在每个表项内触发一次全表发送
  • 把历史通过测试等同当前 spec 兼容
Hint 1 · Concept

先指出哪个协议不变量被破坏，不要直接添加特判。

Hint 2 · Structure

让每个输入事件只经过一次“验证 → 状态转移 → 输出”流水线；把可纯计算的部分提取成无副作用函数。

Hint 3 · Debug strategy

对边界前后各造一个输入，用 spy 记录所有发送动作，并在每次 mutation 后断言控制块/表项关系。

完成后的复盘

  1. 哪个状态是真正的 single source of truth？
  2. 哪些测试只证明输出，哪些测试能证明没有额外副作用？
  3. 如果消息延迟、重复、乱序或刚好落在边界，会破坏哪条假设？
  4. 今天重写时，你会先设计哪三个 helper / invariant？
