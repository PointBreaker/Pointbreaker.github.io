Why Did We Need This?

神经网络接收 tensor，离散字符串既没有固定 shape，也不能直接求梯度。Tokenizer 负责确定离散单元与 ID；embedding table 负责把 ID 映射到可学习连续空间。两步不能混为一谈。

Why Position?

同一个 token ID 每次从 table 取出的初始向量相同；attention 若没有 position，本身只看到一个无序集合。把 position vector 加进去，让“第一个 3”与“第二个 3”在进入 block 前已经可区分。

Historical implementation note：保存的 sinusoidal implementation 使用 floor(a / M) 生成 denominator，导致测试维度中的频率没有按标准公式展开。它通过了 Notebook 给定的 saved check，但现代严格实现应使用不被 floor 抹平的 2i/M 频率指数。

Why This Design?

  • 把数字拆成 digits，可用 10 个数字 token 组合未见过的两位数；代价是模型必须学习位值和进位。
  • 共享 embedding table，让同一符号在 encoder/decoder 都从同一基础向量出发。
  • position 与 token vector 同 shape，相加后不改变后续 block 的接口。

Common misconceptions：Token ID 11 不比 ID 3 “更大”；embedding 不是 contextual representation；两个相同 digit 的初始 embedding 可相同，但 position 与 attention 之后 representation 会不同。

Then vs Now · 连接 CS336

EECS498 toy tokenizer

人工定义 16-token vocab；special words 保持整体；数字按 digit 切分。

Modern LLM tokenizer

Unicode → UTF-8 bytes → BPE/subword merges → token IDs；vocab 从数据学习。

概念链没变：string → discrete tokens → IDs → embedding。变化的是 token boundary 如何确定，以及 vocabulary 的规模与训练方式。

Concept Checks

V=16, M=64，输入 IDs shape=[32,9]，embedding 后 shape？embedding 参数 shape？

输出 [32,9,64]；table 参数 [16,64]。每个 ID 选择一行，不增加 one-hot 维。

为什么 token ID 14 不能理解成“语义数值 14”？

它只是 BOS 所在的 row index；任意重排 IDs 并同步重排 embedding rows，模型语义不变。

两个 token ID 都是 3，进入 embedding 时相同，经过 Transformer 后为什么可不同？

位置向量不同；并且每个位置根据周围 tokens 读取不同信息，逐层形成不同 contextual representation。
