Training vs Inference

Training

每一步拿到真实 previous target tokens（teacher forcing），所有 positions 并行算 loss。

Inference

只有自己先前生成的 tokens；预测一个、append、再 forward。错误可能滚入后续 prefix。

Why This Design?

若训练也逐 token sampling，会浪费并行性并让早期随机错误污染监督；teacher forcing 提供稳定、正确 prefix。代价是 exposure mismatch：训练总见真 prefix，生成会见自己的错误。

Historical implementation note：Notebook 同时记录 DecoderBlock unit-check mismatch 与完整模型训练成功。二者可以同时成立：局部 expected check、skeleton/version 或实现细节有差异；最终 metric 也不能反过来证明每个 unit 完全正确。

Common misconception：Encoder 不是先“算出数字答案”再交给 decoder。它产生可查询 representations；最终答案规律由 cross-attention、decoder states 与 vocab projection 共同学习。

Concept Checks

target shape=[32,5]，为何通常得到 32×4 个 next-token predictions？

BOS … EOS 有 5 tokens，但 decoder input/label 各错位一格，所以有 4 个 transition targets。

若移除 causal mask但仍 shift target，模型能作弊吗？

能。位置 i 的 self-attention 可读 decoder tensor 中后续真实 target embeddings，包括自己将预测的 token。

Validation token accuracy 0.8213 是否意味着完整答案 accuracy 也约 82%？

不一定。完整 sequence 要多个 tokens 全对，sequence accuracy 通常更低；autoregressive inference 还有 error propagation。

Teacher forcing 与现代 next-token prediction 的直接关系？

都用真实 prefix 预测下一 token；一个 batch 中通过 shift+causal mask 并行监督所有位置。
