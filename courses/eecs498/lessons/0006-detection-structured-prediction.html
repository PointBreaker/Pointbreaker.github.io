Why Did We Need This?

Image classifier 把整图压成一个 label，无法表示多对象与位置。Detector 保留 backbone 的空间 grid，让每个位置/anchor 都能提出一个结构化假设。

image[B,3,H₀,W₀]
features[B,1280,H,W]
anchors[B,A,H,W,4]
predictionsconf + offsets + class
detectionsvariable count × 6

Mental model

Detection 把“一个输入对应一个答案”改成“空间中每个候选位置都提出一个带置信度的结构化答案，再去重”。

Mechanism · anchor → offset → proposal

Anchor 是预定义 reference box；网络不从零预测绝对坐标，而是预测相对中心/尺度的 offset。IoU 把 proposal 与 ground truth 配对，正负 anchor 决定哪些输出接受监督。

One stage vs two stage

One-stage

直接在 dense grid 上同时做 objectness、box regression 与 class prediction；你完成的主线在这里。

Two-stage

先用 RPN 提 proposals，再对较少候选做 ROI classification/regression，分开“哪里可能有物体”与“是什么”。

Why NMS?

相邻 anchors 常对同一物体产生高分重叠框。NMS 按 score 取最高框，再删除 IoU 超阈值的候选；它不是训练出的 reasoning，而是把冗余 dense hypotheses 变成最终集合的后处理规则。

Common misconception：class score 高不等于 box 准。Detection loss 必须分别监督 objectness、localization 与 class；最终排序还可能组合这些信号。

Then vs Now

DETR 用 set prediction 与 bipartite matching 减少 anchors/NMS 依赖，但 structured output 的核心问题没变：模型必须把 dense representation 转成数量可变、带位置的对象集合。

Concept Checks

B=2,A=9,H=W=7，每个 anchor 预测 1 conf + 4 offsets，共多少 anchor hypotheses？

2×9×7×7=882；每张图 441 个，之后还要结合 class scores 与 NMS。

为什么用 offsets 而非直接预测全图绝对坐标更容易？

每个 anchor 提供局部 reference 与尺度，目标变成相对的小修正，分布更稳定且可在各 grid location 共享预测头。

两框 IoU 很大但类别不同，class-agnostic NMS 可能有什么问题？

它可能错误删除另一个真实类别；class-aware NMS 会分开类别处理。这说明后处理规则也是模型行为的一部分。
