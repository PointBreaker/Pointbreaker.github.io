Backtrace 中等

在 kernel/printf.c 中实现 backtrace() 函数。在 sys_pause 中插入对此函数的调用，然后运行 bttest。

backtrace:
0x0000000080002cda
0x0000000080002bb6
0x0000000080002898

一些提示：

  • 将 backtrace() 的原型添加到 kernel/defs.h
  • GCC 编译器将当前函数的帧指针存储在寄存器 s0 中。在 kernel/riscv.h 中添加： 
    static inline uint64
r_fp()
{
  uint64 x;
  asm volatile("mv %0, s0" : "=r" (x) );
  return x;
}
  • 返回地址位于帧指针的固定偏移 -8 处，保存的帧指针位于偏移 -16 处
  • 使用 PGROUNDDOWN(fp) 识别帧指针引用的页

Alarm 困难

你将向 xv6 添加一个功能，在使用 CPU 时间时定期提醒进程。添加一个新的 sigalarm(interval, handler) 系统调用。如果应用调用 sigalarm(n, fn)，则在程序消耗每个 n 个 CPU "tick" 后，内核应该调用应用函数 fn。

$ alarmtest
test0 start
........alarm!
test0 passed
...
test3 passed
$ usertests -q
...
ALL TESTS PASSED

test0：调用处理程序

一些提示：

  • 修改 Makefile 编译 alarmtest.c
  • 在 user/user.h 中放入正确的声明： 
    int sigalarm(int ticks, void (*handler)());
int sigreturn(void);
  • 更新 user/usys.pl、kernel/syscall.h 和 kernel/syscall.c
  • sys_sigalarm() 应该将警报间隔和处理程序函数指针存储在 proc 结构的新字段中
  • 在 usertrap() 中，仅当有定时器中断时操作警报 tick（if(which_dev == 2)）
  • 当进程的警报间隔到期时，用户进程应该执行处理程序函数

test1/test2()/test3()：恢复中断的代码

你必须确保当警报处理程序完成后，控制返回到用户程序被定时器中断中断的指令。你必须确保寄存器内容恢复到中断时的值。

一些提示：

  • 你需要保存和恢复寄存器——哪些寄存器需要保存和恢复？
  • 让 usertrap 在定时器到期时在 struct proc 中保存足够的状态，使 sigreturn 可以正确返回到中断的用户代码
  • 防止处理程序的重入调用——如果处理程序尚未返回，内核不应该再次调用它
  • 确保恢复 a0（sigreturn 是系统调用，其返回值存储在 a0 中）
