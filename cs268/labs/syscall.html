沙箱化命令 中等

在这个任务中，你将"沙箱化"一个进程以限制它可以进行的系统调用。例如，可以沙箱化一个进程以禁止打开文件。你将创建一个新的 interpose 系统调用，指定内核应该拒绝哪些系统调用。

interpose 应该接受两个参数：一个整数掩码和一个路径。掩码的位指定要拒绝的系统调用。例如，要阻止进程使用 open 系统调用，它应该调用 interpose(1 << SYS_open, "-")。

$ sandbox 32768 - cat README
cat: cannot open README
$

一些提示：

  • 将 $U/_sandbox 添加到 Makefile 中的 UPROGS
  • 将 interpose 的原型添加到 user/user.h，将桩添加到 user/usys.pl，将系统调用号添加到 kernel/syscall.h
  • 在 kernel/sysproc.c 中添加 sys_interpose() 函数
  • 修改 kfork() 将掩码从父进程复制到子进程
  • 修改 syscall() 函数检查是否必须拒绝系统调用

允许路径名的沙箱 简单

在这个任务中，你将扩展沙箱以允许基于路径名的掩码 open 和 exec 系统调用。如果 open 或 exec 被掩码但路径名与允许的路径名匹配，则应该允许这些系统调用。

$ sandbox 32768 README grep xv6 README
xv6 is a re-implementation of Dennis Ritchie's and Ken Thompson's Unix Version 6 (v6).
$ sandbox 32768 README grep xv6 x
grep: cannot open x
$

攻击 xv6 中等

user/secret.c 在其内存中写入一个秘密字符串，然后退出（释放其内存）。你的目标是在 user/attack.c 中添加几行代码，找到前一次执行 secret.c 写入内存的秘密，并单独打印该秘密。

$ secret xyzzy
$ attack
xyzzy
$

本实验故意省略了 uvmalloc() 中的 memset(mem, 0, sz) 和 kalloc.c 中的两行 memset。结果是，新分配的内存保留上次使用的内容。
