Lab: 网络驱动

在本实验中，你将编写一个 xv6 网络设备卡（NIC）驱动程序，然后编写以太网/IP/UDP 协议处理栈的接收半部分。

难度：中等

分支：net

实验日期：2026 秋季

$ git fetch

背景

在编写代码之前，你可能需要复习xv6 手册的第 6 章："中断和设备驱动程序"。

你将使用称为 E1000 的网络设备来处理网络通信。对 xv6（和你编写的驱动程序）来说，E1000 看起来像连接到真实以太网局域网（LAN）的真实硬件。事实上，你的驱动程序将与之通信的 E1000 是由 qemu 提供的仿真。

在此仿真 LAN 上，xv6（"客户"）的 IP 地址为 10.0.2.15。运行 qemu 的计算机（"主机"）以 IP 地址 10.0.2.2 出现在 LAN 上。

我们将 QEMU 配置为将所有传入和传出数据包记录到实验目录中的文件 packets.pcap 中：

tcpdump -XXnr packets.pcap

我们为本实验向 xv6 仓库添加了一些文件：

  • kernel/e1000.c：E1000 的初始化和空函数，你将填写
  • kernel/e1000_dev.h：E1000 定义的寄存器和标志位
  • kernel/net.c 和 kernel/net.h：实现 IP、UDP 和 ARP 协议的简单网络栈
  • kernel/pci.c：在 xv6 启动时在 PCI 总线上搜索 E1000 卡的代码

第一部分：NIC 中等

你的工作是完成 kernel/e1000.c 中的 e1000_transmit() 和 e1000_recv()，以便驱动程序可以发送和接收数据包。

在编写代码时，你将参考 E1000 软件开发人员手册，特别是：

  • 第 3.2 节描述数据包接收（但跳过 3.2.8 和 3.2.9）
  • 第 3.3.1、3.3.2、3.3.3 和 3.4 节描述传输
  • 第 13 节描述 E1000 的寄存器

我们提供的 e1000_init() 函数配置 E1000 从 RAM 读取要传输的数据包，并将接收到的数据包写入 RAM。这种技术称为 DMA（直接内存访问）。

E1000 需要一个"描述符"数组来描述接收缓冲区。描述符数组称为接收环（receive ring）或接收队列。struct rx_desc 描述描述符格式。还有一个传输环。

e1000_transmit 提示

  • 首先通过读取 E1000_TDT 控制寄存器获取 E1000 期望下一个数据包的 TX 环索引
  • 检查环是否溢出。如果 E1000_TXD_STAT_DD 未在索引为 E1000_TDT 的描述符中设置，返回错误
  • 使用 kfree() 释放从该描述符传输的最后一个缓冲区（如果有）
  • 填写描述符，设置必要的 cmd 标志
  • 通过将 E1000_TDT 加 1 模 TX_RING_SIZE 来更新环位置

e1000_recv 提示

  • 首先通过获取 E1000_RDT 控制寄存器并加 1 模 RX_RING_SIZE 来获取下一个等待接收的数据包的环索引
  • 通过检查描述符状态部分的 E1000_RXD_STAT_DD 位检查新数据包是否可用。如果没有，停止
  • 通过调用 net_rx() 将数据包缓冲区传递给网络栈
  • 使用 kalloc() 分配新缓冲区替换刚给 net_rx() 的那个
  • 最后，将 E1000_RDT 寄存器更新为最后处理的环描述符的索引
  • e1000 可以在一个中断中传递多个数据包；你的 e1000_recv 应该处理这种情况

第二部分：UDP 接收 中等

UDP（用户数据报协议）允许不同 Internet 主机上的用户进程交换单个数据包（数据报）。UDP 分层在 IP 之上。

你的工作是填写 kernel/net.c 中 ip_rx()、sys_recv() 和 sys_bind() 的实现。

系统调用 API 规范

// 发送 UDP 数据包
send(short sport, int dst, short dport, char *buf, int len)

// 接收 UDP 数据包
recv(short dport, int *src, short *sport, char *buf, int maxlen)

// 绑定端口（在 recv 之前调用）
bind(short port)

一些提示：

  • 创建一个结构跟踪绑定端口及其队列中的数据包
  • 参考 kernel/proc.c 中的 sleep() 和 wakeup() 函数实现 recv() 的等待逻辑
  • sys_recv() 复制到的目标地址是虚拟地址；你需要从内核复制到当前用户进程
  • 确保释放已被复制或丢弃的数据包
